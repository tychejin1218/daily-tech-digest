### 1. `Collectors.partitioningBy(predicate, downstream)`로 `if/else` 두 번 필터링하는 관성 벗어나기 (Java 8 정식)

한 컬렉션을 조건에 따라 둘로 나눌 때, `filter(pred)`와 `filter(pred.negate())`로 스트림을 두 번 소비하는 코드가 흔하다. `partitioningBy`는 단 한 번의 순회로 `Map<Boolean, List<T>>`를 만들며, downstream 콜렉터를 함께 넘기면 `Map<Boolean, Long>`(개수), `Map<Boolean, Double>`(합계) 등으로 바로 집계까지 끝낼 수 있다. `groupingBy`와 달리 항상 `true`/`false` 두 키가 보장되므로 `getOrDefault(true, List.of())` 같은 안전장치도 필요 없다.

```java
// AS-IS: 스트림 두 번 순회 + 방어 코드
List<Order> paid = orders.stream().filter(Order::isPaid).toList();
List<Order> unpaid = orders.stream().filter(o -> !o.isPaid()).toList();

// TO-BE: 한 번 순회 + downstream으로 합계까지
Map<Boolean, BigDecimal> totalByPaid = orders.stream()
    .collect(Collectors.partitioningBy(
        Order::isPaid,
        Collectors.reducing(BigDecimal.ZERO, Order::amount, BigDecimal::add)
    ));
BigDecimal paidTotal = totalByPaid.get(true);   // 항상 존재
BigDecimal unpaidTotal = totalByPaid.get(false); // 항상 존재
```

> 💡 **왜 중요한가**: 이진 분류(성공/실패, 유료/무료, VIP/일반)는 실무의 절반 이상을 차지하는 패턴인데, `groupingBy(bool)` 대신 `partitioningBy`를 쓰면 "빈 그룹이 아예 없다"는 컴파일러 대신 콜렉터가 주는 계약을 얻는다.

### 2. `StructuredTaskScope.open()`(ShutdownOnFailure)로 병렬 호출 중 하나만 실패해도 나머지를 자동 취소하기 (Java 25 정식, JEP 505)

여러 외부 API를 병렬로 호출할 때 `CompletableFuture.allOf()`는 하나가 실패해도 나머지를 계속 돌린다 — CPU·커넥션·비용을 낭비하고, 심지어 실패 원인을 감춘다. Java 25에서 정식화된 `StructuredTaskScope`는 "하나 실패 → 형제 태스크 자동 인터럽트 → 부모까지 예외 전파"라는 구조적 동시성 계약을 제공하며, try-with-resources로 스코프가 닫힐 때 모든 자식 스레드의 생명주기가 부모와 함께 끝난다는 것이 보장된다.

```java
// TO-BE: 하나 실패하면 나머지 fetch는 즉시 취소됨
try (var scope = StructuredTaskScope.open(
        StructuredTaskScope.Joiner.<Object>anySuccessfulResultOrThrow())) {
    // 실패 시 전체 취소 원할 땐 awaitAll() + 아래처럼 별도 처리
}

try (var scope = StructuredTaskScope.<Object>open()) {
    Subtask<User>    user    = scope.fork(() -> userApi.find(id));
    Subtask<Order>   orders  = scope.fork(() -> orderApi.recent(id));
    Subtask<Coupon>  coupons = scope.fork(() -> couponApi.available(id));

    scope.join();  // 하나라도 실패하면 예외 전파 + 형제들 자동 인터럽트

    return new Dashboard(user.get(), orders.get(), coupons.get());
} // 스코프 종료 시 모든 자식 스레드 정리 보장
```

> 💡 **왜 중요한가**: `CompletableFuture` 조합은 "실패해도 흘러가는" 비구조적 모델이라 취소·타임아웃·예외 전파를 개발자가 직접 엮어야 했지만, `StructuredTaskScope`는 그것을 언어 수준 계약으로 만들어 리소스 누수와 좀비 태스크의 근본 원인을 제거한다.
