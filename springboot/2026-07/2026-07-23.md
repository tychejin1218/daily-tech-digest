### `@Transactional`의 `readOnly = true`는 단순 힌트가 아니라 성능 최적화 트리거다

`@Transactional(readOnly = true)`는 롤백만 하는 안전장치로 오해하기 쉽지만, Hibernate에게 `FlushMode.MANUAL`을 설정해 dirty checking 대상에서 제외하고 스냅샷 저장을 생략한다. 또한 MySQL/PostgreSQL 드라이버는 이 플래그를 받아 read replica로 라우팅하거나 read-only 트랜잭션으로 처리해 락 오버헤드를 줄인다.

```java
@Transactional(readOnly = true)
public List<UserDto> findAll() {
    return userRepository.findAll().stream()
        .map(UserDto::from)
        .toList();
}
```

> 💡 **왜 중요한가**: 조회 메서드에 `readOnly = true`를 붙이는 것만으로 스냅샷 메모리 절감과 replica 라우팅이 동시에 활성화된다.

### `HttpMessageConverter` 순서에 따라 `application/json` 응답이 텍스트로 나갈 수 있다

`WebMvcConfigurer.configureMessageConverters()`에서 컨버터 리스트에 커스텀 `StringHttpMessageConverter`를 앞쪽에 추가하면 `MappingJackson2HttpMessageConverter`보다 우선순위가 높아져 `Accept: */*` 요청이 문자열로 직렬화된다. `extendMessageConverters()`로 기존 순서를 유지한 채 확장하거나, `converters.add(0, ...)` 대신 `converters.add(...)`로 뒤에 추가해야 안전하다.

```java
@Override
public void extendMessageConverters(List<HttpMessageConverter<?>> converters) {
    converters.add(new ProtobufHttpMessageConverter());
}
```

> 💡 **왜 중요한가**: `configureMessageConverters`는 기본 컨버터를 모두 덮어쓰기 때문에 순서를 잘못 잡으면 JSON API가 조용히 텍스트 응답으로 바뀐다.
