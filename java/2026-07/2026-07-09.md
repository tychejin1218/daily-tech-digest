### `Thread.ofVirtual()`로 I/O 바운드 작업을 수만 개 동시에 처리하기 (Java 21 정식)

가상 스레드는 OS 스레드에 1:1로 매핑되지 않고 JVM이 스케줄링하는 경량 스레드로, 블로킹 I/O가 발생하면 캐리어 스레드에서 언마운트되어 다른 가상 스레드에 자리를 내준다. `Thread.ofVirtual().start(...)` 또는 `Executors.newVirtualThreadPerTaskExecutor()`로 태스크당 스레드 하나를 생성해도 수십만 개까지 부담 없이 굴러가므로, 리액티브 코드로 뒤틀지 않고도 동시성 처리량을 극적으로 끌어올릴 수 있다.

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<String>> results = urls.stream()
        .map(url -> executor.submit(() -> httpClient.send(request(url), ofString()).body()))
        .toList();
    for (var f : results) System.out.println(f.get());
}
```

> 💡 **왜 중요한가**: 스레드 풀 사이징·백프레셔·논블로킹 콜백 지옥 없이도 "스레드당 요청" 모델 그대로 수만 건의 I/O를 동시에 처리할 수 있다.

### `HexFormat`으로 바이트 배열↔16진수 변환을 표준 API로 끝내기 (Java 17 정식)

해시·암호·바이너리 프로토콜을 다룰 때 흔히 `String.format("%02x", b)` 루프나 서드파티 유틸(Apache Commons, Guava)에 의존했지만, Java 17부터는 `HexFormat`이 인코딩과 파싱을 양방향으로 지원한다. 구분자·접두사·대소문자까지 설정할 수 있어 로그 출력이든 REST 페이로드든 한 줄이면 끝난다.

```java
byte[] digest = MessageDigest.getInstance("SHA-256").digest(payload);
String hex = HexFormat.of().formatHex(digest);              // "e3b0c442..."
String pretty = HexFormat.ofDelimiter(":").withUpperCase()
                          .formatHex(digest);               // "E3:B0:C4:42:..."
byte[] parsed = HexFormat.of().parseHex(hex);               // 역변환도 지원
```

> 💡 **왜 중요한가**: JDK 표준 API만으로 인코딩·파싱·포맷팅이 완결되므로, 손수 만든 유틸이나 외부 라이브러리 의존성을 제거하고 성능·정확성도 함께 확보한다.
