### PostgreSQL `pg_repack` — 운영 중 테이블 락 없이 VACUUM FULL 효과 내기

`VACUUM FULL`은 테이블 전체에 `ACCESS EXCLUSIVE` 락을 걸어 사실상 다운타임을 유발하지만, `pg_repack` 확장은 트리거로 변경 사항을 임시 테이블에 모으며 새 테이블을 만들고 마지막에 짧은 락만으로 스왑한다. Bloat가 심한 대용량 테이블이나 인덱스를 무중단으로 재구성할 수 있어 운영 환경에서 표준 도구로 자리잡았다.

```bash
# 테이블 전체 재구성 (온라인)
pg_repack -h localhost -U postgres -d mydb -t orders

# 인덱스만 재구성
pg_repack -d mydb -t orders --only-indexes
```

> 💡 **왜 중요한가**: 24/7 운영 서비스에서 VACUUM FULL은 사실상 사용할 수 없고, pg_repack이 사실상 유일한 무중단 bloat 해소 수단이다.

### JPA `@DynamicUpdate` — 변경된 컬럼만 UPDATE 문에 포함시키기

Hibernate는 기본적으로 엔티티의 모든 컬럼을 UPDATE 문에 포함하기 때문에 컬럼이 많은 테이블에서는 불필요한 쓰기와 인덱스 갱신이 발생한다. `@DynamicUpdate`를 붙이면 더티 체킹으로 변경이 감지된 컬럼만 동적으로 SQL을 만들어 발행하므로, 인덱스 수가 많거나 TOAST 컬럼이 있는 테이블에서 쓰기 비용을 크게 줄일 수 있다.

```java
@Entity
@DynamicUpdate
public class Product {
    @Id private Long id;
    private String name;
    private BigDecimal price;
    @Lob private String description;  // TOAST 대상
}
```

대신 쿼리 캐싱 효율이 떨어지므로(매번 다른 SQL 생성), 컬럼이 적고 거의 항상 같이 변경되는 엔티티에는 오히려 손해다.

> 💡 **왜 중요한가**: 인덱스가 많은 와이드 테이블에서 `@DynamicUpdate` 한 줄로 UPDATE 비용과 인덱스 유지 비용을 동시에 줄일 수 있다.
