### 1. `Suspense` 안에서 `useState`가 "초기화"되는 함정 — Suspense가 자식을 "언마운트"시키는 숨겨진 메커니즘

`<Suspense fallback={...}>` 안의 컴포넌트가 데이터 fetching이나 lazy loading으로 "다시 suspend"되는 순간, React는 fallback을 보여주기 위해 해당 서브트리를 **언마운트에 가까운 상태**로 전환합니다. 이때 `useState`로 담아둔 폼 입력값, 스크롤 위치, 토글 상태 등이 **조용히 초기화**되는데, 많은 개발자가 "왜 입력값이 사라지지?"라며 `useEffect`나 외부 state로 우회하다가 구조를 망칩니다. 진짜 해결책은 `useDeferredValue`나 `startTransition`으로 "기존 UI를 유지한 채" 새 데이터를 기다리게 만드는 것 — fallback으로 떨어지지 않으면 state도 보존됩니다.

```jsx
// ❌ 검색어가 바뀔 때마다 Suspense fallback이 뜨면서
//    SearchResults 내부의 "정렬 옵션" state가 초기화됨
<Suspense fallback={<Spinner />}>
  <SearchResults query={query} />
</Suspense>

// ✅ deferredQuery로 "이전 결과를 보여주면서" 새 데이터 기다림
//    → Suspense가 다시 트리거되지 않아 자식 state 보존
const deferredQuery = useDeferredValue(query);
<Suspense fallback={<Spinner />}>
  <SearchResults query={deferredQuery} />
</Suspense>
```

> 💡 **왜 중요한가**: Suspense는 "로딩 UI 보여주기"가 아니라 "서브트리의 생명주기를 제어하는 경계"다 — 이를 모르면 React 18의 데이터 fetching 패턴 전체가 버그의 온상이 된다.

### 2. `children` prop은 "성능 최적화 도구"다 — 부모가 리렌더링돼도 자식이 리렌더링되지 않는 비밀

React에서 부모 컴포넌트가 리렌더링되면 자식도 함께 리렌더링되는 게 기본값이지만, **`children`으로 전달된 JSX는 "부모의 부모"가 만든 것**이라 부모 컴포넌트의 state가 바뀌어도 `children`의 참조는 바뀌지 않습니다. 이 성질 덕분에 `React.memo` 없이도 "자주 바뀌는 state를 가진 컴포넌트" 안에 "비싼 자식"을 안전하게 둘 수 있습니다. 많은 개발자가 성능 문제를 `useMemo`나 `memo`로 해결하려 하지만, **컴포넌트 경계를 다시 그리는 것**만으로 끝나는 경우가 대부분입니다.

```jsx
// ❌ MousePosition이 매 마우스 이동마다 ExpensiveChart를 리렌더링
function Page() {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={e => setPos({ x: e.clientX, y: e.clientY })}>
      <p>{pos.x}, {pos.y}</p>
      <ExpensiveChart />  {/* 매번 리렌더링됨 */}
    </div>
  );
}

// ✅ state를 소유한 컴포넌트를 분리하고, 비싼 자식은 children으로 주입
function Page() {
  return (
    <MouseTracker>
      <ExpensiveChart />  {/* Page에서 생성 → MouseTracker state 바뀌어도 참조 동일 */}
    </MouseTracker>
  );
}

function MouseTracker({ children }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={e => setPos({ x: e.clientX, y: e.clientY })}>
      <p>{pos.x}, {pos.y}</p>
      {children}  {/* Page가 넘긴 참조 그대로 → 리렌더링 X */}
    </div>
  );
}
```

> 💡 **왜 중요한가**: React의 리렌더링은 "컴포넌트 트리"가 아니라 "JSX가 어디서 만들어졌는가"를 따라간다 — 이 원리를 알면 `memo` 남발 없이 컴포넌트 구조만으로 성능 문제를 해결할 수 있다.
