### `StructuredTaskScope.open()` (Java 25 정식, JEP 505)로 fork/join 병렬 작업을 구조화하기 — `CompletableFuture.allOf()`로 묶어 예외 전파·cancel 전파를 손수 조율하던 관성 벗어나기

구조화된 동시성(Structured Concurrency)이 Java 25에서 **정식 API**로 승격됐다. `try-with-resources`로 스코프를 열고 `scope.fork()`로 subtask를 던진 뒤 `scope.join()`만 하면, 한 subtask가 실패하는 순간 나머지 형제들이 자동으로 인터럽트되고 예외는 호출자까지 그대로 전파된다. `CompletableFuture.allOf(...).join()`으로는 "하나 터지면 나머지 cancel" 같은 상위 레벨 조율을 매번 손으로 짜야 했다.

```java
try (var scope = StructuredTaskScope.open()) {   // 기본 정책: fail-fast
    Subtask<User>  u = scope.fork(() -> userClient.find(id));
    Subtask<Order> o = scope.fork(() -> orderClient.fetch(id));
    scope.join();                                 // 모두 끝나거나 하나 터질 때까지
    return new Profile(u.get(), o.get());         // 실패 시 여기서 바로 ExecutionException
}
// 스코프 벗어나는 순간 미완료 subtask는 인터럽트 + 리소스 정리 보장
```

> 💡 **왜 중요한가**: 가상 스레드(Loom)의 "스레드는 싸다"가 실무에서 안전하려면 *수명을 묶는* 문법이 필수다. StructuredTaskScope는 fan-out/join을 **스택 프레임처럼** 다루게 해서, leak된 좀비 태스크와 "한 쪽만 살아남은 좀비 응답" 같은 분산 호출 버그를 컴파일러 수준이 아닌 **스코프 종료 규칙**으로 막아준다.

### `Stream.iterate(seed, hasNext, next)` (Java 9 정식, JEP 269 계열)로 for-loop을 스트림에 1:1로 옮기기 — `Stream.iterate(seed, next).limit(n)` / `.takeWhile(...)` 로 두 단계 나눠 쓰던 관성 벗어나기

2-인자 `Stream.iterate`는 종료 조건이 없어서 꼭 `limit`나 `takeWhile`을 한 단계 더 붙여야 했다. Java 9부터 들어온 **3-인자 오버로드**는 `for (int i = seed; hasNext(i); i = next(i))` 삼박자를 **그대로** 스트림으로 옮겨 쓸 수 있고, 내부적으로 `SIZED`가 아닌 **종료가능(ORDERED) spliterator**를 만들어주기 때문에 `takeWhile`이 하던 "조건이 처음 거짓이 된 뒤에도 소스가 계속 발행하는" 낭비도 없다.

```java
// Before: 두 단계로 쪼개져 의도가 흐려짐
Stream.iterate(1, i -> i * 2).limit(20).takeWhile(i -> i < 1_000_000);

// After: for-loop 삼요소를 한 호출에
Stream.iterate(1, i -> i < 1_000_000, i -> i * 2)
      .forEach(System.out::println);

// 날짜 순회도 깔끔
Stream.iterate(start, d -> !d.isAfter(end), d -> d.plusDays(1))
      .map(reportService::daily)
      .toList();
```

> 💡 **왜 중요한가**: "스트림으로 바꾸려다 결국 for-loop이 더 읽히는데?"의 90%는 *종료 조건*을 표현할 자연스러운 문법이 없어서였다. 3-인자 `iterate`는 **명령형의 종료 조건을 함수형 파이프라인 안으로 끌어들이는 다리**라, 리포트·백오프·페이지네이션처럼 "조건이 충족될 때까지 반복하며 변환" 패턴을 한 번에 함수형으로 선언할 수 있게 해준다.
