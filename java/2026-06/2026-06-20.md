### `Files.lines()`를 try-with-resources로 안전하게 스트리밍 읽기 (Java 8 정식)
`Files.lines(path)`는 파일을 한 줄씩 지연(Lazy) 평가로 흘려보내 거대한 로그/CSV를 메모리 폭주 없이 처리하지만, 내부적으로 파일 핸들을 잡고 있어 반드시 `Stream`을 `close()` 해야 디스크립터 누수가 생기지 않습니다. `Files.readAllLines()`와 달리 try-with-resources 블록 안에 묶어 사용하는 것이 정석입니다.

```java
try (Stream<String> lines = Files.lines(Path.of("access.log"), StandardCharsets.UTF_8)) {
    long errors = lines.filter(l -> l.contains(" 5"))
                       .count();
    System.out.println("5xx count = " + errors);
}
```

> 💡 **왜 중요한가**: 수 GB 로그 분석에서도 힙 사용량이 일정하게 유지되며, try-with-resources 누락만 막아도 운영 서버의 "Too many open files" 장애 한 종류를 통째로 예방할 수 있습니다.

### `Comparator.comparing()` 메서드 레퍼런스 체인으로 다단 정렬 가독성 살리기 (Java 8 정식)
복합 정렬을 만들 때 `(a, b) -> a.getX().compareTo(b.getX())`를 직접 작성하면 null 처리·역순·다단 조건이 섞이며 금세 뒤엉킵니다. `Comparator.comparing()`을 `thenComparing()`·`reversed()`·`nullsLast()`와 조합하면 정렬 규칙을 코드 줄 그대로 읽을 수 있는 DSL처럼 작성할 수 있습니다.

```java
Comparator<Order> cmp = Comparator
    .comparing(Order::getPriority, Comparator.reverseOrder())  // 우선순위 내림차순
    .thenComparing(Order::getCreatedAt)                        // 같으면 오래된 것 먼저
    .thenComparing(Order::getCustomerName,                     // 그래도 같으면 고객명 사전순
                   Comparator.nullsLast(String::compareTo));
orders.sort(cmp);
```

> 💡 **왜 중요한가**: 정렬 우선순위와 null 처리를 한눈에 검토할 수 있어, "왜 이 행이 위로 올라왔지?" 같은 회귀 디버깅 시간이 크게 줄어듭니다.
