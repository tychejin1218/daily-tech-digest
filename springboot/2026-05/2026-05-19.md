### `@Cacheable`의 `sync = true`로 캐시 스탬피드(Cache Stampede) 방지하기

`@Cacheable(value = "products", key = "#id", sync = true)`처럼 `sync` 속성을 활성화하면 동일 키에 대한 동시 요청이 들어와도 단 하나의 스레드만 원본 메서드를 실행하고, 나머지는 그 결과를 대기 후 공유합니다. 캐시 만료 직후 트래픽이 몰리는 상황(특히 외부 API 호출이나 무거운 DB 쿼리)에서 백엔드 폭주를 막는 가장 간단한 방법입니다. 단, 분산 환경에서는 JVM 내부 락만 제공하므로 Redis 등에서는 Redisson 분산 락과 조합해야 합니다.

> 💡 **왜 중요한가**: 동일 키 동시 미스 시 백엔드 호출이 한 번으로 수렴되어, 캐시 만료 순간의 트래픽 스파이크에서도 원본 시스템이 보호됩니다.

### `@Validated`를 클래스 레벨에 붙여 서비스 계층 메서드 파라미터까지 검증하기

`@Valid`는 `@RequestBody` 같은 컨트롤러 진입점에서만 동작하지만, 클래스에 `@Validated`를 선언하면 메서드 파라미터(`@NotBlank String name`, `@Min(1) int page` 등)까지 AOP 프록시 기반으로 검증됩니다. 서비스/리포지토리 내부 호출에서도 잘못된 입력을 빠르게 차단할 수 있어 방어 코드(`if (name == null) throw ...`)를 크게 줄일 수 있습니다. 검증 실패 시 `ConstraintViolationException`이 던져지므로 `@RestControllerAdvice`에서 별도로 핸들링해 일관된 응답을 반환하는 것이 좋습니다.

> 💡 **왜 중요한가**: 검증 책임을 컨트롤러에만 의존하지 않고 서비스 계층까지 확장해, 내부 호출 경로에서 발생하는 잘못된 입력도 일관되게 차단할 수 있습니다.
