### 1. React 18 "자동 배칭(Automatic Batching)"은 왜 `setTimeout` 안에서도 setState를 묶어주는가 — React 17에서 "두 번 렌더되던" 코드가 갑자기 한 번으로 바뀌는 함정

React 17까지는 이벤트 핸들러 안의 `setState`만 배칭되고, `setTimeout`·`Promise.then`·`fetch` 콜백 안의 setState는 **각각 리렌더링을 트리거**했다. React 18은 이 제약을 걷어내고 "어디서 호출되든 같은 틱의 setState는 하나의 렌더로 묶는" 방식으로 바꿨는데, 이 덕분에 성능은 좋아졌지만 "두 번 렌더링을 가정하고 짜둔 레거시 코드"가 조용히 깨진다. 예외적으로 즉시 반영이 필요할 때(예: DOM 측정 후 스크롤 이동)만 `flushSync(() => setState(...))`로 배칭을 수동으로 뚫어야 한다.

```jsx
// React 17: 두 번 렌더링 (count, flag 각각)
// React 18: 한 번 렌더링 (자동 배칭)
setTimeout(() => {
  setCount(c => c + 1);
  setFlag(f => !f);
}, 0);

// 배칭을 깨야 할 때만
import { flushSync } from 'react-dom';
flushSync(() => setCount(c => c + 1));  // 여기서 즉시 DOM 반영
divRef.current.scrollTop = divRef.current.scrollHeight;  // 그 다음 측정
```

> 💡 **왜 중요한가**: "렌더 사이에 DOM이 중간 상태로 노출될 것"이라 가정한 코드—예를 들어 setState 후 바로 `ref.current.offsetHeight`를 읽는 로직—가 React 18로 올리는 순간 조용히 어긋난다. 해결책은 `flushSync`지만, 남용하면 자동 배칭의 성능 이점을 통째로 버리게 되므로 "DOM 측정이 반드시 필요한 지점"에만 국소적으로 써야 한다.

### 2. `createPortal`로 렌더링한 자식은 "DOM 트리상 다른 곳"에 있어도 이벤트가 **React 트리의 부모**로 버블링된다 — 모달 안 클릭이 바깥 `onClick`을 터뜨리는 미스터리의 정체

`createPortal(child, document.body)`로 모달을 `body` 바로 아래에 띄우면 DOM 구조상으로는 완전히 분리되지만, React는 이벤트를 **실제 DOM 부모가 아니라 JSX상의 부모**로 전파시킨다. 즉 Portal 자식에서 발생한 `click`은 DOM 상으로는 `body → html`로만 올라가는데, React의 합성 이벤트 레이어가 가로채서 "원래 JSX에서 Portal을 선언한 컴포넌트의 조상"까지 버블링시킨다. 이 때문에 모달 바깥 영역의 `onClick={closeModal}`이 모달 내부 클릭에도 터지는 "닫히지 말아야 할 때 닫히는" 버그가 생긴다.

```jsx
function Parent() {
  return (
    <div onClick={() => console.log('부모 클릭!')}>  {/* ← 이게 터진다 */}
      {createPortal(
        <button onClick={() => console.log('모달 버튼')}>확인</button>,
        document.body  // DOM상 완전히 분리된 위치
      )}
    </div>
  );
}
// 버튼 클릭 → "모달 버튼" + "부모 클릭!" 둘 다 출력
// 해결: 모달 버튼에서 e.stopPropagation() 또는 부모 핸들러에서 e.target 체크
```

> 💡 **왜 중요한가**: 드롭다운·툴팁·모달 같은 "바깥 클릭 시 닫기(outside click)" 패턴을 `document.addEventListener('click')`로 구현하면 Portal 자식 클릭이 바깥 클릭으로 오인되어 즉시 닫혀버린다. React 합성 이벤트 버블링을 이해해야 "왜 ref 비교는 통과하는데 모달이 깜빡 닫히는지"의 근본 원인을 잡을 수 있고, `event.target`을 DOM 트리가 아닌 React 트리 관점에서 검사해야 한다.
