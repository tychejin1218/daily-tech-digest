### 1. `spring.threads.virtual.enabled=true`로 가상 스레드(Virtual Threads) 활성화하기 (Spring Boot 3.2+)

Java 21의 가상 스레드를 프로퍼티 한 줄로 Tomcat 워커, `@Async`, `TaskScheduler`에 일괄 적용할 수 있습니다. I/O 대기가 많은 API 서버라면 플랫폼 스레드 풀 튜닝 없이 훨씬 많은 동시 요청을 처리할 수 있고, 애플리케이션 코드는 그대로 두어도 됩니다. 단, `synchronized` 블록 안에서의 블로킹 I/O는 캐리어 스레드를 핀(pin)시켜 이점을 상쇄하므로 `ReentrantLock`으로 바꾸는 검토가 필요합니다.

```yaml
spring:
  threads:
    virtual:
      enabled: true
```

> 💡 **왜 중요한가**: 스레드 풀 크기 = 동시성 상한이라는 오래된 제약이 사라져, 커넥션 풀·다운스트림 지연이 진짜 병목인지 드러납니다.

### 2. `HikariCP`의 `leak-detection-threshold`로 커넥션 누수 조기 탐지하기

트랜잭션 밖에서 `EntityManager`를 열거나 반환하지 않은 커넥션이 있으면 Pool Exhausted 장애로 이어지는데, HikariCP는 임계 시간을 넘긴 커넥션 대여자의 스택 트레이스를 경고 로그로 남겨줍니다. 프로덕션에서도 성능 영향이 거의 없어 상시 켜두는 것을 권장하며, 값은 트랜잭션이 정상적으로 끝날 수 있는 최대 시간보다 살짝 크게 잡습니다.

```yaml
spring:
  datasource:
    hikari:
      leak-detection-threshold: 5000  # ms
      maximum-pool-size: 20
```

> 💡 **왜 중요한가**: 커넥션 누수는 재현이 어려운 반면, 이 옵션 하나로 누수 지점의 스택 트레이스를 로그에서 바로 확인할 수 있어 원인 규명 시간이 극적으로 줄어듭니다.
