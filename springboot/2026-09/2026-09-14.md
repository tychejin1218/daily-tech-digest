### `spring.jpa.open-in-view`의 기본값은 `true` — 뷰 렌더링이 끝날 때까지 DB 커넥션을 붙잡고 있다

Spring Boot는 OSIV(Open Session In View) 패턴을 **경고 로그만 남기고 조용히 활성화**한다. 컨트롤러가 뷰(또는 JSON 직렬화)를 반환하는 순간까지 영속성 컨텍스트와 커넥션이 유지되므로, Lazy 로딩이 마법처럼 동작하는 대신 외부 API 호출·복잡한 응답 직렬화 시간 내내 커넥션 풀이 소모된다. 트래픽이 몰리는 순간 커넥션 풀이 먼저 고갈되고, DB는 멀쩡한데 앱이 대기하는 현상이 벌어진다.

> 💡 **왜 중요한가**: 개발할 땐 편하지만 프로덕션에선 커넥션 풀 튜닝을 아무리 해도 답이 안 나오는 원인이 되며, `false`로 끄는 순간 Lazy 로딩 예외가 쏟아져 서비스 계층 리팩터링이 강제된다.

### `@Async`의 기본 실행기는 `SimpleAsyncTaskExecutor` — 요청마다 **새 스레드를 만든다**

`TaskExecutor` 빈을 명시하지 않으면 Spring은 풀이 없는 `SimpleAsyncTaskExecutor`로 폴백하는데, 이 클래스는 이름만 "Executor"일 뿐 **매 호출마다 `new Thread()`를 생성**한다. 트래픽이 튀면 수천 개의 스레드가 순식간에 만들어져 메모리와 컨텍스트 스위칭 비용이 폭발하고, JVM은 `OutOfMemoryError: unable to create new native thread`로 죽는다. Spring Boot 3.2+에서는 가상 스레드 옵션이 생겼지만, 그것도 명시적으로 켜야 적용된다.

> 💡 **왜 중요한가**: `@EnableAsync`만 붙이고 커스텀 `Executor` 빈을 등록하지 않으면 부하 테스트 없이는 절대 드러나지 않는 시한폭탄을 심어두는 셈이다.
