### MCP 2026-07-28 스펙 정식 채택 확산 — Stateless Core + OIDC로 프로토콜에 '엔터프라이즈 자물쇠'를 걸다
Anthropic Claude를 시작으로 새 MCP(Model Context Protocol) 2026-07-28 스펙 지원이 벤더 전반에 확산됐다. **상태 비저장(stateless) 코어**, 강화된 **OAuth/OIDC 인가**, Apps·Tasks용 **버전드 확장**을 도입했고, 커넥터에는 임베디드 UI·관리형 인증·관측성·프라이빗 네트워크 터널링이 표준 편입됐다. "실험적 개방 프로토콜"에서 감사(audit) 가능한 산업 표준으로 승격되는 순간이다.

> 💡 **왜 중요한가**: 이제 사내 툴 MCP 서버가 SSO·네트워크 정책 심사를 통과해야 붙는다 — MCP가 "AI가 회사 시스템에 그냥 연결되는 구멍"에서 "보안팀이 관리하는 정식 인터페이스"로 성격이 바뀌었다.

### Cursor 3 'Multi-Agent Dispatch' 정식 도입 — 프로젝트를 잘라 여러 에이전트에 병렬 할당, 리뷰 UI에서 병합
Cursor 3가 하나의 프로젝트를 여러 영역으로 분할해 서로 다른 에이전트에게 **동시 할당**하고, 각 결과물을 통합 리뷰 UI에서 diff·머지하는 워크플로우를 정식 지원한다. 백엔드 리팩토링, 프런트 컴포넌트 추가, 마이그레이션 스크립트 작성을 한 개발자가 병렬로 돌리는 게 실제 IDE UX로 구현됐다. 트레이드오프는 명확하다 — 병렬성이 늘수록 컨텍스트 충돌·중복 편집을 잡아내는 **리뷰 병목**이 사람에게 되돌아온다.

> 💡 **왜 중요한가**: "1 개발자 = 1 에이전트"에서 "1 개발자 = N개 에이전트의 오케스트레이터"로 역할이 바뀌면, 이후 개발자 생산성 지표는 '코드 작성량'이 아니라 '병렬 PR 승인/거부 처리량'으로 재정의될 가능성이 크다.
