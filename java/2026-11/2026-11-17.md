### 1. `HexFormat.of().formatHex(bytes)` (Java 17 정식, JEP 356)로 바이트 배열을 16진수 문자열로 변환하기 — `StringBuilder`에 `String.format("%02x", b)`를 루프 돌려 붙이는 관성 벗어나기

해시, 서명, 바이너리 로깅에서 `byte[]` → hex 문자열 변환은 매번 `for` 루프 + `String.format("%02x", ...)`로 짜게 되는데, 이건 포매터 파싱 오버헤드가 바이트 수만큼 쌓인다. `HexFormat.of()`는 구분자·대소문자·접두어를 한 번에 설정할 수 있고 (`HexFormat.of().withDelimiter(":").withUpperCase()`), 역변환도 `parseHex(str)` 한 줄이라 MAC 주소 포맷이나 SHA-256 다이제스트 출력을 직접 조립하지 않아도 된다.

```java
// Before: 매 바이트마다 포맷 파싱
StringBuilder sb = new StringBuilder();
for (byte b : digest) sb.append(String.format("%02x", b));
String hex = sb.toString();

// After
String hex = HexFormat.of().formatHex(digest);
byte[] back = HexFormat.of().parseHex(hex);

// MAC 주소 스타일
String mac = HexFormat.ofDelimiter(":").withUpperCase().formatHex(bytes);
// -> "AA:BB:CC:DD:EE:FF"
```

> 💡 **왜 중요한가**: `String.format("%02x", b)` 루프는 포맷 문자열을 매번 파싱·캐싱해 바이트 수가 늘어나면 체감될 만큼 느려지는 반면, `HexFormat`은 전용 인코더로 돌아 할당도 적고 역변환까지 대칭으로 제공해 "한 방향만 편한 유틸"이라는 함정을 피한다.

### 2. `Math.clamp(value, min, max)` (Java 21 정식)로 값을 범위 안에 가두기 — `Math.max(min, Math.min(max, value))` 중첩 호출 관성 벗어나기

페이지 크기, 볼륨, 좌표처럼 "최소~최대 사이로 자르기"는 늘 `Math.max(0, Math.min(100, v))` 꼴로 두 번 중첩해 썼는데, 어느 쪽이 min이고 어느 쪽이 max인지 읽을 때마다 머리로 풀어야 한다. Java 21부터는 `int`, `long`, `float`, `double` 네 가지 오버로드로 `Math.clamp(value, min, max)`가 들어와 의도가 그대로 드러나고, `min > max`일 때는 `IllegalArgumentException`을 던져 잘못된 범위를 숨기지 않는다.

```java
// Before
int pageSize = Math.max(1, Math.min(100, requested));
double volume = Math.max(0.0, Math.min(1.0, raw));

// After
int pageSize = Math.clamp(requested, 1, 100);
double volume = Math.clamp(raw, 0.0, 1.0);

// 잘못된 범위는 조용히 통과하지 않음
Math.clamp(5, 10, 3); // IllegalArgumentException: min > max
```

> 💡 **왜 중요한가**: `max(min, min(max, v))` 패턴은 인자 순서가 뒤집혀도 컴파일되고 "이상한 범위"가 그대로 결과로 흘러가지만, `Math.clamp`는 (값, 하한, 상한) 순서를 시그니처가 강제하고 뒤집힌 범위를 런타임에 즉시 터뜨려 로직 버그를 조용히 삼키지 않는다.
