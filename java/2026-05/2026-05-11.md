### `JEP 467: Markdown Documentation Comments`로 Javadoc을 마크다운 문법으로 작성하기 (Java 23 정식)

기존 `/** */` Javadoc은 HTML 태그(`<p>`, `<pre>`, `<code>`)를 직접 써야 해 가독성이 떨어졌다. Java 23부터는 `///`로 시작하는 라인을 마크다운으로 인식해 헤더, 리스트, 코드 펜스, 링크를 자연스러운 문법으로 작성할 수 있다.

```java
/// 사용자 정보를 조회한다.
///
/// ## 예시
/// ```java
/// User user = service.findById(42L);
/// ```
///
/// - **인자**: 유효한 사용자 ID
/// - **반환**: [User] 인스턴스
///
/// 자세한 내용은 [공식 문서](https://example.com)를 참고.
public User findById(long id) { ... }
```

`[User]`처럼 대괄호만으로 자동 링크가 만들어지고, 코드 펜스 안에서는 HTML 이스케이프를 신경 쓸 필요가 없다.

> 💡 **왜 중요한가**: 소스에서 읽을 때나 IDE 호버에서나 동일하게 깔끔해 문서화 진입 장벽을 크게 낮춘다.

### `Cleaner` API로 `finalize()` 없이 네이티브 리소스를 안전하게 정리하기 (Java 9 정식)

`finalize()`는 호출 시점이 보장되지 않고 GC 성능을 망쳐 Java 9에서 deprecated, Java 18에서 사실상 폐기 수순에 들어갔다. 대체재인 `java.lang.ref.Cleaner`는 객체가 unreachable이 된 시점을 별도 스레드로 통지받아 누수 안전망(safety net)을 구축할 수 있다.

```java
public class NativeBuffer implements AutoCloseable {
    private static final Cleaner CLEANER = Cleaner.create();
    private final Cleaner.Cleanable cleanable;
    private final State state;

    private static class State implements Runnable {
        long handle;
        State(long h) { this.handle = h; }
        public void run() { nativeFree(handle); } // this 참조 금지
    }

    public NativeBuffer(int size) {
        this.state = new State(nativeAlloc(size));
        this.cleanable = CLEANER.register(this, state);
    }

    @Override public void close() { cleanable.clean(); }
}
```

핵심은 `State`가 바깥 `NativeBuffer`를 참조하면 안 된다는 점이다 — 참조하면 객체가 영원히 reachable로 남아 Cleaner가 동작하지 않는다.

> 💡 **왜 중요한가**: try-with-resources로 정상 정리하되, 사용자가 `close()`를 잊었을 때의 마지막 방어선으로 메모리 누수를 막아준다.
