### `@ImportRuntimeHints`로 GraalVM Native Image 리플렉션 힌트 등록하기 (Spring Boot 3+)
Spring Boot 3의 AOT는 표준 `@Component`/`@Bean`/`@Configuration` 그래프는 자동으로 힌트를 만들어주지만, 리플렉션·동적 프록시·리소스 로딩을 직접 쓰는 코드는 Native Image에서 런타임 클래스로딩이 막혀 깨집니다. `RuntimeHintsRegistrar`를 만들어 필요한 클래스를 등록하고 설정 클래스에 `@ImportRuntimeHints`로 붙이면 빌드 시 메타데이터에 합쳐집니다.

```java
public class MyHints implements RuntimeHintsRegistrar {
    @Override
    public void registerHints(RuntimeHints hints, ClassLoader classLoader) {
        hints.reflection().registerType(InternalDto.class,
            MemberCategory.INVOKE_DECLARED_CONSTRUCTORS,
            MemberCategory.DECLARED_FIELDS);
        hints.resources().registerPattern("config/feature-flags.yml");
        hints.serialization().registerType(Audit.class);
    }
}

@Configuration
@ImportRuntimeHints(MyHints.class)
class AppConfig { }
```

> 💡 **왜 중요한가**: Native Image 빌드에서 런타임에 터지는 `ClassNotFoundException`·`MissingResourceException`을 사전에 잡아낼 수 있어, 라이브러리 업그레이드마다 AOT가 깨지는 문제를 통제 가능한 형태로 다룰 수 있습니다.

### `spring.task.scheduling.pool.size`로 `@Scheduled` 스레드 풀 키워 작업이 서로를 막지 않게 하기
Spring Boot의 기본 스케줄러 풀은 **1** 입니다. 그 결과 한 `@Scheduled` 메서드가 30초를 끌면 같은 시간 트리거된 다른 잡들이 줄줄이 밀리며 모니터링이 침묵 속에 망가집니다. 풀 크기를 잡 수에 맞춰 키우고, 가능하면 각 잡의 `Async`/`taskExecutor`를 분리해야 안전합니다.

```yaml
spring:
  task:
    scheduling:
      pool:
        size: 8
      thread-name-prefix: sched-
```

```java
@Scheduled(fixedDelay = 1_000)
public void heartbeat() { /* 1초마다 */ }

@Scheduled(cron = "0 */5 * * * *")
public void reconcile() { /* 5분마다, 오래 걸려도 heartbeat을 막지 않음 */ }
```

> 💡 **왜 중요한가**: 스케줄러는 "조용히 늦는" 종류의 사고가 잘 일어나는 영역이라, 풀 크기 설정 한 줄이 운영 알람의 신뢰도를 좌우합니다.
