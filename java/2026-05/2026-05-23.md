### `Records`로 불변 데이터 캐리어 클래스를 한 줄로 선언하기 (Java 16 정식)

DTO나 값 객체를 만들 때 `equals`, `hashCode`, `toString`, 생성자, getter를 매번 작성하는 보일러플레이트를 없앨 수 있다. `record` 키워드 하나로 컴파일러가 이 모든 것을 자동 생성하며, 컴팩트 생성자로 유효성 검증도 간결하게 처리한다.

```java
public record Point(int x, int y) {
    public Point {
        if (x < 0 || y < 0) throw new IllegalArgumentException("음수 불가");
    }
}

Point p = new Point(3, 5);
System.out.println(p.x());        // 3
System.out.println(p);            // Point[x=3, y=5]
System.out.println(p.equals(new Point(3, 5)));  // true
```

> 💡 **왜 중요한가**: Lombok 없이도 표준 API만으로 불변 데이터 클래스를 안전하게 만들 수 있다.

### `Sealed Classes`로 상속 가능한 하위 타입을 명시적으로 제한하기 (Java 17 정식)

`sealed` 키워드로 클래스나 인터페이스의 하위 타입을 `permits` 절에 나열된 것들로 제한할 수 있다. 도메인 모델에서 "가능한 상태가 유한하다"는 제약을 타입 시스템으로 표현할 수 있고, switch 패턴 매칭과 결합하면 컴파일러가 모든 케이스 처리 여부까지 검사해준다.

```java
public sealed interface Shape permits Circle, Square, Triangle {}

public record Circle(double radius) implements Shape {}
public record Square(double side) implements Shape {}
public record Triangle(double base, double height) implements Shape {}

double area(Shape s) {
    return switch (s) {
        case Circle c   -> Math.PI * c.radius() * c.radius();
        case Square sq  -> sq.side() * sq.side();
        case Triangle t -> 0.5 * t.base() * t.height();
    };  // default 불필요 — 컴파일러가 완전성 검증
}
```

> 💡 **왜 중요한가**: 대수적 데이터 타입(ADT) 스타일의 모델링이 가능해져 상태 누락으로 인한 런타임 버그를 컴파일 타임에 잡아낸다.
