### 1. 스코프 함수 (let, run, apply, also, with): 코드의 흐름을 바꾸는 5가지 도구

Kotlin의 스코프 함수는 객체 컨텍스트 안에서 임시 영역을 만들어 코드를 간결하게 만드는 람다 기반 함수들이다. `let`은 null 체크 후 처리(`user?.let { println(it.name) }`), `apply`는 객체 초기화 후 자기 자신 반환(`Person().apply { name = "Kim"; age = 30 }`), `also`는 부가 작업(로깅, 디버깅) 후 자기 자신 반환, `run`은 블록의 마지막 표현식 반환, `with`는 수신 객체의 여러 멤버에 연속 접근할 때 사용한다. 선택 기준은 **(1) 수신 객체 참조 방식(`it` vs `this`)** 과 **(2) 반환값(수신 객체 vs 람다 결과)** 두 축으로 결정하면 혼란이 없다.

```kotlin
// let: null-safe 체이닝, 결과 반환
val length = user?.name?.let { it.length } ?: 0

// apply: 초기화 (this, 자기 자신 반환)
val intent = Intent().apply {
    action = "VIEW"
    flags = FLAG_NEW_TASK
}

// also: 사이드 이펙트 (it, 자기 자신 반환)
val numbers = mutableListOf(1, 2, 3)
    .also { println("Before: $it") }
    .apply { add(4) }
    .also { println("After: $it") }

// run: 블록 결과 반환 (this)
val result = user.run {
    validate()
    toDto()  // 이게 반환됨
}
```

> 💡 **왜 중요한가**: 스코프 함수를 잘 쓰면 임시 변수가 사라지고 의도(초기화/변환/부수효과)가 함수 이름만으로 드러나지만, 남용하면 `it`/`this`가 겹쳐 가독성이 오히려 떨어진다 — "언제 어떤 걸 쓸지"의 기준을 가진 개발자와 아닌 개발자의 코드 차이가 가장 크게 벌어지는 영역이다.

### 2. 확장 함수 (Extension Function): 남의 클래스에 메서드를 "꽂아 넣는" 마법

확장 함수는 **기존 클래스를 수정하거나 상속하지 않고** 새로운 메서드를 추가하는 Kotlin의 핵심 기능이다. `String.toSlug()` 같은 유틸리티를 `StringUtils.toSlug(str)` 대신 `str.toSlug()`로 호출할 수 있어 Java의 정적 유틸 클래스 지옥(`CollectionUtils`, `StringUtils`, `DateUtils`...)을 깔끔하게 대체한다. 내부적으로는 **수신 객체를 첫 인자로 받는 정적 메서드로 컴파일**되기 때문에, 런타임 다형성이 없고 **정적 디스패치**된다는 점이 중요하다 (즉, 부모 타입 변수로 호출하면 자식의 확장 함수가 아닌 부모의 확장 함수가 호출됨).

```kotlin
// String에 메서드 추가 — 원본 코드 수정 없이
fun String.toSlug(): String =
    lowercase().replace(" ", "-").replace(Regex("[^a-z0-9-]"), "")

"Hello Kotlin World!".toSlug()  // "hello-kotlin-world"

// 컬렉션에 도메인 메서드 추가
fun List<Order>.totalAmount(): BigDecimal =
    sumOf { it.price * it.quantity.toBigDecimal() }

orderList.totalAmount()  // Java였다면 OrderUtils.totalAmount(orderList)

// 주의: 정적 디스패치 — 다형성 X
open class Animal
class Dog : Animal()
fun Animal.sound() = "???"
fun Dog.sound() = "멍멍"

val a: Animal = Dog()
println(a.sound())  // "???" (Animal의 확장 함수 호출됨!)
```

**실무 활용 포인트**:
- **DTO ↔ Entity 변환**: `fun UserEntity.toDto(): UserDto` 형태로 변환 로직을 타입 가까이 배치
- **DSL 설계**: `HTML { body { div { ... } } }` 같은 Type-Safe Builder의 기반
- **Nullable receiver**: `fun String?.orEmpty()` 처럼 null 수신자도 가능

> 💡 **왜 중요한가**: Java 개발자가 Kotlin에 넘어오면 가장 먼저 "와, 이거다" 하는 기능이 확장 함수인데, 이는 단순한 문법 설탕이 아니라 **"관심사의 지역화"** 라는 설계 철학을 코드에 녹일 수 있게 해준다 — Order 변환 로직이 OrderMapper, OrderConverter, OrderUtils로 흩어지지 않고 Order 파일 옆에서 자연스럽게 읽히는 코드를 만들 수 있다.
