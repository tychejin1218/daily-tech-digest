### `Thread.ofVirtual().start()`로 OS 스레드 없이 수십만 개의 경량 스레드 동시 실행하기 (Java 21 정식)

`Thread.ofVirtual().start(Runnable)` 또는 `Executors.newVirtualThreadPerTaskExecutor()`를 사용하면 JVM이 관리하는 가상 스레드(Virtual Thread)를 생성할 수 있어, 블로킹 I/O 작업을 수행할 때도 캐리어 스레드를 점유하지 않고 자동으로 언마운트됩니다. 기존 플랫폼 스레드는 OS 자원 한계로 수천 개가 한계였지만, 가상 스레드는 힙 메모리만 소비하므로 동일한 코드를 그대로 두고 `Executors.newFixedThreadPool()`만 교체해도 동시 처리량을 대폭 끌어올릴 수 있습니다.

> 💡 **왜 중요한가**: "스레드당 요청 하나" 모델을 유지하면서도 리액티브 코드의 복잡성 없이 높은 동시성을 얻을 수 있어, 디버깅과 스택 트레이스 추적이 자연스럽습니다.

### `String Templates`의 대안으로 `Formatter`와 `StringBuilder`를 적재적소에 활용하기

Java 21/22에서 프리뷰로 등장했던 `String Templates`(JEP 430)는 Java 23에서 제거되어 재설계 중이므로, 그동안은 `String.format()`, `Formatter`, `StringBuilder`를 상황에 맞게 구분해 쓰는 것이 중요합니다. 단순 결합은 `+` 연산자(JIT가 `StringBuilder`로 최적화), 반복 로직이 들어간 누적은 명시적 `StringBuilder`, 로케일/포맷 지정이 필요한 출력은 `Formatter`나 `String.format()`을 사용하면 됩니다.

> 💡 **왜 중요한가**: 프리뷰 기능에 성급히 의존했다가 제거되는 경우가 있으므로, JEP 상태(Preview/Incubator/Standard)를 확인하고 안정 API 위주로 코드베이스를 유지하는 습관이 장기 유지보수 비용을 줄입니다.
