### 1. `Collectors.toUnmodifiableList()` (Java 10 정식)로 수집하기 — `stream.collect(Collectors.toList())` 결과를 다시 `Collections.unmodifiableList()`로 감싸는 관성 벗어나기

Java 10부터 추가된 `Collectors.toUnmodifiableList/Set/Map()`은 수집과 동시에 불변 컬렉션을 돌려준다. 기존 2단계 패턴(`toList()` → `unmodifiableList()`)은 가변 `ArrayList`를 먼저 할당하고 다시 래퍼로 감싸 두 번의 간접 참조를 만들지만, 이 수집기는 내부적으로 `List.of(...)` 계열의 진짜 불변 리스트를 직접 생성한다. null 요소가 있으면 `NullPointerException`이 바로 터지므로 데이터 정합성 검증까지 겸한다.

```java
// Before
List<String> result = Collections.unmodifiableList(
    users.stream().map(User::getName).collect(Collectors.toList())
);

// After
List<String> result = users.stream()
    .map(User::getName)
    .collect(Collectors.toUnmodifiableList());
```

> 💡 **왜 중요한가**: API 반환값이나 DTO 필드에 불변 컬렉션을 돌려주는 패턴을 한 줄로 끝내면서, "반환받은 쪽이 몰래 add() 하는 버그"를 설계 단계에서 차단할 수 있다.

### 2. `Executors.newVirtualThreadPerTaskExecutor()` (Java 21 정식, JEP 444)를 try-with-resources로 — 가상 스레드 풀을 `shutdown()` + `awaitTermination()` 수동 관리하는 관성 벗어나기

가상 스레드 Executor는 `AutoCloseable`을 구현하므로 try-with-resources 블록만 나가면 `close()`에서 자동으로 모든 작업 완료를 기다린다(`awaitTermination` 내장). 고전적인 `ExecutorService`는 `shutdown()` 호출 누락, `awaitTermination` 타임아웃 설정 실수, 예외 경로에서 자원 누수 같은 함정이 많았는데, 이 패턴은 그 보일러플레이트를 통째로 걷어낸다. "태스크 다 끝날 때까지 기다린다"는 의도가 코드 구조에 그대로 드러난다.

```java
// Before
ExecutorService executor = Executors.newFixedThreadPool(10);
try {
    List<Future<String>> futures = urls.stream()
        .map(url -> executor.submit(() -> fetch(url)))
        .toList();
    for (var f : futures) results.add(f.get());
} finally {
    executor.shutdown();
    executor.awaitTermination(1, TimeUnit.MINUTES);
}

// After
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<String>> futures = urls.stream()
        .map(url -> executor.submit(() -> fetch(url)))
        .toList();
    for (var f : futures) results.add(f.get());
} // close() = shutdown + awaitTermination 자동
```

> 💡 **왜 중요한가**: 가상 스레드 시대에는 "스레드 풀 사이즈 튜닝"이 아니라 "작업 단위의 생명주기 관리"가 본질이고, try-with-resources는 그 생명주기를 언어 레벨에서 보장해주는 가장 깔끔한 구조다.
