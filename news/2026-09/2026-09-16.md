### 1. Sakana AI, Fugu Ultra v2 + Fugu Max 동시 공개 — 단일 프론티어 모델 시대에 '오케스트레이션 모델'로 정면 도전
9월 11일 도쿄 스타트업 Sakana AI가 요청을 받으면 프론티어 오픈웨이트/특화 모델 풀에 동적으로 라우팅하는 오케스트레이터 Fugu Ultra v2(1M 컨텍스트, $5/$30)와 저가형 Fugu Max($2/$6)를 함께 릴리스했다. Ultra v2는 Chartography 벤치마크에서 48.3점을 기록해 Anthropic Opus 5(27.3)와 Fable 5(29.5)를 큰 격차로 앞섰고, Max는 Sonnet 5·GPT-5.6 Terra·Kimi K3 대비 출력 토큰 기준 40~60% 저렴하다고 발표됐다.

> 💡 **왜 중요한가**: "하나의 거대 모델 vs. 라우터형 멀티모델" 아키텍처 논쟁이 벤치마크 숫자로 결판나기 시작했다 — 백엔드에서 LLM API를 고를 때 '단일 프로바이더 락인'이 아니라 '라우팅 계층'을 먼저 설계해야 하는 시대의 신호탄이다.

### 2. GitHub, Project HydraFusion 공개 — Copilot이 태스크마다 '모델 조합 워크플로우'를 런타임에 짠다
9월 4일 GitHub가 Copilot CLI에 리서치 프리뷰로 HydraFusion을 투입했다. Auto 모델 선택이 "가장 잘 맞는 모델 하나"를 고르는 반면, HydraFusion은 태스크마다 (a) 단일 모델, (b) 저가 모델이 초안 → 게이트가 상위 모델로 에스컬레이션할지 판단하는 캐스케이드, (c) 다른 모델 패밀리가 초안을 크리틱한 뒤 1회 리비전하는 워크플로우 중 하나를 실행 계획으로 조립한다. 모든 Copilot 플랜에서 `/experimental`로 켤 수 있고, VS Code·GitHub 앱에도 9월 안에 이식된다.

> 💡 **왜 중요한가**: 코딩 에이전트의 병목이 "어느 모델을 쓸까"에서 "어떤 모델 파이프라인을 짤까"로 이동한다는 뜻이다 — Cursor·Claude Code의 단일 모델 라우팅 방식과 정면 충돌하며, 앞으로 IDE·CLI 툴 벤더 모두 '워크플로우 컴파일러'를 내장하게 될 것이다.

### 3. Microsoft Agent Framework .NET 1.21.0 릴리스 — LocalCodeAct 격리 강화, A2A·MCP 아카이브 호환성 브레이킹
Microsoft가 지난 4월 GA한 Agent Framework의 .NET 1.21.0을 9월 초에 배포하며, 호스티드 에이전트 응답 안정성 개선, LocalCodeAct(로컬 코드 실행 툴)의 샌드박스 격리·승인 흐름 강화, File Skill·워크플로우 버그픽스와 함께 A2A(Agent-to-Agent) 프로토콜과 MCP 아카이브 처리에 브레이킹 체인지를 넣었다. Azure AI Projects·Bedrock 커넥터도 함께 갱신됐다.

> 💡 **왜 중요한가**: 엔터프라이즈 .NET 진영에서 "AI 에이전트가 서버 안에서 임의 코드를 실행하는" 시나리오가 프로덕션 등급 격리·감사 흐름을 요구받기 시작했다는 신호다 — 자바/노드 백엔드에서도 곧 LocalCodeAct급 샌드박스 요구사항이 표준 체크리스트로 들어올 것이다.
