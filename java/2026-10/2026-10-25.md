### 1. `Objects.checkIndex(index, length)` (Java 9 정식)로 `if (i < 0 || i >= arr.length) throw new IndexOutOfBoundsException()` 수동 가드 관성 벗어나기

배열/리스트 인덱스 검증할 때 손수 범위 체크해서 예외 던지는 보일러플레이트, JDK가 이미 내장 메서드로 제공한다. `Objects.checkIndex(i, len)`는 유효하면 `i`를 그대로 반환하고 벗어나면 JVM 내부 포맷의 `IndexOutOfBoundsException`을 던진다 — 즉 `return arr[Objects.checkIndex(i, arr.length)]`처럼 한 줄에 끼워 쓸 수 있다. `checkFromToIndex(from, to, len)`, `checkFromIndexSize(from, size, len)` 변형까지 있어서 서브리스트/슬라이스 경계 검증도 커버된다. 추가로 JIT가 이 메서드의 범위 체크를 인식해서 뒤이은 배열 접근의 바운드 체크를 제거(bounds-check elimination)해주기 때문에 수동 체크보다 성능상 손해도 없다.

> 💡 **왜 중요한가**: 가드 코드를 한 줄로 압축하면서 JIT 최적화 힌트까지 공짜로 받는다 — 표현식 안에 녹여 쓸 수 있다는 게 핵심이다.

### 2. `Deque<E>` as Stack (Java 6부터, 공식 권장)로 `java.util.Stack` 쓰는 관성 벗어나기

`Stack<E>`은 `Vector`를 상속한 레거시 클래스라 모든 메서드가 `synchronized`로 묶여 있다 — 싱글 스레드에서도 락 획득/해제 오버헤드를 매번 지불한다는 뜻이다. 공식 javadoc조차 "A more complete and consistent set of LIFO stack operations is provided by the Deque interface and its implementations, which should be used in preference to this class"라고 명시하고 있다. `Deque<Integer> stack = new ArrayDeque<>()`로 선언하고 `push`/`pop`/`peek`만 쓰면 된다 — API 모양은 동일하면서 락은 없고, `ArrayDeque`가 내부적으로 순환 배열이라 `LinkedList`보다 캐시 지역성도 좋다.

> 💡 **왜 중요한가**: `Stack`은 "쓰면 안 되는 클래스" 공식 리스트에 올라있다 — 신규 코드에서 발견되면 리뷰에서 바로 지적 대상이다.
