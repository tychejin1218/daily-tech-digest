### `Stream.takeWhile(Predicate)`로 정렬된 스트림의 앞부분만 잘라내기 (Java 9 정식)

정렬된 스트림에서 조건을 만족하는 접두(prefix) 요소만 뽑고 싶을 때 `filter()`는 "조건 만족하는 모든 요소"를 반환하므로 부적절하다. `takeWhile()`은 첫 번째로 조건을 위배하는 요소를 만나는 순간 스트림을 즉시 종료해 불필요한 순회를 없앤다. 정렬된 로그 타임스탬프, 페이지네이션 초과 지점 컷팅 등에서 SQL의 `LIMIT ... WHERE`처럼 동작한다.

```java
// 시간순 정렬된 이벤트에서 마감 시각 이전 것만
List<Event> before = events.stream()
    .takeWhile(e -> e.time().isBefore(deadline))
    .toList();

// filter는 뒤에 조건 맞는 게 또 있으면 다 가져옴 (원치 않는 동작)
// takeWhile은 첫 위반에서 중단 → 조기 종료
```

반대로 조건을 위배하는 첫 요소부터 끝까지 얻고 싶다면 `dropWhile()`을 쓴다. `filter()`와 달리 요소 순서에 의존하므로 정렬된 스트림에서만 의미 있다.

> 💡 **왜 중요한가**: 정렬된 대용량 스트림에서 조기 종료(short-circuiting)를 통해 O(N)을 O(k)로 줄일 수 있으며, "조건 만족 전체"와 "조건 만족 접두"의 의도 차이를 코드로 명시할 수 있다.

### `Predicate.not(Predicate)`로 메서드 참조를 부정형으로 그대로 쓰기 (Java 11 정식)

`String::isBlank`, `Optional::isPresent` 같은 메서드 참조를 부정할 때 `s -> !s.isBlank()`처럼 람다로 풀어 써야 하는 게 오랜 불편이었다. `Predicate.not()`은 메서드 참조를 인자로 받아 부정형 `Predicate`로 감싸주므로 가독성을 유지하면서 부정 조건을 표현할 수 있다. 정적 임포트하면 `not(String::isBlank)` 형태로 자연스럽게 읽힌다.

```java
import static java.util.function.Predicate.not;

// Before: 람다로 풀어야 함
lines.stream().filter(s -> !s.isBlank()).toList();

// After: 메서드 참조 그대로 부정
lines.stream().filter(not(String::isBlank)).toList();

// 여러 부정 조건 조합도 깔끔
users.stream()
    .filter(not(User::isDeleted).and(not(User::isSuspended)))
    .toList();
```

주의: `not()`은 정적 메서드이므로 인스턴스 메서드 참조와 정적 메서드 참조 모두에 쓸 수 있지만, 이미 `Predicate` 타입으로 선언된 변수는 `predicate.negate()`가 더 직관적이다.

> 💡 **왜 중요한가**: 도메인 메서드에 이미 명명된 술어(`isBlank`, `isEmpty`, `isValid`)가 있다면 굳이 익명 람다로 다시 감쌀 이유가 없다 — 이름 있는 술어를 그대로 재사용하는 게 의도가 더 잘 드러난다.
