### 1. `HexFormat.of()` (Java 17 정식, JEP 306)로 바이트 배열 ↔ 16진수 문자열 변환할 때 `String.format("%02x", b)` 루프 돌리는 관성 벗어나기

해시, 토큰, 바이너리 디버깅 로그에서 `byte[]`를 hex string으로 뽑을 때 `StringBuilder`에 `String.format("%02x", b)`를 돌리거나, 역방향으로 `Integer.parseInt(s.substring(i, i+2), 16)`을 반복하는 코드가 레거시에 쌓여 있다. `HexFormat.of().formatHex(bytes)` / `parseHex(str)` 한 줄로 끝나고, 구분자(`:`, 공백)와 대소문자, 프리픽스(`0x`)까지 `HexFormat.ofDelimiter(":").withUpperCase().withPrefix("0x")`로 선언형 지정이 가능하다. 매 루프마다 `Formatter` 인스턴스 생성 + 가변 인자 박싱 오버헤드까지 함께 사라진다.

> 💡 **왜 중요한가**: 암호화 해시(SHA-256, HMAC) 출력이나 MAC 주소 포맷 같이 "바이트를 사람이 읽는 hex로" 변환하는 코드는 거의 모든 프로젝트에 있는데, 손으로 짠 루프는 포맷 버그(홀수 길이, 대소문자, 음수 바이트의 sign extension)가 지뢰처럼 숨어 있어서 표준 API로 옮기는 것만으로 테스트 몇 개가 없어진다.

### 2. `Math.clamp(value, min, max)` (Java 21 정식, JEP 431)로 `Math.max(min, Math.min(max, v))` 중첩 관성 벗어나기

페이지 사이즈 상한, 볼륨 0~100, 재시도 백오프 상한 같은 "값을 범위로 밀어 넣는" 코드에서 `Math.max(min, Math.min(max, value))` 이중 중첩이나 `if (v < min) v = min; else if (v > max) v = max;` 가드를 쓰는 관성이 있다. Java 21부터 `Math.clamp(v, min, max)`가 정식으로 들어왔고 `int`, `long`, `float`, `double` 오버로드가 모두 제공된다. 중요한 건 `min > max`면 `IllegalArgumentException`을 던진다는 점 — 손으로 짠 `max/min` 중첩은 이 경우 조용히 `min`을 반환해 값이 상한을 넘어버리는 버그를 숨긴다.

> 💡 **왜 중요한가**: `Math.max(min, Math.min(max, v))`는 읽는 사람이 min/max 순서를 매번 머릿속에서 풀어야 하고, 반대로 쓰거나 인자 하나를 바꿔치기하는 실수가 코드리뷰에서 가장 흔한 "보여도 안 보이는" 버그 중 하나다. `clamp`는 의도가 함수 이름에 박혀 있어서 리뷰 비용 자체가 사라진다.
