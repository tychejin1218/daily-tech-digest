오늘의 Spring Boot 팁 2개입니다. 제외 목록과 겹치지 않는 주제로 골랐습니다.

---

### 1. `spring.threads.virtual.enabled=true`로 가상 스레드(Virtual Threads) 켜서 처리량 끌어올리기

Spring Boot 3.2+와 Java 21 이상에서 이 한 줄만 추가하면 Tomcat 요청 처리, `@Async`, `@Scheduled` 작업이 플랫폼 스레드 대신 경량 가상 스레드 위에서 실행됩니다. I/O 대기(DB 쿼리, 외부 API 호출)가 많은 블로킹 애플리케이션에서 스레드 풀 고갈 없이 동시 처리량을 크게 늘릴 수 있습니다. 단, `synchronized` 블록 안에서 블로킹 호출을 하면 캐리어 스레드가 고정(pinning)되어 효과가 사라지므로 `ReentrantLock`으로 바꾸는 점검이 필요합니다.

```properties
spring.threads.virtual.enabled=true
```

> 💡 **왜 중요한가**: 코드를 리액티브로 다시 쓰지 않고도 블로킹 스타일 그대로 높은 동시성을 얻을 수 있습니다.

### 2. `ProblemDetail`(RFC 7807)로 REST API 에러 응답 형식 표준화하기

Spring Boot 3(Spring Framework 6)부터 내장된 `ProblemDetail`을 쓰면 `type`, `title`, `status`, `detail`, `instance` 필드를 가진 표준 에러 JSON을 일관되게 반환할 수 있습니다. `@ExceptionHandler`에서 `ProblemDetail`을 직접 반환하거나 `ResponseEntityExceptionHandler`를 상속해 프레임워크 예외까지 통일된 형식으로 변환할 수 있고, `setProperty()`로 추적 ID 같은 커스텀 필드도 덧붙일 수 있습니다. 클라이언트가 에러 포맷을 예측 가능하게 파싱할 수 있어 프론트엔드·외부 연동 비용이 줄어듭니다.

```java
@ExceptionHandler(OrderNotFoundException.class)
ProblemDetail handle(OrderNotFoundException ex) {
    ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
    pd.setTitle("주문을 찾을 수 없음");
    pd.setProperty("traceId", MDC.get("traceId"));
    return pd;
}
```

> 💡 **왜 중요한가**: 들쭉날쭉한 자체 에러 포맷 대신 업계 표준(RFC 7807)을 따라 API 에러 응답의 일관성과 상호운용성을 확보합니다.
