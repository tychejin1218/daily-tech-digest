### 1. `String.indent(n)` (Java 12 정식)로 멀티라인 문자열에 들여쓰기 수동으로 붙이는 관성 벗어나기

텍스트 블록이나 멀티라인 로그 메시지에 공통 들여쓰기를 주고 싶을 때, 보통 `lines().map(l -> " ".repeat(n) + l).collect(joining("\n"))` 같은 체인을 짜게 된다. `String.indent(int n)`은 음수를 넘기면 들여쓰기를 역으로 제거까지 해주고, 각 라인 끝에 `\n`을 자동 정규화해준다. 로그 포매터, 에러 메시지 중첩 출력, YAML/JSON 조각을 템플릿에 끼워 넣을 때 1줄로 끝난다.

```java
String block = """
    line1
    line2
    """;

// Before: Stream API로 수동 들여쓰기
String padded = block.lines()
    .map(l -> "    " + l)
    .collect(Collectors.joining("\n"));

// After: String.indent로 끝
String padded2 = block.indent(4);        // 들여쓰기 추가
String stripped = block.indent(-2);      // 들여쓰기 제거 (음수)
```

> 💡 **왜 중요한가**: 텍스트 블록(Java 15+)이 늘어나면서 "들여쓰기 조정" 수요가 급증했는데, Stream 체인 대신 메서드 1개로 끝낼 수 있다는 사실을 모르면 코드가 쓸데없이 장황해진다.

### 2. `Thread.ofVirtual().start(Runnable)` 반환값 무시하지 않고 `join(Duration)` (Java 19 정식)으로 타임아웃 조인 관성 들이기

가상 스레드 시대에 `thread.join()`을 무한 대기로 호출하는 코드가 늘고 있는데, `Thread.join(Duration)`은 Java 19에서 정식 추가된 오버로드로 `millis + nanos` 두 인자 쪼개는 레거시 API를 대체한다. 타임아웃 만료 시 `false`를 반환하므로 `interrupt()` 폴백 로직을 깔끔하게 분기할 수 있고, `TimeUnit.SECONDS.toMillis()` 변환 보일러플레이트가 사라진다.

```java
Thread t = Thread.ofVirtual().start(() -> heavyWork());

// Before: 레거시 join(long millis) + 수동 변환
t.join(TimeUnit.SECONDS.toMillis(5));
if (t.isAlive()) t.interrupt();

// After: Duration 받는 join + boolean 반환으로 분기
if (!t.join(Duration.ofSeconds(5))) {
    t.interrupt();
    log.warn("worker timeout, interrupted");
}
```

> 💡 **왜 중요한가**: 가상 스레드는 "싸게 만들고 버린다"는 특성상 타임아웃 없는 `join()`이 리소스 누수가 아니라 **응답 지연**으로 번져 장애를 키우기 때문에, `Duration` 기반 조인을 기본 습관으로 만들어야 한다.
