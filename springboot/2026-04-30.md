### `@Lookup`으로 싱글턴 빈에서 프로토타입 빈 매번 새로 주입받기

싱글턴 스코프 빈에 프로토타입 빈을 그냥 `@Autowired`하면 최초 주입 시점에 한 번만 생성되어 프로토타입의 의미가 사라진다. `@Lookup` 애노테이션을 추상 메서드(또는 일반 메서드)에 붙이면 Spring이 CGLIB 프록시로 메서드를 오버라이드하여 호출할 때마다 컨테이너에서 새 인스턴스를 가져온다. `ObjectProvider<T>`나 `Provider<T>` 주입과 동일한 효과지만, 명시적인 메서드 시그니처로 의도를 코드에 드러낼 수 있다.

```java
@Component
public abstract class ReportProcessor {
    public void process() {
        ReportContext ctx = createContext(); // 호출 시마다 새 인스턴스
        ctx.run();
    }

    @Lookup
    protected abstract ReportContext createContext();
}
```

> 💡 **왜 중요한가**: 스코프 불일치(scoped proxy mismatch) 버그는 디버깅이 까다로운데, `@Lookup`은 빈 라이프사이클을 컴파일 타임 시그니처에 박아 사고를 예방한다.

### `spring-boot-docker-compose` 모듈로 로컬 개발 인프라 자동 기동

Spring Boot 3.1+에서 도입된 `spring-boot-docker-compose` 의존성을 추가하면 애플리케이션 기동 시 프로젝트 루트의 `compose.yaml`을 자동으로 감지하여 PostgreSQL, Redis, Kafka 등의 컨테이너를 띄우고 `DataSource` URL·자격증명까지 ServiceConnection으로 자동 바인딩한다. 별도의 `application-local.yml` 분기나 `docker compose up` 사전 실행 없이 `bootRun` 한 번으로 환경이 준비되며, 종료 시 컨테이너 정리 정책(`stop`/`down`/`none`)도 `spring.docker.compose.lifecycle-management`로 제어할 수 있다.

```yaml
# compose.yaml
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
    ports: ["5432:5432"]
```

> 💡 **왜 중요한가**: 신규 합류자 온보딩 시 "README의 docker 명령을 빼먹어서 부팅 실패"하는 마찰이 사라지고, 로컬·CI 환경의 인프라 정의가 단일 소스로 통일된다.
