### Sequenced Collections API로 순서 있는 컬렉션의 첫/마지막 요소에 일관되게 접근하기 (Java 21 정식)

Java 21에서 도입된 `SequencedCollection`, `SequencedSet`, `SequencedMap` 인터페이스는 순서가 정의된 컬렉션에서 첫 번째·마지막 요소를 `getFirst()` / `getLast()`로 통일된 방법으로 가져오고, `reversed()`로 역순 뷰를 반환한다. 기존에는 `LinkedList`의 `peek()`, `TreeMap`의 `firstEntry()`, `ArrayDeque`의 `peekFirst()` 등 컬렉션마다 다른 API를 외워야 했지만, 이제 하나의 인터페이스로 추상화된다. `List`, `Deque`, `SortedSet`, `LinkedHashSet`, `LinkedHashMap` 등 기존 클래스들이 소급 적용(retrofit)되므로 코드 변경 없이 혜택을 받는다.

```java
// 기존: 컬렉션 종류마다 API가 달랐음
LinkedList<String> list = new LinkedList<>(List.of("a", "b", "c"));
String first = list.getFirst(); // 원래도 있었지만 인터페이스 보장 없음

// Java 21: SequencedCollection 인터페이스로 통일
SequencedCollection<String> col = new LinkedHashSet<>(List.of("x", "y", "z"));
col.getFirst();   // "x"
col.getLast();    // "z"
col.reversed().forEach(System.out::println); // z, y, x

// SequencedMap도 동일한 패턴
SequencedMap<String, Integer> map = new LinkedHashMap<>();
map.put("one", 1); map.put("two", 2); map.put("three", 3);
map.firstEntry(); // one=1
map.reversed();   // 역순 뷰 (copy 아님)
```

> 💡 **왜 중요한가**: 컬렉션 구현체를 교체해도 `SequencedCollection`을 타입으로 선언하면 API 변경이 없어지고, 역순 순회가 방어적 복사 없이 뷰로 처리되어 메모리 효율도 유지된다.

### Stream Gatherers(JEP 473)로 커스텀 중간 연산 구현하기 (Java 24 정식)

Java 24에서 정식 도입된 `Stream.gather(Gatherer)` API는 기존 `filter`·`map`·`flatMap`으로 표현하기 어려운 **상태 유지(stateful)** 또는 **다대다(many-to-many)** 변환을 스트림 파이프라인 안에서 직접 정의할 수 있게 해 준다. `Gatherer.of()`로 초기화(initializer)·통합(integrator)·완료(finisher) 세 단계를 조합하면 슬라이딩 윈도우, 연속 중복 제거, 청크 분할 같은 연산을 구현할 수 있으며, `java.util.stream.Gatherers` 유틸리티 클래스에 `windowFixed`, `windowSliding`, `scan`, `fold` 등의 기본 구현체가 미리 제공된다.

```java
import java.util.stream.Gatherers;

// 기본 제공 Gatherer: 슬라이딩 윈도우
List.of(1, 2, 3, 4, 5).stream()
    .gather(Gatherers.windowSliding(3))
    .forEach(System.out::println);
// [1, 2, 3], [2, 3, 4], [3, 4, 5]

// 커스텀 Gatherer: 연속된 중복 제거 (distinct와 달리 인접한 것만 제거)
Gatherer<Integer, ?, Integer> dedupAdjacent = Gatherer.ofSequential(
    () -> new int[]{Integer.MIN_VALUE},  // initializer: 이전 값 저장
    (state, element, downstream) -> {
        if (element != state[0]) {
            state[0] = element;
            downstream.push(element);
        }
        return true;
    }
);

List.of(1, 1, 2, 2, 2, 3, 1, 1).stream()
    .gather(dedupAdjacent)
    .toList(); // [1, 2, 3, 1]

// scan: 누적 합계를 요소마다 방출
List.of(1, 2, 3, 4).stream()
    .gather(Gatherers.scan(() -> 0, Integer::sum))
    .toList(); // [1, 3, 6, 10]
```

> 💡 **왜 중요한가**: 기존 스트림의 중간 연산 표현력 한계를 공식적으로 확장하여, 외부 루프나 `Collector` 우회 없이 복잡한 상태 기반 파이프라인을 선언적으로 작성할 수 있고 병렬 스트림과도 통합된다.
