### 1. `@HttpExchange` + `HttpServiceProxyFactory`로 Feign 없이 선언적 HTTP 클라이언트 만들기 (Spring 6+)

`@HttpExchange`를 인터페이스에 붙이고 `HttpServiceProxyFactory`로 프록시를 만들면, Spring Cloud OpenFeign 의존성 없이도 Retrofit·Feign 스타일의 선언적 HTTP 호출이 가능합니다. `RestClient`나 `WebClient`를 어댑터로 감싸기 때문에 재시도·인터셉터·타임아웃 설정을 그대로 재활용할 수 있고, 컨트롤러 매핑처럼 `@GetExchange("/users/{id}")`로 경로와 파라미터를 명확히 표현합니다.

```java
public interface UserApi {
    @GetExchange("/users/{id}")
    User findById(@PathVariable Long id);
}

@Bean
UserApi userApi(RestClient.Builder builder) {
    RestClient client = builder.baseUrl("https://api.example.com").build();
    return HttpServiceProxyFactory
        .builderFor(RestClientAdapter.create(client))
        .build()
        .createClient(UserApi.class);
}
```

> 💡 **왜 중요한가**: Feign 스타터·리본 같은 외부 의존성 없이 Spring 코어만으로 타입 안전한 HTTP 클라이언트를 얻어, 버전 충돌과 러닝커브 없이 API 호출 코드를 도메인 인터페이스로 추상화할 수 있습니다.

### 2. `@Cacheable(sync = true)`로 캐시 스탬피드(Thundering Herd) 막기

`@Cacheable`의 기본 동작은 캐시 미스 시 동시에 들어온 여러 요청이 각자 원본 로직(예: DB 조회)을 실행하기 때문에, 인기 키가 만료되는 순간 백엔드에 부하가 몰리는 캐시 스탬피드가 발생합니다. `sync = true`를 주면 동일 키에 대해 한 스레드만 값을 계산하고 나머지는 대기했다가 계산된 결과를 공유받아, 백엔드 호출을 한 번으로 줄일 수 있습니다.

```java
@Cacheable(cacheNames = "products", key = "#id", sync = true)
public Product findProduct(Long id) {
    return productRepository.findById(id).orElseThrow();
}
```

> 💡 **왜 중요한가**: 트래픽이 몰리는 순간 캐시 미스 한 번으로 DB가 무너지는 사고를 애노테이션 옵션 하나로 방지할 수 있어, 별도 분산 락 인프라 없이도 방어선을 확보합니다.
