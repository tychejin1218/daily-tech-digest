### `@ServiceConnection`으로 Testcontainers 컨테이너를 자동 배선하기 (Spring Boot 3.1+)

Testcontainers로 띄운 PostgreSQL/Redis/Kafka 등의 컨테이너에 `@ServiceConnection`을 붙이면, `DynamicPropertyRegistry`로 URL·포트·자격증명을 일일이 등록하던 보일러플레이트가 사라진다. Spring Boot가 컨테이너 타입을 인식해 `ConnectionDetails` 빈을 자동으로 만들어주기 때문에, 테스트 클래스는 `@SpringBootTest`만 붙여도 실제 DB에 곧바로 연결된다.

```java
@TestConfiguration(proxyBeanMethods = false)
class TestcontainersConfig {
    @Bean @ServiceConnection
    PostgreSQLContainer<?> postgres() {
        return new PostgreSQLContainer<>("postgres:16-alpine");
    }
}
```

> 💡 **왜 중요한가**: 컨테이너 스펙과 애플리케이션 프로퍼티가 분리되지 않아 오타·타입 불일치로 인한 테스트 플레이키니스를 원천 차단할 수 있다.

### `@HttpExchange`로 선언적 HTTP 인터페이스 클라이언트 만들기 (Spring 6+)

Feign처럼, 인터페이스에 `@HttpExchange`(또는 `@GetExchange`, `@PostExchange`)만 선언하면 Spring이 `RestClient`/`WebClient` 기반의 프록시 구현체를 만들어준다. 외부 API 호출 코드를 어댑터 클래스 대신 타입 안전한 메서드 시그니처로 표현할 수 있고, 인증 헤더·Base URL 같은 공통 설정은 팩토리 한 곳에 몰아둘 수 있다.

```java
interface GithubApi {
    @GetExchange("/repos/{owner}/{repo}")
    Repo getRepo(@PathVariable String owner, @PathVariable String repo);
}

@Bean GithubApi githubApi(RestClient.Builder builder) {
    RestClient client = builder.baseUrl("https://api.github.com").build();
    return HttpServiceProxyFactory
        .builderFor(RestClientAdapter.create(client))
        .build()
        .createClient(GithubApi.class);
}
```

> 💡 **왜 중요한가**: 외부 서드파티 의존성(OpenFeign 등) 없이도 요청/응답 규약을 인터페이스로 문서화하면서, 테스트에서는 Mock으로 손쉽게 대체할 수 있다.
