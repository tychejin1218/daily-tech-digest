### 1. PostgreSQL `pg_hint_plan` — 옵티마이저가 잘못된 실행계획을 고를 때 힌트로 강제하기
PostgreSQL은 Oracle/MySQL과 달리 기본적으로 쿼리 힌트를 지원하지 않지만, `pg_hint_plan` 확장을 설치하면 주석 형태(`/*+ IndexScan(t idx_name) */`)로 조인 순서, 인덱스 선택, 조인 방식을 강제할 수 있다. 통계가 왜곡되거나 데이터 분포가 급변하는 테이블에서 옵티마이저가 Seq Scan을 고집할 때 임시 우회책으로 유용하며, 핫픽스 후에는 반드시 통계 갱신(`ANALYZE`)이나 쿼리 리팩토링으로 근본 원인을 해결해야 한다.

> 💡 **왜 중요한가**: 옵티마이저 오판으로 인한 장애를 코드 배포 없이 즉시 막을 수 있는 비상 수단이다.

### 2. JPA `OSIV(Open Session In View)` 비활성화 — 영속성 컨텍스트를 트랜잭션 경계로 좁히기
Spring Boot는 `spring.jpa.open-in-view=true`가 기본값이라 컨트롤러/뷰 렌더링이 끝날 때까지 영속성 컨텍스트와 DB 커넥션이 유지된다. 이는 지연 로딩을 편리하게 해주지만 커넥션 풀을 오래 점유해 트래픽이 몰릴 때 풀 고갈의 주범이 되므로, `false`로 끄고 서비스 계층에서 `@Transactional`과 페치 조인으로 필요한 데이터를 명시적으로 로드하는 것이 운영 환경에서는 더 안전하다.

> 💡 **왜 중요한가**: OSIV를 끄는 것만으로도 DB 커넥션 점유 시간이 비즈니스 로직 수행 구간으로 줄어 동시 처리량이 크게 개선된다.
