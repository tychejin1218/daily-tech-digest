### 1. `Files.mismatch(path1, path2)` (Java 12 정식)로 두 파일 바이트 비교할 때 `MessageDigest`로 해시 떠서 비교하는 관성 벗어나기

두 파일이 같은지 확인하려고 SHA-256 해시를 양쪽 다 떠서 문자열 비교하는 코드, 사실 과하다. `Files.mismatch(p1, p2)`는 첫 번째로 다른 바이트의 위치를 `long`으로 돌려주고, 완전히 같으면 `-1L`을 반환한다 — 내부적으로 버퍼 단위로 읽다가 다른 바이트를 만나는 순간 즉시 종료하므로 해시 전체 스캔보다 평균적으로 훨씬 빠르다. 심지어 파일 크기가 다르면 바로 다른 지점을 돌려주고 끝낸다.

```java
// Before: 해시 뜨고 문자열로 비교
byte[] h1 = MessageDigest.getInstance("SHA-256").digest(Files.readAllBytes(p1));
byte[] h2 = MessageDigest.getInstance("SHA-256").digest(Files.readAllBytes(p2));
boolean same = Arrays.equals(h1, h2);

// After: 다른 바이트를 만나면 그 순간 끝
boolean same = Files.mismatch(p1, p2) == -1L;
```

> 💡 **왜 중요한가**: "같은지 비교"의 하한선은 "다른 지점을 찾을 때까지"이지 "전체를 다 해싱할 때까지"가 아니다 — 조기 종료가 공짜로 따라오는 API를 쓰는 게 당연한 디폴트다.

### 2. `List.copyOf(collection)` (Java 10 정식)로 `Collections.unmodifiableList(new ArrayList<>(src))` 이중 래핑 관성 벗어나기

방어적 복사 + 불변화하려고 `Collections.unmodifiableList(new ArrayList<>(input))`을 쓰는 손이 익어있는데, `List.copyOf(input)`은 이 둘을 한 번에 처리한다. 더 중요한 건, 입력이 이미 `List.copyOf`로 만들어진 불변 리스트면 **복사하지 않고 그대로 반환**한다 — DTO 생성자에서 매번 copyOf 걸어도 중복 복사가 안 일어난다. 단, `null` 요소를 허용하지 않으니 nullable 요소 리스트에는 쓰면 안 된다.

```java
// Before: 복사 + 래핑 두 단계, 매번 새 ArrayList 생성
public Order(List<Item> items) {
    this.items = Collections.unmodifiableList(new ArrayList<>(items));
}

// After: 한 줄, 이미 copyOf된 리스트면 복사도 생략
public Order(List<Item> items) {
    this.items = List.copyOf(items);
}
```

> 💡 **왜 중요한가**: 불변 컬렉션 관용구는 "방어적 복사"와 "읽기 전용 뷰"가 섞여서 나오는데, `List.copyOf`는 둘을 합치고 중복 복사까지 걸러준다 — 생성자/빌더가 체인으로 불변 리스트를 넘길 때마다 메모리를 아끼는 디폴트다.
