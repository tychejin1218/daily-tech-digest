### 1. `String Templates` 대신 `Formatted String` 또는 외부 라이브러리로 안전한 문자열 보간 처리하기

Java 21/22에서 프리뷰로 도입되었던 String Templates(STR."...")는 보안 및 설계 이슈로 Java 23에서 제거되어 정식 기능이 되지 못했습니다. 따라서 현재로서는 `String.format()`, `formatted()` 인스턴스 메서드, 또는 `MessageFormat`을 사용하거나 SQL 같은 민감한 컨텍스트에서는 PreparedStatement를 활용해 인젝션을 방지해야 합니다. 향후 재설계된 보간 기능이 다시 제안될 수 있으므로 프리뷰 코드는 마이그레이션 계획을 미리 세워두는 것이 좋습니다.

```java
// 권장: formatted() 인스턴스 메서드
String msg = "User %s logged in at %tT".formatted(name, Instant.now());

// SQL은 절대 문자열 보간 금지 → PreparedStatement 사용
var ps = conn.prepareStatement("SELECT * FROM users WHERE id = ?");
ps.setLong(1, userId);
```

> 💡 **왜 중요한가**: 사라진 프리뷰 기능에 의존한 코드를 그대로 두면 컴파일 자체가 깨지므로, 표준 API로 회귀하고 보간이 필요한 영역의 보안 경계를 다시 점검해야 합니다.

### 2. `Thread.onSpinWait()`로 짧은 대기 루프의 성능과 전력 효율 개선하기

Java 9에서 도입된 `Thread.onSpinWait()`은 스레드가 busy-wait 루프(예: lock-free 큐의 producer 대기)에 있다는 것을 JVM과 CPU에 힌트로 알려줍니다. x86의 `PAUSE` 명령어, ARM의 `YIELD` 같은 아키텍처 고유 명령으로 매핑되어 파이프라인 스톨을 줄이고 메모리 순서 위반 페널티를 감소시키며 전력 소비도 낮춰줍니다.

```java
// AtomicReference 기반 lock-free 대기 루프
while (!ready.get()) {
    Thread.onSpinWait(); // CPU에 spin 중임을 알림
}

// 일정 횟수 spin 후 yield/park로 전환하는 적응적 패턴이 일반적
for (int i = 0; i < 64; i++) {
    if (ready.get()) return;
    Thread.onSpinWait();
}
LockSupport.parkNanos(1_000);
```

> 💡 **왜 중요한가**: 고성능 동시성 코드에서 `while(!cond);` 형태의 빈 spin 루프는 코어를 100%로 점유하고 메모리 시스템에도 부담을 주는데, 한 줄 추가만으로 하드웨어 수준의 협력을 얻을 수 있습니다.
