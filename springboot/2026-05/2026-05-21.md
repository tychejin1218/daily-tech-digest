### 1. `@ServiceConnection`으로 Testcontainers를 자동 구성 프로퍼티에 자동 연결하기
Spring Boot 3.1+에서는 Testcontainers 컨테이너 빈에 `@ServiceConnection`만 붙이면, 컨테이너가 노출하는 호스트·포트·자격증명을 `spring.datasource.*`, `spring.data.redis.*` 등 자동 구성 프로퍼티에 자동으로 바인딩해줍니다. 기존에 `@DynamicPropertySource`로 일일이 람다를 작성하던 보일러플레이트가 사라지고, 지원되는 컨테이너(`PostgreSQLContainer`, `KafkaContainer`, `RedisContainer` 등)는 `@Bean` 선언만으로 즉시 연결됩니다.

```java
@TestConfiguration(proxyBeanMethods = false)
class TestcontainersConfig {
    @Bean
    @ServiceConnection
    PostgreSQLContainer<?> postgres() {
        return new PostgreSQLContainer<>("postgres:16-alpine");
    }
}
```

> 💡 **왜 중요한가**: 인프라 종속성을 코드로 선언하는 통합 테스트가 `application.yml`이나 별도 프로퍼티 오버라이드 없이도 운영 환경과 동일한 자동 구성 경로를 그대로 타게 됩니다.

### 2. `ObjectProvider<T>`로 선택적·다중·지연 의존성을 안전하게 주입하기
생성자 주입 시 빈이 없거나 여러 개일 수 있는 의존성에 `ObjectProvider<T>`를 사용하면, `Optional` 주입이나 `@Autowired(required = false)`보다 풍부한 API(`getIfAvailable()`, `getIfUnique()`, `orderedStream()`, `ifAvailable()`)로 0개·1개·N개 케이스를 명시적으로 다룰 수 있습니다. 또한 실제 호출 시점에 빈을 해소(resolve)하므로 순환 의존성과 초기화 순서 문제 회피에도 유용합니다.

```java
@Service
class NotificationService {
    private final ObjectProvider<MessageSender> senders;

    NotificationService(ObjectProvider<MessageSender> senders) {
        this.senders = senders;
    }

    void notifyAll(String msg) {
        senders.orderedStream().forEach(s -> s.send(msg));
    }
}
```

> 💡 **왜 중요한가**: 플러그인 형태의 확장 포인트나 조건부 빈을 다룰 때, 빈 부재·중복 상황을 컴파일러가 강제하는 타입으로 표현해 런타임 NPE와 `NoUniqueBeanDefinitionException`을 동시에 예방합니다.
