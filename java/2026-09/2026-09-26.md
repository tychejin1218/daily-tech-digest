### 1. `Stream.mapMulti((elem, downstream) -> ...)`로 `flatMap` + 임시 스트림 생성 오버헤드 벗어나기 (Java 16 정식)

`flatMap`은 각 요소마다 새 `Stream` 인스턴스를 생성하는데, 요소당 0~2개의 결과만 뽑는 케이스에선 이 래핑 비용이 순수 낭비다. `mapMulti`는 `Consumer`를 직접 호출해 결과를 밀어넣기 때문에 중간 스트림 할당 없이 fan-out이 가능하고, 타입 캐스팅이 얽힌 필터+매핑 조합에서도 `filter(x -> x instanceof Foo).map(x -> (Foo)x)` 두 단계를 한 콜백으로 압축할 수 있다.

```java
// 기존: 요소마다 Stream.of(...) 인스턴스 생성
List<String> tags = posts.stream()
    .flatMap(p -> p.getTags().stream())
    .toList();

// mapMulti: Consumer로 직접 push, 중간 Stream 없음
List<String> tags = posts.stream()
    .<String>mapMulti((p, downstream) -> p.getTags().forEach(downstream))
    .toList();

// instanceof 패턴 + 캐스팅 압축
List<Admin> admins = users.stream()
    .<Admin>mapMulti((u, out) -> {
        if (u instanceof Admin a) out.accept(a);
    })
    .toList();
```

> 💡 **왜 중요한가**: 대용량 스트림에서 `flatMap`을 반복 호출할 때 JIT가 이스케이프 분석에 실패하면 요소당 스트림 객체 할당이 GC 압력으로 이어지는데, `mapMulti`는 이 할당 자체를 없앤다.

### 2. `Thread.ofVirtual().unstarted(Runnable)`로 가상 스레드의 "생성 ≠ 시작" 분리하기 (Java 21 정식)

`Thread.startVirtualThread()`는 편하지만 생성과 동시에 실행이 시작되므로, 스레드 참조를 확보하기 전에 이미 러너블이 돌아버려 초기 설정(인터럽트 핸들러 등록, uncaughtExceptionHandler 세팅)을 놓칠 수 있다. `ofVirtual().unstarted()`는 시작되지 않은 `Thread` 인스턴스만 만들어 반환하므로, 필요한 설정을 모두 끝낸 뒤 `start()`를 명시적으로 호출할 수 있다.

```java
// 기존: 시작과 동시에 실행 - 설정 주입 타이밍이 애매
Thread t = Thread.startVirtualThread(() -> doWork());
t.setUncaughtExceptionHandler(handler); // 이미 실행 중일 수도 있음

// unstarted: 생성만 하고 설정 후 시작
Thread t = Thread.ofVirtual()
    .name("worker-", counter.getAndIncrement())
    .unstarted(() -> doWork());
t.setUncaughtExceptionHandler((thread, ex) -> log.error("crashed", ex));
registry.register(t); // 시작 전에 안전하게 등록
t.start();
```

> 💡 **왜 중요한가**: 가상 스레드는 생성 비용이 극도로 낮아 "일단 시작하고 나중에 설정" 관성이 생기는데, uncaught 예외 핸들러는 스레드가 죽는 순간에 필요하므로 시작 전에 반드시 걸려있어야 한다.
