### 1. `Stream.toList()`로 스트림 결과를 불변 리스트로 한 방에 수집하기 (Java 16 정식)

기존에는 `stream.collect(Collectors.toList())`를 써야 했는데, 이 메서드는 반환 타입이 `ArrayList`인지 불변인지 문서상 보장이 없어서 팀마다 해석이 갈렸다. Java 16부터 `Stream`에 직접 추가된 `toList()`는 **명시적으로 불변 리스트**를 반환하며, `Collectors` 임포트도 필요 없고 널 요소도 허용한다. `Collectors.toUnmodifiableList()`와 달리 널을 넣어도 NPE가 나지 않는다는 점이 미묘한 차이.

```java
// Before
List<String> names = users.stream()
    .map(User::getName)
    .collect(Collectors.toList()); // 가변? 불변? 애매

// After (Java 16+)
List<String> names = users.stream()
    .map(User::getName)
    .toList(); // 확실한 불변 리스트, 짧고 명확
```

> 💡 **왜 중요한가**: 반환 리스트를 실수로 수정해서 발생하는 공유 상태 버그를 컴파일 후 즉시 `UnsupportedOperationException`으로 잡아낼 수 있고, `Collectors` 보일러플레이트도 사라진다.

### 2. `Pattern Matching for switch`로 instanceof 캐스팅 사슬 걷어내기 (Java 21 정식)

전통적인 `if-else` + `instanceof` + 캐스팅 조합은 코드가 길어질수록 실수하기 쉽고, 특히 `sealed` 계층에서 `default` 없이 모든 케이스를 처리했는지 컴파일러가 검증해주지 못했다. Java 21에서 정식이 된 switch 패턴 매칭은 **타입 검사, 캐스팅, 분기**를 한 줄로 처리하고, sealed 타입이면 exhaustiveness까지 컴파일러가 강제한다. `when` 절로 가드 조건도 얹을 수 있다.

```java
sealed interface Shape permits Circle, Square, Triangle {}

// Before
static double area(Shape s) {
    if (s instanceof Circle c) return Math.PI * c.radius() * c.radius();
    else if (s instanceof Square sq) return sq.side() * sq.side();
    else if (s instanceof Triangle t) return 0.5 * t.base() * t.height();
    throw new IllegalStateException(); // 새 타입 추가 시 컴파일러가 못 잡음
}

// After (Java 21+)
static double area(Shape s) {
    return switch (s) {
        case Circle c   -> Math.PI * c.radius() * c.radius();
        case Square sq  -> sq.side() * sq.side();
        case Triangle t when t.height() > 0 -> 0.5 * t.base() * t.height();
        case Triangle t -> 0; // exhaustive — 새 permits 추가 시 컴파일 에러
    };
}
```

> 💡 **왜 중요한가**: sealed + switch 패턴 조합은 "새 하위 타입 추가 시 처리 누락"이라는 도메인 확장 사고를 컴파일 타임에 원천 차단하는 대표적인 타입 안전 설계 도구다.
