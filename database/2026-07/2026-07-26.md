### 1. PostgreSQL `pg_advisory_xact_lock` — 다중 인스턴스 스케줄러·배치의 중복 실행을 DB 락으로 원천 차단하기

애플리케이션 정의 정수 키에 트랜잭션 스코프 락을 걸어, 여러 서버가 같은 스케줄러·배치를 동시에 실행하는 상황을 막는다. 커밋·롤백 시 자동 해제되므로 락 해제를 신경 쓸 필요가 없고, Redis·ZooKeeper 같은 외부 조율 시스템 없이 DB만으로 리더 선출을 흉내 낼 수 있다.

```sql
BEGIN;
-- 잡 ID를 해시해 정수 키로 사용
SELECT pg_advisory_xact_lock(hashtext('daily-report-job'));
-- 이 트랜잭션이 커밋될 때까지 다른 세션은 대기 (SKIP 원하면 pg_try_advisory_xact_lock)
INSERT INTO report_history(...) VALUES (...);
COMMIT;  -- 락 자동 해제
```

> 💡 **왜 중요한가**: `@Scheduled`를 N대 서버에서 굴려도 중복 실행을 DB 한 방으로 봉쇄할 수 있다.

### 2. JPA `hibernate.jdbc.batch_size` + `order_inserts` — 수천 건 `INSERT`를 한 번의 네트워크 왕복으로 묶어 처리하기

Hibernate는 기본적으로 엔티티마다 개별 `INSERT`를 날리지만, `batch_size`와 `order_inserts=true`를 켜면 같은 테이블의 INSERT를 모아 JDBC batch로 전송한다. 단, IDENTITY 키(`GeneratedValue.IDENTITY`)는 배치가 비활성화되므로 반드시 `SEQUENCE` 또는 `TABLE` 전략을 써야 한다.

```yaml
# application.yml
spring:
  jpa:
    properties:
      hibernate:
        jdbc.batch_size: 50
        order_inserts: true
        order_updates: true
```

```java
@Entity
class Item {
    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "item_seq")
    @SequenceGenerator(name = "item_seq", sequenceName = "item_seq", allocationSize = 50)
    Long id;
}
```

> 💡 **왜 중요한가**: 초기 데이터 마이그레이션·CSV 임포트가 수 분에서 수 초로 줄어드는 가장 손쉬운 튜닝 지점이다.
