### `VarHandle`로 `volatile`·`Atomic*` 없이 필드 단위 원자 연산 표현하기 (Java 9 정식)
필드 하나에만 가시성·원자성이 필요할 때 `AtomicInteger`로 통째로 박스로 감싸거나 `Unsafe`를 끌어쓰는 대신, `VarHandle`로 동일한 메모리 시맨틱(`getAcquire`/`setRelease`/`compareAndSet`)을 표준 API로 표현할 수 있습니다. 박스 객체와 추가 할당이 없어 캐시 라인 친화적이고, JIT가 인트린식으로 최적화하기도 쉽습니다.

```java
class Counter {
    private static final VarHandle VALUE;
    static {
        try {
            VALUE = MethodHandles.lookup()
                .findVarHandle(Counter.class, "value", int.class);
        } catch (ReflectiveOperationException e) {
            throw new ExceptionInInitializerError(e);
        }
    }
    @SuppressWarnings("unused") private int value;

    int incrementAndGet() {
        int prev, next;
        do {
            prev = (int) VALUE.getVolatile(this);
            next = prev + 1;
        } while (!VALUE.compareAndSet(this, prev, next));
        return next;
    }
}
```

> 💡 **왜 중요한가**: 락 없이 카운터·플래그·상태 머신을 구현해야 하는 핫 패스(요청별 메트릭, 배압 제어 등)에서 `Unsafe`에 의존하지 않고도 동등한 성능과 메모리 시맨틱을 표준 API만으로 얻을 수 있습니다.

### `Cleaner` API로 `finalize()`를 안전하게 대체하기 (Java 9 정식)
`Object.finalize()`는 Java 9에서 deprecated, 18에서 forRemoval로 단계적으로 잘려나가는 중입니다. 네이티브 핸들·파일 디스크립터·오프힙 버퍼처럼 GC 외부의 리소스를 닫아야 할 때는 `Cleaner`에 등록한 콜백을 사용하고, **콜백이 감싼 객체 자신을 참조하지 않도록** 정적 inner 클래스나 람다 외부 변수를 피해서 작성해야 합니다.

```java
class NativeBuffer implements AutoCloseable {
    private static final Cleaner CLEANER = Cleaner.create();
    private final long ptr;
    private final Cleaner.Cleanable cleanable;

    NativeBuffer(long size) {
        this.ptr = allocateNative(size);
        // 람다가 'this'를 캡쳐하지 않도록 ptr만 캡쳐
        long capturedPtr = ptr;
        this.cleanable = CLEANER.register(this, () -> freeNative(capturedPtr));
    }

    @Override public void close() { cleanable.clean(); }
}
```

> 💡 **왜 중요한가**: `finalize`보다 예측 가능한 시점에 호출되고 ParkedThread에서 안전하게 동작해, JNI·MappedByteBuffer 같은 외부 리소스를 누수 없이 회수할 수 있습니다.
