### PostgreSQL `idle_in_transaction_session_timeout` — 좀비 트랜잭션이 VACUUM을 막지 못하게 끊어내기

애플리케이션이 `BEGIN` 후 커밋/롤백 없이 방치한 커넥션은 그 시점 이후의 모든 dead tuple을 VACUUM이 회수하지 못하게 막아 테이블 부풀림(bloat)과 트랜잭션 ID wraparound 위험을 키운다. `idle_in_transaction_session_timeout`을 설정해두면 일정 시간 IDLE 상태인 트랜잭션을 서버가 자동으로 종료시켜 좀비 세션을 차단할 수 있다.

```sql
-- 전역 (postgresql.conf)
ALTER SYSTEM SET idle_in_transaction_session_timeout = '60s';
SELECT pg_reload_conf();

-- 특정 사용자/DB에만 적용
ALTER ROLE app_user SET idle_in_transaction_session_timeout = '30s';

-- 현재 idle in transaction 상태 세션 확인
SELECT pid, state, xact_start, now() - xact_start AS duration, query
FROM pg_stat_activity
WHERE state = 'idle in transaction'
ORDER BY xact_start;
```

> 💡 **왜 중요한가**: 끊기지 않은 한 개의 트랜잭션이 전체 DB의 VACUUM을 무력화시킬 수 있으므로, 타임아웃은 운영 PostgreSQL의 기본 안전장치다.

### JPA `@BatchSize` — `@EntityGraph` 없이 N+1을 IN 절 묶음 페치로 완화하기

연관 엔티티를 지연 로딩할 때 컬렉션마다 별도 SELECT가 나가는 N+1 문제는, 엔티티/컬렉션에 `@BatchSize(size = N)`을 붙이면 Hibernate가 N개씩 묶어 `WHERE id IN (?, ?, …)` 한 방으로 가져오도록 바꿔준다. `@EntityGraph`/fetch join처럼 카테시안 곱이나 페이징 부작용을 일으키지 않고 쿼리 수를 1+ceil(전체/N)로 줄일 수 있다.

```java
@Entity
public class Team {
    @Id Long id;

    @OneToMany(mappedBy = "team", fetch = FetchType.LAZY)
    @BatchSize(size = 100) // Team 100개의 members를 IN 절 하나로 페치
    private List<Member> members;
}

// 또는 전역 기본값
// application.yml: spring.jpa.properties.hibernate.default_batch_fetch_size: 100
```

> 💡 **왜 중요한가**: fetch join이 부적절한 페이징/다중 컬렉션 상황에서도 N+1을 실용적으로 잡을 수 있는, 운영에서 가장 부작용이 적은 처방이다.
