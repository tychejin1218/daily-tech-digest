### 1. `spring.threads.virtual.enabled=true`로 톰캣 요청 처리에 Virtual Threads 적용하기 (Spring Boot 3.2+, Java 21)

Java 21의 가상 스레드를 Spring Boot에서 활성화하면 톰캣 요청 처리, `@Async`, `@Scheduled`가 모두 가벼운 가상 스레드로 실행된다. I/O 대기가 많은 워크로드(외부 API 호출, DB 쿼리 등)에서 스레드 풀 크기에 발목 잡히지 않고 수만 개 동시 요청을 처리할 수 있다.

```properties
# application.properties
spring.threads.virtual.enabled=true
```

```java
// 별도 코드 변경 없이 컨트롤러가 가상 스레드에서 실행됨
@GetMapping("/orders/{id}")
public Order getOrder(@PathVariable Long id) {
    // Thread.currentThread() → VirtualThread[#123]/runnable@ForkJoinPool
    return orderClient.fetch(id); // 블로킹 I/O도 캐리어 스레드를 점유하지 않음
}
```

단, `synchronized` 블록이나 네이티브 메서드 안에서 블로킹하면 캐리어 스레드가 pinning되므로 커넥션 풀 락(HikariCP는 `ReentrantLock` 기반이라 안전) 등은 사전 점검이 필요하다.

> 💡 **왜 중요한가**: I/O 바운드 서비스에서 스레드 풀 튜닝 없이도 처리량이 수 배 이상 뛴다.

### 2. `@ConfigurationProperties` + `@Validated`로 애플리케이션 부팅 시점에 설정 오류 잡아내기

`@Value`로 흩어진 설정을 타입 안전한 POJO로 묶고, JSR-303(`@NotBlank`, `@Min`, `@Email` 등)을 걸어두면 잘못된 설정이 있을 때 앱이 아예 뜨지 않는다. 프로덕션에서 첫 요청이 들어온 뒤에야 `NumberFormatException`이 터지는 사고를 원천 차단할 수 있다.

```java
@ConfigurationProperties(prefix = "app.mail")
@Validated
public record MailProperties(
        @NotBlank String host,
        @Min(1) @Max(65535) int port,
        @Email String from,
        @NotNull Duration timeout
) {}

@SpringBootApplication
@EnableConfigurationProperties(MailProperties.class)
public class Application { }
```

```yaml
# application.yml — port가 없으면 부팅 시 BindValidationException으로 즉시 실패
app:
  mail:
    host: smtp.example.com
    port: 587
    from: noreply@example.com
    timeout: 5s
```

`record`로 선언하면 불변성까지 확보되고, IDE 자동완성과 `spring-boot-configuration-processor`의 메타데이터도 함께 활용할 수 있다.

> 💡 **왜 중요한가**: 설정 오류를 런타임이 아닌 부팅 시점에 잡아 프로덕션 장애를 예방한다.
