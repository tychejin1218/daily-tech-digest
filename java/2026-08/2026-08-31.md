### 1. `Stream.toList()`로 불변 리스트를 한 줄에 얻고 `Collectors.toList()` 관성 벗어나기 (Java 16 정식)

`stream.collect(Collectors.toList())`는 매번 `Collectors` 클래스를 거쳐야 하고, 반환되는 리스트가 가변인지 불변인지도 JDK 구현에 따라 달라진다. Java 16부터 도입된 `Stream.toList()`는 `null`을 허용하는 **불변(unmodifiable) 리스트**를 명확한 계약으로 반환하며, 중간 컬렉터 객체 생성 오버헤드도 없다. 다만 반환된 리스트에 `add()`나 `set()`을 호출하면 `UnsupportedOperationException`이 터지므로, 가변 리스트가 필요하면 여전히 `Collectors.toCollection(ArrayList::new)`를 써야 한다.

```java
// Before (Java 8)
List<String> names = users.stream()
    .map(User::name)
    .collect(Collectors.toList()); // 가변? 불변? JDK 구현 마음대로

// After (Java 16+)
List<String> names = users.stream()
    .map(User::name)
    .toList(); // 명시적으로 불변, null 허용
```

> 💡 **왜 중요한가**: 대부분의 스트림 결과는 조회용 스냅샷이라 불변이 오히려 안전하고, 코드 라인도 짧아진다.

### 2. `HttpClient.newHttpClient()`로 Apache HttpClient·OkHttp 없이 표준 API로 REST 호출하기 (Java 11 정식)

Java 11 이전에는 `HttpURLConnection`의 API가 워낙 원시적이라 실무에서는 Apache HttpClient나 OkHttp 같은 외부 라이브러리를 강제로 붙여왔다. Java 11의 `java.net.http.HttpClient`는 동기(`send`)와 비동기(`sendAsync`) 호출을 모두 지원하고, HTTP/2와 WebSocket까지 표준으로 처리한다. `HttpClient` 인스턴스는 스레드 안전하므로 애플리케이션 수명 동안 한 번만 생성해 재사용하는 것이 정석이다.

```java
// 애플리케이션 시작 시 한 번만 생성
private static final HttpClient CLIENT = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(5))
    .version(HttpClient.Version.HTTP_2)
    .build();

// 비동기 호출 — CompletableFuture로 파이프라이닝
HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users/42"))
    .header("Accept", "application/json")
    .timeout(Duration.ofSeconds(3))
    .GET()
    .build();

CLIENT.sendAsync(req, HttpResponse.BodyHandlers.ofString())
    .thenApply(HttpResponse::body)
    .thenAccept(System.out::println);
```

> 💡 **왜 중요한가**: 간단한 REST 호출 하나 때문에 무거운 외부 의존성을 끌어들일 필요가 없어져 라이브러리 버전 충돌·CVE 대응 부담이 줄어든다.
