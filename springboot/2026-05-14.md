### 1. `JdbcClient`로 `JdbcTemplate`보다 간결하게 SQL 작성하기
Spring Framework 6.1 / Spring Boot 3.2부터 추가된 fluent JDBC API로, named/positional 파라미터 바인딩과 `RowMapper` 적용을 메서드 체인 하나로 표현할 수 있다. `jdbcClient.sql("select * from member where id = :id").param("id", 1L).query(Member.class).single()` 형태라 기존 `JdbcTemplate`/`NamedParameterJdbcTemplate`의 이원화된 API를 한 객체로 통합한다.

> 💡 **왜 중요한가**: JPA를 쓰기엔 과한 단순 쿼리 영역에서, 보일러플레이트 없이 타입 안전한 SQL 매핑을 얻을 수 있다.

### 2. `@TransactionalEventListener(phase = AFTER_COMMIT)`로 커밋 이후에만 부수효과 실행하기
일반 `@EventListener`는 `publishEvent` 시점에 동기 실행되므로, 발행 이후 트랜잭션이 롤백돼도 외부 API 호출·메일 발송 같은 부수효과가 이미 일어나 데이터 정합성이 깨진다. `@TransactionalEventListener`의 `AFTER_COMMIT` phase를 사용하면 트랜잭션이 실제로 커밋된 후에만 리스너가 동작해 "DB는 롤백됐는데 알림은 나간" 상황을 원천 차단할 수 있다.

> 💡 **왜 중요한가**: 도메인 이벤트 기반 아키텍처에서 "절반만 성공한 상태"를 막아 결제·알림 같은 비가역 작업의 신뢰성을 확보한다.
