### PostgreSQL `SELECT ... FOR UPDATE SKIP LOCKED` — 여러 워커가 같은 작업 큐를 안전하게 나눠 처리하기
DB 테이블을 작업 큐로 쓸 때, 여러 워커가 동시에 `SELECT ... FOR UPDATE`로 같은 행을 집으면 한 워커만 잠금을 얻고 나머지는 대기하다 줄줄이 막힙니다. `SKIP LOCKED`를 붙이면 이미 잠긴 행은 건너뛰고 잠기지 않은 다음 행을 즉시 가져오므로, 워커마다 서로 다른 작업을 받아 경합 없이 병렬 소비할 수 있습니다. 보통 `... ORDER BY id LIMIT 1 FOR UPDATE SKIP LOCKED` 형태로 한 건씩 집어 처리 후 상태를 업데이트하는 패턴으로 씁니다.

> 💡 **왜 중요한가**: 카프카/Redis 큐를 따로 두지 않고도 기존 RDB만으로 락 경합 없는 분산 작업 분배를 구현할 수 있습니다.

---

### 커버링 인덱스와 `INCLUDE` — 테이블을 건드리지 않는 Index-Only Scan 만들기
인덱스로 행을 찾은 뒤 추가 컬럼을 읽으려고 다시 테이블(힙)을 방문하는 비용(heap fetch)이 쿼리 시간의 상당 부분을 차지할 때가 있습니다. 자주 조회하는 컬럼을 `CREATE INDEX idx ON orders (user_id) INCLUDE (status, amount)`처럼 인덱스 리프에 함께 저장하면, 필요한 데이터가 모두 인덱스 안에 있어 테이블 접근 없이 Index-Only Scan으로 끝납니다. `INCLUDE` 컬럼은 정렬·검색에 쓰이지 않고 "데이터만 얹는" 용도라 인덱스 키를 불필요하게 키우지 않는 게 장점입니다. (MySQL InnoDB는 PK가 클러스터링 키이므로 보조 인덱스에 조회 컬럼을 직접 포함시켜 같은 효과를 냅니다.)

> 💡 **왜 중요한가**: 읽기 빈도가 높은 쿼리에서 힙 방문을 제거해 디스크 I/O를 크게 줄일 수 있습니다.
