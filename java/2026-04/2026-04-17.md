### `Instant.now(Clock)`으로 테스트 가능한 시간 의존 코드 작성하기 (Java 8 정식)

`Instant.now()`를 직접 호출하면 테스트에서 시간을 고정할 수 없어 시간 의존 로직을 검증하기 어렵다. `Clock`을 주입 받아 `Instant.now(clock)` 형태로 사용하면 프로덕션에선 `Clock.systemUTC()`, 테스트에선 `Clock.fixed(instant, zone)`을 주입해 시점을 완벽히 통제할 수 있다.

```java
public class OrderService {
    private final Clock clock;

    public OrderService(Clock clock) { this.clock = clock; }

    public Order create(String item) {
        return new Order(item, Instant.now(clock));
    }
}

// 테스트
Clock fixed = Clock.fixed(Instant.parse("2026-04-17T09:00:00Z"), ZoneOffset.UTC);
OrderService service = new OrderService(fixed);
assertEquals(Instant.parse("2026-04-17T09:00:00Z"), service.create("book").createdAt());
```

> 💡 **왜 중요한가**: 시간 의존 로직을 결정론적으로 테스트할 수 있어 `Thread.sleep`이나 시간 목킹 라이브러리 없이도 만료·스케줄·타임아웃 로직을 안정적으로 검증할 수 있다.

### `CompletableFuture.orTimeout()` / `completeOnTimeout()`으로 비동기 작업 타임아웃 처리하기 (Java 9 정식)

Java 8의 `CompletableFuture`엔 타임아웃 API가 없어 `ScheduledExecutorService`로 직접 구현해야 했지만, Java 9부터 `orTimeout()`(시간 초과 시 `TimeoutException`)과 `completeOnTimeout()`(시간 초과 시 기본값 반환)을 표준으로 제공한다. 두 메서드 모두 원본 Future를 반환해 파이프라인 중간에 자연스럽게 끼워 넣을 수 있다.

```java
CompletableFuture<String> result = CompletableFuture
    .supplyAsync(() -> callSlowApi())
    .completeOnTimeout("fallback", 2, TimeUnit.SECONDS)  // 2초 초과 시 fallback
    .thenApply(String::toUpperCase);

CompletableFuture<String> strict = CompletableFuture
    .supplyAsync(() -> callSlowApi())
    .orTimeout(2, TimeUnit.SECONDS)  // 2초 초과 시 TimeoutException
    .exceptionally(ex -> "error: " + ex.getMessage());
```

> 💡 **왜 중요한가**: 외부 API 호출이나 느린 I/O에서 스레드가 무한 대기하는 것을 표준 API로 방지해 시스템 전체의 응답성과 장애 격리를 크게 개선할 수 있다.
