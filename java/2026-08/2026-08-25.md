### 1. `HexFormat.of()`로 바이트 배열과 16진수 문자열을 표준 API로 변환하기 (Java 17 정식)

해시값이나 바이너리 데이터를 hex 문자열로 다룰 때 `String.format("%02x", b)` 루프나 `DatatypeConverter`, Apache Commons 같은 외부 의존성을 쓰던 시절이 있었다. Java 17부터는 `HexFormat.of().formatHex(byte[])`와 `parseHex(CharSequence)`로 양방향 변환이 표준 라이브러리 한 줄로 끝난다. 대문자·구분자·접두사까지 `HexFormat.of().withUpperCase().withDelimiter(":")`로 커스터마이징 가능하다.

```java
byte[] hash = MessageDigest.getInstance("SHA-256").digest(input);
String hex = HexFormat.of().formatHex(hash);           // "a591a6d40bf420..."
byte[] back = HexFormat.of().parseHex(hex);            // 역변환도 한 줄
String mac = HexFormat.ofDelimiter(":").withUpperCase().formatHex(macBytes); // "AA:BB:CC:..."
```

> 💡 **왜 중요한가**: 암호화 해시·MAC 주소·바이너리 로깅에서 매번 재발명하던 hex 인코딩을 표준 API로 통일하면, 외부 의존성과 성능 문제가 있는 자체 구현 유틸을 통째로 걷어낼 수 있다.

### 2. `Math.floorDiv(int, int)`와 `Math.floorMod(int, int)`로 음수 나눗셈의 함정 피하기

Java의 `/`와 `%`는 0을 향해 절삭(truncation)하므로 `-7 / 2`는 `-3`, `-7 % 2`는 `-1`이 된다. 하지만 배열 인덱스나 요일 계산처럼 "항상 양수 나머지"가 필요한 상황에서는 이 동작이 버그의 온상이다. `Math.floorDiv`와 `Math.floorMod`는 음의 무한대 방향으로 내림하므로, 나머지가 제수와 같은 부호를 갖는 수학적으로 자연스러운 결과를 반환한다.

```java
int a = -7 % 3;              // -1 (배열 인덱스로 쓰면 즉시 예외)
int b = Math.floorMod(-7, 3); // 2  (인덱스로 안전)

// 요일 계산: 오늘이 월요일(1)일 때 3일 전은?
int day = Math.floorMod(1 - 3, 7); // 5 (금요일). % 로 하면 -2가 나옴
```

> 💡 **왜 중요한가**: "왜 이 인덱스가 음수지?" 하는 로또식 버그는 대부분 `%` 연산자 때문인데, 원형 큐·해시 슬롯·달력 계산에서 `floorMod` 하나로 캐스팅·`+ n` 보정 코드를 전부 지울 수 있다.
