### 1. `Stream.gatherers(Gatherer)`로 슬라이딩 윈도우·상태 있는 중간 연산의 커스텀 관성 벗어나기 (Java 24 정식)

Java 22부터 프리뷰로 등장한 `Stream.gather()`는 Java 24에서 정식화되며, 그동안 `Collectors`로만 표현 가능했던 **상태 있는 중간 연산**을 스트림 파이프라인 안에서 자유롭게 조립할 수 있게 해준다. 내장 `Gatherers.windowSliding(n)`, `Gatherers.windowFixed(n)`, `Gatherers.scan(...)`, `Gatherers.fold(...)`만으로도 그동안 `IntStream.range().mapToObj(i -> list.subList(...))`로 억지로 짜던 슬라이딩 윈도우, 누적합, 청크 분할이 한 줄로 정리된다.

```java
// 최근 3개 값의 이동 평균 — 예전에는 IntStream + subList 조합의 산물
List<Double> movingAvg = prices.stream()
    .gather(Gatherers.windowSliding(3))
    .map(w -> w.stream().mapToDouble(Double::doubleValue).average().orElse(0))
    .toList();

// 커스텀 Gatherer: 연속된 중복 제거 (Unix uniq)
Gatherer<T, ?, T> uniq = Gatherer.ofSequential(
    () -> new Object[]{null},
    (state, elem, downstream) -> {
        if (!Objects.equals(state[0], elem)) {
            state[0] = elem;
            return downstream.push(elem);
        }
        return true;
    }
);
```

> 💡 **왜 중요한가**: `Collector`는 스트림의 *종단*에서만 상태를 다룰 수 있어 "누적하면서 계속 흘려보내기"가 불가능했지만, `Gatherer`는 중간 연산이라 파이프라인을 끊지 않고도 상태 기반 변환을 조합할 수 있다.

### 2. `StructuredTaskScope.ShutdownOnFailure`로 병렬 호출의 첫 실패 시 나머지를 즉시 취소하기 (Java 21 프리뷰, JEP 453 / 25에서 정식화 목표)

가상 스레드로 여러 원격 호출을 병렬화할 때 `CompletableFuture.allOf()`는 한 호출이 실패해도 나머지가 계속 자원을 낭비한다. `StructuredTaskScope.ShutdownOnFailure`는 자식 태스크 중 **하나라도 예외를 던지면 나머지 태스크에 인터럽트를 걸어 즉시 취소**하고, `join()`이 반환되기 전까지 스코프를 벗어나지 못하게 강제해 "고아 스레드"를 원천 봉쇄한다.

```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<User>    user    = scope.fork(() -> userApi.fetch(id));
    Subtask<Order>   order   = scope.fork(() -> orderApi.fetch(id));
    Subtask<Payment> payment = scope.fork(() -> paymentApi.fetch(id));

    scope.join()               // 모두 완료되거나 첫 실패까지 대기
         .throwIfFailed();     // 실패 있으면 원인 예외 재던지기

    return new Dashboard(user.get(), order.get(), payment.get());
}
// 스코프를 벗어나는 순간 모든 자식 스레드가 반드시 종료됨 — 자원 누수 불가능
```

반대로 "가장 먼저 성공한 결과만 필요"라면 `ShutdownOnSuccess`를 쓰면 첫 성공 후 나머지가 자동 취소된다. 백엔드에서 흔한 **fan-out → gather → 부분 실패 시 전체 실패** 패턴을 언어 차원에서 표현할 수 있게 된 것.

> 💡 **왜 중요한가**: `ExecutorService` + `Future` 조합은 "부모 태스크가 실패했는데 자식이 살아남는" 구조적 누수를 언어가 막아주지 못했지만, 구조적 동시성은 **try-with-resources의 스코프 = 스레드의 수명**이라는 규율을 강제해 취소·에러 전파를 예측 가능하게 만든다.
