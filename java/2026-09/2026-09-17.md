### 1. `Collectors.filtering(predicate, downstream)`로 `filter().collect(groupingBy())` 순서 뒤집기 관성 벗어나기 (Java 9 정식)

`stream.filter(pred).collect(groupingBy(key))`는 필터에 걸린 그룹 자체가 사라져 "빈 리스트라도 있어야 하는 그룹"이 실종되는 함정이 있다. `groupingBy(key, filtering(pred, toList()))`로 순서를 뒤집으면 그룹은 유지한 채 값만 필터링되어, "카테고리별 재고 있는 상품 목록 (없어도 카테고리는 남김)" 같은 요구를 한 줄로 표현할 수 있다. Java 9에서 정식 도입됐지만 여전히 다들 `filter().collect()` 관성에 갇혀 있다.

```java
// 관성: 필터 먼저 → 재고 없는 카테고리가 아예 사라짐
Map<Category, List<Product>> bad = products.stream()
    .filter(p -> p.stock() > 0)
    .collect(groupingBy(Product::category));

// 개선: 그룹은 유지, 값만 필터링
Map<Category, List<Product>> good = products.stream()
    .collect(groupingBy(Product::category, filtering(p -> p.stock() > 0, toList())));
// → 재고 0인 카테고리도 빈 리스트로 살아있음
```

> 💡 **왜 중요한가**: "필터 → 그룹핑" vs "그룹핑 → 필터링"은 결과 집합의 도메인 의미가 완전히 다르다. UI 카테고리 탭처럼 "그룹 자체는 항상 노출해야 하는" 요구에서 이 차이를 모르면 프론트에 빈 응답을 흘려 버그 리포트로 돌아온다.

### 2. `ScopedValue`로 `ThreadLocal`의 상속·정리·가시성 3중 함정 벗어나기 (Java 25 정식, JEP 506)

`ThreadLocal`은 (1) 명시적으로 `remove()` 안 하면 스레드 풀에서 값이 유령처럼 남고, (2) `InheritableThreadLocal`은 자식 스레드에 얕은 복사되어 가상 스레드 수백만 개 환경에서 메모리를 폭발시키며, (3) 어디서 어떤 값이 세팅되는지 코드 리딩이 지옥이다. `ScopedValue`는 불변·바인딩 범위 명시·구조적 동시성과의 자연스러운 상속을 제공해서, 특히 가상 스레드 시대의 요청 컨텍스트(테넌트 ID, 트레이스 ID, 인증 주체) 전달의 정답이 됐다.

```java
// 관성: ThreadLocal — 정리 안 하면 누수, 상속 시 복사 오버헤드
private static final ThreadLocal<TenantId> TENANT = new ThreadLocal<>();
TENANT.set(tenant);
try { handle(request); } finally { TENANT.remove(); }  // 빠뜨리면 오염

// 개선: ScopedValue — 스코프 종료 시 자동 해제, 자식은 참조만 상속
private static final ScopedValue<TenantId> TENANT = ScopedValue.newInstance();
ScopedValue.where(TENANT, tenant).run(() -> handle(request));
// TENANT.get() 은 이 람다 내부에서만 유효, 밖으로 새지 않음

// StructuredTaskScope와 함께 쓰면 자식 가상 스레드도 자동으로 같은 바인딩 상속
try (var scope = StructuredTaskScope.open()) {
    scope.fork(() -> callService1());  // 여기서도 TENANT.get() 가능
    scope.fork(() -> callService2());
    scope.join();
}
```

> 💡 **왜 중요한가**: 가상 스레드로 넘어가면서 "요청당 스레드 하나"가 진짜가 됐고, 스레드가 수백만 개인 세계에서는 `ThreadLocal`의 정리 실수 하나가 GC 압력·데이터 유출·크로스 테넌트 사고로 직결된다. `ScopedValue`는 이 문제를 언어/런타임 레벨에서 구조적으로 봉인한다.
