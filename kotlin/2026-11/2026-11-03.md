### 1. Null Safety: Kotlin이 Java의 10억 달러 실수를 해결한 방법

Kotlin은 타입 시스템 레벨에서 nullable(`String?`)과 non-nullable(`String`)을 구분하여 NullPointerException을 컴파일 타임에 잡아낸다. 안전 호출 연산자 `?.`은 null이면 null을 반환하고, 엘비스 연산자 `?:`은 null일 때 기본값을 지정하며, 강제 언래핑 `!!`은 null이면 NPE를 던진다 (사실상 Java로 되돌아가는 셈이니 최후의 수단).

```kotlin
val name: String? = user.name           // nullable 선언
val length = name?.length ?: 0          // null이면 0
val upper = name?.uppercase()           // null이면 null, 아니면 대문자
val must = name!!                       // null이면 NPE (지양)

// 체이닝: 중간에 null이 하나라도 있으면 전체가 null
val city = user?.address?.city?.uppercase() ?: "UNKNOWN"
```

> 💡 **왜 중요한가**: `!!`를 남발하는 코드는 Kotlin을 쓸 이유가 없는 코드이며, nullable 타입을 설계 단계에서 명확히 분리하는 것이 Kotlin의 핵심 가치다.

### 2. Data Class: Lombok 없이 한 줄로 끝내는 DTO

`data class`는 `equals()`, `hashCode()`, `toString()`, `copy()`, `componentN()`을 컴파일러가 자동 생성해주는 특수 클래스로, Java의 Lombok `@Data` + `@Builder`를 언어 레벨에서 흡수한 것이다. 특히 `copy()`는 불변 객체를 유지하면서 일부 필드만 변경한 새 인스턴스를 만들어 함수형 스타일에 어울린다.

```kotlin
data class User(val id: Long, val name: String, val email: String)

val u1 = User(1L, "박진영", "jy@example.com")
val u2 = u1.copy(email = "new@example.com")   // 불변 유지하며 변경
val (id, name, _) = u1                         // 구조 분해 할당

// Spring Boot에서 요청/응답 DTO로 바로 사용
data class CreateUserRequest(val name: String, val email: String)

@PostMapping("/users")
fun create(@RequestBody req: CreateUserRequest): UserResponse { ... }
```

주의: JPA 엔티티에는 `data class`를 쓰지 말 것 — `equals/hashCode`가 모든 필드를 포함해 지연 로딩이나 양방향 관계에서 무한 루프/성능 문제를 일으킨다. DTO/VO 전용으로만 쓰는 것이 관례다.

> 💡 **왜 중요한가**: DTO 보일러플레이트가 사라지면 코드 리뷰에서 "진짜 비즈니스 로직"에 집중할 수 있고, `copy()` 기반 불변 패턴은 멀티스레드 환경에서 버그 발생률을 극적으로 낮춘다.
