### 1. `Collectors.toUnmodifiableMap()`으로 스트림 → 불변 Map을 한 줄에, 그리고 중복 키를 조용히 삼키지 않기 (Java 10 정식)

`stream().collect(Collectors.toMap(...))`로 만든 `HashMap`을 `Collections.unmodifiableMap()`으로 다시 감싸는 두 단계 관성을 벗어나면 `Collectors.toUnmodifiableMap(keyMapper, valueMapper)` 한 줄로 끝난다. 더 중요한 점은 이 콜렉터가 `null` 키/값을 허용하지 않고 중복 키를 만나면 `IllegalStateException`을 던진다는 것 — `toMap`의 기본 동작과 동일하지만, "불변"이라는 계약이 문서화되어 다운스트림에서 방어 복사가 사라진다. 도메인상 중복 키가 가능하다면 `toUnmodifiableMap(k, v, mergeFunction)` 오버로드로 병합 전략을 **명시적으로** 선언하는 것이 조용한 덮어쓰기 버그를 예방한다.

```java
// Before: 두 단계 + 가변 Map 노출 위험
Map<String, User> byEmail = Collections.unmodifiableMap(
    users.stream().collect(Collectors.toMap(User::email, u -> u))
);

// After: 불변 계약이 API에 박혀 있음
Map<String, User> byEmail = users.stream()
    .collect(Collectors.toUnmodifiableMap(User::email, Function.identity()));

// 중복 키가 도메인상 가능하다면 → 병합 전략을 강제로 명시하게 됨
Map<String, Integer> countByCategory = items.stream()
    .collect(Collectors.toUnmodifiableMap(Item::category, i -> 1, Integer::sum));
```

> 💡 **왜 중요한가**: `Collections.unmodifiableMap(new HashMap<>(...))`는 원본 참조가 살아있으면 여전히 변경 가능한 "가짜 불변"인 반면, `toUnmodifiableMap`은 컴파일 시점부터 진짜 불변 스냅샷을 강제한다.

### 2. `Thread.ofVirtual().name("worker-", 0).start(runnable)`으로 가상 스레드에 관측 가능한 이름 자동 부여하기 (Java 21 정식)

가상 스레드를 대량으로 띄우면 스레드 덤프·프로파일러·로그 MDC에서 `VirtualThread[#42]/runnable@...` 같은 익명 이름만 보여서 디버깅이 지옥이 된다. `Thread.ofVirtual().name(prefix, startIndex)` 빌더는 생성 시점마다 자동으로 `worker-0`, `worker-1`, ... 순번을 붙여주므로, 별도 카운터 관리 없이 관측 가능한 이름을 확보할 수 있다. `Executors.newVirtualThreadPerTaskExecutor()`가 익명 스레드를 만드는 것과 대비해, 직접 이름을 통제해야 할 때 (예: 배치 워커, 스케줄러) 이 빌더가 정답이다.

```java
// Before: 익명 가상 스레드 — 스레드 덤프에서 구분 불가
IntStream.range(0, 100).forEach(i ->
    Thread.startVirtualThread(() -> processTask(i))
);

// After: worker-0, worker-1, ... 자동 넘버링
ThreadFactory factory = Thread.ofVirtual()
    .name("order-worker-", 0)
    .uncaughtExceptionHandler((t, e) -> log.error("{} died", t.getName(), e))
    .factory();

try (var executor = Executors.newThreadPerTaskExecutor(factory)) {
    IntStream.range(0, 100).forEach(i ->
        executor.submit(() -> processTask(i))
    );
}
```

핵심은 `ofVirtual()` 빌더가 `name(prefix, start)` 외에도 `uncaughtExceptionHandler`, `inheritInheritableThreadLocals(false)` 등을 체이닝으로 지정할 수 있다는 점 — 가상 스레드의 `ThreadLocal` 상속을 끄면 메모리 누수 위험도 함께 잡을 수 있다.

> 💡 **왜 중요한가**: 가상 스레드는 초당 수만 개가 생성될 수 있어 익명 이름으로는 장애 분석이 불가능하며, 빌더의 자동 넘버링은 커스텀 `AtomicInteger` 카운터를 관리하는 보일러플레이트를 통째로 제거한다.
