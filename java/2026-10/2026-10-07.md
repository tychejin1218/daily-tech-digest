### 1. `Stream.toList()` (Java 16 정식)로 `.collect(Collectors.toList())` 호출 관성 벗어나기

Java 16부터 `Stream`에 종결 연산 `toList()`가 추가되어, 가장 흔한 수집 작업을 `Collectors` 임포트 없이 한 메서드 호출로 끝낼 수 있다. 중요한 차이는 반환되는 리스트가 **불변(unmodifiable)** 이라는 점으로, `.collect(Collectors.toList())`가 돌려주던 `ArrayList`와 달리 `add()`/`remove()` 호출 시 `UnsupportedOperationException`이 터진다. 수집 후 리스트를 수정할 일이 없다면 `toList()`가 기본값이고, 수정이 필요한 경우에만 명시적으로 `.collect(Collectors.toCollection(ArrayList::new))`로 의도를 드러내자.

```java
// Before — 관성적인 .collect(Collectors.toList())
List<String> names = users.stream()
    .filter(User::isActive)
    .map(User::name)
    .collect(Collectors.toList());  // 가변 ArrayList, 임포트 필요

// After — Stream.toList() (Java 16+)
List<String> names = users.stream()
    .filter(User::isActive)
    .map(User::name)
    .toList();  // 불변, 임포트 불필요, null 허용

// 수정이 필요하면 의도를 명시
List<String> mutable = users.stream()
    .map(User::name)
    .collect(Collectors.toCollection(ArrayList::new));
```

| 구분 | `.collect(Collectors.toList())` | `.toList()` |
|------|-------------------------------|-------------|
| 반환 타입 | `ArrayList` (가변) | 불변 `List` |
| null 허용 | O | O (`List.of()`와 다름) |
| 성능 | 중간 수집기 할당 | 내부 배열 직접 사용, 약간 빠름 |
| 임포트 | `Collectors` 필요 | 불필요 |

> 💡 **왜 중요한가**: 스트림 결과를 수정하지 않는 게 90%인데도 가변 리스트를 반환하는 관성이 "실수로 add 호출"과 "방어 복사" 양쪽 비용을 만들어 왔고, `toList()`는 그 기본값을 바로잡는다.

### 2. `Pattern Matching for switch` (Java 21 정식, JEP 441)로 `instanceof` 캐스팅 + if-else 사다리 관성 벗어나기

Java 21부터 `switch`에서 타입 패턴, 가드(`when`), null 패턴을 공식 지원하여, 다형성 분기를 한 블록으로 선언적으로 표현할 수 있다. 기존 `if (x instanceof Dog d) {...} else if (x instanceof Cat c) {...}` 사다리는 분기마다 캐스팅 변수를 수동으로 뽑아야 했지만, switch 패턴은 **바인딩**(`Dog d`)과 **가드**(`when d.age() > 10`)와 **null 분기**를 한자리에 모아 컴파일러의 **완전성 검사**(sealed 타입이면 모든 subtype을 다뤘는지 체크)까지 제공한다. 특히 `sealed interface`와 조합하면 "새 타입을 추가했을 때 switch에서 컴파일 에러로 알려주는" 안전망이 생긴다.

```java
sealed interface Shape permits Circle, Square, Triangle {}
record Circle(double radius) implements Shape {}
record Square(double side) implements Shape {}
record Triangle(double base, double height) implements Shape {}

// Before — instanceof + 캐스팅 사다리
static double area(Shape s) {
    if (s == null) throw new NullPointerException();
    if (s instanceof Circle c) return Math.PI * c.radius() * c.radius();
    else if (s instanceof Square sq) return sq.side() * sq.side();
    else if (s instanceof Triangle t) return 0.5 * t.base() * t.height();
    else throw new IllegalStateException("unknown shape");  // 수동 fallthrough 처리
}

// After — Pattern Matching for switch (Java 21+)
static double area(Shape s) {
    return switch (s) {
        case Circle c       -> Math.PI * c.radius() * c.radius();
        case Square sq      -> sq.side() * sq.side();
        case Triangle t when t.base() > 0 && t.height() > 0
                            -> 0.5 * t.base() * t.height();
        case Triangle t     -> throw new IllegalArgumentException("invalid triangle");
        case null           -> throw new NullPointerException();
        // sealed라 default 불필요 — 새 Shape 추가 시 컴파일 에러로 알려줌
    };
}
```

**함정 하나**: 패턴은 선언 순서대로 매칭되므로, 가드가 있는 `case Triangle t when ...`을 가드 없는 `case Triangle t`보다 **먼저** 둬야 한다. 반대 순서면 가드 없는 분기가 모든 Triangle을 삼켜버려 "unreachable" 컴파일 에러가 난다.

> 💡 **왜 중요한가**: `instanceof` 사다리의 "새 subtype 추가 시 분기 누락이 런타임까지 숨는" 고전 버그를 sealed + switch 완전성 검사가 **컴파일 타임**으로 끌어올려, 다형성 코드의 유지보수성을 질적으로 바꿔놓는다.
