### 1. `@Observed` 어노테이션과 Micrometer Observation API로 메트릭·트레이싱·로깅 한 번에 처리하기

Spring Boot 3.x부터는 `@Observed` 어노테이션 하나로 메서드 실행에 대한 메트릭(Metrics), 분산 추적(Tracing), 로그를 동시에 계측할 수 있습니다. 기존에는 `@Timed`, `@NewSpan`, MDC 로깅을 각각 따로 설정해야 했지만, Observation API는 `ObservationRegistry`를 통해 이 세 가지를 단일 추상화로 통합합니다. `@EnableAspectJAutoProxy`와 `ObservedAspect` 빈만 등록하면 비즈니스 코드에 계측 코드가 침투하지 않습니다.

```java
@Observed(name = "order.process", contextualName = "process-order",
          lowCardinalityKeyValues = {"type", "online"})
public Order processOrder(Long orderId) { ... }
```

> 💡 **왜 중요한가**: 관측성(Observability) 3대 요소를 분리된 코드로 관리하면 일관성이 깨지고 유지보수 비용이 폭증하지만, Observation API는 이를 단일 진실 공급원으로 통합해 줍니다.

### 2. `@DynamicPropertySource`로 테스트 컨텍스트에 런타임 속성 동적으로 주입하기

`@TestPropertySource`는 정적인 프로퍼티만 주입할 수 있어 Testcontainers처럼 컨테이너가 시작된 후에야 포트나 URL이 결정되는 상황에는 사용할 수 없습니다. 반면 `@DynamicPropertySource`는 `DynamicPropertyRegistry`를 인자로 받아 `Supplier`를 등록하므로, ApplicationContext가 로드되기 직전에 실제 값으로 평가됩니다. Kafka, Redis, LocalStack 등 동적으로 결정되는 외부 의존성을 테스트에 연결할 때 필수적입니다.

```java
@DynamicPropertySource
static void registerProps(DynamicPropertyRegistry registry) {
    registry.add("spring.kafka.bootstrap-servers", kafka::getBootstrapServers);
    registry.add("spring.data.redis.port", redis::getFirstMappedPort);
}
```

> 💡 **왜 중요한가**: 정적 설정으로는 풀 수 없는 "런타임에 결정되는 외부 인프라 연결" 문제를 깔끔하게 해결해, 통합 테스트의 신뢰성과 격리성을 동시에 확보할 수 있습니다.
