### 1. `Map.Entry.copyOf(entry)` (Java 17 정식)로 `new AbstractMap.SimpleImmutableEntry<>(k, v)` 수동 복사 관성 벗어나기

`Map.entrySet()`에서 받은 엔트리를 외부로 노출할 때, 원본 맵의 변경이 전파되는 걸 막으려고 `new AbstractMap.SimpleImmutableEntry<>(e.getKey(), e.getValue())`로 감싸는 코드가 흔하다. Java 17부터는 `Map.Entry.copyOf(e)` 한 줄이면 불변 복사본이 나오고, 이미 불변이면 자기 자신을 그대로 반환해서 할당조차 생략한다. 특히 `stream().map(Map.Entry::copyOf).toList()` 패턴에서 가독성과 성능 둘 다 챙긴다.

> 💡 **왜 중요한가**: "엔트리를 외부로 넘길 때 캡슐화 깨지지 않게 복사" 라는 흔한 요구가 표준 API 한 줄로 끝나고, 불변 입력에 대해서는 복사 비용 자체가 사라진다.

### 2. `Thread.ofPlatform().name("worker-", 0).factory()` (Java 21 정식, JEP 444)로 `new ThreadFactory() { AtomicInteger n = ...; public Thread newThread(...) {...} }` 익명 클래스 관성 벗어나기

`ExecutorService` 쓸 때마다 "스레드 덤프에서 'pool-3-thread-7' 말고 'order-worker-7'로 보이게 하자"고 `ThreadFactory` 익명 클래스를 깎고, `AtomicInteger`로 번호를 돌리고, `setDaemon(true)`, `setUncaughtExceptionHandler(...)`를 줄줄이 호출하는 보일러플레이트가 쌓인다. Java 21의 `Thread.Builder`는 `Thread.ofPlatform().name("order-worker-", 0).daemon(true).uncaughtExceptionHandler(h).factory()` 한 체인으로 끝나며, 가상 스레드가 필요하면 `Thread.ofVirtual()`로 접두사만 바꾸면 된다. 번호 자동 증가(`"order-worker-0"`, `"order-worker-1"`, ...)까지 빌더가 처리해주니 `AtomicInteger` 선언도 사라진다.

> 💡 **왜 중요한가**: 스레드 네이밍/데몬 설정/카운터 조립이라는 "모든 프로젝트가 반복해서 깎는" 보일러플레이트가 표준 빌더 체인으로 흡수되고, 가상 스레드 전환이 `ofPlatform` ↔ `ofVirtual` 한 단어 교체로 끝난다.
