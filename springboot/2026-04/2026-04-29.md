### 1. `@ConditionalOnProperty`로 기능 플래그(Feature Flag) 기반 빈 등록 제어

특정 프로퍼티 값에 따라 빈 등록 여부를 동적으로 결정할 수 있는 어노테이션으로, 자동 구성 클래스에서 환경별로 활성화될 컴포넌트를 분기 처리할 때 강력합니다. `havingValue`와 `matchIfMissing` 옵션을 조합하면 점진적 롤아웃이나 카나리 배포에서 코드 변경 없이 설정만으로 기능을 켜고 끌 수 있습니다. 라이브러리 작성자라면 `@ConditionalOnClass`, `@ConditionalOnMissingBean`과 함께 사용해 사용자가 의존성을 추가하는 것만으로 자동 활성화되는 모듈을 만들 수 있습니다.

> 💡 **왜 중요한가**: 운영 환경에서 코드 재배포 없이 `application.yml`만 수정해 즉시 기능을 토글할 수 있어, 장애 발생 시 빠른 롤백 수단이 됩니다.

### 2. `JdbcClient`로 Spring 6.1+ 현대적 SQL 실행 API 활용

Spring 6.1에서 도입된 `JdbcClient`는 기존 `JdbcTemplate`과 `NamedParameterJdbcTemplate`을 대체하는 플루언트 API로, 메서드 체이닝 방식으로 파라미터 바인딩과 결과 매핑을 직관적으로 표현할 수 있습니다. `query().param().single()`, `update().param().rows()`처럼 가독성 높은 코드가 작성되며, `Optional` 반환과 레코드 매핑을 1급 시민으로 지원해 NPE 방지에도 유리합니다. JPA의 오버헤드 없이 가벼운 데이터 접근이 필요한 통계·리포트 쿼리나 대량 배치 작업에 특히 적합합니다.

> 💡 **왜 중요한가**: 복잡한 콜백·익명 클래스 없이도 타입 안전한 SQL 실행이 가능해, JPA가 과한 영역에서 보일러플레이트를 크게 줄이면서도 성능을 확보할 수 있습니다.
