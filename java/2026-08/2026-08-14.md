### 1. `Stream.gatherers()`로 스트림 파이프라인에 커스텀 중간 연산 끼워 넣기 (Java 24 정식)

`Stream.gather(Gatherer)`는 스트림 API에 없는 중간 연산(슬라이딩 윈도우, 상태 누적, N개씩 그룹핑 등)을 직접 정의할 수 있게 해주는 확장 지점입니다. 기존에는 `collect()`로 종료하거나 외부 라이브러리(Guava, StreamEx)에 의존해야 했던 로직을 표준 API 안에서 파이프라인으로 이어갈 수 있어, 병렬 처리·지연 평가 특성을 그대로 유지합니다.

```java
// 3개씩 묶어 리스트로 출력 - 기존에는 collect + IntStream 조합 필요
List<List<Integer>> windows = Stream.of(1, 2, 3, 4, 5, 6, 7)
    .gather(Gatherers.windowFixed(3))
    .toList();
// [[1,2,3], [4,5,6], [7]]

// 누적 스캔 - reduce와 달리 중간 결과를 모두 방출
List<Integer> runningSum = Stream.of(1, 2, 3, 4)
    .gather(Gatherers.scan(() -> 0, Integer::sum))
    .toList();
// [1, 3, 6, 10]
```

> 💡 **왜 중요한가**: `Collector`가 "종료 연산의 확장"이었다면 `Gatherer`는 "중간 연산의 확장"입니다. 스트림을 중간에 잘라 별도 로직으로 우회하던 코드를 다시 한 줄 파이프라인으로 복원할 수 있습니다.

### 2. `Thread.ofVirtual().name(...).start(Runnable)`로 스레드 덤프에서 식별 가능한 가상 스레드 만들기 (Java 21 정식)

가상 스레드를 `Executors.newVirtualThreadPerTaskExecutor()`로 뽑으면 이름이 비어 있어 스레드 덤프에서 어떤 요청이 어디서 멈췄는지 추적이 어렵습니다. `Thread.ofVirtual()` 빌더는 이름·이름 시퀀스·`UncaughtExceptionHandler`를 지정할 수 있어, 프로덕션에서 장애 원인을 좁힐 때 결정적 차이를 만듭니다.

```java
// 이름 없는 가상 스레드 - 덤프에서 "VirtualThread[#123]/runnable@ForkJoinPool" 만 보임
Thread.startVirtualThread(() -> handleOrder(orderId));

// 이름 있는 가상 스레드 - 덤프에서 "order-worker-42" 로 즉시 식별
Thread.ofVirtual()
    .name("order-worker-", 42)  // prefix + 자동 증가 카운터
    .uncaughtExceptionHandler((t, e) -> log.error("가상 스레드 {} 실패", t.getName(), e))
    .start(() -> handleOrder(orderId));

// ThreadFactory로 뽑아 ExecutorService에 주입도 가능
ThreadFactory factory = Thread.ofVirtual().name("api-", 0).factory();
var executor = Executors.newThreadPerTaskExecutor(factory);
```

> 💡 **왜 중요한가**: 가상 스레드는 수만 개가 동시에 뜨기 때문에 이름이 없으면 `jstack` 덤프가 사실상 판독 불가능합니다. 스레드당 비용이 거의 없다고 관측 가능성까지 공짜인 건 아니며, 이름 전략은 가상 스레드 도입 시 반드시 세워야 하는 규약입니다.
