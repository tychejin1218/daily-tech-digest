### 1. useState의 함수형 업데이트: 클로저 함정에서 벗어나는 법

`setState(prev => prev + 1)` 형태의 함수형 업데이트는 **최신 상태값**을 보장받을 수 있는 패턴입니다. 특히 `setInterval`, 비동기 콜백, 연속된 상태 업데이트처럼 "오래된 state 값"을 참조하기 쉬운 상황에서 필수적입니다. 그냥 `setState(count + 1)`을 쓰면 클로저에 캡처된 과거의 `count`를 기준으로 동작해 버그가 생깁니다.

```jsx
// ❌ 버그: 3번 호출해도 1만 증가 (같은 count 참조)
const handleClick = () => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
};

// ✅ 함수형 업데이트: 3번 호출하면 3 증가
const handleClick = () => {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
};

// ✅ setInterval에서도 안전
useEffect(() => {
  const id = setInterval(() => {
    setCount(prev => prev + 1); // 항상 최신값
  }, 1000);
  return () => clearInterval(id);
}, []); // deps에 count 없어도 OK
```

> 💡 **왜 중요한가**: React의 state는 렌더 시점의 스냅샷이므로, 이전 값에 의존하는 업데이트는 반드시 함수형으로 작성해야 레이스 컨디션과 stale closure 버그를 원천 차단할 수 있습니다.

### 2. useEffect 의존성 배열: 3가지 패턴을 구분하라

`useEffect`는 의존성 배열의 형태에 따라 동작이 완전히 달라집니다. **생략/빈 배열/값 포함** 세 가지를 명확히 구분하지 못하면 무한 루프나 "값이 안 바뀌는" 버그로 이어집니다. ESLint의 `react-hooks/exhaustive-deps` 룰을 켜두는 것이 사실상 필수입니다.

```jsx
// 1) deps 생략: 매 렌더마다 실행 (거의 쓰지 말 것, 성능 문제)
useEffect(() => {
  console.log('매번 실행');
});

// 2) 빈 배열 []: 마운트 시 1회만 (초기화, 구독 등)
useEffect(() => {
  const subscription = api.subscribe();
  return () => subscription.unsubscribe(); // cleanup
}, []);

// 3) 값 포함 [userId]: userId 바뀔 때만 실행
useEffect(() => {
  fetchUser(userId).then(setUser);
}, [userId]);

// ⚠️ 흔한 함정: 객체/배열을 deps에 넣으면 매번 새 참조 → 무한 루프
useEffect(() => {
  fetchData(options);
}, [options]); // options = {} 가 매 렌더 새로 만들어지면 무한 호출

// ✅ 해결: 원시값으로 분해하거나 useMemo로 감싸기
useEffect(() => {
  fetchData({ page, size });
}, [page, size]);
```

> 💡 **왜 중요한가**: `useEffect`는 "렌더 결과를 외부 세계와 동기화"하는 유일한 공식 통로이므로, 의존성 배열을 제대로 다루지 못하면 네트워크 폭주·메모리 누수·stale UI가 즉시 발생합니다.
