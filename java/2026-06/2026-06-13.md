### `Math.clamp()`로 값을 특정 범위 안으로 제한하기 (Java 21 정식)

`Math.clamp(value, min, max)`는 값이 `min`보다 작으면 `min`, `max`보다 크면 `max`, 그 사이면 그대로 반환합니다. 기존에 `Math.max(min, Math.min(max, value))`로 표현하던 패턴을 한 줄로 대체할 수 있고, `int`/`long`/`float`/`double` 오버로드가 모두 제공됩니다. `min > max`인 경우 `IllegalArgumentException`을 던져 잘못된 경계값을 조기에 잡아줍니다.

```java
int volume = Math.clamp(userInput, 0, 100);          // 0 ~ 100 사이로 보정
double alpha = Math.clamp(opacity, 0.0, 1.0);        // 색상 알파값 범위 제한
long retryDelayMs = Math.clamp(backoff, 100L, 5000L); // 지수 백오프 상·하한
```

> 💡 **왜 중요한가**: UI 좌표, 볼륨, 백오프 지연 등 "범위 보정" 패턴이 한 번에 표현 가능해져 가독성과 의도가 명확해집니다.

### `HashMap.newHashMap(int)`로 리사이즈 없는 정확한 초기 용량 지정 (Java 19 정식)

기존 `new HashMap<>(expectedSize)`는 생성자에 넘긴 값이 *초기 용량(capacity)*이라 load factor(0.75) 때문에 예상 엔트리 수에 도달하기 전 리사이즈가 발생했습니다. `HashMap.newHashMap(numMappings)`는 인자를 "넣을 엔트리 개수"로 받아 내부에서 적절한 capacity를 계산해 주므로 리해시 없이 정확한 용량을 확보할 수 있습니다. `LinkedHashMap.newLinkedHashMap()`, `HashSet.newHashSet()`, `LinkedHashSet.newLinkedHashSet()`도 같은 시그니처로 제공됩니다.

```java
// Before: 16개를 넣을 거지만 capacity 16 + load factor 0.75 → 12개째에 리사이즈
Map<String, User> users = new HashMap<>(16);

// After: 정확히 16개 엔트리를 리해시 없이 담을 수 있는 맵
Map<String, User> users = HashMap.newHashMap(16);
```

> 💡 **왜 중요한가**: 대량 엔트리를 한 번에 적재하는 캐시·인덱스 구축에서 불필요한 리사이즈와 메모리 낭비를 줄여 성능을 안정화합니다.
