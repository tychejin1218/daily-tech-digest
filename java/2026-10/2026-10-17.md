### 1. `Collection.toArray(IntFunction<T[]> generator)` (Java 11 정식)로 `collection.toArray(new T[0])` 혹은 `new T[collection.size()]` 관성 벗어나기

`list.toArray(new String[0])`은 리플렉션 기반 배열 생성 + 사이즈 재계산이 섞여 있어 매번 "왜 0을 넘기지?"라는 의문을 남긴다. Java 11부터는 `list.toArray(String[]::new)`로 메서드 레퍼런스 하나만 넘기면 되고, 가변 컬렉션에서도 내부적으로 정확한 사이즈로 한 번에 할당해 성능상 손해도 없다. `size()`를 명시적으로 넘기는 패턴보다 의도("빈 배열 타입 힌트 아님, 생성자 전달")가 분명해진다.

> 💡 **왜 중요한가**: `new T[0]`은 JVM이 내부 최적화해주지만, `IntFunction` 오버로드가 등장한 뒤로는 "왜 0인지"를 신입에게 설명할 필요 자체가 없어진다 — 가독성은 미시 성능보다 비싸다.

### 2. `Math.floorDiv(x, y)` / `Math.floorMod(x, y)` (Java 8 정식)로 음수에서 `/`, `%` 결과가 뒤집히는 관성 벗어나기

Java의 `/`와 `%`는 0 방향 절삭(truncation toward zero)이라, `-7 / 3 == -2`, `-7 % 3 == -1`이 되어 "날짜 순환 인덱스", "그리드 좌표 wrap", "원형 버퍼" 같은 코드에서 음수가 들어오는 순간 조용히 틀어진다. `Math.floorDiv(-7, 3) == -3`, `Math.floorMod(-7, 3) == 2`는 수학적 바닥 나눗셈/모듈로를 제공해서 `((x % n) + n) % n` 같은 방어 코드를 지울 수 있다. 요일 계산, 각도 정규화(0~359°), 음수 타임존 오프셋에서 특히 효과가 크다.

> 💡 **왜 중요한가**: 테스트에 음수 케이스가 없으면 몇 년 동안 숨어있다가 "DST 넘어가는 날 알림이 이상한 시간에 울린다" 같은 버그로 터진다 — 언어 기본 연산자가 수학적으로 "틀린" 영역에서는 표준 라이브러리의 수학적 올바름을 빌려야 한다.
