### `Stream.gather()`로 슬라이딩 윈도우·중복 제거·상태 유지 연산을 표준 API로 처리하기 (Java 24 정식)

`Stream.gather(Gatherer)`는 `map`/`filter`/`reduce`로 표현하기 어려운 **상태를 가진 중간 연산**을 사용자가 직접 정의할 수 있게 해주는 확장 지점입니다. 내장된 `Gatherers.windowSliding(n)`, `windowFixed(n)`, `fold()`, `scan()`, `mapConcurrent()`을 바로 쓸 수도 있고, 커스텀 `Gatherer`를 조합(`andThen`)해 파이프라인을 만들 수도 있어서, 지금까지 for 루프로 내려가야 했던 "이전 요소를 기억하며 처리" 로직을 스트림 안에 자연스럽게 녹일 수 있습니다.

```java
// 최근 3개씩 묶어 이동 평균 구하기 — 기존엔 IntStream + subList로 어색했던 패턴
List<Double> movingAvg = Stream.of(10, 20, 30, 40, 50)
    .gather(Gatherers.windowSliding(3))
    .map(w -> w.stream().mapToInt(Integer::intValue).average().orElse(0))
    .toList();
// [20.0, 30.0, 40.0]

// scan: 누적 합을 각 단계마다 방출 (reduce는 최종값만)
List<Integer> runningSum = Stream.of(1, 2, 3, 4)
    .gather(Gatherers.scan(() -> 0, Integer::sum))
    .toList();
// [1, 3, 6, 10]
```

> 💡 **왜 중요한가**: `Stream.gather()`는 `Collector`가 "종결"만 확장했던 것과 달리 **중간 연산 자체를 확장**할 수 있게 해, 커스텀 스트림 연산을 위해 외부 라이브러리(vavr, StreamEx)에 의존하거나 명령형 코드로 후퇴할 필요가 없어졌습니다.

### `ScopedValue`로 ThreadLocal 대신 불변·구조화된 컨텍스트를 전파하기 (Java 25 정식)

`ScopedValue`는 특정 코드 블록 범위 안에서만 값을 바인딩해 하위 호출로 전파하는 API로, `ThreadLocal`의 세 가지 고질병 — **가변성**, **누수(remove 누락)**, **가상 스레드에서의 메모리 오버헤드** — 을 근본적으로 해결합니다. `ScopedValue.where(KEY, value).run(() -> ...)` 블록이 끝나면 값이 자동으로 사라지므로 finally에서 정리할 필요가 없고, 값 자체가 불변이라 하위 스레드가 실수로 덮어쓸 수도 없습니다.

```java
public final class RequestContext {
    public static final ScopedValue<String> USER_ID = ScopedValue.newInstance();
    public static final ScopedValue<String> TRACE_ID = ScopedValue.newInstance();
}

// 요청 진입점에서 바인딩 — 블록 밖으로 값이 새어나가지 않음
ScopedValue.where(RequestContext.USER_ID, "user-42")
           .where(RequestContext.TRACE_ID, UUID.randomUUID().toString())
           .run(() -> orderService.placeOrder(cart));

// 깊은 호출 스택 어디서든 읽기 — 파라미터로 넘길 필요 없음
void audit() {
    log.info("user={}, trace={}", 
        RequestContext.USER_ID.get(), 
        RequestContext.TRACE_ID.get());
}

// 가상 스레드 수백만 개에서도 안전 — StructuredTaskScope와 결합 시 자동 상속
try (var scope = StructuredTaskScope.open()) {
    scope.fork(() -> callPaymentApi()); // USER_ID.get() 그대로 접근 가능
    scope.fork(() -> callInventoryApi());
    scope.join();
}
```

> 💡 **왜 중요한가**: 가상 스레드 시대에 `ThreadLocal`은 스레드당 별도 저장소를 잡아 수백만 스레드에서 메모리를 폭발시키지만, `ScopedValue`는 콜 스택 기반 조회라 오버헤드가 거의 없고 값 누수도 원천 차단됩니다.
