### `Stream.toList()`로 `collect(Collectors.toList())` 관성 벗어나기 + 불변성 보너스 챙기기 (Java 16 정식)

Java 16부터 `Stream`에 직접 `toList()` 종단 연산이 추가되어, `collect(Collectors.toList())`의 길고 반복적인 보일러플레이트를 한 단어로 대체할 수 있다. 게다가 반환되는 List는 **불변(unmodifiable)** 이라, 반환값을 함부로 수정하는 호출자로 인한 버그를 컴파일이 아닌 런타임에서라도 즉시 잡아낼 수 있다. 단, `Collectors.toList()`는 `ArrayList`(가변)를 반환하므로 기존 코드를 무심코 치환하면 `UnsupportedOperationException`이 터질 수 있으니 반환 계약을 반드시 확인해야 한다.

```java
// Before — 관성적으로 쓰던 코드
List<String> names = users.stream()
    .map(User::getName)
    .collect(Collectors.toList());  // 가변 ArrayList

// After — Java 16+
List<String> names = users.stream()
    .map(User::getName)
    .toList();  // 불변 List, null 허용

// 주의: 가변 리스트가 필요하다면 명시적으로
List<String> mutable = users.stream()
    .map(User::getName)
    .collect(Collectors.toCollection(ArrayList::new));
```

`Collectors.toUnmodifiableList()`와 달리 `Stream.toList()`는 **null 원소를 허용**한다는 미묘한 차이도 기억해두면 좋다. DTO 매핑 결과에 `null`이 섞일 수 있는 파이프라인이라면 이 차이가 결정적이다.

> 💡 **왜 중요한가**: `.collect(Collectors.toList())`는 Java 개발자가 하루에도 수십 번 타이핑하는 관성인데, 한 글자만 줄이는 게 아니라 "반환값 불변성"이라는 방어 계약까지 공짜로 얻는다.

### `Map.Entry.copyOf(entry)`로 `AbstractMap.SimpleImmutableEntry` 생성 관성 벗어나기 (Java 17 정식)

키-값 쌍을 로컬에서 만들거나 스트림에서 튜플처럼 다룰 때, 지금까지는 `new AbstractMap.SimpleImmutableEntry<>(k, v)`나 `Map.entry(k, v)`를 썼지만, Java 17부터는 **기존 Entry를 안전하게 스냅샷 복사**하는 `Map.Entry.copyOf(Entry)`가 추가됐다. `TreeMap.firstEntry()`처럼 뷰(view) 성격의 Entry를 반환하는 API는 원본 Map이 바뀌면 Entry의 값도 바뀔 수 있는데, 이걸 방어적으로 복사해두는 이디엄이 한 줄로 표준화된 것이다.

```java
// Before — 뷰 Entry를 그대로 반환하면 원본 Map 변경 시 값이 바뀜
public Map.Entry<String, Integer> peekOldest(TreeMap<String, Integer> scores) {
    return scores.firstEntry();  // 위험: 뷰일 수 있음
}

// 예전 방어 코드 — 장황함
public Map.Entry<String, Integer> peekOldestOld(TreeMap<String, Integer> scores) {
    Map.Entry<String, Integer> e = scores.firstEntry();
    return new AbstractMap.SimpleImmutableEntry<>(e.getKey(), e.getValue());
}

// After — Java 17+
public Map.Entry<String, Integer> peekOldest(TreeMap<String, Integer> scores) {
    return Map.Entry.copyOf(scores.firstEntry());  // 불변 스냅샷
}
```

캐시나 스냅샷 API를 설계할 때 특히 유용하다. `ConcurrentHashMap`의 iterator가 반환하는 Entry는 살아있는 참조라, 다른 스레드가 값을 갱신하면 방금 읽은 Entry의 `getValue()` 결과도 바뀐다. `Map.Entry.copyOf()`는 이런 동시성 함정을 한 줄로 차단한다.

> 💡 **왜 중요한가**: "Entry는 그냥 튜플" 이라는 오해가 낳는 가장 흔한 버그는 뷰 Entry를 리턴해서 원본 변경이 새어 나가는 것인데, `copyOf`는 이 방어 이디엄을 표준 API 한 줄로 만들어 코드 리뷰에서 "왜 여기서 SimpleImmutableEntry를 new 하고 있죠?" 라는 질문 자체를 없앤다.
