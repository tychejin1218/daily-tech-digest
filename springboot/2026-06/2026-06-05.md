### 1. `RestClient`로 `RestTemplate`을 대체하는 동기식 Fluent HTTP 클라이언트 쓰기

Spring Framework 6.1(Boot 3.2+)부터 도입된 `RestClient`는 `WebClient`의 Fluent API를 그대로 차용하면서도 동기식으로 동작해, `spring-webflux` 의존성 없이 `RestTemplate`을 깔끔하게 대체할 수 있습니다. `.uri()`, `.retrieve()`, `.body()` 체이닝과 `onStatus()`로 에러 처리까지 선언형으로 구성할 수 있어, 기존 `RestTemplate`의 명령형 코드보다 가독성이 크게 향상됩니다.

```java
RestClient client = RestClient.builder()
    .baseUrl("https://api.example.com")
    .defaultHeader("X-API-Key", apiKey)
    .build();

User user = client.get()
    .uri("/users/{id}", userId)
    .retrieve()
    .onStatus(HttpStatusCode::is4xxClientError,
        (req, res) -> { throw new UserNotFoundException(); })
    .body(User.class);
```

> 💡 **왜 중요한가**: `RestTemplate`은 유지보수 모드로 신규 기능이 추가되지 않으므로, 동기 호출에는 `RestClient`가 사실상의 표준 선택지입니다.

### 2. `LazyConnectionDataSourceProxy`로 DB 커넥션 획득 시점을 실제 쿼리 직전까지 미루기

스프링은 `@Transactional` 메서드 진입 즉시 커넥션 풀에서 커넥션을 점유하는데, 트랜잭션 안에 외부 API 호출이나 비즈니스 로직만 있고 실제 쿼리는 일부 분기에서만 실행되는 경우 커넥션이 불필요하게 오래 잡혀 풀이 고갈됩니다. `DataSource`를 `LazyConnectionDataSourceProxy`로 감싸면 첫 SQL 실행 시점까지 커넥션 획득이 지연되고, AbstractRoutingDataSource 기반의 Read/Write 분기에서도 `@Transactional(readOnly = true)` 플래그를 정확히 읽어 올바른 슬레이브로 라우팅됩니다.

```java
@Bean
@Primary
public DataSource dataSource(@Qualifier("routingDataSource") DataSource routing) {
    return new LazyConnectionDataSourceProxy(routing);
}
```

> 💡 **왜 중요한가**: 트랜잭션 경계가 넓은 서비스일수록 커넥션 점유 시간을 짧게 줄이는 것이 풀 크기를 키우는 것보다 처리량 개선에 효과적입니다.
