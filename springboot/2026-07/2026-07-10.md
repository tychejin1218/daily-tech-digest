### `@TestConfiguration`으로 슬라이스 테스트에 필요한 빈만 추가 등록하기

`@SpringBootTest` 없이 `@WebMvcTest`, `@DataJpaTest` 같은 슬라이스 테스트를 쓰면 필요한 빈만 로드되는데, 정작 테스트에서 특정 빈(예: `PasswordEncoder`, 스텁 서비스)이 필요할 때가 있다. `@TestConfiguration`을 static inner class로 두거나 `@Import(MyTestConfig.class)`로 명시적으로 붙이면 기존 슬라이스 컨텍스트를 오염시키지 않고 필요한 빈만 얹을 수 있다. `@Configuration`과 달리 컴포넌트 스캔에 자동 포함되지 않아 다른 테스트로 새어나가지 않는다.

```java
@WebMvcTest(UserController.class)
class UserControllerTest {

    @TestConfiguration
    static class TestConfig {
        @Bean
        PasswordEncoder passwordEncoder() {
            return new BCryptPasswordEncoder();
        }
    }
}
```

> 💡 **왜 중요한가**: 슬라이스 테스트 컨텍스트를 넓히지 않으면서 필요한 협력 빈만 정확히 주입할 수 있어, 테스트 부팅 속도와 격리 수준을 모두 지킬 수 있다.

### `RestTemplate`의 `ResponseErrorHandler`를 커스터마이즈해 4xx/5xx 응답을 예외가 아닌 값으로 다루기

`RestTemplate`은 기본적으로 4xx/5xx 응답에서 `HttpClientErrorException`, `HttpServerErrorException`을 던져 정상 흐름을 끊는다. 외부 API가 404를 "없음"의 정상 시그널로 사용하는 경우, `DefaultResponseErrorHandler`를 상속해 `hasError()`를 오버라이드하거나 아예 `NoOpResponseErrorHandler`로 교체하면 응답을 예외가 아닌 `ResponseEntity`로 그대로 받을 수 있다.

```java
RestTemplate restTemplate = new RestTemplateBuilder()
    .errorHandler(new DefaultResponseErrorHandler() {
        @Override
        public boolean hasError(ClientHttpResponse response) throws IOException {
            return response.getStatusCode().is5xxServerError();
        }
    })
    .build();

ResponseEntity<User> res = restTemplate.getForEntity("/users/{id}", User.class, id);
if (res.getStatusCode() == HttpStatus.NOT_FOUND) return Optional.empty();
```

> 💡 **왜 중요한가**: 예외 기반 제어 흐름을 없애면 stack trace 비용이 사라지고, 정상 케이스와 실패 케이스가 코드에서 대칭적으로 표현되어 가독성이 크게 오른다.
