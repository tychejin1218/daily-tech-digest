### `@TransactionalAdvisor` 대신 `TransactionTemplate`로 부분 트랜잭션 경계 세밀하게 제어하기

`@Transactional` 어노테이션은 메서드 전체를 하나의 트랜잭션으로 묶기 때문에, 외부 API 호출이나 무거운 연산이 포함된 메서드에서 커넥션을 너무 오래 점유하는 문제가 생깁니다. `TransactionTemplate`을 주입받아 `execute()` 블록 안에서 DB 작업만 짧게 감싸면 트랜잭션 범위를 정확히 필요한 곳으로 좁힐 수 있고, 결과/예외 처리도 람다로 깔끔하게 표현됩니다. `PROPAGATION_REQUIRES_NEW`나 격리 수준도 인스턴스별로 분리 설정해두면 가독성이 좋아집니다.

> 💡 **왜 중요한가**: 트랜잭션 범위를 좁힐수록 DB 커넥션 점유 시간이 줄어 커넥션 풀 고갈과 락 경합을 동시에 완화할 수 있습니다.

### `@ServiceConnection`으로 Testcontainers와 Spring Boot 자동 설정 연결하기 (Spring Boot 3.1+)

`@DynamicPropertySource`로 일일이 URL/username/password를 주입하던 보일러플레이트를, `@ServiceConnection` 한 줄이면 컨테이너 종류를 인식해서 Spring Boot의 `ConnectionDetails`로 자동 등록해 줍니다. PostgreSQL, Kafka, Redis, RabbitMQ, MongoDB 등 주요 컨테이너를 지원하며, `@Bean` 메서드 위나 필드 위에 붙이기만 하면 됩니다. `SpringBootTest` 안에서 별도 프로퍼티 매핑 없이 컨테이너가 곧장 살아 있는 데이터소스로 동작합니다.

> 💡 **왜 중요한가**: 통합 테스트 설정 코드가 사라지면서 "프로덕션과 동일한 인프라" 테스트의 진입장벽이 크게 낮아지고, 컨테이너 종류를 바꿔도 테스트 코드 수정이 거의 필요 없습니다.
