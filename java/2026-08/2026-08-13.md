### 1. `String.formatted(Object...)`로 `String.format`의 정적 호출을 인스턴스 메서드 체이닝으로 바꾸기 (Java 15 정식)

`String.format("Hello %s, age %d", name, age)` 대신 `"Hello %s, age %d".formatted(name, age)`로 쓸 수 있습니다. 포맷 문자열이 주어(subject)가 되어 왼쪽에서 오른쪽으로 자연스럽게 읽히고, 텍스트 블록(`"""..."""`)과 결합하면 SQL·JSON·로그 템플릿 작성이 극적으로 깔끔해집니다.

```java
// Before: 포맷 문자열과 인자가 정적 메서드 안에 뒤섞임
String log = String.format("[%s] user=%s action=%s", level, userId, action);

// After: 템플릿이 주어가 되어 좌→우로 읽힘
String log = "[%s] user=%s action=%s".formatted(level, userId, action);

// 텍스트 블록과 결합 시 진가 발휘
String sql = """
        SELECT id, name
        FROM users
        WHERE tenant_id = %d AND status = '%s'
        """.formatted(tenantId, status);
```

> 💡 **왜 중요한가**: 로그·SQL·에러 메시지처럼 "템플릿 + 값" 조합이 반복되는 코드에서 시선의 흐름이 자연스러워지고, 텍스트 블록과 만나면 별도 템플릿 엔진 없이도 가독성 있는 문자열 조립이 가능해집니다.

### 2. `Objects.requireNonNullElseGet(T, Supplier<T>)`로 기본값 계산을 지연시켜 불필요한 객체 생성 피하기 (Java 9 정식)

`Objects.requireNonNullElse(value, defaultValue)`는 기본값을 항상 미리 평가하지만, `requireNonNullElseGet(value, () -> compute())`은 `value`가 `null`일 때만 `Supplier`를 호출합니다. 기본값 생성이 비싼 경우(DB 조회, 리스트 복사, 대용량 문자열 등) 성능 차이가 크게 벌어집니다.

```java
// Before: value가 null이 아니어도 new ArrayList<>()가 매번 생성됨
List<String> tags = Objects.requireNonNullElse(user.getTags(), new ArrayList<>());

// After: null일 때만 Supplier가 실행됨 — 정상 경로에서는 할당 0
List<String> tags = Objects.requireNonNullElseGet(user.getTags(), ArrayList::new);

// 비싼 기본값 조회 시 효과가 극대화됨
Config config = Objects.requireNonNullElseGet(
        cache.get(key),
        () -> repository.loadDefaultConfig()  // null일 때만 DB 히트
);
```

> 💡 **왜 중요한가**: `orElse` vs `orElseGet` 관계와 동일한 함정이 `Objects` 유틸에도 존재합니다. 핫패스에서 기본값이 거의 사용되지 않는 경우, 이 한 글자 차이(`Get`)가 GC 압박과 불필요한 IO를 없애는 결정적 최적화가 됩니다.
