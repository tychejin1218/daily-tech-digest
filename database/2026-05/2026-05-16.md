### 1. PostgreSQL HOT(Heap-Only Tuple) 업데이트와 `fillfactor` — 인덱스 갱신 비용 줄이기

PostgreSQL은 UPDATE 시 새로운 튜플 버전을 만드는데, 인덱스 컬럼이 변경되지 않고 같은 페이지에 빈 공간이 있으면 인덱스를 건드리지 않는 HOT 업데이트가 동작합니다. 자주 갱신되는 테이블은 `ALTER TABLE orders SET (fillfactor = 80);` 처럼 채움 비율을 낮춰 페이지 내 여유 공간을 확보하면 HOT 비율이 올라가 인덱스 부풀림(bloat)과 WAL 양을 동시에 줄일 수 있습니다.

> 💡 **왜 중요한가**: 인덱스가 많은 테이블에서 HOT만 활성화되어도 UPDATE 비용이 수 배 떨어지고 VACUUM 부담이 함께 줄어듭니다.

### 2. Hibernate `hibernate.jdbc.batch_size` + `order_inserts` — 대량 쓰기를 JDBC 배치로 묶기

JPA는 기본적으로 INSERT/UPDATE를 한 건씩 네트워크 왕복하므로, 수천 건 저장 시 RTT가 병목이 됩니다. `spring.jpa.properties.hibernate.jdbc.batch_size=50`, `order_inserts=true`, `order_updates=true`를 켜고 PK 생성 전략을 `IDENTITY` 대신 `SEQUENCE`(혹은 `pooled`)로 두면 같은 엔티티끼리 묶여 하나의 `addBatch()`로 전송됩니다.

> 💡 **왜 중요한가**: `IDENTITY` 전략은 미리 PK를 못 얻어 배치가 자동으로 비활성화되므로, 배치 설정만 켜고 동작 안 한다고 오해하기 쉬운 함정입니다.
