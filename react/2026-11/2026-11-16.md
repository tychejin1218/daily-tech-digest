### 1. `useImperativeHandle`: 부모가 자식의 "내부 함수"를 호출해야 할 때 — ref를 커스텀 API로 포장하는 탈출구

React의 단방향 데이터 흐름에서 부모가 자식의 메서드(예: `focus()`, `scrollToBottom()`, `reset()`)를 직접 호출해야 할 때가 있다. `forwardRef`로 ref만 넘기면 DOM 노드 전체가 노출되어 자식의 내부 구조가 부모에 새어 나가지만, `useImperativeHandle(ref, () => ({ focus, scrollToBottom }))`로 감싸면 "필요한 메서드만" 선택적으로 노출하는 명시적 명령형 API를 만들 수 있다. 이는 선언적 React 세계에서 "어쩔 수 없이 명령형이 필요한 경계 지점"(미디어 플레이어, 포커스 관리, 폼 리셋 등)을 처리하는 공식 탈출구다.

```tsx
const ChatInput = forwardRef((props, ref) => {
  const inputRef = useRef<HTMLInputElement>(null);
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current?.focus(),
    clear: () => { if (inputRef.current) inputRef.current.value = ''; },
  }), []);
  return <input ref={inputRef} />;
});

// 부모: chatRef.current?.focus() 만 호출 가능, DOM 직접 접근 불가
```

> 💡 **왜 중요한가**: ref로 DOM 전체를 노출하는 순간 자식의 내부 구현(어떤 태그를 쓰는지, 몇 겹으로 감쌌는지)이 부모의 의존성이 되지만, `useImperativeHandle`은 그 경계에 "공식 계약"을 세워 리팩터링 안전성을 지킨다.

### 2. `useEffect` 의존성 배열에 "객체/배열"을 넣으면 매 렌더마다 재실행되는 함정 — 참조 동일성이 지배하는 세계

`useEffect(fn, [config])`에서 `config`가 `{ limit: 10 }` 같은 객체 리터럴이면, 부모가 리렌더링될 때마다 "같은 내용이지만 다른 참조"의 객체가 새로 만들어져서 React는 의존성이 바뀐 것으로 판단하고 effect를 무한히 다시 실행한다. 해결책은 (1) 객체를 분해해서 원시값(`[config.limit]`)만 의존성에 넣거나, (2) 객체 자체를 `useMemo`로 캐싱하거나, (3) effect 내부에서 최신값을 읽어야 한다면 `useRef`에 담아 의존성에서 빼는 것이다. "얕은 비교(Object.is)"로 돌아가는 React의 세계관을 이해하지 못하면, 네트워크 요청이 1초에 60번 터지는 지옥을 보게 된다.

```tsx
// ❌ 매 렌더마다 fetch 재실행 (params 객체가 매번 새로 생성됨)
function UserList({ page }) {
  const params = { page, limit: 10 };
  useEffect(() => { fetch(`/api/users?${qs(params)}`); }, [params]);
}

// ✅ 원시값으로 분해
useEffect(() => { fetch(`/api/users?page=${page}&limit=10`); }, [page]);

// ✅ 또는 useMemo로 참조 안정화
const params = useMemo(() => ({ page, limit: 10 }), [page]);
```

> 💡 **왜 중요한가**: React의 Hook 의존성 비교는 "값 비교"가 아니라 "참조 비교(Object.is)"다 — 이 한 줄을 모르면 `exhaustive-deps` 린트가 시키는 대로 넣다가 무한 루프에 빠지고, 알면 리렌더링과 effect 실행을 완전히 통제할 수 있다.
