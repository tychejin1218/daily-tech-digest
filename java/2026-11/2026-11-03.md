### 1. `Collectors.collectingAndThen(downstream, finisher)` (Java 8 정식)로 수집 직후 바로 변환할 때, 수집 결과를 변수에 받아 다시 `Collections.unmodifiableList`로 감싸는 2단계 관성 벗어나기

스트림의 터미널 연산 안에서 "수집"과 "후처리"를 한 번에 묶는 콜렉터다. 리스트로 모아서 지역 변수에 담고 다시 unmodifiable로 래핑하는 두 줄을 `collectingAndThen(toList(), Collections::unmodifiableList)` 한 줄로 치환하면, 가변 리스트 참조가 밖으로 새어나갈 순간 자체가 사라진다. `groupingBy`/`toMap`의 downstream으로 쓰면 "그룹별로 모은 뒤 각 그룹을 변환"하는 패턴도 그대로 적용된다.

> 💡 **왜 중요한가**: 수집 → 변수 저장 → 변환이라는 3단 체인은 "수집 결과가 가변 상태로 잠깐 노출되는 창문"을 만든다 — `collectingAndThen`은 그 창문을 아예 닫는다.

### 2. `Record Pattern` (Java 21 정식, JEP 440)으로 `switch`에서 `case Point(int x, int y) -> x + y`처럼 분해 매칭할 때, `if (obj instanceof Point p) { int x = p.x(); int y = p.y(); ... }` 캐스팅 + getter 호출 관성 벗어나기

Java 21부터 switch 식과 `instanceof`가 레코드를 "분해"해 필드를 바로 로컬 변수로 바인딩한다. 캐스팅 후 getter 두 번 부르던 3~4줄 분기가 `case Point(int x, int y) -> ...` 한 줄로 압축되고, 중첩 레코드도 `case Line(Point(var x1, var y1), Point(var x2, var y2)) -> ...`처럼 깊이까지 한 번에 꺼낸다. sealed 타입과 결합하면 컴파일러가 분기 누락까지 잡아준다.

> 💡 **왜 중요한가**: `p.x()`, `p.y()` 같은 getter 호출은 전부 "진짜 값에 도달하기 위한 임시 발판"일 뿐 — 레코드 패턴은 발판 없이 필드 자체를 바로 이름 붙여 꺼낸다.
