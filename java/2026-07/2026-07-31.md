### `Collectors.teeing()`으로 두 개의 다운스트림 결과를 하나로 합치기 (Java 12 정식)

하나의 스트림을 두 번 순회하지 않고 min/max, sum/count, 합계/평균 같은 두 집계를 동시에 계산해 최종 병합자로 합치는 컬렉터입니다. `Collectors.teeing(downstream1, downstream2, BiFunction)` 형태로 두 컬렉터의 결과를 받아 하나의 객체(레코드, 튜플 등)로 조립할 수 있어, 별도 반복문이나 `Stream.collect` 두 번 호출을 없앨 수 있습니다. 특히 통계 리포트나 min-max 범위를 함께 반환하는 API 계층에서 코드가 극적으로 짧아집니다.

```java
record Range(int min, int max) {}

Range range = Stream.of(3, 1, 4, 1, 5, 9, 2, 6)
    .collect(Collectors.teeing(
        Collectors.minBy(Integer::compare),
        Collectors.maxBy(Integer::compare),
        (mn, mx) -> new Range(mn.orElseThrow(), mx.orElseThrow())
    ));
// Range[min=1, max=9]
```

> 💡 **왜 중요한가**: 두 번 순회하면 O(2N)에 코드도 두 배지만, `teeing()`은 단일 파이프라인에서 두 집계를 병렬 안전하게 병합해 성능·가독성을 모두 잡습니다.

### `Optional.ifPresentOrElse()`로 값의 유무를 한 번에 분기 처리하기 (Java 9 정식)

`isPresent()`로 검사 후 `get()`으로 꺼내는 안티패턴 대신, 값이 있을 때의 액션과 없을 때의 액션을 한 호출로 선언합니다. 두 번째 인자는 `Runnable`이라 로깅·기본값 세팅·메트릭 증가 같은 부수 효과 처리에 자연스럽게 맞습니다. `orElseGet()`은 반환형이 있고, `ifPresent()`는 없을 때 분기가 없으니, "있으면 A 하고 없으면 B 한다"의 완결형이 필요할 때 최적의 API입니다.

```java
Optional<User> user = repository.findByEmail(email);

user.ifPresentOrElse(
    u -> auditLogger.loginSuccess(u.id()),
    () -> auditLogger.loginFailed(email)
);
```

> 💡 **왜 중요한가**: `if (opt.isPresent()) { ... } else { ... }` 패턴은 null 체크를 Optional로 감쌌을 뿐 명령형 그대로인데, `ifPresentOrElse()`는 분기 의도를 API 시그니처로 드러내 리뷰어와 정적 분석기 모두에게 실수 여지를 줄여줍니다.
