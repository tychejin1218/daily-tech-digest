### 1. `Collectors.partitioningBy(predicate, downstream)` (Java 8 정식)로 참/거짓 두 그룹으로 가를 때 `groupingBy(predicate::test)` 쓰거나 `filter` 두 번 돌리는 관성 벗어나기

`Map<Boolean, List<T>>`를 받아 `true`/`false` 두 버킷으로 정확히 나눠주며, 내부적으로 2칸짜리 배열로 구현되어 `HashMap` 기반 `groupingBy`보다 메모리/조회가 가볍다. downstream 콜렉터를 중첩하면 "합격자는 평균, 불합격자는 count" 같은 비대칭 집계도 한 번의 패스로 끝난다. `partition.get(true)`는 결과가 비어도 빈 리스트를 돌려주므로 `getOrDefault` 보일러플레이트도 사라진다.

```java
Map<Boolean, Long> result = orders.stream()
    .collect(Collectors.partitioningBy(
        o -> o.amount() >= 100_000,
        Collectors.counting()));
// result.get(true)  → VIP 주문 수
// result.get(false) → 일반 주문 수
```

> 💡 **왜 중요한가**: 이분 분류는 `groupingBy`보다 의미가 명확하고 더 빠르다 — "참/거짓으로 가른다"는 의도가 타입에 박혀 있어 리뷰어가 코드를 읽을 필요 없이 시그니처만 봐도 안다.

### 2. `Future.state()` + switch 패턴 매칭 (Java 19 정식, JEP 405)으로 `isDone()`/`isCancelled()`/`get()` try-catch 중첩으로 상태 분기하는 관성 벗어나기

`Future.State`는 `RUNNING`, `SUCCESS`, `FAILED`, `CANCELLED` 4가지 enum을 반환하므로 switch 하나로 모든 경로가 망라된다 — 컴파일러가 누락된 상태를 잡아준다. 기존 `isDone()` → `isCancelled()` → `get()` try-catch 체인은 "완료됐지만 예외"인 경우를 놓치기 쉽고, 체크 예외 두 개(`InterruptedException`, `ExecutionException`)를 매번 선언/처리해야 한다. `resultNow()`/`exceptionNow()` 조합으로 체크 예외 없이 값/원인을 바로 꺼낼 수 있다.

```java
String message = switch (future.state()) {
    case SUCCESS   -> "✓ " + future.resultNow();
    case FAILED    -> "✗ " + future.exceptionNow().getMessage();
    case CANCELLED -> "취소됨";
    case RUNNING   -> "진행 중";
};
```

> 💡 **왜 중요한가**: `Future` 상태 처리는 역사적으로 `InterruptedException` + `ExecutionException` + `CancellationException` 3중 예외 지뢰밭이었는데, enum + switch 패턴 매칭으로 "선언적 상태 조회"로 바뀌어 분기 누락 자체가 컴파일 에러로 드러난다.
