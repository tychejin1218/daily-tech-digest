### 1. `Stream.iterate(seed, hasNext, next)`로 `Stream.iterate().limit()` 이중 호출 관성 벗어나기 (Java 9 정식)

Java 9부터 `Stream.iterate`에 종료 조건(`hasNext`) 오버로드가 추가되어 `.limit()` 없이도 유한 스트림을 만들 수 있다. `for(int i=1; i<1024; i*=2)` 같은 전통적 for 루프의 3요소(초기값·조건·증가)를 스트림 언어로 1:1로 옮길 수 있어, 인덱스 기반 반복을 스트림으로 리팩터링할 때 표현력이 확 올라간다.

```java
// Before: limit으로 강제 종료 — "값이 1024 미만까지"를 개수로 환산해야 함
Stream.iterate(1, i -> i * 2)
      .limit(10)  // 왜 10인가? 계산해봐야 안다
      .forEach(System.out::println);

// After: for 루프의 조건식 그대로
Stream.iterate(1, i -> i < 1024, i -> i * 2)
      .forEach(System.out::println);
```

> 💡 **왜 중요한가**: `.limit(N)`은 "개수" 기반 종료만 표현되는데, 실무의 종료 조건은 "값이 임계치를 넘을 때까지" · "특정 상태가 될 때까지"인 경우가 훨씬 많다 — 개수로 환산하는 순간 매직 넘버가 박힌다.

### 2. `SequencedCollection.getFirst() / getLast() / reversed()`로 `list.get(list.size()-1)` 관성 벗어나기 (Java 21 정식, JEP 431)

Java 21의 `SequencedCollection` 인터페이스가 `List`, `Deque`, `LinkedHashSet` 등 "순서가 있는" 컬렉션에 통일된 첫/끝 접근 API를 추가했다. 그동안 타입마다 흩어져 있던 `list.get(0)`, `deque.peekFirst()`, `sortedSet.first()`를 한 이름으로 묶고, `reversed()`는 **복사 없는 뷰**를 돌려주므로 `Collections.reverse()`의 O(n) 오버헤드가 사라진다.

```java
// Before: 타입마다 문법이 다르고, 마지막 원소는 인덱스 계산 필요
T last = list.get(list.size() - 1);   // IndexOutOfBoundsException 지뢰
T first = deque.peekFirst();          // 이건 왜 peek로 시작하지?
Collections.reverse(list);            // 원본 파괴적 변경

// After: 모든 순차 컬렉션에서 동일한 API
T last = list.getLast();              // 빈 컬렉션이면 NoSuchElementException (명확)
T first = deque.getFirst();
List<T> view = list.reversed();       // 뷰 — 원본 변경 시 즉시 반영, O(1)
```

> 💡 **왜 중요한가**: `list.reversed()`는 **뷰**라서 순회 중 원본이 바뀌면 그대로 반영된다 — 스트림 파이프라인에서 "역순으로 처리하고 싶다"를 표현할 때 새 리스트를 만들 필요가 없어졌다.
