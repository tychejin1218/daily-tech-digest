### 1. `ExecutorService`가 `AutoCloseable` (Java 19 정식)로 `shutdown() → awaitTermination() → shutdownNow()` finally 3단 콤보 관성 벗어나기

기존에는 `ExecutorService`를 안전하게 종료하려면 `try/finally` 안에서 `shutdown()`을 부르고, `awaitTermination(timeout)`으로 기다린 뒤 타임아웃이 나면 `shutdownNow()`를 호출하는 정형화된 보일러플레이트를 매번 손으로 써야 했다. Java 19부터 `ExecutorService`가 `AutoCloseable`을 구현하므로 `try (var pool = Executors.newVirtualThreadPerTaskExecutor()) { ... }` 한 줄로 감싸면 블록을 벗어나는 순간 `close()`가 위의 3단계 종료 프로토콜(정상 종료 시도 → 대기 → 인터럽트)을 표준화된 방식으로 수행한다. 특히 가상 스레드 풀과 조합하면 "리소스 누수 방지 + 명시적 라이프사이클"이 언어 레벨에서 강제되어 실수 여지가 사라진다.

> 💡 **왜 중요한가**: 스레드 풀 종료 로직은 "다들 쓰지만 다들 조금씩 틀리는" 대표적 코드였는데, 이제 `try-with-resources`로 규격화되어 코드 리뷰에서 종료 시퀀스를 검증할 필요 자체가 사라진다.

### 2. `Files.mismatch(path1, path2)` (Java 12 정식)로 두 파일 바이트 비교할 때 스트림 열고 청크 비교하는 관성 벗어나기

두 파일이 동일한지 검사할 때 흔히 `MessageDigest`로 해시를 각각 뽑아 비교하거나 `BufferedInputStream` 두 개를 열고 8KB씩 읽어 `Arrays.equals`로 돌리는 코드를 짜왔지만, 이는 파일 전체를 끝까지 읽어야 하고 첫 불일치 위치도 알 수 없다. `Files.mismatch(p1, p2)`는 첫 번째 바이트 차이의 인덱스를 `long`으로 반환하고 완전히 같으면 `-1L`을 돌려주며, 내부적으로 매핑된 버퍼로 짧게-끊기(short-circuit) 비교를 수행하므로 다른 지점을 만나면 즉시 종료된다. 파일 크기가 다르면 짧은 파일 길이를 반환하는 관례까지 규격화되어 있어 "같은가?" 이상의 "어디서 갈라졌는가?"를 공짜로 얻는다.

> 💡 **왜 중요한가**: 백업 검증·업로드 무결성·바이너리 회귀 테스트에서 "다르다면 어디서 다른지"까지 알아야 디버깅이 시작되는데, 이 API 하나로 해시 오버헤드 없이 조기 종료 + 오프셋 리포팅을 동시에 얻을 수 있다.
