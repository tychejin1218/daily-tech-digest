### 1. `Objects.checkIndex(index, length)` (Java 9 정식, JEP 254 계열)로 배열·리스트 인덱스 경계 검증 — `if (i < 0 || i >= size) throw new IndexOutOfBoundsException()` 삼항 조건 손수 쓰는 관성 벗어나기

`Objects.checkIndex(i, length)`는 유효하면 `i`를 그대로 반환하고, 벗어나면 JDK 내부 메시지 포맷("Index 5 out of bounds for length 3")으로 `IndexOutOfBoundsException`을 던진다. HotSpot C2는 이 메서드를 intrinsic으로 인식해서 뒤따르는 배열 접근의 range check를 제거할 수 있어, 핫 루프에서 손으로 짠 `if` 가드보다 오히려 빠르다. `checkFromToIndex(from, to, length)`, `checkFromIndexSize(from, size, length)`도 같은 계열이라 슬라이스 로직에서 off-by-one을 없애준다.

```java
// Before — 메시지도 제각각, intrinsic 혜택도 없음
public E get(int i) {
    if (i < 0 || i >= size) throw new IndexOutOfBoundsException("bad: " + i);
    return elements[i];
}

// After — 반환값을 그대로 쓸 수 있어 한 줄
public E get(int i) {
    return elements[Objects.checkIndex(i, size)];
}

// 범위 체크도 똑같이 — subList, copyOfRange 같은 자리
Objects.checkFromToIndex(from, to, size);
```

> 💡 **왜 중요한가**: 인덱스 가드는 거의 모든 컬렉션/배열 코드에 박혀 있어서, intrinsic으로 치환되는 한 줄짜리 표준 API로 바꾸는 것만으로 성능·에러 메시지 일관성·테스트 기대값 안정성을 동시에 얻는다.

### 2. `ScopedValue.where(KEY, value).run(() -> ...)` (Java 21 Preview / Java 25 정식, JEP 446→506)로 요청 스코프 컨텍스트 전달 — `ThreadLocal.set()` 후 `finally { remove(); }` 로 메모리 누수 조마조마하던 관성 벗어나기

`ScopedValue`는 "이 람다가 실행되는 동안만" 유효한 불변 바인딩을 제공한다. `ThreadLocal`과 달리 값은 immutable이고, 스코프가 끝나면 자동으로 사라지므로 `finally { tl.remove(); }`를 잊어도 유출될 일이 없다. 가상 스레드와의 궁합이 핵심인데, 수백만 개 가상 스레드가 각자 `ThreadLocal` 테이블을 가지면 메모리가 폭발하지만 `ScopedValue`는 호출 스택을 따라 상속되는 구조라 Loom 환경에서 사실상 표준이 되어가고 있다.

```java
// Before — 누수와 승계 문제 둘 다 안고 가는 패턴
static final ThreadLocal<String> REQUEST_ID = new ThreadLocal<>();

void handle(Request req) {
    REQUEST_ID.set(req.id());
    try {
        service.process();           // 하위에서 REQUEST_ID.get() 조회
    } finally {
        REQUEST_ID.remove();         // 빼먹으면 재사용 스레드에서 유령 데이터
    }
}

// After — 불변 + 자동 해제 + 가상 스레드 친화
static final ScopedValue<String> REQUEST_ID = ScopedValue.newInstance();

void handle(Request req) {
    ScopedValue.where(REQUEST_ID, req.id())
               .run(() -> service.process());  // 스코프 종료 시 자동 해제
}

// 조회 측은 거의 동일
String id = REQUEST_ID.get();        // 바인딩 없으면 NoSuchElementException
```

> 💡 **왜 중요한가**: 가상 스레드로 넘어가는 순간 `ThreadLocal`은 메모리 풋프린트·컨텍스트 승계·누수 리스크 3중 지뢰가 되고, `ScopedValue`는 그 3가지를 언어 수준에서 모두 해결하는 Loom 시대의 기본 컨텍스트 전달 수단이다.
