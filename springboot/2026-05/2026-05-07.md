### `@Retryable` + `@Recover`로 일시적 장애를 선언적으로 재시도하고 최종 폴백 처리하기

Spring Retry를 의존성에 추가하고 `@EnableRetry`를 켠 뒤 메서드에 `@Retryable(retryFor = ..., maxAttempts = 3, backoff = @Backoff(delay = 500, multiplier = 2))`를 붙이면 지수 백오프로 자동 재시도된다. 같은 클래스에 시그니처가 호환되는 `@Recover` 메서드를 두면 모든 재시도가 실패했을 때 폴백으로 호출된다. AOP 프록시 기반이므로 `this.`로 자기 호출하면 재시도가 걸리지 않는다는 점만 주의.

```java
@Retryable(retryFor = HttpServerErrorException.class,
           maxAttempts = 3,
           backoff = @Backoff(delay = 500, multiplier = 2))
public PaymentResult charge(Order order) {
    return paymentClient.charge(order);
}

@Recover
public PaymentResult recover(HttpServerErrorException e, Order order) {
    return PaymentResult.failed(order.id(), e.getStatusText());
}
```

> 💡 **왜 중요한가**: 외부 API·DB 커넥션 같은 일시적 실패에 try-catch와 while 루프를 매번 짜지 않고 정책과 폴백을 분리해 선언할 수 있다.

### `@WebMvcTest`로 컨트롤러 계층만 슬라이스 테스트하고 서비스는 `@MockBean`으로 대체하기

`@WebMvcTest(OrderController.class)`를 붙이면 지정한 컨트롤러와 `WebMvc` 관련 빈(`@ControllerAdvice`, `Converter`, `Filter`)만 로드되고 서비스·리포지토리는 컨텍스트에서 제외된다. 의존 서비스는 `@MockBean`으로 넣고 `MockMvc`로 요청/응답을 검증하면 `@SpringBootTest`보다 훨씬 빠르게 컨트롤러 라우팅·검증·직렬화 계약만 좁게 테스트할 수 있다. Spring Security가 클래스패스에 있으면 자동 적용되므로 인증이 필요한 엔드포인트는 `@WithMockUser` 또는 `SecurityMockMvcRequestPostProcessors`로 우회해야 한다.

```java
@WebMvcTest(OrderController.class)
class OrderControllerTest {
    @Autowired MockMvc mockMvc;
    @MockBean OrderService orderService;

    @Test @WithMockUser
    void 주문_조회() throws Exception {
        given(orderService.findById(1L)).willReturn(new OrderDto(1L, "PAID"));
        mockMvc.perform(get("/orders/1"))
               .andExpect(status().isOk())
               .andExpect(jsonPath("$.status").value("PAID"));
    }
}
```

> 💡 **왜 중요한가**: 전체 컨텍스트를 띄우지 않아 테스트 실행이 수 초에서 수백 밀리초로 줄고, 컨트롤러 계약을 서비스 구현 변경과 독립적으로 지킬 수 있다.
