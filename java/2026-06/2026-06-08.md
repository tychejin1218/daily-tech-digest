### `HexFormat`으로 바이트 배열과 16진수 문자열을 안전하게 변환하기 (Java 17 정식)

`HexFormat.of()`를 통해 얻은 인스턴스로 `formatHex(byte[])`와 `parseHex(String)`을 호출하면 바이트 배열과 16진수 문자열을 양방향으로 변환할 수 있습니다. `withDelimiter(":")`, `withPrefix("0x")`, `withUpperCase()` 같은 옵션으로 MAC 주소, 해시값, 디버그 출력 등 다양한 표현 형식을 한 줄로 만들 수 있어 직접 루프를 돌며 `String.format("%02x", b)`를 호출하던 보일러플레이트가 사라집니다.

```java
byte[] hash = MessageDigest.getInstance("SHA-256").digest("hello".getBytes());

// 기본 소문자 16진수
String hex = HexFormat.of().formatHex(hash);
// → "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"

// 콜론 구분 + 대문자 (MAC 주소 스타일)
String mac = HexFormat.ofDelimiter(":").withUpperCase()
    .formatHex(new byte[]{(byte)0xAA, (byte)0xBB, (byte)0xCC});
// → "AA:BB:CC"

// 역변환
byte[] decoded = HexFormat.of().parseHex(hex);
```

> 💡 **왜 중요한가**: 표준 라이브러리만으로 16진수 변환이 가능해져 Apache Commons Codec이나 Guava 같은 외부 의존성 없이도 안전하고 가독성 높은 코드를 작성할 수 있습니다.

### `Files.mismatch()`로 두 파일이 동일한지 빠르게 비교하기 (Java 12 정식)

`Files.mismatch(Path, Path)`는 두 파일을 바이트 단위로 비교해 처음 다른 위치의 오프셋을 반환하고, 완전히 동일하면 `-1L`을 돌려줍니다. 두 파일을 모두 메모리에 읽어 `Arrays.equals()`로 비교하던 방식과 달리 내부적으로 청크 단위로 스트리밍 비교하므로 대용량 파일에서도 메모리 부담이 적고, 다른 바이트가 발견되는 즉시 조기 종료됩니다.

```java
Path original = Path.of("config.yaml");
Path backup   = Path.of("config.yaml.bak");

long diff = Files.mismatch(original, backup);
if (diff == -1L) {
    System.out.println("두 파일은 동일합니다.");
} else {
    System.out.printf("바이트 오프셋 %d 위치부터 다릅니다.%n", diff);
}
```

> 💡 **왜 중요한가**: 백업 검증, 빌드 산출물 비교, 테스트 골든 파일 검증 같은 시나리오에서 해시 계산이나 전체 로딩 없이도 정확하고 효율적인 동등성 비교를 표준 API 한 줄로 구현할 수 있습니다.
