### `@Sql`의 `executionPhase = BEFORE_TEST_METHOD` vs `AFTER_TEST_METHOD`로 테스트 격리 보장하기

`@Sql`은 기본적으로 테스트 메서드 실행 전에 SQL을 실행하지만, `executionPhase = AFTER_TEST_METHOD`로 지정하면 테스트 종료 후 정리 SQL을 실행할 수 있다. `@Transactional`로 롤백이 안 되는 상황(예: 별도 트랜잭션 실행, 커밋된 데이터)에서 데이터 정리에 특히 유용하다.

```java
@SpringBootTest
class OrderServiceTest {

    @Test
    @Sql(scripts = "/sql/insert-order.sql", executionPhase = BEFORE_TEST_METHOD)
    @Sql(scripts = "/sql/cleanup-order.sql", executionPhase = AFTER_TEST_METHOD)
    void 주문_조회_테스트() {
        // given: BEFORE_TEST_METHOD로 데이터 세팅됨
        // when & then
        // AFTER_TEST_METHOD로 자동 정리
    }
}
```

> 💡 **왜 중요한가**: `@Transactional` 롤백에 의존할 수 없는 통합 테스트에서 데이터 격리를 선언적으로 확보한다.

### `spring.jpa.open-in-view=false`를 설정하지 않으면 트랜잭션 밖에서도 커넥션이 물려 있어 커넥션 풀이 고갈된다

Spring Boot는 기본적으로 OSIV(Open Session In View)가 켜져 있어 HTTP 요청 시작부터 응답이 나갈 때까지 영속성 컨텍스트와 DB 커넥션을 잡고 있다. 트랜잭션이 끝났어도 뷰 렌더링 단계까지 커넥션을 반환하지 않기 때문에 트래픽이 늘면 커넥션 풀이 순식간에 고갈된다.

```yaml
# application.yml
spring:
  jpa:
    open-in-view: false  # 트랜잭션 종료 시점에 커넥션 즉시 반환
```

끄면 서비스 계층 밖에서 지연 로딩 시 `LazyInitializationException`이 터지므로, DTO 변환은 반드시 트랜잭션 내부에서 완료해야 한다.

> 💡 **왜 중요한가**: OSIV를 끄지 않으면 커넥션이 뷰 렌더링까지 물려 있어 동시 요청 폭증 시 커넥션 풀이 먼저 무너진다.
