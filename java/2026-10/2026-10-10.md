### 1. `Stream.gather(Gatherer)` (Java 24 정식, JEP 485)로 윈도우/슬라이딩/상태 누적 때 `collect() + 재스트리밍` 관성 벗어나기

`map`/`filter`/`flatMap`으론 "직전 요소까지 본 상태"를 들고 다닐 방법이 없어 `collect()`로 리스트에 모은 뒤 다시 `stream()`을 켜는 2패스가 관성이었다. `Stream.gather(Gatherer)`는 1급 중간 연산으로 상태를 유지하며 `windowFixed`, `windowSliding`, `scan`, `fold` 같은 내장 Gatherer를 바로 꽂을 수 있고, 커스텀 Gatherer를 만들어 "N개씩 묶기", "변할 때만 통과", "누적 합" 같은 로직을 지연 평가(lazy)로 처리한다.

```java
// Before — 2패스
List<Integer> src = List.of(1,2,3,4,5,6,7);
List<List<Integer>> chunks = new ArrayList<>();
for (int i = 0; i < src.size(); i += 3)
    chunks.add(src.subList(i, Math.min(i+3, src.size())));
List<Integer> sums = chunks.stream().map(c -> c.stream().mapToInt(Integer::intValue).sum()).toList();

// After — gather로 1패스
List<Integer> sums = Stream.of(1,2,3,4,5,6,7)
    .gather(Gatherers.windowFixed(3))         // [[1,2,3],[4,5,6],[7]]
    .map(w -> w.stream().mapToInt(Integer::intValue).sum())
    .toList();
```

> 💡 **왜 중요한가**: `Stream`에 20년 만에 "상태 있는 중간 연산"이 1급 시민으로 들어온 것이라, `Collectors.teeing`이 종료 연산에서 하던 조합 트릭을 중간 단계에서 지연 평가로 할 수 있게 된 패러다임 전환이다.

### 2. `_` 언더스코어 변수 (Java 22 정식, JEP 456)로 안 쓰는 람다 파라미터/catch 변수에 `e`, `ignored` 붙이는 관성 벗어나기

`try { ... } catch (NumberFormatException ignored) { ... }`, `map.forEach((k, v) -> count++)` 처럼 "선언은 해야 하는데 안 쓰는" 변수에 `ignored`, `_e`, 쓰이지도 않는 `k` 같은 이름을 억지로 붙이는 건 코드 리뷰어에게 "안 쓴다"는 의도를 이름으로만 암시하는 꼼수였다. Java 22부터 `_` 하나로 **"선언했지만 안 쓴다"**를 문법 레벨에서 선언할 수 있고, 레코드 패턴 매칭에서도 `case Point(int x, _)`처럼 관심 없는 컴포넌트를 생략할 수 있다.

```java
// Before — 안 쓰는 변수에 의미 없는 이름
try {
    Integer.parseInt(s);
} catch (NumberFormatException ignored) { /* fallback */ }

map.forEach((k, v) -> counter.incrementAndGet());  // k, v 둘 다 안 씀

if (obj instanceof Point p && p.x() > 0) { ... }   // y는 관심 없음

// After — `_`로 의도를 1급 문법으로
try {
    Integer.parseInt(s);
} catch (NumberFormatException _) { /* fallback */ }

map.forEach((_, _) -> counter.incrementAndGet());

if (obj instanceof Point(int x, _) && x > 0) { ... }
```

> 💡 **왜 중요한가**: "안 쓰는 변수"가 주석/네이밍 컨벤션이 아니라 **컴파일러가 검증하는 1급 선언**이 되면서, 리뷰어가 "이거 왜 선언만 하고 안 쓰지?"로 1초라도 의심할 여지를 문법으로 제거한다 — Scala/Kotlin/Rust가 10년 전부터 가진 그 기능이 드디어 Java에 왔다.
