### `@Transactional`은 `private` 메서드에서 동작하지 않는다 — 프록시가 접근할 수 없기 때문이다

Spring의 `@Transactional`은 CGLIB/JDK 동적 프록시 기반으로 동작하기 때문에 `private`, `final`, `static` 메서드에는 적용되지 않는다. 컴파일 에러도 없고 경고도 없어서, 개발자는 트랜잭션이 걸린 줄 알고 안심하지만 실제로는 auto-commit 모드로 실행된다. 특히 리팩토링하면서 `public` 메서드를 `private`으로 바꾸는 순간 트랜잭션이 조용히 사라진다.

```java
@Service
public class OrderService {
    @Transactional  // public — 정상 동작
    public void createOrder(Order order) {
        saveOrder(order);
        saveHistory(order);  // 같은 트랜잭션 안에서 실행됨
    }

    @Transactional  // ❌ private — 동작하지 않음, 프록시가 감쌀 수 없다
    private void saveHistory(Order order) {
        historyRepository.save(new History(order));
    }
}
```

> 💡 **왜 중요한가**: 트랜잭션이 걸린 줄 알고 짠 코드가 실제로는 각 SQL마다 커밋되어 롤백이 불가능해진다 — 데이터 정합성이 조용히 깨진다.

### `@RequestBody`는 기본 생성자가 없으면 역직렬화에 실패한다 — Lombok의 `@Builder`만 붙이면 함정에 빠진다

Jackson은 JSON을 객체로 변환할 때 기본 생성자를 호출한 뒤 리플렉션으로 필드를 채운다. 그래서 `@Builder`만 붙이고 `@NoArgsConstructor`를 빠뜨리면 `HttpMessageNotReadableException`이 터진다. `record`나 `@JsonCreator` 없이 불변 DTO를 만들려는 순간 이 문제가 반드시 발생한다.

```java
// ❌ 역직렬화 실패 — 기본 생성자 없음
@Getter
@Builder
public class OrderRequest {
    private String productId;
    private int quantity;
}

// ✅ 해결책 1: 기본 생성자 추가 (하지만 불변성 깨짐)
@Getter
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class OrderRequest { ... }

// ✅ 해결책 2: record 사용 (Jackson 2.12+ 자동 지원)
public record OrderRequest(String productId, int quantity) {}
```

> 💡 **왜 중요한가**: 불변 DTO를 만들려고 `@Builder`만 쓰면 API가 400을 뱉는데, 원인을 모르면 Lombok과 Jackson 사이에서 몇 시간을 헤맨다.
