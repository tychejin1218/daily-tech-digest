### 1. `String.indent(int n)`으로 여러 줄 문자열의 들여쓰기를 일괄 조정하기 (Java 12 정식)

텍스트 블록이나 여러 줄 문자열을 로그·에러 메시지·코드 생성기에 넣을 때 들여쓰기를 손으로 맞추다 보면 `replaceAll("(?m)^", "    ")` 같은 정규식 지옥에 빠지기 쉽습니다. `String.indent(4)`는 각 줄 앞에 지정한 개수만큼 공백을 붙이고, 음수를 주면 그만큼 왼쪽 공백을 제거하며, 마지막 줄에도 안전하게 `\n`을 보정해줍니다.

```java
String sql = """
        SELECT id, name
        FROM users
        WHERE active = true
        """;

// 로그에 들여쓰기 추가
log.info("Executing query:\n{}", sql.indent(4));

// 텍스트 블록의 과도한 들여쓰기 제거
String trimmed = sql.indent(-8);  // 왼쪽 공백 8칸 제거 (부족하면 있는 만큼만)

// 코드 생성기에서 중첩 블록 만들기
String body = "return value;";
String method = "public int get() {\n" + body.indent(4) + "}";
```

> 💡 **왜 중요한가**: 로그 가독성·코드 생성·마크다운 렌더링 같은 실무 상황에서 정규식 없이 `Stream<String>`을 거치지 않고도 들여쓰기를 안전하게 조작할 수 있어, "문자열 포매팅용 유틸 클래스"를 만들 이유가 하나 줄어듭니다.

### 2. `Objects.checkIndex(int index, int length)`로 인덱스 검증을 표준 예외로 통일하기 (Java 9 정식)

배열·리스트를 감싸는 커스텀 자료구조를 만들 때 `if (i < 0 || i >= size) throw new IndexOutOfBoundsException(...)` 같은 방어 코드를 매번 손으로 쓰면 메시지 포맷이 제각각이 되고, HotSpot 인트린식 최적화도 놓치게 됩니다. `Objects.checkIndex(i, length)`는 검증에 통과하면 인덱스 값을 그대로 반환하고, 실패하면 JDK 표준 포맷의 `IndexOutOfBoundsException`을 던져줍니다.

```java
public class RingBuffer<E> {
    private final Object[] data;

    public E get(int index) {
        // 검증 + 반환을 한 줄로. 실패 메시지: "Index 5 out of bounds for length 3"
        Objects.checkIndex(index, data.length);
        return (E) data[index];
    }
}

// 범위 검증(fromIndex, toIndex)이 필요할 때
Objects.checkFromToIndex(from, to, size);   // [from, to) 검증
Objects.checkFromIndexSize(from, len, size); // [from, from+len) 검증
```

> 💡 **왜 중요한가**: JDK 내부에서 `ArrayList`, `String.charAt` 등이 이미 쓰는 표준 검증 API이므로 예외 메시지가 일관되고, HotSpot이 범위 체크를 인트린식으로 인식해 별도 `if`문보다 최적화 여지가 크며, 방어 코드의 시각적 노이즈를 극적으로 줄여줍니다.
