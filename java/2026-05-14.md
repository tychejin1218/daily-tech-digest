### `Scoped Values`로 스레드 간 안전한 불변 컨텍스트 공유하기 (Java 25 정식)

`ScopedValue`는 `ThreadLocal`의 대안으로, 특정 코드 블록 범위 안에서만 유효한 불변 값을 자식 스레드(특히 가상 스레드)에 안전하게 전달하는 메커니즘입니다. `ScopedValue.where(KEY, value).run(() -> ...)` 형태로 바인딩하면 블록 종료 시 자동으로 정리되어 메모리 누수가 없고, 구조적 동시성(`StructuredTaskScope`)과 결합해 수백만 개의 가상 스레드에서도 효율적으로 동작합니다. JEP 506으로 Java 25에서 정식 기능이 되었습니다.

```java
private static final ScopedValue<String> USER_ID = ScopedValue.newInstance();

ScopedValue.where(USER_ID, "user-42").run(() -> {
    try (var scope = StructuredTaskScope.open()) {
        scope.fork(() -> processOrder(USER_ID.get()));
        scope.fork(() -> sendNotification(USER_ID.get()));
        scope.join();
    }
});
```

> 💡 **왜 중요한가**: `ThreadLocal`의 가변성·정리 누락 문제를 없애고, 가상 스레드 시대에 맞는 가벼운 컨텍스트 전파 방식을 제공합니다.

### `Class-File API`로 바이트코드를 표준 API로 안전하게 다루기 (Java 24 정식)

JEP 484로 Java 24에서 정식화된 `java.lang.classfile` 패키지는 ASM·Javassist 같은 외부 라이브러리 없이 JDK 표준으로 클래스 파일을 읽고, 변환하고, 생성할 수 있게 해줍니다. 빌더 기반 API와 불변(immutable) 모델을 채택해 안전하고, 새 JDK 릴리스의 바이트코드 포맷 변화에 JDK가 직접 대응해주므로 라이브러리 업그레이드 지연 문제가 사라집니다.

```java
byte[] bytes = ClassFile.of().build(
    ClassDesc.of("com.example.Hello"),
    cb -> cb.withMethodBody("hello", MethodTypeDesc.of(CD_void), ACC_PUBLIC | ACC_STATIC,
        code -> code.getstatic(ClassDesc.of("java.lang.System"), "out",
                               ClassDesc.of("java.io.PrintStream"))
                    .ldc("Hello!")
                    .invokevirtual(ClassDesc.of("java.io.PrintStream"), "println",
                                   MethodTypeDesc.of(CD_void, CD_String))
                    .return_())
);
```

> 💡 **왜 중요한가**: AOP·프록시·바이트코드 계측을 다루는 프레임워크 개발자가 JDK 버전 종속성 없이 안정적으로 클래스 파일을 조작할 수 있는 공식 통로가 열렸습니다.
