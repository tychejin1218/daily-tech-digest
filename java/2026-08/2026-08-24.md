### 1. `String.chars().filter().count()` 대신 `codePoints()`로 이모지·한자 확장영역까지 정확히 세기

`String.length()`나 `chars()`는 UTF-16 코드 유닛 단위라서 서로게이트 페어(이모지, 일부 한자)를 2로 세는 함정이 있습니다. `codePoints()`는 유니코드 코드 포인트 단위로 순회하므로 "실제 글자 수"에 훨씬 가깝고, 필터·매핑도 int 스트림으로 자연스럽게 이어집니다. Java 9부터 제공되지만 여전히 `length()`로 문자 수 검증하는 코드가 대부분입니다.

```java
String s = "안녕😀𠀋"; // 한글 2 + 이모지 1 + 확장한자 1 = 4글자

s.length();              // 6  (서로게이트 페어 2개가 각각 2로 카운트)
s.chars().count();       // 6  (동일한 함정)
s.codePoints().count();  // 4  ✅ 사람이 세는 글자 수와 일치

// 이모지만 골라내기
long emojiCount = s.codePoints()
    .filter(cp -> Character.getType(cp) == Character.OTHER_SYMBOL)
    .count();
```

> 💡 **왜 중요한가**: 닉네임·SMS 길이 제한처럼 "글자 수 N자 이하" 검증에서 `length()`를 쓰면 이모지 하나 붙는 순간 사용자에게 원인 불명의 에러를 던지게 됩니다.

### 2. `Thread.startVirtualThread(Runnable)`로 일회성 가상 스레드를 한 줄에 띄우기 (Java 21 정식)

`Executors.newVirtualThreadPerTaskExecutor()`까지 갈 필요 없이, fire-and-forget 성격의 단발성 비동기 작업이라면 `Thread.startVirtualThread()` 한 줄이면 충분합니다. 내부적으로 `Thread.ofVirtual().start()`와 동일하지만, ExecutorService 생성·shutdown 보일러플레이트가 사라지고 의도가 코드에 그대로 드러납니다. 로그 전송, 캐시 워밍, 감사 이벤트 발행 등 결과를 기다릴 필요 없는 I/O 작업에 특히 잘 맞습니다.

```java
// Before: 일회성 작업인데도 executor 수명 관리가 딸려온다
ExecutorService es = Executors.newVirtualThreadPerTaskExecutor();
es.submit(() -> auditLogClient.send(event));
es.shutdown(); // 잊으면 리소스 누수

// After: 의도가 명확한 한 줄
Thread.startVirtualThread(() -> auditLogClient.send(event));

// 이름 붙이고 싶으면 ofVirtual() 빌더 사용
Thread.ofVirtual()
    .name("audit-", counter.incrementAndGet())
    .start(() -> auditLogClient.send(event));
```

주의: 반환된 `Thread` 참조를 잡지 않으면 예외가 조용히 삼켜지므로, 실패 로깅이 필요한 작업이라면 Runnable 안에서 try-catch로 감싸거나 `UncaughtExceptionHandler`를 붙여야 합니다.

> 💡 **왜 중요한가**: 플랫폼 스레드 시절엔 "일회성이라도 pool을 재사용해라"가 정답이었지만, 가상 스레드는 생성 비용이 μs 단위라 오히려 pool이 안티패턴이 됩니다 — 코드가 사고방식 전환을 반영해야 합니다.
