### 1. Spring Boot의 `@Transactional(readOnly = true)`는 **JPA에서는 성능 최적화 플래그로 동작하지만, JDBC Template이나 MyBatis에서는 "그냥 힌트"에 불과하다**

`@Transactional(readOnly = true)`를 붙이면 많은 개발자가 "쓰기가 막힌다"고 믿지만, 실제로는 Hibernate가 더티 체킹을 건너뛰고 스냅샷을 저장하지 않는 최적화일 뿐이다. JDBC Template이나 MyBatis를 쓰면 `Connection.setReadOnly(true)`가 호출될 뿐이고, 이 플래그는 DB 드라이버마다 해석이 다르다 — MySQL은 무시하고, PostgreSQL은 실제로 쓰기를 막는다. 그래서 "readOnly인데 INSERT가 되네?"라는 상황이 재현 불가능한 버그로 돌아온다.

```java
@Transactional(readOnly = true)
public void suspiciousRead(Long id) {
    User user = userRepository.findById(id).get();
    user.setName("hacked");  // JPA: 커밋 시 반영 안 됨 (더티 체킹 off)
    jdbcTemplate.update("UPDATE users SET name = ? WHERE id = ?", 
                       "hacked", id);  // MySQL: 그대로 실행됨
}
```

> 💡 **왜 중요한가**: `readOnly = true`를 "읽기 전용 강제"로 믿고 방어 코드를 생략하면, JPA 레이어의 안전 장치가 Raw SQL 레이어에서는 뚫린다 — 같은 트랜잭션 안에서도 쓰기 가능 여부가 갈린다.

### 2. Spring Boot의 `RestTemplate`과 `WebClient`의 `exchange()`는 **4xx/5xx 응답을 기본적으로 "예외"로 취급한다** — 그래서 HTTP 400을 받은 외부 API 호출이 비즈니스 로직까지 터뜨린다

`restTemplate.exchange()`는 2xx가 아닌 응답을 받으면 `HttpClientErrorException`이나 `HttpServerErrorException`을 던진다. 많은 개발자가 "응답 상태 코드로 분기 처리"를 설계하다가, 외부 API가 400을 반환하는 순간 try-catch 없이는 서비스가 터지는 걸 뒤늦게 발견한다. WebClient의 `retrieve()`도 마찬가지로 `WebClientResponseException`을 던지며, `onStatus()`나 `toEntity()`로 명시적으로 처리하지 않으면 상위 호출자까지 예외가 전파된다.

```java
// 위험: 400 응답이 예외로 튀어나와 비즈니스 로직을 중단시킴
ResponseEntity<User> response = restTemplate.exchange(
    url, HttpMethod.GET, entity, User.class);

// 안전: 상태 코드로 분기하려면 ResponseErrorHandler를 커스텀하거나
restTemplate.setErrorHandler(new DefaultResponseErrorHandler() {
    @Override
    public boolean hasError(ClientHttpResponse response) { return false; }
});

// WebClient의 경우 명시적 처리
webClient.get().uri(url)
    .exchangeToMono(response -> {
        if (response.statusCode().is4xxClientError()) {
            return response.bodyToMono(ErrorDto.class)
                           .map(err -> handle4xx(err));
        }
        return response.bodyToMono(User.class);
    });
```

> 💡 **왜 중요한가**: HTTP 클라이언트의 "응답 코드"를 "예외"로 변환하는 기본 동작을 모르면, 외부 API의 정상적인 비즈니스 응답(예: 결제 실패 400)이 당신 서비스의 500으로 둔갑한다.
