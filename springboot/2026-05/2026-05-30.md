### `@ConfigurationPropertiesScan`으로 `@EnableConfigurationProperties` 없이 프로퍼티 클래스 자동 등록하기

Spring Boot 2.2+에서는 메인 클래스에 `@ConfigurationPropertiesScan`을 붙이면 `@ConfigurationProperties` 클래스를 컴포넌트처럼 자동 스캔·등록해준다. 기존처럼 각 설정 클래스마다 `@EnableConfigurationProperties(MyProps.class)`를 나열하거나 `@Component`를 억지로 붙일 필요가 없어진다.

```java
@ConfigurationProperties(prefix = "app.mail")
public record MailProperties(String host, int port, String username) {}

@SpringBootApplication
@ConfigurationPropertiesScan("com.example.app.config")  // 이 한 줄이면 끝
public class Application { ... }
```

> 💡 **왜 중요한가**: 설정 클래스가 늘어날수록 등록 누락으로 인한 `null` 주입 사고가 잦은데, 스캔 방식으로 바꾸면 패키지 안의 모든 프로퍼티 클래스가 일관되게 자동 등록되어 실수를 원천 차단할 수 있다.

### `MockMvc` 대신 `@AutoConfigureMockMvc(printOnlyOnFailure = false)`로 매 요청 로그 확인하기

`MockMvcResultHandlers.print()`를 매 테스트마다 붙이는 대신, `@AutoConfigureMockMvc(printOnlyOnFailure = false)`를 클래스에 한 번만 선언하면 모든 요청/응답이 콘솔에 출력된다. 기본값(`true`)은 실패 시에만 찍히는데, 로컬 디버깅 중이라면 성공 케이스의 헤더·바디도 확인하고 싶을 때가 많다.

```java
@WebMvcTest(OrderController.class)
@AutoConfigureMockMvc(printOnlyOnFailure = false)
class OrderControllerTest {
    @Autowired MockMvc mockMvc;
    // .andDo(print()) 없이도 요청/응답이 모두 출력됨
}
```

> 💡 **왜 중요한가**: `.andDo(print())`를 테스트마다 붙이는 반복 작업을 없애면서, CI에서는 어노테이션 하나만 지우면 로그 노이즈 없이 실패 케이스만 출력되도록 되돌릴 수 있다.
