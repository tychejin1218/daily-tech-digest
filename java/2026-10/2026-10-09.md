### 1. `HexFormat.of().formatHex(bytes)` (Java 17 정식)로 `String.format("%02x", b)` 루프 관성 벗어나기

바이트 배열을 hex 문자열로 변환할 때 매번 `StringBuilder`에 `String.format("%02x", b)`를 반복하거나 `Integer.toHexString(b & 0xff)`로 패딩 수동 처리하는 보일러플레이트를 `HexFormat`이 완전히 대체한다. `HexFormat.of().formatHex(bytes)` 한 줄이면 소문자 hex, `HexFormat.of().withUpperCase()`로 대문자, `withDelimiter(":")`로 `aa:bb:cc` 형식까지 즉시 나온다. 역방향 `parseHex(String)`도 동일 API로 제공되어 MAC 주소, 해시 다이제스트, UUID 바이트 변환 코드가 극적으로 줄어든다.

```java
// Before: 보일러플레이트
StringBuilder sb = new StringBuilder();
for (byte b : digest) sb.append(String.format("%02x", b));
String hex = sb.toString();

// After: Java 17+
String hex = HexFormat.of().formatHex(digest);
String mac = HexFormat.ofDelimiter(":").withUpperCase().formatHex(macBytes); // "AA:BB:CC:DD:EE:FF"
byte[] back = HexFormat.of().parseHex(hex);
```

> 💡 **왜 중요한가**: SHA-256 다이제스트/서명/핑거프린트를 다루는 보안·암호 코드에서 `String.format` 루프는 CPU 수십 배 느리고 가독성도 떨어진다 — `HexFormat`은 내부적으로 lookup table을 쓰는 전용 구현이다.

### 2. `Stream.mapMulti((element, consumer) -> ...)` (Java 16 정식)로 `flatMap(x -> Stream.of(...))` 임시 스트림 생성 관성 벗어나기

하나의 원소에서 **0~N개의 결과를 조건부로 뽑아낼 때** 지금까지는 `flatMap`을 쓰고 그 안에서 매번 `Stream.of(...)`, `Stream.empty()`, `Stream.builder()`를 열어 중간 스트림을 생성·소비·폐기해왔다. `mapMulti`는 Consumer를 직접 넘겨 임시 스트림 할당 없이 결과를 push할 수 있어, 특히 분기가 많거나 원소당 결과 개수가 들쭉날쭉할 때 할당 비용을 완전히 제거한다. 타입 추론을 위해 `<Target>` 또는 `mapMultiToInt/Long/Double` 변형을 쓴다.

```java
// Before: 원소마다 Stream 객체 생성
Stream<String> result = orders.stream()
    .flatMap(o -> o.isPaid() 
        ? o.getItems().stream().map(Item::getSku) 
        : Stream.empty());

// After: Consumer에 직접 push, 중간 Stream 할당 0
Stream<String> result = orders.stream()
    .<String>mapMulti((o, sink) -> {
        if (!o.isPaid()) return;
        for (Item it : o.getItems()) sink.accept(it.getSku());
    });
```

> 💡 **왜 중요한가**: 대량 ETL/배치 파이프라인에서 `flatMap`의 숨은 비용은 "원소당 Stream 객체 생성"이며, `mapMulti`는 이 할당을 제거해 GC 압력을 눈에 띄게 낮춘다 — JDK 벤치마크 기준 분기형 변환에서 2~3배 처리량 차이가 보고된다.
