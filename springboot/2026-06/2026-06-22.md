### `WebTestClient`로 WebMvc·WebFlux를 같은 API로 검증하기 (Spring 5+)
WebFlux 전용으로 알려져 있지만, `WebTestClient.bindToServer()`나 `bindToApplicationContext()`로 일반 MVC 애플리케이션도 호출할 수 있어 동기·비동기 컨트롤러를 **하나의 어서션 DSL**로 검증할 수 있습니다. `MockMvc`의 verbose한 체이닝 대신 fluent한 `expectStatus().isOk()` 형태가 가독성을 높이고, JSON 바디 검증은 `expectBody().jsonPath()`로 같습니다.

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@AutoConfigureWebTestClient
class OrderApiTest {
    @Autowired WebTestClient client;

    @Test
    void list_orders() {
        client.get().uri("/orders?status=PAID")
              .exchange()
              .expectStatus().isOk()
              .expectHeader().contentTypeCompatibleWith(MediaType.APPLICATION_JSON)
              .expectBody()
                .jsonPath("$.length()").isEqualTo(3)
                .jsonPath("$[0].status").isEqualTo("PAID");
    }
}
```

> 💡 **왜 중요한가**: MVC→WebFlux 점진 마이그레이션 중인 코드베이스에서도 테스트 코드만큼은 한 가지 DSL로 통일할 수 있어 학습·유지비용이 줄어듭니다.

### `@JdbcTest`로 JPA 없이 가벼운 슬라이스 테스트 만들기
리포지터리에 `JdbcTemplate`·`JdbcClient`만 쓰는데 `@SpringBootTest`로 전체 컨텍스트를 띄우는 건 과합니다. `@JdbcTest`는 `DataSource`·`JdbcTemplate`·트랜잭션 매니저만 올리고 나머지 자동설정은 모두 제외해 부팅이 1초 미만으로 떨어지며, 기본적으로 임베디드 DB를 사용하고 각 테스트는 자동 롤백됩니다.

```java
@JdbcTest
@AutoConfigureTestDatabase(replace = Replace.NONE)   // 실제 DB(Testcontainers 등)를 그대로 쓰고 싶으면
@Import(OrderJdbcRepository.class)
class OrderJdbcRepositoryTest {
    @Autowired OrderJdbcRepository repo;
    @Autowired JdbcTemplate jdbc;

    @Test
    void save_then_find() {
        jdbc.execute("CREATE TABLE orders(id BIGINT PRIMARY KEY, amount BIGINT)");
        repo.insert(new Order(1L, 9_900L));
        assertThat(repo.findById(1L).orElseThrow().amount()).isEqualTo(9_900L);
    }
}
```

> 💡 **왜 중요한가**: 리포지터리 한두 개를 바꿀 때 전체 컨텍스트를 띄우지 않으므로 TDD 사이클이 분→초 단위로 짧아지고, 의도하지 않은 자동설정 의존이 새는 것도 막을 수 있습니다.
