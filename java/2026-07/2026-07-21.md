### `SequencedCollection`으로 List·Deque·LinkedHashSet의 첫/끝 원소 접근을 통일하기 (Java 21 정식)
`List`, `Deque`, `LinkedHashSet`처럼 순서가 있는 컬렉션은 그동안 첫/마지막 원소에 접근하는 방식이 제각각이었습니다. Java 21에서 도입된 `SequencedCollection` 인터페이스는 `getFirst()`, `getLast()`, `addFirst()`, `addLast()`, `reversed()`를 공통 API로 제공하여, 타입에 관계없이 동일한 문법으로 순서 접근을 처리할 수 있게 해줍니다.

```java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
list.getFirst();   // "a"  (이전엔 list.get(0))
list.getLast();    // "c"  (이전엔 list.get(list.size() - 1))
list.reversed();   // [c, b, a] — 역순 뷰 (원본 유지)

LinkedHashSet<Integer> set = new LinkedHashSet<>(List.of(1, 2, 3));
set.getFirst();    // 1  (이전엔 iterator().next())
set.getLast();     // 3  (이전엔 전체 순회 필요)

Deque<String> deque = new ArrayDeque<>();
deque.addFirst("x");
deque.addLast("y");
```

> 💡 **왜 중요한가**: 컬렉션 타입마다 흩어져 있던 첫/끝 접근 관용구를 하나의 표준 API로 통일해, 제네릭 유틸리티 작성이 쉬워지고 코드 가독성이 크게 향상됩니다.

### Helpful NullPointerException으로 NPE 발생 시 어떤 참조가 null이었는지 정확히 파악하기 (Java 14 도입, Java 15부터 기본 활성화)
`a.b().c.d()` 같은 체인 호출에서 NPE가 터지면 예전엔 스택 트레이스의 줄 번호만 보고 어느 참조가 null이었는지 유추해야 했습니다. Java 14부터 JVM은 NPE 메시지에 정확히 어떤 필드/메서드 반환값이 null이었는지 명시해주며, Java 15부터는 별도 옵션 없이 기본 활성화됩니다.

```java
// order.getCustomer().getAddress().getZipCode()  ← 이 줄에서 NPE 발생 시

// Java 13 이하:
// Exception in thread "main" java.lang.NullPointerException
//     at Main.main(Main.java:10)

// Java 15+:
// Exception in thread "main" java.lang.NullPointerException:
//   Cannot invoke "Address.getZipCode()" because the return value of
//   "Customer.getAddress()" is null
//     at Main.main(Main.java:10)
```

Java 14에서는 `-XX:+ShowCodeDetailsInExceptionMessages` 플래그를 켜야 활성화됐지만, Java 15 이후로는 별도 설정 없이 즉시 사용할 수 있습니다.

> 💡 **왜 중요한가**: 로그 한 줄만 보고도 체인 어디에서 null이 발생했는지 즉시 알 수 있어, 재현 없이도 원인을 특정할 수 있고 디버깅 시간이 크게 줄어듭니다.
