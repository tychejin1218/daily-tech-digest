### 1. `HexFormat.of().formatHex(byte[])`로 `String.format("%02x", ...)` 루프 관성 벗어나기 (Java 17 정식)

SHA-256 해시나 UUID를 hex 문자열로 변환할 때 흔히 `StringBuilder`에 `String.format("%02x", b)`를 반복 append하는 코드를 쓰지만, Java 17부터는 `HexFormat` 표준 API가 정식으로 들어왔다. `HexFormat.of().formatHex(bytes)`면 소문자 hex 한 방, `HexFormat.ofDelimiter(":").withUpperCase().formatHex(bytes)`면 `AA:BB:CC` 같은 MAC 주소 포맷까지 한 줄로 나오고, 역방향은 `parseHex(String)`로 대칭적으로 처리된다. `String.format` 루프 대비 벤치마크에서 5~10배 빠른데, 매번 포맷 파서를 새로 돌리지 않기 때문이다.

```java
// Before: 관성적으로 쓰는 코드
StringBuilder sb = new StringBuilder();
for (byte b : hash) sb.append(String.format("%02x", b));
String hex = sb.toString();

// After: Java 17 표준
String hex = HexFormat.of().formatHex(hash);

// 구분자 + 대문자 (MAC 주소, 인증서 지문 등)
String fingerprint = HexFormat.ofDelimiter(":").withUpperCase().formatHex(certBytes);
// → "3A:7F:C2:..."

// 역변환도 대칭적
byte[] restored = HexFormat.of().parseHex(hex);
```

> 💡 **왜 중요한가**: 해시·시그니처·바이너리 로깅은 백엔드에서 매일 나오는 작업인데, 대부분 팀 코드베이스는 아직도 `String.format("%02x", b)` 루프를 쓴다 — 표준 API가 있다는 걸 모르면 성능과 가독성을 동시에 잃는다.

### 2. `Objects.checkIndex(index, length)`로 수동 범위 검사 관성 벗어나기 (Java 9 정식)

배열이나 리스트의 인덱스 범위를 검사할 때 `if (i < 0 || i >= length) throw new IndexOutOfBoundsException(...)`을 반복해서 쓰지만, JDK 자체가 내부적으로 쓰는 `Objects.checkIndex(index, length)`가 Java 9부터 공개돼 있다. 한 줄로 검사와 예외 던지기가 끝나고, 반환값이 검증된 인덱스이므로 그대로 대입해서 쓸 수 있다. 배열 슬라이스 검증은 `checkFromToIndex(from, to, length)`, `checkFromIndexSize(from, size, length)`가 짝을 이뤄서 반개구간 검증까지 커버한다.

```java
// Before: 관성적으로 쓰는 코드
public Element get(int index) {
    if (index < 0 || index >= size) {
        throw new IndexOutOfBoundsException("Index: " + index + ", Size: " + size);
    }
    return elements[index];
}

// After: Java 9 표준
public Element get(int index) {
    return elements[Objects.checkIndex(index, size)];
}

// 슬라이스 검증 (buffer.copyRange(from, to) 같은 API)
public byte[] copyRange(int from, int to) {
    Objects.checkFromToIndex(from, to, buffer.length);
    return Arrays.copyOfRange(buffer, from, to);
}

// size 기반 검증 (offset + length 패턴)
public void write(byte[] src, int offset, int length) {
    Objects.checkFromIndexSize(offset, length, src.length);
    // ...
}
```

> 💡 **왜 중요한가**: 인덱스 검증은 컬렉션·버퍼·바이너리 프로토콜 코드 어디에나 나오는데, 손으로 짠 검사는 오프바이원과 메시지 포맷 불일치의 온상이다 — JDK 내부와 동일한 검증 로직을 한 줄로 재사용하면 버그 표면과 코드 라인 수가 동시에 줄어든다.
