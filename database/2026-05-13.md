### 1. PostgreSQL 부분 인덱스(Partial Index) — `WHERE` 절로 필요한 행만 인덱싱하기

`CREATE INDEX ... ON orders (created_at) WHERE status = 'PENDING'` 처럼 인덱스 정의에 조건을 붙이면, 해당 조건을 만족하는 행만 인덱스에 포함된다. "전체 100만 건 중 처리 대기 1만 건만 자주 조회" 같은 패턴에서 인덱스 크기가 1% 수준으로 작아지고, 쓰기 시 인덱스 갱신 비용도 줄어든다. 단, 쿼리의 `WHERE` 조건이 인덱스 조건과 일치(또는 더 좁아야)해야 플래너가 사용한다.

> 💡 **왜 중요한가**: 대부분의 테이블은 "최근/활성/미처리" 같은 소수의 행에 쿼리가 집중되므로, 전체 인덱싱은 디스크와 쓰기 비용 낭비다.

### 2. Spring `@Transactional` 자가 호출(self-invocation) 함정 — 같은 클래스 내 호출은 트랜잭션이 적용되지 않는다

`@Transactional`은 Spring AOP 프록시 기반이라, **외부에서 빈을 통해 호출될 때만** 트랜잭션 인터셉터가 동작한다. 같은 클래스의 `methodA()`가 `this.methodB()`를 호출하면 프록시를 거치지 않으므로 `methodB`의 `@Transactional`이 무시되고, `REQUIRES_NEW`로 분리하려던 의도도 깨진다. 자기 자신을 빈으로 주입받아 호출하거나, 별도 빈으로 분리하거나, `TransactionTemplate`을 직접 쓰는 식으로 우회해야 한다.

> 💡 **왜 중요한가**: "분명히 어노테이션을 붙였는데 롤백이 안 된다"는 버그의 가장 흔한 원인이며, 코드 리뷰로 잡기 어렵고 운영에서 드러난다.
