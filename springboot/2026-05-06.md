### 1. `@TransactionalEventListener(phase = AFTER_COMMIT)`로 커밋 이후 부수 효과 분리하기

`ApplicationEventPublisher`로 도메인 이벤트를 발행하고 리스너에 `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`을 붙이면, 본 트랜잭션이 정상 커밋된 뒤에만 알림 전송·외부 API 호출·캐시 무효화 같은 부수 효과를 실행할 수 있습니다. 일반 `@EventListener`처럼 동기 흐름 안에서 호출되면 롤백 시 외부 시스템과 DB 상태가 어긋나는 문제가 생기는데, 이 어노테이션은 그 시점을 명확히 분리해 줍니다.

> 💡 **왜 중요한가**: 트랜잭션이 롤백되어도 이미 보낸 이메일이나 외부 호출은 되돌릴 수 없으므로, "성공한 거래에 대해서만" 부수 효과를 트리거하는 경계가 안정성의 핵심입니다.

### 2. `MockMvcTester`로 AssertJ 기반 유창한(fluent) 컨트롤러 테스트 작성하기

Spring Framework 6.2(Spring Boot 3.4+)에서 도입된 `MockMvcTester`는 기존 `MockMvc` + `MockMvcResultMatchers` 체이닝을 AssertJ 스타일로 재작성한 API로, `assertThat(mvc.get().uri("/users/{id}", 1)).hasStatusOk().bodyJson().extractingPath("$.name").isEqualTo("Alice")`처럼 IDE 자동완성과 타입 안정성을 살린 단언이 가능합니다. 예외도 `.hasFailed().failure().isInstanceOf(...)`로 직접 검증할 수 있어 try/catch 없이 컨트롤러 예외 흐름을 테스트할 수 있습니다.

> 💡 **왜 중요한가**: 기존 `andExpect(jsonPath(...))` 체인은 문자열 경로와 정적 메서드 의존이 커서 리팩터링·디버깅이 불편했는데, AssertJ 통합으로 테스트 가독성과 실패 메시지 품질이 크게 개선됩니다.
