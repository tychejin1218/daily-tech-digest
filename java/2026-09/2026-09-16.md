### 1. `Collectors.teeing(down1, down2, merger)`로 스트림을 두 번 순회하는 관성 벗어나기 (Java 12 정식)

평균과 합계, 최소·최대 등 같은 스트림에서 두 개의 집계 결과를 뽑아 하나로 합쳐야 할 때, 보통은 리스트로 먼저 모으거나 스트림을 두 번 돌린다. `Collectors.teeing(downstream1, downstream2, BiFunction)`을 쓰면 두 collector에 원소를 동시에 흘려보내고 마지막에 merger로 결합해서 한 번의 순회로 끝난다.

```java
record Stats(double avg, long count) {}

Stats stats = orders.stream()
    .collect(Collectors.teeing(
        Collectors.averagingDouble(Order::amount),
        Collectors.counting(),
        Stats::new
    ));

// 최솟값·최댓값을 한 번에
Range range = numbers.stream()
    .collect(Collectors.teeing(
        Collectors.minBy(Comparator.naturalOrder()),
        Collectors.maxBy(Comparator.naturalOrder()),
        (min, max) -> new Range(min.orElseThrow(), max.orElseThrow())
    ));
```

> 💡 **왜 중요한가**: 스트림을 두 번 돌리는 건 O(2n)이지만 지연 평가·병렬 처리에선 재사용도 안 된다. `teeing`은 한 번의 순회로 두 결과를 뽑아 성능과 가독성을 동시에 챙긴다.

### 2. `String.formatted(args)` 인스턴스 메서드로 `String.format(fmt, args)` 정적 호출 관성 벗어나기 (Java 15 정식)

포매팅 문자열을 로컬 변수나 상수로 뽑아 쓸 때, `String.format(template, args)`는 템플릿이 첫 인자로 들어가 눈이 왼쪽으로 튀는 순서 뒤집힘 문제가 있다. Java 15부터 `String.formatted(args)`가 인스턴스 메서드로 추가되어 텍스트 블록·상수 문자열 뒤에 자연스럽게 붙일 수 있다.

```java
// Before — 템플릿과 인자가 물리적으로 분리됨
String msg = String.format("user=%s, age=%d", name, age);

// After — 템플릿 → 값 순서로 왼→오 읽힘
String msg = "user=%s, age=%d".formatted(name, age);

// 텍스트 블록과 궁합이 특히 좋음
String query = """
    SELECT *
      FROM users
     WHERE id = %d
       AND status = '%s'
    """.formatted(userId, status);
```

> 💡 **왜 중요한가**: 텍스트 블록 시대에 SQL·JSON·로그 템플릿이 길어질수록 `String.format(..., args)` 패턴은 스크롤을 강요한다. `.formatted()`는 템플릿을 앞에 두고 값을 뒤에 붙이는 인간의 읽기 순서를 지켜준다.
