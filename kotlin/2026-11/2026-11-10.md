### 1. `Flow` vs `LiveData` vs `StateFlow`: "스트림의 시대"에 살아남는 3가지 선택지

Kotlin `Flow`는 "콜드 스트림"으로, collect 하는 순간부터 값을 발행하며 백프레셔와 취소를 자동으로 처리한다. `StateFlow`는 항상 최신 상태 하나를 보관하는 "핫 스트림"으로 UI 상태 관리에 최적이고, `LiveData`는 Android 생명주기와 결합된 레거시 선택지다. Spring WebFlux나 Android UI 레이어에서 "값의 흐름"을 다룰 때, 콜드/핫, 생명주기 인식, 멀티 구독 여부를 기준으로 셋 중 하나를 고른다.

```kotlin
// ❌ 매번 새로 발행 — 구독자마다 다른 스트림 (콜드)
val priceFlow: Flow<Int> = flow {
    emit(fetchPrice()) // 구독할 때마다 API 호출
}

// ✅ 최신 값 하나를 공유 — UI 상태에 적합 (핫)
class PriceViewModel : ViewModel() {
    private val _price = MutableStateFlow(0)
    val price: StateFlow<Int> = _price.asStateFlow()

    fun refresh() = viewModelScope.launch {
        _price.value = fetchPrice() // 모든 구독자가 즉시 받음
    }
}

// Spring WebFlux에서 Flow 반환 — Reactor Flux로 자동 변환
@GetMapping("/prices")
fun prices(): Flow<Price> = priceRepository.findAllAsFlow()
```

| 구분 | Flow | StateFlow | LiveData |
|------|------|-----------|----------|
| 타입 | Cold | Hot | Hot |
| 초기값 | 없음 | 필수 | 선택 |
| 생명주기 | 수동 (`repeatOnLifecycle`) | 수동 | 자동 |
| 용도 | 일회성 데이터 스트림 | UI 상태 | Android UI 상태 (레거시) |

> 💡 **왜 중요한가**: "RxJava 시대"는 끝났고, Kotlin 네이티브 스트림 생태계(Flow/StateFlow)가 표준이 되었다 — 새 프로젝트에서 LiveData를 쓰고 있다면 그 자체가 기술 부채다.

### 2. `operator fun`: 연산자 오버로딩으로 DSL을 만드는 Kotlin의 "숨겨진 설계 도구"

Kotlin은 `+`, `-`, `[]`, `()`, `in`, `..` 등을 `operator fun` 키워드로 오버로딩할 수 있다. Scala처럼 임의의 기호를 만들 수는 없지만 — 미리 정해진 "컨벤션 함수명"(plus, minus, get, invoke, contains, rangeTo)을 구현하면 연산자 문법을 쓸 수 있다. 이게 바로 Kotlin DSL(Gradle KTS, Ktor, Exposed)이 자연어처럼 읽히는 비결이다.

```kotlin
// ❌ Java 스타일 — 메서드 호출이 노이즈
val total = money1.plus(money2).multiply(BigDecimal(1.1))

// ✅ Kotlin — 연산자 오버로딩
data class Money(val amount: BigDecimal, val currency: String) {
    operator fun plus(other: Money): Money {
        require(currency == other.currency) { "통화 불일치" }
        return Money(amount + other.amount, currency)
    }
    operator fun times(rate: BigDecimal) = copy(amount = amount * rate)
}

val total = money1 + money2 * BigDecimal("1.1") // 자연스러운 수식

// invoke 연산자 — 객체를 함수처럼 호출
class EmailValidator {
    operator fun invoke(email: String): Boolean = email.contains("@")
}
val isValid = EmailValidator()
if (isValid("foo@bar.com")) { /* ... */ } // 객체를 함수처럼!

// contains 연산자 — in 키워드 지원
class DateRange(val start: LocalDate, val end: LocalDate) {
    operator fun contains(date: LocalDate) = date in start..end
}
if (today in dateRange) { /* ... */ }
```

| 연산자 | 함수명 | 예시 |
|--------|--------|------|
| `+`, `-` | `plus`, `minus` | `a + b` |
| `*`, `/` | `times`, `div` | `a * b` |
| `[]` | `get`, `set` | `map["key"]` |
| `()` | `invoke` | `obj()` |
| `in` | `contains` | `x in range` |
| `..` | `rangeTo` | `1..10` |
| `==` | `equals` | 자동 (data class) |

> 💡 **왜 중요한가**: 연산자 오버로딩은 "장난감 기능"이 아니라 도메인 모델을 자연어처럼 읽히게 만드는 설계 무기다 — Money, Vector, Duration 같은 값 타입을 다룰 때 코드 가독성이 10배 뛴다. 단, 남용하면 "`+`가 뭘 하는지 모르는 코드"가 되므로, 수학적/직관적 의미가 명확할 때만 써라.
