### 1. `Optional.orElseThrow()`로 값 없을 때 명시적 예외 던지기 (Java 10 정식)

`Optional`에서 값이 없을 때 예외를 던지고 싶다면 `orElseThrow()`를 인자 없이 호출하면 `NoSuchElementException`이 자동으로 발생합니다. Java 8의 `get()`은 이름만 봐서는 예외 가능성이 드러나지 않지만, `orElseThrow()`는 메서드 이름 자체가 "값이 없으면 예외"라는 의도를 명확히 표현합니다. IntelliJ와 SonarQube도 `get()` 사용에 대해 경고를 띄우기 때문에 팀 컨벤션으로 `orElseThrow()`를 강제하는 것이 좋습니다.

```java
// Before (Java 8, 의도 불명확 + IDE 경고)
User user = userRepository.findById(id).get();

// After (Java 10, 의도 명확)
User user = userRepository.findById(id).orElseThrow();

// 커스텀 예외를 던지고 싶다면
User user = userRepository.findById(id)
    .orElseThrow(() -> new UserNotFoundException(id));
```

> 💡 **왜 중요한가**: `get()`은 `NPE`처럼 "존재를 확신했는데 없더라" 버그의 온상이지만, `orElseThrow()`는 코드 리뷰에서 "여기서 예외가 날 수 있다"를 즉시 인지시켜 방어 코드 위치를 자연스럽게 유도합니다.

### 2. `Map.entry(K, V)`로 불변 맵 초기화 시 가독성 확보하기 (Java 9 정식)

`Map.of()`는 최대 10개 엔트리까지만 지원하고, 그 이상은 `Map.ofEntries(Map.entry(...), ...)`를 써야 합니다. `new AbstractMap.SimpleEntry<>()`나 `new HashMap<>() {{ put(...); }}` (이중 중괄호 초기화) 대비 훨씬 간결하고, 반환되는 `Map.Entry`는 불변이라 리스트로 모아 스트림 파이프라인에 넘겨도 안전합니다. Spring의 설정 상수 맵, 코드-메시지 매핑 테이블 같은 곳에서 특히 유용합니다.

```java
// Before (이중 중괄호 초기화 - 익명 클래스로 메모리 릭 위험)
Map<String, Integer> priorities = new HashMap<>() {{
    put("HIGH", 1);
    put("MEDIUM", 2);
    put("LOW", 3);
}};

// After (Java 9, 불변 + 간결)
Map<String, Integer> priorities = Map.ofEntries(
    Map.entry("HIGH", 1),
    Map.entry("MEDIUM", 2),
    Map.entry("LOW", 3),
    Map.entry("CRITICAL", 0)  // 10개 넘어도 OK
);

// 스트림과 조합
Map<String, Integer> result = Stream.of(rawData)
    .map(d -> Map.entry(d.getCode(), d.getValue()))
    .collect(Collectors.toUnmodifiableMap(Entry::getKey, Entry::getValue));
```

> 💡 **왜 중요한가**: 이중 중괄호 초기화(`{{ put(...); }}`)는 익명 내부 클래스를 생성해 외부 인스턴스 참조를 유지하기 때문에 GC를 방해할 수 있는데, `Map.entry()`는 이 함정을 완전히 피하면서 불변성까지 공짜로 얻습니다.
