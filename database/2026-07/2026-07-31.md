### MySQL `Invisible Index` — 인덱스를 지우지 않고 "숨겨서" 실제 영향 검증하기

MySQL 8.0의 `ALTER TABLE ... ALTER INDEX idx_name INVISIBLE`는 옵티마이저에게만 인덱스를 감추고 물리적으로는 유지한다. `DROP INDEX` 후 문제가 생기면 재생성에 수 시간이 걸리지만, Invisible Index는 즉시 다시 `VISIBLE`로 되돌릴 수 있어 "이 인덱스 정말 필요한가?"를 프로덕션에서 안전하게 실험할 수 있다.

```sql
-- 1) 인덱스를 숨겨서 옵티마이저가 못 보게 함 (물리적으로는 존재)
ALTER TABLE orders ALTER INDEX idx_customer_created INVISIBLE;

-- 2) 애플리케이션 쿼리들의 실행 계획·응답 시간 모니터링
-- 슬로우 쿼리 로그, performance_schema.events_statements_summary_by_digest 확인

-- 3-a) 문제 없으면 진짜 삭제
ALTER TABLE orders DROP INDEX idx_customer_created;

-- 3-b) 특정 쿼리가 느려지면 즉시 복구 (재빌드 없이 1초 내)
ALTER TABLE orders ALTER INDEX idx_customer_created VISIBLE;

-- 특정 세션에서만 invisible 인덱스를 다시 보게 하려면
SET SESSION optimizer_switch = 'use_invisible_indexes=on';
```

내부적으로 인덱스는 여전히 INSERT/UPDATE 시 유지되기 때문에 쓰기 비용은 그대로다. 따라서 최종 목적은 언제나 `DROP`이어야 하고, Invisible 상태는 "검증 창"으로만 짧게 사용해야 한다.

> 💡 **왜 중요한가**: "안 쓰는 것 같은데 지우기 무섭다"는 인덱스를 롤백 비용 없이 실증적으로 검증할 수 있는 유일한 안전장치다.

### PostgreSQL `FILLFACTOR` — HOT Update를 유도해 인덱스 부풀기(Bloat) 원천 차단하기

PostgreSQL은 UPDATE 시 새 튜플을 만들고 기존 튜플을 dead로 표시하는데, 인덱싱된 컬럼이 변경되지 않고 같은 페이지에 여유 공간이 있으면 **HOT(Heap-Only Tuple) Update**로 처리되어 인덱스를 건드리지 않는다. `FILLFACTOR`를 낮춰(예: 90 → 70) 페이지에 의도적으로 여유를 남기면 HOT 비율이 극적으로 올라가 인덱스 bloat와 VACUUM 부담이 함께 줄어든다.

```sql
-- UPDATE가 잦은 테이블은 fillfactor를 낮춰서 페이지에 여유 확보
ALTER TABLE user_sessions SET (fillfactor = 70);

-- 인덱스 자체에도 별도 fillfactor 설정 가능 (B-Tree 기본 90)
ALTER INDEX idx_sessions_user_id SET (fillfactor = 80);

-- 재작성해서 새 fillfactor 적용
VACUUM FULL user_sessions;  -- 또는 pg_repack로 무중단 재작성

-- HOT Update가 얼마나 발생하는지 확인
SELECT relname,
       n_tup_upd,
       n_tup_hot_upd,
       ROUND(100.0 * n_tup_hot_upd / NULLIF(n_tup_upd, 0), 2) AS hot_ratio_pct
FROM pg_stat_user_tables
WHERE relname = 'user_sessions';
```

트레이드오프는 명확하다 — 페이지가 덜 꽉 차므로 테이블 크기가 커지고 순차 스캔이 약간 느려진다. INSERT-only 로그 테이블은 `fillfactor=100`이 옳고, `last_login_at` 같은 컬럼이 계속 갱신되는 세션·카운터 테이블에서만 60~80으로 낮추는 게 정답이다.

> 💡 **왜 중요한가**: UPDATE 폭풍을 맞는 테이블의 인덱스 bloat 문제는 90%가 fillfactor 하나로 해결되는데, 대부분의 팀이 기본값 100을 그대로 두고 매주 REINDEX로 응급처치를 반복한다.
