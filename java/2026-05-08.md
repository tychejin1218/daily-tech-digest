### 1. `Files.mismatch()`로 두 파일의 내용 차이를 효율적으로 비교하기 (Java 12 정식)

Java 12부터 추가된 `Files.mismatch(Path, Path)`는 두 파일을 바이트 단위로 비교해 처음으로 다른 위치(byte index)를 반환하며, 완전히 동일하면 `-1`을 반환합니다. 파일 전체를 메모리에 읽어 들이거나 해시를 계산할 필요 없이 내부적으로 버퍼링된 스트림으로 비교하므로 대용량 파일에도 안전하게 사용할 수 있습니다.

```java
long diffPos = Files.mismatch(Path.of("a.bin"), Path.of("b.bin"));
if (diffPos == -1L) {
    System.out.println("두 파일은 동일합니다.");
} else {
    System.out.println(diffPos + " 바이트 위치에서 차이 발생");
}
```

> 💡 **왜 중요한가**: 배포 산출물 검증, 백업 무결성 확인, 테스트 골든파일 비교 등에서 외부 라이브러리 없이 표준 API만으로 안전하고 빠르게 동등성을 판별할 수 있습니다.

### 2. `Thread.startVirtualThread()` 대신 가상 스레드 기반 `ExecutorService`로 구조화된 라이프사이클 관리하기 (Java 21 정식)

가상 스레드를 즉석에서 띄우는 `Thread.startVirtualThread(...)`는 편리하지만 실패 처리·취소·완료 대기를 직접 구현해야 합니다. `Executors.newVirtualThreadPerTaskExecutor()`를 try-with-resources로 사용하면 블록 종료 시 자동으로 모든 작업의 완료를 기다리고, `Future`를 통해 예외 전파와 결과 수집이 일관되게 처리됩니다.

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<String>> results = urls.stream()
        .map(url -> executor.submit(() -> fetch(url)))
        .toList();
    for (var f : results) {
        System.out.println(f.get()); // 예외는 ExecutionException으로 전파
    }
} // 블록 종료 시 모든 가상 스레드 완료 대기
```

> 💡 **왜 중요한가**: 가상 스레드의 경량성 이점을 누리면서도 누수·미처리 예외·좀비 작업 같은 동시성 운영 리스크를 표준 ExecutorService 모델로 방지할 수 있습니다.
