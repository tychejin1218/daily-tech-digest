### 1. `Files.mismatch(Path, Path)`로 두 파일이 같은지 바이트 단위로 한 줄에 비교하기 (Java 12 정식)

두 파일의 내용이 동일한지 확인할 때 예전에는 `MessageDigest`로 해시를 뽑거나 스트림을 열어 바이트를 하나씩 비교하는 코드를 직접 짜야 했다. `Files.mismatch(Path, Path)`는 두 파일에서 처음으로 달라지는 바이트의 오프셋(같으면 `-1L`)을 돌려주기 때문에 `Files.mismatch(a, b) == -1L` 한 줄로 동등성 판정을 끝낼 수 있고, 내부적으로 크기 비교 → 버퍼드 비교 순으로 최적화되어 있어 큰 파일도 빠르다.

```java
if (Files.mismatch(expected, actual) == -1L) {
    log.info("두 파일 내용 일치");
} else {
    long pos = Files.mismatch(expected, actual);
    log.warn("바이트 {} 위치에서 불일치", pos);
}
```

> 💡 **왜 중요한가**: 배포 산출물 검증, 백업 무결성 확인, 스냅샷 테스트 같은 곳에서 "같은 파일인가?"를 판정하는 표준 API가 생겼다는 뜻이다. 해시 라이브러리 의존이나 자체 비교 루프 없이도 정확하고 성능도 안전하게 확보된다.

### 2. `switch` 표현식과 화살표(`->`) 문법으로 fall-through와 예외 처리 흔적 없애기 (Java 14 정식)

전통적인 `switch` 문은 `break`를 빼먹으면 아래 `case`로 흘러 내려가는(fall-through) 버그가 나기 쉽고, 값을 반환하려면 임시 변수를 선언해 각 `case`에서 대입해야 했다. Java 14부터 정식이 된 화살표 스타일 `switch` 표현식은 값 자체를 반환하고, 여러 라벨을 콤마로 묶을 수 있으며, 컴파일러가 모든 케이스 커버 여부를 검사하기 때문에 `enum`이나 sealed 타입에서 특히 안전하다.

```java
int daysInMonth = switch (month) {
    case JAN, MAR, MAY, JUL, AUG, OCT, DEC -> 31;
    case APR, JUN, SEP, NOV               -> 30;
    case FEB -> year.isLeap() ? 29 : 28;
};
```

블록이 필요하면 `case X -> { ... yield 값; }`로 `yield` 키워드를 쓴다. `return`이 아니라 `yield`인 이유는 메서드 반환이 아니라 표현식의 값을 지정하기 때문이다.

> 💡 **왜 중요한가**: 상태 기계, 응답 코드 매핑, DTO 변환처럼 "입력에 따라 값 하나를 고르는" 코드에서 실수 여지를 원천 차단한다. 특히 sealed 인터페이스와 결합하면 새 하위 타입이 추가됐을 때 컴파일 에러로 누락을 알려주므로 도메인 확장에 강해진다.
