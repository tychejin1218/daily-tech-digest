### 1. `HashMap.newHashMap(int)` 계열 팩토리로 리사이즈 없이 정확한 초기 용량 지정하기 (Java 19 정식)
기존에는 `new HashMap<>(expectedSize)`를 써도 내부 임계치(load factor 0.75) 때문에 예상 항목 수의 약 1.33배를 직접 계산해야 리사이즈를 피할 수 있었습니다. Java 19부터 `HashMap.newHashMap(n)`, `LinkedHashMap.newLinkedHashMap(n)`, `HashSet.newHashSet(n)` 등이 제공되어 “이만큼의 엔트리를 담아도 재해싱이 일어나지 않는” 용량을 라이브러리가 알아서 계산해줍니다.

```java
// Before: 직접 계산해야 했음
Map<String, User> m = new HashMap<>((int) (10_000 / 0.75f) + 1);

// After (Java 19+)
Map<String, User> m = HashMap.newHashMap(10_000);
```

> 💡 **왜 중요한가**: 대용량 맵을 미리 채울 때 불필요한 리사이즈/재해싱 비용을 제거하면서 의도가 코드에 명확히 드러납니다.

### 2. `Collectors.filtering()`과 `Collectors.flatMapping()`으로 `groupingBy` 다운스트림에서 필터·평탄화하기 (Java 9 정식)
`groupingBy` 후 스트림에서 다시 `filter`/`flatMap`을 호출하면 빈 그룹이 사라지거나 두 번 순회하게 됩니다. 다운스트림 컬렉터인 `Collectors.filtering()`은 키는 유지하면서 값만 걸러내고, `Collectors.flatMapping()`은 각 요소를 스트림으로 펼친 결과를 그룹별로 모아줍니다.

```java
// 부서별로 급여 50k 초과 직원만 모으되, 비어 있는 부서도 빈 리스트로 보존
Map<Dept, List<Employee>> byDept = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::dept,
        Collectors.filtering(e -> e.salary() > 50_000, Collectors.toList())
    ));

// 주문별 라인아이템을 고객 단위로 평탄화
Map<Customer, List<LineItem>> byCustomer = orders.stream()
    .collect(Collectors.groupingBy(
        Order::customer,
        Collectors.flatMapping(o -> o.lineItems().stream(), Collectors.toList())
    ));
```

> 💡 **왜 중요한가**: 그룹화 전 `filter`/`flatMap`은 키 자체를 잃게 만들지만, 다운스트림 컬렉터를 쓰면 그룹 구조를 보존한 채 한 번의 순회로 집계할 수 있습니다.
