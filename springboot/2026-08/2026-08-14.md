### `@PostConstruct`는 프록시가 아직 완성되기 전에 호출되어 `@Transactional`, `@Async`가 동작하지 않는다

`@PostConstruct`는 빈 초기화 직후 실행되지만, 이 시점에는 AOP 프록시가 완전히 감싸지지 않아 트랜잭션이나 비동기 어드바이스가 적용되지 않는다. 초기 데이터 로딩을 트랜잭션 안에서 하고 싶다면 `ApplicationRunner`, `CommandLineRunner`, 또는 `ApplicationReadyEvent` 리스너를 사용해야 한다. `TransactionTemplate`을 직접 주입해 프로그래밍 방식으로 트랜잭션을 여는 것도 대안이다.

```java
// ❌ 트랜잭션이 시작되지 않음 - 프록시 우회
@Component
public class DataInitializer {
    @PostConstruct
    @Transactional
    public void init() {
        userRepository.save(new User("admin")); // TransactionRequiredException 위험
    }
}

// ✅ ApplicationReadyEvent - 컨텍스트 완전 초기화 후 실행
@Component
@RequiredArgsConstructor
public class DataInitializer {
    private final UserService userService;

    @EventListener(ApplicationReadyEvent.class)
    public void init() {
        userService.createAdminIfNotExists(); // 여기서 @Transactional 정상 동작
    }
}
```

> 💡 **왜 중요한가**: "왜 초기화 로직에서 lazy loading 예외가 나지?"의 90%는 `@PostConstruct` 안에서 프록시가 우회되기 때문이며, 이 시점을 잘못 알면 데이터 정합성 문제까지 이어진다.

### Jackson의 `@JsonIgnore`는 시리얼라이즈만 막을 뿐 역직렬화는 여전히 통과시킨다

`@JsonIgnore`를 필드에 붙이면 응답에서는 제거되지만, 요청 바디에서 해당 필드를 그대로 넣으면 그대로 매핑되어 들어온다. 이는 Mass Assignment 취약점의 전형적인 패턴으로, 예를 들어 `role` 필드에 `@JsonIgnore`만 붙였다면 클라이언트가 `{"role": "ADMIN"}`을 보내면 그대로 저장된다. 방향을 명시하려면 `@JsonProperty(access = Access.READ_ONLY)`(응답에만 노출)나 `WRITE_ONLY`(요청에서만 받음)를 써야 한다.

```java
// ❌ 취약 - PATCH /users/1 { "role": "ADMIN" } 요청이 그대로 통과
public class UserDto {
    private String name;

    @JsonIgnore // 응답에는 안 나가지만 요청은 받아들임
    private String role;
}

// ✅ 방향을 명시적으로 지정
public class UserDto {
    private String name;

    @JsonProperty(access = JsonProperty.Access.READ_ONLY)
    private String role; // 응답에만 노출, 요청 바디에서는 무시

    @JsonProperty(access = JsonProperty.Access.WRITE_ONLY)
    private String password; // 요청에서만 받고 응답에는 절대 안 나감
}
```

| 어노테이션 | 직렬화(응답) | 역직렬화(요청) |
|---|---|---|
| `@JsonIgnore` | ❌ 제외 | ❌ 제외 (혼동됨, 실제로는 통과) |
| `Access.READ_ONLY` | ✅ 포함 | ❌ 무시 |
| `Access.WRITE_ONLY` | ❌ 제외 | ✅ 받음 |

> 💡 **왜 중요한가**: DTO 하나 잘못 설계하면 권한 상승(privilege escalation) 취약점이 API 전면에 열리는데, `@JsonIgnore`의 이름이 너무 강해서 안전하다고 착각하는 개발자가 절대 다수다.
