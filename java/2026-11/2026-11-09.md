### 1. `Stream.toList()` (Java 16 정식, JEP 361)로 스트림 결과를 바로 리스트로 — `stream.collect(Collectors.toList())` 관성 벗어나기

스트림을 리스트로 수집할 때 `collect(Collectors.toList())`는 **수정 가능한(mutable) ArrayList**를 반환하지만, `Stream.toList()`는 **수정 불가능한(unmodifiable) List**를 바로 돌려준다. 코드도 짧아지고, 호출자가 실수로 추가/삭제하는 사고를 타입 수준에서 막을 수 있어 방어적 복사를 한 번 더 할 필요가 없다.

```java
// ❌ 관성: 컬렉터 임포트 + 가변 리스트 반환 → 외부에서 변경 위험
import static java.util.stream.Collectors.toList;

List<String> names = users.stream()
    .map(User::getName)
    .filter(Objects::nonNull)
    .collect(toList());  // ArrayList — add/remove 가능

names.add("악의적 추가");  // ✅ 컴파일/런타임 모두 통과

// ✅ Stream.toList(): 임포트 불필요 + 불변 리스트 보장
List<String> names = users.stream()
    .map(User::getName)
    .filter(Objects::nonNull)
    .toList();

names.add("악의적 추가");  // ❌ UnsupportedOperationException
```

주의: `null` 요소는 허용한다는 점은 `toUnmodifiableList()`와 다르다 (`toUnmodifiableList()`는 NPE). 그래서 `.filter(Objects::nonNull)`을 쓰지 않은 스트림에 `null`이 섞일 가능성이 있다면 `toList()`가 더 유연하다.

> 💡 **왜 중요한가**: `.collect(toList())`가 돌려주는 가변 리스트는 "DTO 응답을 받은 쪽이 리스트에 add()를 해서 캐시가 오염되는" 전형적인 사고의 근원이고, `Stream.toList()`는 코드도 짧고 안전하기까지 하다.

### 2. `switch` 패턴 매칭 + `null case` (Java 21 정식, JEP 441)로 `null` 처리 — `if (obj == null) return ...; switch (obj) { ... }` 두 단계 분기 관성 벗어나기

전통적으로 `switch`는 `null`을 던지면 `NullPointerException`이 났기 때문에, `switch` 전에 반드시 `null` 체크를 따로 해야 했다. Java 21부터는 `case null`을 `switch` 안에 직접 쓸 수 있고, `case null, default ->`로 묶어 "null이거나 알 수 없는 타입"을 한 가지 가지로 통합할 수도 있다.

```java
// ❌ 관성: null 체크를 switch 밖에서 선행 — 분기가 두 겹
String describe(Object obj) {
    if (obj == null) return "없음";
    return switch (obj) {
        case Integer i -> "정수: " + i;
        case String s  -> "문자열: " + s;
        default        -> "기타";
    };
}

// ✅ null case를 switch 안으로 흡수 — 패턴 하나로 일관 분기
String describe(Object obj) {
    return switch (obj) {
        case null      -> "없음";
        case Integer i -> "정수: " + i;
        case String s  -> "문자열: " + s;
        default        -> "기타";
    };
}

// ✅ null과 default를 하나로 묶기 — "모르거나 없음"을 한 가지로
String describe(Object obj) {
    return switch (obj) {
        case Integer i        -> "정수: " + i;
        case String s         -> "문자열: " + s;
        case null, default    -> "알 수 없음";
    };
}
```

주의: `case null`을 넣지 않은 `switch`에 `null`이 들어오면 여전히 `NullPointerException`이다 — 즉 이전 코드와의 호환성은 깨지지 않는다. "null도 받을 수 있는 switch"로 바뀐 게 아니라 "null도 명시적으로 처리할 수 있는 switch"가 된 것.

> 💡 **왜 중요한가**: 도메인 객체가 null일 수 있을 때 바깥 `if (obj == null)`와 안쪽 `switch`가 따로 노는 "분기 두 겹" 구조는 분기 추가 시 두 곳을 모두 건드리게 만들고, `case null` 한 줄은 그 중복을 없애면서 "이 switch는 null도 고려했다"는 의도를 코드에 박아둔다.
