### `MethodHandle`과 `VarHandle`로 리플렉션보다 빠른 동적 멤버 접근 구현하기 (Java 9 정식)

`java.lang.invoke.MethodHandles.Lookup`으로 메서드 핸들을 얻거나 `VarHandle`로 필드·배열 원소에 접근하면, 기존 `java.lang.reflect` API보다 훨씬 가벼운 비용으로 동적 호출을 할 수 있습니다. JIT가 인라이닝 친화적인 형태로 최적화할 수 있어 핫 패스에서 거의 직접 호출 수준의 성능이 나오고, `VarHandle`은 `getAcquire`/`setRelease`/`compareAndSet` 같은 메모리 순서 옵션까지 제공해 `sun.misc.Unsafe`를 안전하게 대체합니다.

> 💡 **왜 중요한가**: 프레임워크·직렬화 라이브러리에서 리플렉션을 남발하면 성능 병목이 생기는데, `MethodHandle`/`VarHandle`은 동일한 동적 유연성을 유지하면서도 JIT 최적화 대상이 되어 부하를 크게 줄여줍니다.

### `JEP 491: Synchronize Virtual Threads without Pinning`으로 `synchronized` 블록 안에서도 가상 스레드 마운트 해제 (Java 24 정식)

Java 21 가상 스레드에서는 `synchronized` 블록 내부에서 블로킹 호출이 일어나면 캐리어 스레드에 핀(pin)되어 스케일링이 막히는 문제가 있었지만, Java 24부터는 `synchronized`도 일반 블로킹 연산처럼 캐리어를 점유하지 않고 마운트를 해제합니다. 이제 기존 락 코드를 `ReentrantLock`으로 굳이 갈아엎지 않아도 가상 스레드 위에서 안전하게 확장할 수 있습니다.

> 💡 **왜 중요한가**: 레거시 라이브러리(JDBC 드라이버, 로깅 프레임워크 등)는 내부적으로 `synchronized`를 많이 쓰는데, 이 변경으로 별도 수정 없이 가상 스레드 기반 서버에서 처리량을 끌어올릴 수 있습니다.
