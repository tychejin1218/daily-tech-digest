### 1. AWS OpenSearch Serverless NextGen 정식 출시 — "에이전트 워크로드 위해 처음부터 다시 설계"
Amazon이 기존 OpenSearch Serverless의 아키텍처를 폐기하고, AI 에이전트 트래픽 패턴(급격한 버스트 + 긴 아이들)에 맞춰 재설계한 차세대 서비스를 GA로 공개했다. 10분간 유휴 상태이면 컴퓨트가 0으로 스케일다운되고, 트래픽 재개 시 약 10초 만에 복귀하며, 오토스케일 속도는 20배 개선, 피크 대비 최대 60% 비용 절감을 보장한다. Vercel·Kiro 같은 AI 개발 플랫폼과 네이티브로 연동돼 인프라 관리 없이 에이전트용 벡터 백엔드를 붙일 수 있다.

> 💡 **왜 중요한가**: RAG·에이전트용 벡터 스토어를 "쓰는 만큼만 낸다"는 원칙으로 처음 실현한 매니지드 옵션이라, 사이드 프로젝트에서도 프로덕션급 벡터 검색을 부담 없이 얹을 수 있다.

### 2. Google GKE Labs, 'OpenRL' 오픈소스 공개 — 쿠버네티스 위에서 LLM 파인튜닝을 표준화
Google이 자체 K8s 클러스터에서 LLM 사후 학습(post-training)과 파인튜닝을 실행하는 셀프호스트 API `OpenRL`을 공개했다. Thinking Machines의 Tinker 설계 패턴을 채택해 4개의 API로 RL 루프를 표준화했고, 개발자는 Mac에서 로컬로 테스트한 뒤 동일 코드를 GKE 엔드포인트로 스위치해 GPU 클러스터로 스케일할 수 있다. 초기 버전은 LoRA 기반 튜닝에 집중되며, 인프라 엔지니어와 AI 리서처가 서로 병목이 되지 않도록 레이어를 분리한 게 설계 철학이다.

> 💡 **왜 중요한가**: "튜닝 파이프라인은 각자 알아서 만든다"는 관행에서 벗어나, 오픈웨이트 모델의 K8s 네이티브 튜닝 표준을 노리는 첫 벤더 프로젝트다.

### 3. Google Cloud 'Australia API Horizon' 멜버른 개최 — Apigee가 AI Gateway로 재정의되는 날
오늘(2026-08-04) Google 멜버른에서 열리는 API Horizon 이벤트는 Apigee를 "거버넌스가 걸린 AI 에이전트를 위한 지능형 게이트웨이"로 공식 재포지셔닝한다. 기존 REST API를 MCP 도구로 자동 변환하고, 토큰 예산·PII 필터·감사 로그·레이트 리미트를 API 게이트웨이 계층에서 강제하는 아키텍처 청사진이 핵심 세션이다. 챗봇에서 자율 에이전트로 넘어가는 시점에 "가장 중요한 통합 지점은 게이트웨이"라는 게 Google의 베팅이다.

> 💡 **왜 중요한가**: 에이전트가 "혼자 노는 SDK"에서 "회사 정책이 걸린 API 게이트웨이 뒤에서만 돌아가는 시민"으로 강제 이동하는 신호로, 엔터프라이즈 도입의 병목이 모델이 아니라 거버넌스임을 재확인한다.
