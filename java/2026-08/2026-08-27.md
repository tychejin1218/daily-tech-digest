### 1. `Deque<E>`를 `Stack` 대신 사용해서 레거시 동기화 오버헤드 벗어나기

`java.util.Stack`은 `Vector`를 상속받아 모든 메서드가 `synchronized`로 묶여 있는 레거시 클래스라, 단일 스레드 환경에서도 불필요한 락 획득 비용을 계속 지불합니다. `Deque<Integer> stack = new ArrayDeque<>();`로 선언하고 `push()`, `pop()`, `peek()`를 그대로 쓰면 동일한 LIFO 시맨틱을 얻으면서 훨씬 빠릅니다. Java 공식 문서(`Deque` Javadoc)에서도 `Stack` 클래스보다 `Deque` 인터페이스 사용을 명시적으로 권장합니다.

> 💡 **왜 중요한가**: DFS 알고리즘이나 파서처럼 스택 연산이 뜨거운 루프에 들어가면, 락 오버헤드만 걷어내도 처리량이 눈에 띄게 올라간다.

### 2. `record` 패턴으로 중첩된 데이터 구조를 한 번에 분해하기 (Java 21 정식)

`switch`나 `instanceof`와 결합하는 record 패턴은 `if (obj instanceof Point p && p.x() == 0)` 같은 단계별 접근을 `if (obj instanceof Point(int x, int y) && x == 0)`처럼 한 번에 분해합니다. 중첩된 record도 `case Rectangle(Point(int x1, int y1), Point(int x2, int y2)) -> ...`처럼 계층을 따라 그대로 풀어낼 수 있어, 도메인 이벤트나 AST를 다룰 때 boilerplate가 극적으로 줄어듭니다. Sealed 인터페이스와 조합하면 컴파일러가 exhaustiveness까지 검증해 줍니다.

> 💡 **왜 중요한가**: 이벤트 소싱이나 표현식 트리처럼 "타입 판별 → 필드 꺼내기 → 분기" 흐름이 반복되는 코드에서, 패턴 매칭 하나로 방문자 패턴이나 getter 체이닝을 대체할 수 있다.
