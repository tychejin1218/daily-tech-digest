### 1. `java.util.random.RandomGeneratorFactory.of("L64X128MixRandom").create(seed)` (Java 17 정식, JEP 356)로 용도별 난수 알고리즘 선택하기 — `new Random(seed)` 하나로 보안·시뮬레이션·게임 다 돌려쓰는 관성 벗어나기

`java.util.Random`은 48비트 선형 합동 생성기(LCG)로, 멀티스레드 환경에서 `AtomicLong` CAS 경합이 심하고 통계적 품질도 낮다. Java 17부터는 `RandomGenerator` 인터페이스 아래 L64X128Mix(범용), Xoshiro256++(고속), L128X1024Mix(장주기 시뮬레이션) 등 알고리즘을 이름으로 골라 쓸 수 있고, `jumpableGenerator()`로 병렬 스트림에 서로 겹치지 않는 서브시퀀스를 안전하게 분배할 수 있다. 몬테카를로 시뮬레이션에서 1000개 워커가 `ThreadLocalRandom`을 공유하는 대신 `SplittableGenerator.splits()`로 독립 스트림을 쪼개면 재현성도 유지된다.

```java
// Before: 어떤 알고리즘인지도 모르고 쓰는 Random
Random r = new Random(42L);
double sample = r.nextGaussian();

// After: 용도를 선언하고 품질을 선택
RandomGenerator rng = RandomGeneratorFactory.of("L64X128MixRandom").create(42L);
double sample = rng.nextGaussian();

// 병렬 시뮬레이션: 겹치지 않는 서브시퀀스 분배
SplittableGenerator parent = (SplittableGenerator)
    RandomGeneratorFactory.of("L64X128MixRandom").create(42L);
parent.splits(1000)
    .parallel()
    .mapToDouble(gen -> monteCarloTrial(gen))
    .average();
```

> 💡 **왜 중요한가**: `new Random()`은 "난수가 필요하다"는 말일 뿐 "어떤 품질의 어떤 알고리즘"이라는 설계 결정을 숨긴다 — 보안엔 `SecureRandom`, 시뮬레이션엔 장주기 분할 가능 생성기를 명시적으로 고르는 게 2017년 이후의 기본값이다.

### 2. `Collectors.filtering(predicate, downstream)` (Java 9 정식)로 `groupingBy` 안에서 조건부 집계하기 — 바깥 `stream.filter()`로 먼저 걸러 빈 그룹 자체가 사라지는 관성 벗어나기

`stream.filter(cond).collect(groupingBy(key))`로 쓰면 조건에 안 맞는 원소뿐 아니라 **그룹 자체가 결과 맵에서 빠진다**. 예를 들어 부서별 "30대 이상 사원 수"를 집계할 때 30대 이상이 없는 부서는 아예 키조차 없어져서 UI에서 "0명"으로 표시할 방법이 사라진다. `Collectors.filtering`을 downstream collector 위치에 쓰면 그룹핑은 전체 원소로 하고 집계만 조건부로 적용돼서, 빈 그룹도 `0`이나 `[]`로 남는다.

```java
// Before: 30대 이상이 한 명도 없는 부서는 결과 맵에서 증발
Map<String, Long> seniorByDept = employees.stream()
    .filter(e -> e.age() >= 30)
    .collect(groupingBy(Employee::dept, counting()));
// {"개발팀": 5, "영업팀": 3}  ← 디자인팀이 없다! 0명인지 부서가 없는 건지 모름

// After: 모든 부서가 남고, 조건에 맞는 원소만 집계
Map<String, Long> seniorByDept = employees.stream()
    .collect(groupingBy(
        Employee::dept,
        filtering(e -> e.age() >= 30, counting())
    ));
// {"개발팀": 5, "영업팀": 3, "디자인팀": 0}  ← 명시적 0

// 리스트 수집도 동일 패턴
Map<String, List<Employee>> seniorsByDept = employees.stream()
    .collect(groupingBy(
        Employee::dept,
        filtering(e -> e.age() >= 30, toList())
    ));
// 디자인팀: [] (빈 리스트지만 키는 존재)
```

> 💡 **왜 중요한가**: "필터 후 그룹핑"과 "그룹핑 후 필터"는 보기엔 비슷해도 **빈 그룹의 존재 여부**가 다르다 — 리포트·대시보드·0건 알림 같은 "없음도 정보"인 도메인에서 이 차이가 버그로 이어진다.
