### 1. `RestClient`로 `RestTemplate`을 대체하는 Fluent 동기 HTTP 클라이언트 만들기

Spring Framework 6.1(Boot 3.2+)부터 제공되는 `RestClient`는 `RestTemplate`의 메서드 폭발과 `WebClient`의 리액티브 복잡도를 동시에 해결하는 동기 fluent API다. 빌더 체인으로 `baseUrl`·기본 헤더·메시지 컨버터·상태 코드 핸들러를 한 곳에 모을 수 있고, `retrieve().body(Type)`이나 `toEntity()`로 응답 처리를 간결하게 표현한다. Spring Boot가 `RestClient.Builder`를 자동 구성하므로 인터셉터·트레이싱이 그대로 적용된다.

```java
@Bean
RestClient userApiClient(RestClient.Builder builder) {
    return builder
        .baseUrl("https://api.example.com")
        .defaultHeader(HttpHeaders.ACCEPT, MediaType.APPLICATION_JSON_VALUE)
        .defaultStatusHandler(HttpStatusCode::is5xxServerError,
            (req, res) -> { throw new UpstreamException(res.getStatusCode()); })
        .build();
}

User user = userApiClient.get()
    .uri("/users/{id}", id)
    .retrieve()
    .body(User.class);
```

> 💡 **왜 중요한가**: 리액티브 스택을 도입하지 않고도 `WebClient` 수준의 표현력과 일관된 에러 처리를 얻을 수 있어, `RestTemplate` 기반 레거시를 점진적으로 현대화할 수 있다.

### 2. `JwtAuthenticationConverter`로 JWT 커스텀 클레임을 Spring Security 권한으로 매핑하기

OAuth2 Resource Server는 기본적으로 JWT의 `scope`/`scp` 클레임만 `SCOPE_xxx` 권한으로 변환하므로, 자체 발급 토큰의 `roles`나 `permissions` 같은 커스텀 클레임을 쓰려면 `JwtAuthenticationConverter`를 갈아끼워야 한다. `JwtGrantedAuthoritiesConverter`로 클레임 이름과 접두사를 지정하면 `@PreAuthorize("hasRole('ADMIN')")` 같은 표준 표현식이 그대로 동작하고, `setPrincipalClaimName`으로 `Authentication#getName`이 반환할 클레임도 바꿀 수 있다.

```java
@Bean
JwtAuthenticationConverter jwtAuthenticationConverter() {
    var granted = new JwtGrantedAuthoritiesConverter();
    granted.setAuthoritiesClaimName("roles");
    granted.setAuthorityPrefix("ROLE_");

    var converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(granted);
    converter.setPrincipalClaimName("sub");
    return converter;
}

http.oauth2ResourceServer(oauth -> oauth
    .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtAuthenticationConverter())));
```

> 💡 **왜 중요한가**: 인증 서버가 발급하는 토큰 구조를 그대로 활용하면서도 Spring Security의 표현식 기반 인가 로직을 손대지 않고 통합할 수 있어, 권한 체계 변경 시 컨트롤러 코드를 수정할 필요가 없다.
