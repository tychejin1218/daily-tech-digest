### 1. `HashMap` 대신 `ConcurrentHashMap.computeIfAbsent()`로 멀티스레드 환경의 캐싱 안전하게 처리하기

여러 스레드가 동시에 같은 키를 조회할 때 `if (map.get(key) == null) map.put(...)` 패턴은 race condition으로 중복 계산을 일으킨다. `ConcurrentHashMap.computeIfAbsent(key, k -> expensiveCompute(k))`는 키 단위 락(bin-level lock)으로 한 번만 계산을 보장하며, 람다는 정확히 한 번만 실행된다. 단, 람다 내부에서 같은 맵의 다른 키에 재귀적으로 접근하면 데드락이나 무한 루프가 발생할 수 있으니 주의해야 한다.

> 💡 **왜 중요한가**: 메모이제이션 캐시에서 흔히 발생하는 중복 계산과 race condition을 동기화 블록 없이 한 줄로 해결할 수 있어 코드가 단순해지고 처리량도 향상된다.

---

### 2. `Vector API`(인큐베이터)로 SIMD 명령을 활용한 데이터 병렬 연산 가속하기

Java 25 기준 9차 인큐베이터(JEP 508)인 Vector API는 `IntVector`, `FloatVector` 같은 타입으로 CPU의 SIMD 명령어(AVX, NEON 등)를 직접 활용하게 해준다. `var va = FloatVector.fromArray(SPECIES_256, a, i); va.mul(vb).intoArray(result, i);` 같은 코드는 일반 루프 대비 4~16배의 처리량을 낼 수 있어 ML 추론, 신호 처리, 암호화 등에 효과적이다. 인큐베이터 모듈이므로 `--add-modules jdk.incubator.vector`가 필요하며, Project Valhalla의 value class와 함께 정식화될 예정이다.

> 💡 **왜 중요한가**: JNI 없이 순수 Java로 SIMD 가속을 활용할 수 있어, 네이티브 라이브러리 의존 없이 수치 연산 핫스팟의 성능을 극대화할 수 있다.
