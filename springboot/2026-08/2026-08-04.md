### `@Transactional(readOnly = true)`는 JPA에서 단순 힌트가 아니라 스냅샷 저장을 스킵해 메모리와 CPU를 절약한다

`readOnly = true`가 붙은 트랜잭션에서 Hibernate는 엔티티의 원본 스냅샷을 저장하지 않고 dirty checking도 건너뛴다. 조회 전용 API에서 이 옵션을 빼면 수천 건의 엔티티마다 스냅샷이 PersistenceContext에 쌓여 GC 압박과 flush 비용이 발생한다. 또한 일부 DB 드라이버(MySQL Connector/J)는 이 힌트를 받아 read-only 커넥션으로 전환해 replica 라우팅까지 가능해진다.

> 💡 **왜 중요한가**: 조회 API에 `readOnly`를 붙이는 것만으로 힙 사용량과 flush 오버헤드를 절반 이하로 줄일 수 있고, 향후 read replica 분리 시 코드 변경 없이 대응된다.

### `Spring Security`의 `PasswordEncoder`는 `NoOpPasswordEncoder`가 아니라 `DelegatingPasswordEncoder`가 기본이며, 저장된 해시 앞의 `{bcrypt}` 같은 prefix로 알고리즘을 식별한다

Spring Security 5+ 기본 `PasswordEncoder`는 `{bcrypt}$2a$...` 형태로 알고리즘 ID를 해시 앞에 붙여 저장하며, 검증 시 이 prefix를 보고 어떤 인코더로 매칭할지 결정한다. 이 구조 덕분에 나중에 bcrypt → argon2로 마이그레이션할 때 기존 사용자를 강제 로그아웃시키지 않고 로그인 시점에 점진적 재해싱이 가능하다. 반대로 DB에 prefix 없이 순수 bcrypt 해시만 저장돼 있으면 `IllegalArgumentException: There is no PasswordEncoder mapped for the id "null"`이 터진다.

> 💡 **왜 중요한가**: 비밀번호 해시 알고리즘은 5년 주기로 교체 압박이 오는데, prefix 기반 저장 없이는 전 사용자 강제 리셋 외에는 마이그레이션 경로가 없다.
