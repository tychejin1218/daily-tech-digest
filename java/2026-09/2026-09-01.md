### 1. `Collection.toArray(IntFunction<T[]>)`로 제네릭 배열 변환의 낡은 관성 벗어나기 (Java 11 정식)

기존에는 `list.toArray(new String[0])`처럼 빈 배열을 매번 넘겨줘야 했고, 크기가 맞지 않으면 내부적으로 리플렉션 기반 재할당이 일어났다. Java 11부터는 `list.toArray(String[]::new)`처럼 배열 생성자 참조를 넘길 수 있어 의도가 명확해지고, JVM이 크기를 알고 있어 최적화 여지도 커진다.

```java
List<String> names = List.of("Kim", "Lee", "Park");

// Old: 빈 배열 인스턴스가 매번 생성되고 버려짐
String[] arr1 = names.toArray(new String[0]);

// New: 생성자 참조로 크기가 확정된 배열을 한 번에 할당
String[] arr2 = names.toArray(String[]::new);
```

> 💡 **왜 중요한가**: 코드 리뷰에서 `new T[0]` 관용구를 발견하면 "이 코더는 Java 11 이후를 안 쓰는구나"라는 신호가 되고, 대량 데이터 변환 시 배열 재할당 비용까지 사라진다.

### 2. `StringTemplate.STR."..."`로 문자열 연결·`String.format`을 안전하게 대체하기 (Java 21 프리뷰, JEP 430)

Java 21은 문자열 템플릿을 프리뷰로 도입해 `"안녕, " + name + "! 나이는 " + age`나 `String.format("안녕, %s! 나이는 %d", name, age)` 같은 관용구를 `STR."안녕, \{name}! 나이는 \{age}"`로 대체한다. 단순 치환뿐 아니라 SQL·JSON 같은 도메인용 커스텀 프로세서를 만들 수 있어 인젝션 방어까지 타입 수준에서 가능하다.

```java
String name = "진영";
int age = 34;

// Old: 가독성 낮은 concat, 또는 포맷 지정자 어긋나면 런타임 폭발
String msg1 = "안녕, " + name + "! 나이는 " + age;
String msg2 = String.format("안녕, %s! 나이는 %d", name, age);

// New (preview, --enable-preview 필요)
String msg3 = STR."안녕, \{name}! 나이는 \{age}";

// 커스텀 프로세서로 SQL 인젝션 방어 (예: 자체 SQL 템플릿)
// PreparedStatement ps = SQL."SELECT * FROM users WHERE id = \{userId}";
```

> 💡 **왜 중요한가**: `String.format`의 위치·타입 불일치는 컴파일 타임에 못 잡지만, 템플릿은 표현식을 파서가 직접 인식해 오탈자 사고를 원천 차단하고, 로깅·SQL·HTML 등 도메인별 안전한 문자열 조립의 표준 관문이 된다.
