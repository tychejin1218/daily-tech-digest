### Pattern Matching for switch로 타입별 분기를 간결하게 처리하기

`switch` 표현식에서 타입 패턴을 직접 사용해 `instanceof` + 캐스팅의 반복을 없앨 수 있습니다. `case Integer i ->`처럼 패턴 변수까지 한 줄에 묶이며, `when` 절로 추가 조건을 붙이거나 `null` 케이스도 명시적으로 다룰 수 있습니다 (Java 21 정식).

```java
String describe(Object obj) {
    return switch (obj) {
        case null            -> "값이 없음";
        case Integer i when i < 0 -> "음수: " + i;
        case Integer i       -> "정수: " + i;
        case String s        -> "문자열(길이=" + s.length() + ")";
        case int[] arr       -> "정수 배열(크기=" + arr.length + ")";
        default              -> "기타: " + obj.getClass().getSimpleName();
    };
}
```

> 💡 **왜 중요한가**: 길고 위험한 `if (x instanceof T) { T t = (T) x; ... }` 사다리를 컴파일러가 완전성까지 검증해주는 표현식 하나로 대체할 수 있습니다.

### Unnamed Variables `_`로 쓰지 않는 변수임을 명시하기

람다 파라미터, 예외 변수, 패턴 분해, try-with-resources 등에서 값을 사용하지 않을 때 변수명 자리에 `_`를 적어 "의도적으로 무시한다"는 신호를 줄 수 있습니다. 같은 스코프에서 여러 번 써도 충돌하지 않으며, IDE의 "사용되지 않은 변수" 경고도 사라집니다 (Java 22 정식).

```java
// 예외 객체가 필요 없을 때
try {
    return Integer.parseInt(s);
} catch (NumberFormatException _) {
    return 0;
}

// 람다에서 두 번째 인자만 사용
map.forEach((_, v) -> System.out.println(v));

// 레코드 패턴에서 일부 필드만 추출
if (shape instanceof Rectangle(Point topLeft, _, _, _)) {
    System.out.println(topLeft);
}
```

> 💡 **왜 중요한가**: `unused`, `ignored` 같은 임시 이름이 사라져 "이 값은 쓰지 않는다"는 의도가 코드에 그대로 드러나고, 리뷰어가 실수로 빠뜨린 변수와 혼동할 여지가 없어집니다.
