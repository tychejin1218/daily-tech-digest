### `@Transactional`의 `rollbackFor` 기본값은 `RuntimeException`과 `Error`뿐이라 체크 예외는 롤백되지 않는다

Spring의 트랜잭션은 기본적으로 unchecked exception에서만 롤백된다. `IOException`, `SQLException` 같은 checked exception이 발생해도 커밋되므로, DB 작업 후 파일 저장에서 `IOException`이 터지면 DB는 이미 커밋된 상태가 된다. 명시적으로 `@Transactional(rollbackFor = Exception.class)`을 지정해야 안전하다.

```java
@Transactional(rollbackFor = Exception.class)
public void saveOrderAndSendFile(Order order) throws IOException {
    orderRepository.save(order);
    fileService.write(order);  // IOException 터져도 기본값이면 커밋됨
}
```

> 💡 **왜 중요한가**: 기본값만 믿고 checked exception을 던지면 트랜잭션 무결성이 조용히 깨진다.

### `@MockBean`은 ApplicationContext를 캐시 무효화시켜 테스트 속도를 크게 떨어뜨린다

`@SpringBootTest`는 동일한 컨텍스트 구성을 캐시해 재사용하지만, `@MockBean`이 붙는 순간 해당 컨텍스트는 새로 로드된다. 여러 테스트 클래스에 흩어진 각기 다른 `@MockBean` 조합은 매번 컨텍스트를 다시 뜨게 만들어 전체 테스트 실행 시간이 배로 늘어난다. 공통 목 구성은 `@TestConfiguration`으로 모으거나, Mockito의 `@ExtendWith(MockitoExtension.class)` + 순수 단위 테스트로 분리하는 것이 낫다.

> 💡 **왜 중요한가**: 편리해 보이는 `@MockBean` 남용이 CI 파이프라인 시간을 몇 배로 늘리는 주범이 된다.
