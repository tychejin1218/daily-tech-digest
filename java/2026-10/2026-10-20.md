### 1. `Stream.toList()` (Java 16 정식)로 `.collect(Collectors.toList())` 관성 벗어나기

`stream.collect(Collectors.toList())`는 가변 `ArrayList`를 반환하지만, `stream.toList()`는 불변 리스트를 반환하면서 null 요소도 허용한다. 대부분의 "리스트로 변환" 코드가 사실은 가변성이 필요 없는데도, 손가락이 먼저 `collect(toList())` 를 치고 있다면 — 이제 그 체인을 끊을 때다.

```java
// Before — 가변성이 필요 없는데도 ArrayList 반환
List<String> names = users.stream()
    .map(User::getName)
    .collect(Collectors.toList());

// After — Java 16+
List<String> names = users.stream()
    .map(User::getName)
    .toList();  // 불변, null 허용, 성능도 약간 더 좋음
```

주의: `Collectors.toUnmodifiableList()`와 달리 `Stream.toList()`는 `null` 요소를 허용한다. 반대로 가변 리스트가 필요하면 명시적으로 `new ArrayList<>(stream.toList())` 또는 기존 `collect(toList())`를 유지해야 한다. 즉, "불변성 전환"이 의도적인 선택이 되어야 한다.

> 💡 **왜 중요한가**: 호출부에서 반환받은 리스트에 `.add()`를 하는 코드가 멀쩡히 돌다가 `UnsupportedOperationException`을 던지는 순간, `toList()`로의 이주는 "짧아서 좋다"가 아니라 "계약을 바꾸는 결정"이라는 걸 깨닫게 된다.

### 2. `switch` 패턴 매칭 + `record` 디컨스트럭션 (Java 21 정식, JEP 441/440)으로 `instanceof` 체인 + 캐스팅 관성 벗어나기

`if (obj instanceof Foo f) { ... } else if (obj instanceof Bar b) { ... }` 체인은 Java 16에서 `instanceof` 패턴이 들어오면서 많이 짧아졌지만, 여전히 분기가 많으면 지저분하다. Java 21부터는 `switch` 표현식에 패턴 매칭과 record 디컨스트럭션이 정식 지원되어, 타입 분기 + 필드 추출을 한 줄로 끝낼 수 있다.

```java
sealed interface Shape permits Circle, Rectangle, Triangle {}
record Circle(double radius) implements Shape {}
record Rectangle(double width, double height) implements Shape {}
record Triangle(double base, double height) implements Shape {}

// Before — instanceof 패턴 체인
double area;
if (shape instanceof Circle c) {
    area = Math.PI * c.radius() * c.radius();
} else if (shape instanceof Rectangle r) {
    area = r.width() * r.height();
} else if (shape instanceof Triangle t) {
    area = 0.5 * t.base() * t.height();
} else {
    throw new IllegalStateException();
}

// After — Java 21+ switch 패턴 매칭 + record 디컨스트럭션
double area = switch (shape) {
    case Circle(double r)                  -> Math.PI * r * r;
    case Rectangle(double w, double h)     -> w * h;
    case Triangle(double b, double h)      -> 0.5 * b * h;
};
```

`sealed interface`와 결합하면 컴파일러가 모든 하위 타입을 처리했는지 **완전성(exhaustiveness)** 을 검사해주므로, `default` 분기나 "여기 도달하면 안 됨" 예외를 쓰지 않아도 된다. 새로운 타입이 추가되면 컴파일 에러로 바로 알려준다.

> 💡 **왜 중요한가**: "타입에 따라 다른 처리"는 OOP에서 다형성으로 풀어야 한다고 배우지만, 도메인 로직을 데이터 타입 안에 두기 싫거나(record는 데이터 캐리어다) 외부 라이브러리 타입을 다룰 때는 패턴 매칭이 훨씬 깔끔하다 — 그리고 `sealed`가 "분기 빠뜨림" 버그를 컴파일 타임에 잡아준다.
