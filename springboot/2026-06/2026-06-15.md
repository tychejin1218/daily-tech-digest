### 1. `@ConfigurationPropertiesScan`과 `@ConstructorBinding`으로 불변(Immutable) 설정 객체 만들기

`@ConfigurationProperties`를 `record` 또는 `final` 필드 클래스에 적용하면 생성자 기반으로 설정값이 주입되어 런타임에 변경 불가능한 타입-세이프 설정 객체를 만들 수 있습니다. `@ConfigurationPropertiesScan`을 메인 클래스에 붙이면 `@EnableConfigurationProperties`로 일일이 등록할 필요 없이 패키지를 스캔하여 자동 등록되며, Spring Boot 3+에서는 `@ConstructorBinding`을 생략해도 동작합니다.

```java
@ConfigurationProperties(prefix = "app.mail")
public record MailProperties(
    String host,
    int port,
    @DefaultValue("UTF-8") String encoding,
    Duration timeout
) {}

@SpringBootApplication
@ConfigurationPropertiesScan("com.example.config")
public class Application { }
```

> 💡 **왜 중요한가**: 설정값을 불변 객체로 다루면 멀티스레드 환경에서의 사이드 이펙트를 차단하고, IDE 자동완성과 컴파일 타임 검증으로 설정 오타로 인한 운영 장애를 예방할 수 있습니다.

### 2. `@TestConfiguration`과 `@Import`로 테스트 전용 빈을 격리하여 슬라이스 테스트 구성하기

`@SpringBootTest`에 `@TestConfiguration`을 `@Import`하면 운영 컨텍스트를 오염시키지 않고 테스트에서만 필요한 빈(Mock 외부 API 클라이언트, 고정 Clock, 인메모리 캐시 등)을 주입할 수 있습니다. 정적 내부 클래스로 선언하면 해당 테스트 클래스에서만 자동 로드되고, 별도 클래스로 분리하면 여러 테스트에서 재사용할 수 있습니다.

```java
@TestConfiguration
public class FixedClockTestConfig {
    @Bean
    @Primary
    public Clock fixedClock() {
        return Clock.fixed(Instant.parse("2026-06-15T00:00:00Z"), ZoneOffset.UTC);
    }
}

@SpringBootTest
@Import(FixedClockTestConfig.class)
class OrderServiceTest { /* ... */ }
```

> 💡 **왜 중요한가**: 시간·외부 의존성 등 비결정적 요소를 테스트 컨텍스트에서만 교체할 수 있어, 운영 코드를 흔들지 않고도 안정적이고 재현 가능한 통합 테스트를 작성할 수 있습니다.
