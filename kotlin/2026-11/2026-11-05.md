### 1. Sealed Class: when 문의 "else 지옥"을 탈출하는 타입 안전 설계

Sealed class는 **같은 파일(또는 같은 모듈) 안에서만 상속이 허용되는 제한된 클래스 계층**이다. 컴파일러가 하위 타입을 전부 알고 있기 때문에 `when` 분기에서 모든 케이스를 처리하면 `else` 없이도 컴파일이 되고, 새로운 상태를 추가했을 때 **처리하지 않은 분기를 컴파일 에러로 잡아준다**. API 응답(Success/Error/Loading), 결제 상태, 도메인 이벤트처럼 "유한한 상태 집합"을 모델링할 때 최고의 선택이다.

```kotlin
sealed class ApiResult<out T> {
    data class Success<T>(val data: T) : ApiResult<T>()
    data class Error(val code: Int, val message: String) : ApiResult<Nothing>()
    data object Loading : ApiResult<Nothing>()
}

fun handle(result: ApiResult<User>): String = when (result) {
    is ApiResult.Success -> "유저: ${result.data.name}"
    is ApiResult.Error   -> "에러 ${result.code}: ${result.message}"
    ApiResult.Loading    -> "로딩 중..."
    // else 불필요 — 새 하위 타입 추가 시 컴파일 에러로 알려줌
}
```

**enum vs sealed class 선택 기준**

| 상황 | 추천 |
|---|---|
| 단순 상수 집합 (ACTIVE, INACTIVE) | `enum class` |
| 각 케이스가 **서로 다른 데이터**를 가짐 | `sealed class` |
| 계층적 상태 + 패턴 매칭 | `sealed class` |

> 💡 **왜 중요한가**: 새로운 상태를 추가했을 때 "처리 안 한 곳"을 런타임이 아니라 **컴파일 타임에** 찾아주므로, 결제·주문처럼 상태가 늘어나는 도메인에서 버그가 원천 차단된다.

### 2. Kotlin Coroutines 기초: suspend, launch, async — "스레드보다 싼 동시성"

코루틴은 **스레드가 아닌 함수 레벨에서 일시정지/재개가 가능한 경량 동시성 단위**다. `suspend` 함수는 "중단될 수 있는" 함수이고, 스레드를 블로킹하지 않고 대기하다가 결과가 준비되면 다시 실행된다. 수만 개를 띄워도 OS 스레드 1~2개로 처리되기 때문에 외부 API 호출·DB I/O가 많은 서버에서 Tomcat 스레드 풀 고갈 문제를 근본적으로 해결한다.

```kotlin
// suspend: 중단 가능한 함수
suspend fun fetchUser(id: Long): User {
    delay(100)  // Thread.sleep과 달리 스레드를 블로킹하지 않음
    return userRepository.findById(id)
}

// launch: fire-and-forget (결과 불필요)
// async: 결과를 await()로 받음 — 병렬 호출의 핵심
suspend fun loadDashboard(userId: Long): Dashboard = coroutineScope {
    val user    = async { fetchUser(userId) }          // 병렬 시작
    val orders  = async { fetchOrders(userId) }        // 병렬 시작
    val coupons = async { fetchCoupons(userId) }       // 병렬 시작
    Dashboard(user.await(), orders.await(), coupons.await())
    // 총 소요시간 = max(각 호출) — 순차 호출이면 합산
}
```

**launch vs async 비교**

| 구분 | `launch` | `async` |
|---|---|---|
| 반환 | `Job` | `Deferred<T>` |
| 결과 | 없음 | `.await()`로 수신 |
| 예외 | 즉시 전파 | `.await()` 시점에 전파 |
| 용도 | 로깅, 알림 발송 | 병렬 API 호출 결과 합치기 |

**Spring Boot 연동 주의점**: Controller에 `suspend fun`을 쓰면 Spring WebFlux/MVC(Kotlin 지원)가 자동으로 넌블로킹으로 처리한다. 단, **내부에서 JPA 같은 블로킹 I/O를 그대로 호출하면 이득이 사라지므로** `withContext(Dispatchers.IO)`로 감싸야 한다.

> 💡 **왜 중요한가**: `RestTemplate`으로 외부 API 3개를 순차 호출하면 300ms, 코루틴 `async`로 병렬화하면 100ms — 동일 코드량에 스레드 자원은 1/100만 쓰면서 응답속도가 3배 빨라진다.
