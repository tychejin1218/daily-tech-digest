### `@Async` 메서드에서 `SecurityContextHolder`가 비어있는 문제 — `DelegatingSecurityContextAsyncTaskExecutor`로 컨텍스트 전파하기

Spring Security의 `SecurityContext`는 기본적으로 `ThreadLocal`에 저장되므로 `@Async`로 비동기 실행되는 별도 스레드에서는 `SecurityContextHolder.getContext().getAuthentication()`이 `null`을 반환한다. `TaskExecutor`를 `DelegatingSecurityContextAsyncTaskExecutor`로 감싸거나 `SecurityContextHolder.setStrategyName(MODE_INHERITABLETHREADLOCAL)`을 설정하면 부모 스레드의 인증 정보가 자식 스레드로 전파된다.

```java
@Configuration
public class AsyncConfig implements AsyncConfigurer {
    @Override
    public Executor getAsyncExecutor() {
        ThreadPoolTaskExecutor delegate = new ThreadPoolTaskExecutor();
        delegate.setCorePoolSize(10);
        delegate.initialize();
        return new DelegatingSecurityContextAsyncTaskExecutor(delegate);
    }
}
```

> 💡 **왜 중요한가**: 비동기 로직에서 감사 로그·권한 체크가 조용히 무너지는 사고를 원천 차단한다.

### `spring.jpa.properties.hibernate.jdbc.batch_size`만 켜도 배치 INSERT가 안 되는 이유 — `IDENTITY` 전략을 `SEQUENCE`로 바꿔야 진짜 배치가 된다

`batch_size=50`, `order_inserts=true`를 설정해도 PK 전략이 `GenerationType.IDENTITY`면 Hibernate가 배치 INSERT를 아예 비활성화한다. `IDENTITY`는 INSERT 실행 후에야 PK를 알 수 있어 배치 큐잉이 불가능하기 때문이며, PostgreSQL/Oracle이라면 `SEQUENCE` + `allocationSize`로 전환해 실제 배치가 동작하도록 만들어야 한다.

```java
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "order_seq")
@SequenceGenerator(name = "order_seq", sequenceName = "order_seq", allocationSize = 50)
private Long id;
```

> 💡 **왜 중요한가**: 배치 옵션만 켜고 성능 개선을 기대하다가 여전히 N번의 INSERT가 나가는 함정을 피할 수 있다.
