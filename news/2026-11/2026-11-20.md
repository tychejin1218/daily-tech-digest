### 1. OpenAI 'GPT-6.1 Codex Max' 정식 출시 — '컨텍스트 창 1000만 토큰' 시대가 열렸다, 모노레포 전체를 한 호출에 집어넣는 '풀 레포 리팩토링'이 디폴트가 됐다

OpenAI가 오늘 코드 특화 모델 'GPT-6.1 Codex Max'를 GA로 공개했다. 공식 블로그에 따르면 컨텍스트 창 1000만 토큰, 출력 2M 토큰을 지원하며 Linux 커널(약 2800만 LoC)의 ⅓을 한 번에 로드해 '크로스파일 리팩토링'을 단일 호출로 처리하는 벤치마크가 함께 공개됐다. 가격은 입력 100만 토큰당 $0.80, 출력 $3.20으로 Sonnet 4.6 대비 40% 낮게 책정되면서 'RAG 없이 그냥 전부 넣는다'는 패턴이 현실적인 선택지가 됐다.

> 💡 **왜 중요한가**: '벡터 DB로 코드 조각 검색 후 LLM 호출'이라는 2년간의 코딩 에이전트 아키텍처 전제가 무너지기 시작했다 — 레포 전체를 통째로 밀어넣는 쪽이 더 싸고 정확해지는 변곡점이다.

### 2. Oracle, 'MySQL HeatWave Agent Mode' GA — RDBMS가 '에이전트 툴 콜'을 SQL 다이얼렉트로 흡수했다, 'DB 안에서 LLM을 돌리는' 설계가 처음으로 엔터프라이즈 디폴트가 됐다

Oracle이 MySQL HeatWave에 'Agent Mode'를 정식 추가하면서 `CALL AGENT.invoke('claude-sonnet-4-6', prompt, tools)`라는 SQL 네이티브 구문으로 LLM과 툴 콜을 DB 세션 안에서 직접 실행할 수 있게 됐다. 트랜잭션 경계 안에서 LLM 호출이 일어나므로 에이전트의 중간 상태를 애플리케이션 레이어에 둘 필요가 없어졌고, Oracle은 'AWS Lambda + Bedrock 조합 대비 p99 레이턴시 71% 감소'를 벤치마크로 내세웠다. 결제·주문 같은 '사이드 이펙트 트랜잭션'을 한 ACID 경계 안에서 LLM이 실행하는 데모가 특히 주목받고 있다.

> 💡 **왜 중요한가**: '애플리케이션이 LLM과 DB를 오케스트레이션'하던 3-tier 구도가 깨지고, DB가 스스로 에이전트 런타임이 되는 '2-tier 재압축'이 시작됐다 — 백엔드 레이어링 교과서가 다시 쓰여야 할 변화다.

### 3. Meta 'Llama 5 Coder 400B' Apache 2.0 라이선스 공개 — '오픈 가중치 코딩 모델'이 처음으로 상용 폐쇄형의 '툴 사용' 벤치마크를 넘어섰다

Meta가 오늘 Llama 5 Coder 400B를 Apache 2.0 라이선스로 Hugging Face에 공개했다. SWE-bench Verified 78.4%, Terminal-Bench 71.2%로 GPT-6.1 Codex Max(76.9%)를 소폭 앞섰고, 특히 '툴 콜 시퀀스 7단계 이상'의 장기 추론 태스크에서 Claude Sonnet 4.6 대비 +4.2%p 우위를 기록했다. 4bit 양자화 시 단일 H100 노드(8× 80GB)에서 추론이 가능해, '사내 Codex 셀프호스팅'이 재무적으로 처음 성립한다는 평가가 나온다.

> 💡 **왜 중요한가**: '코딩 에이전트는 반드시 프런티어 폐쇄형 API를 호출해야 한다'는 2026년 상반기의 전제가 무너졌다 — 규제·보안 민감 조직이 '에이전트 워크로드 전량 사내 추론'을 진지하게 검토할 분기점이다.
