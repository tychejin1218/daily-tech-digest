### 1. GitHub 'Spark Agent' GA 공개 — Copilot이 '파일을 수정'하는 시대에서 '리포지토리를 운영'하는 시대로 넘어갔다, PR 리뷰·배포·롤백까지 한 에이전트가 맡는다

GitHub가 Universe 2026에서 Copilot Workspace의 후속작인 Spark Agent를 GA로 공개했다. 이슈 하나를 던지면 브랜치 생성 → 코드 작성 → 테스트 실행 → PR 작성 → 리뷰 반영 → 머지 → 배포 → 모니터링까지를 하나의 장기 세션으로 묶고, 중간에 CI가 실패하면 스스로 롤백해 다른 접근으로 재시도한다. Anthropic Claude Opus 4.7과 OpenAI GPT-6 Astra를 '작업별 라우팅'으로 섞어 쓰며, 엔터프라이즈는 자체 모델 엔드포인트 바인딩도 가능해졌다.

> 💡 **왜 중요한가**: '코딩 에이전트'의 단위가 '파일 단위 패치'에서 '서비스 단위 운영'으로 올라섰다 — 앞으로 백엔드 엔지니어의 1차 리뷰 대상은 사람의 PR이 아니라 에이전트가 운영한 '배포 히스토리'가 된다.

### 2. Cloudflare 'Workers AI Gateway v2' 공개 — LLM 호출에 BGP처럼 '멀티 프로바이더 페일오버'가 기본으로 들어왔다, OpenAI가 죽어도 Anthropic으로 60ms 안에 넘어간다

Cloudflare가 Workers AI Gateway v2를 공개하면서 LLM 호출을 '네트워크 레이어'로 끌어내렸다. 하나의 엔드포인트로 요청을 보내면 OpenAI → Anthropic → Google → Bedrock 순으로 지정한 fallback 정책을 따라 자동으로 라우팅되고, 프로바이더 장애·레이트리밋·지역 차단을 BGP 라우팅처럼 60ms 내에 우회한다. 응답 캐시, 프롬프트 레벨 WAF, 비용 상한, OpenTelemetry 메트릭이 전부 게이트웨이에 내장돼 애플리케이션 코드에서 `openai.chat.completions.create`를 호출하는 코드는 한 줄도 바뀌지 않는다.

> 💡 **왜 중요한가**: '멀티 LLM 프로바이더 전략'이 아키텍처 다이어그램의 토픽에서 인프라 레이어의 기본값으로 내려왔다 — 애플리케이션 코드에서 프로바이더 전환 로직을 짜던 시대가 끝났고, SRE가 LLM 가용성을 관리하는 시대가 왔다.

### 3. HashiCorp Terraform 2.0 공개 — IaC에 'AI Plan Review'가 1급 단계로 들어왔다, `terraform plan`과 `terraform apply` 사이에 'terraform explain'이 새로 생겼다

IBM 인수 후 첫 메이저 릴리스인 Terraform 2.0이 공개됐다. 가장 큰 변화는 `terraform plan`과 `apply` 사이에 끼어든 신규 명령 `terraform explain` — plan 결과를 LLM에 넘겨 "이 변경이 프로덕션에 어떤 영향을 미치는가"를 자연어로 설명하고, 정책 위반(퍼블릭 S3 버킷, IAM 와일드카드, DB 삭제 등)이 감지되면 apply를 자동으로 차단한다. Sentinel 정책과 결합되면 에이전트가 생성한 IaC를 사람 리뷰 없이 머지해도 안전 가드가 걸리고, 모델은 로컬 Ollama·Bedrock·Vertex 중 선택할 수 있다.

> 💡 **왜 중요한가**: 코딩 에이전트가 Terraform을 생성하는 시대의 가장 큰 리스크 — '설득력 있는 디프가 프로덕션을 날려버리는 사고' — 를 IaC 툴 자체가 1급 가드로 흡수했다. '사람 리뷰어가 Terraform plan을 읽는다'는 가정이 Day 1부터 깨진다.
