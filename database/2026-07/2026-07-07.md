### MySQL `Online DDL`의 `ALGORITHM=INSTANT` — 초대형 테이블에 컬럼 추가를 밀리초 안에 끝내기

MySQL 8.0부터 `ALTER TABLE ... ADD COLUMN` 같은 일부 DDL은 `ALGORITHM=INSTANT` 옵션으로 메타데이터만 수정해 즉시 반영된다. 수십 GB 테이블도 테이블 재작성 없이 완료되며 락 대기 시간이 사라지므로, 서비스 중단 없이 스키마를 진화시켜야 하는 운영 환경에서 필수 기법이다.

```sql
ALTER TABLE orders
  ADD COLUMN status_v2 TINYINT NOT NULL DEFAULT 0,
  ALGORITHM=INSTANT, LOCK=NONE;
```

단, `INSTANT`가 지원되지 않는 변경(예: 컬럼 타입 변경, `AUTO_INCREMENT` 재정의)을 시도하면 에러가 나므로 `ALGORITHM`을 명시해 실수로 `COPY` 방식으로 떨어지는 것을 방지해야 한다.

> 💡 **왜 중요한가**: 무중단 배포가 기본이 된 환경에서 "테이블이 커서 컬럼 하나 못 추가한다"는 변명을 없애준다.

### PostgreSQL `NULLS NOT DISTINCT` — 유니크 인덱스에서 NULL을 중복으로 취급하기

PostgreSQL은 기본적으로 유니크 인덱스에서 NULL을 서로 다른 값으로 보기 때문에, `email` 컬럼에 NULL이 여러 행 들어가도 유니크 제약을 위반하지 않는다. PostgreSQL 15부터 도입된 `NULLS NOT DISTINCT` 옵션은 이 동작을 뒤집어, NULL 하나만 허용하고 두 번째 NULL은 유니크 위반으로 거부하게 만든다.

```sql
CREATE UNIQUE INDEX idx_users_email
  ON users (email) NULLS NOT DISTINCT;
```

기존에는 `COALESCE(email, '')` 표현식 인덱스나 부분 인덱스로 우회했던 "선택 입력 필드지만 값이 있다면 유일해야 한다"는 요구사항을 한 줄로 해결할 수 있다.

> 💡 **왜 중요한가**: 애플리케이션 검증 로직에 흩어져 있던 NULL 중복 처리를 DB 제약으로 통합해 데이터 정합성을 한 곳에서 보장한다.
