### 1. `@ServiceConnection`으로 Testcontainers 연결 정보 자동 주입하기 (Spring Boot 3.1+)

기존에는 `@DynamicPropertySource`로 컨테이너의 JDBC URL·유저·패스워드를 하나하나 `registry.add(...)`로 주입해야 했지만, Spring Boot 3.1부터는 컨테이너 빈에 `@ServiceConnection`만 붙이면 `ConnectionDetails`가 자동 등록되어 `spring.datasource.*` 설정이 필요 없어집니다. PostgreSQL·MySQL·Redis·Kafka·MongoDB 등 대부분의 공식 모듈을 지원하며, 컨테이너 이미지 태그가 바뀌어도 별도 매핑 코드가 필요 없습니다.

```java
@TestConfiguration(proxyBeanMethods = false)
class TestcontainersConfig {
    @Bean
    @ServiceConnection
    PostgreSQLContainer<?> postgres() {
        return new PostgreSQLContainer<>("postgres:16-alpine");
    }
}
```

> 💡 **왜 중요한가**: `@DynamicPropertySource` 보일러플레이트를 제거해 통합 테스트 세팅이 짧아지고, 프로퍼티 키 오타로 인한 커넥션 실패가 원천적으로 사라집니다.

### 2. `JpaRepository.getReferenceById()`로 FK 연관관계 저장 시 불필요한 SELECT 없애기

새 엔티티를 저장하면서 FK만 연결하면 되는 상황에서 `findById().orElseThrow()`를 쓰면 부모를 조회하는 SELECT가 무조건 한 번 나갑니다. 반면 `getReferenceById()`는 하이버네이트 프록시(id만 채워진 껍데기)를 반환하기 때문에 INSERT 시 FK 컬럼에 id만 꽂고 실제 SELECT는 발생하지 않습니다. 부모 존재를 반드시 확인해야 하는 케이스가 아니라면 대량 저장 API에서 큰 성능 차이를 만듭니다.

```java
Order order = new Order();
order.setMember(memberRepository.getReferenceById(memberId)); // SELECT 없음
order.setProduct(productRepository.getReferenceById(productId));
orderRepository.save(order);
```

> 💡 **왜 중요한가**: 주문·로그처럼 부모를 이미 검증한 뒤 자식만 INSERT하는 흐름에서 왕복 쿼리 수를 절반 이하로 줄여 응답 지연과 DB 부하를 동시에 낮춥니다.
