### `Duration.toDaysPart()` / `toHoursPart()` 등 파트 API로 기간을 사람이 읽는 단위로 분해하기 (Java 9 정식)

`Duration`을 "2일 3시간 45분" 형태로 표시하려고 `toHours() % 24` 같은 수동 나머지 연산을 쓰다 실수하기 쉬운데, Java 9부터는 `toDaysPart()`, `toHoursPart()`, `toMinutesPart()`, `toSecondsPart()`, `toMillisPart()`, `toNanosPart()`가 표준 API로 제공되어 각 단위의 나머지 값을 바로 얻을 수 있다. 총량을 얻는 `toHours()`와 파트 값을 얻는 `toHoursPart()`가 이름으로 구분되어 의도가 명확하다.

```java
Duration d = Duration.ofSeconds(90061); // 1일 1시간 1분 1초
String pretty = String.format("%d일 %d시간 %d분 %d초",
        d.toDaysPart(), d.toHoursPart(), d.toMinutesPart(), d.toSecondsPart());
// "1일 1시간 1분 1초"
```

> 💡 **왜 중요한가**: 나머지 연산 실수 없이 기간을 사람이 읽는 단위로 안전하게 분해할 수 있다.

### `Character.isAlphabetic(int)` vs `isLetter(int)`로 유니코드 문자 판정 범위를 정확히 구분하기 (Java 7 정식)

`Character.isLetter()`는 `LETTER` 일반 카테고리(Lu/Ll/Lt/Lm/Lo)만 잡지만, `isAlphabetic()`은 여기에 `Nl`(문자 형태의 숫자, 예: 로마 숫자 Ⅴ)과 `Other_Alphabetic` 속성(예: 히브리어의 일부 부호)을 포함해 유니코드 표준의 "알파벳" 정의에 맞춘 판정을 한다. 국제화 텍스트에서 "문자로 취급할 것"을 판단할 땐 `isAlphabetic`이 더 안전하며, `int` 코드포인트를 받는 오버로드를 써야 서러게이트 페어(이모지·확장 한자 등)도 올바르게 처리된다.

```java
Character.isLetter('Ⅴ');         // false (Nl 카테고리)
Character.isAlphabetic('Ⅴ');     // true
"𝐀".codePoints().allMatch(Character::isAlphabetic); // true (BMP 밖 문자도 안전)
```

> 💡 **왜 중요한가**: 국제화·유니코드 텍스트에서 "문자냐 아니냐"를 표준 정의대로 판정해 지역화 버그를 줄인다.
