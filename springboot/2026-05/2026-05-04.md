### `@Scheduled`의 `scheduler` 속성으로 작업별 전용 스케줄러 분리하기

Spring Boot 3.2+부터 `@Scheduled` 어노테이션의 `scheduler` 속성을 통해 개별 작업마다 사용할 `TaskScheduler` 빈 이름을 지정할 수 있습니다. 기본 단일 스레드 스케줄러는 한 작업이 지연되면 다른 작업까지 줄줄이 밀리는 병목을 만들기 때문에, 무거운 배치성 작업과 짧은 헬스체크성 작업을 별도 스케줄러로 분리해 격리하는 것이 안전합니다. `ThreadPoolTaskScheduler`를 작업 특성에 맞게 풀 크기·이름 접두사·에러 핸들러를 다르게 구성해 등록해두면 운영 중 스레드 덤프 분석도 훨씬 수월해집니다.

> 💡 **왜 중요한가**: 단일 디폴트 스케줄러를 공유하면 한 작업의 지연이 전체 스케줄링 시스템을 마비시키는데, `scheduler` 속성으로 작업 특성별 격리가 가능합니다.

### `RestClient.Builder`의 `defaultStatusHandler`로 HTTP 에러를 도메인 예외로 일괄 변환

여러 컨트롤러·서비스에서 외부 API를 호출할 때 매번 `onStatus`를 체이닝하는 대신, `RestClient.Builder`에 `defaultStatusHandler`를 설정해 4xx/5xx 응답을 도메인 예외로 변환하는 정책을 한 곳에 모을 수 있습니다. 클라이언트 빈을 구성하는 단계에서 상태 코드 매핑·재시도 가능 여부·에러 본문 파싱 로직을 공통화하면 호출부 코드가 비즈니스 흐름만 남게 됩니다. `RestClientResponseException`에서 응답 헤더와 본문을 모두 읽을 수 있으므로, 상관관계 ID 같은 추적 정보도 함께 예외에 실어 보낼 수 있습니다.

> 💡 **왜 중요한가**: 외부 API 에러 처리 로직이 호출부마다 흩어지면 일관성이 깨지고 누락이 생기는데, 빌더 단계에서 한번에 정책을 정의하면 모든 호출이 동일한 규칙을 따르게 됩니다.
