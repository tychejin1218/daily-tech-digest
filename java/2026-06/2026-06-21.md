### `Collectors.groupingBy()` + 다운스트림 컬렉터로 한 번에 집계까지 끝내기 (Java 8 정식)
`groupingBy(classifier)`만 쓰면 `Map<K, List<T>>`가 나오지만, 두 번째 인자에 다운스트림 컬렉터를 넘기면 그룹 안에서 합계·평균·카운트·매핑 같은 추가 가공을 한 번의 스트림 통과로 끝낼 수 있습니다. `mapping()`·`counting()`·`summingLong()`·`reducing()`을 조합하면 SQL `GROUP BY` 수준의 표현력이 나옵니다.

```java
// 카테고리별로 가장 비싼 상품명만 수집
Map<String, Optional<Product>> topByCategory = products.stream()
    .collect(Collectors.groupingBy(
        Product::getCategory,
        Collectors.maxBy(Comparator.comparingLong(Product::getPriceCents))));

// 카테고리별 평균 가격
Map<String, Double> avgByCategory = products.stream()
    .collect(Collectors.groupingBy(
        Product::getCategory,
        Collectors.averagingLong(Product::getPriceCents)));
```

> 💡 **왜 중요한가**: 그룹별 List를 따로 만들어 두 번째 스트림으로 다시 가공하던 두 단계 코드를 한 번에 줄여, GC 부담과 가독성 양쪽이 함께 개선됩니다.

### `EnumSet`과 `EnumMap`으로 비트마스크·해시맵을 대체해 메모리·속도 잡기 (Java 5 정식)
열거형 키를 다룰 때 `HashSet<MyEnum>`/`HashMap<MyEnum, V>` 대신 `EnumSet`/`EnumMap`을 쓰면 내부적으로 long 비트 벡터·배열 인덱싱으로 동작해 해시 계산이 사라지고 메모리도 수 배 작아집니다. 권한 플래그·상태 머신·요일 마스크 같은 시나리오의 표준 자료구조입니다.

```java
enum Permission { READ, WRITE, ADMIN, AUDIT }

EnumSet<Permission> granted = EnumSet.of(Permission.READ, Permission.WRITE);
granted.contains(Permission.ADMIN);          // O(1), 비트 AND

EnumMap<Permission, String> labels = new EnumMap<>(Permission.class);
labels.put(Permission.READ, "읽기");
labels.put(Permission.WRITE, "쓰기");
```

> 💡 **왜 중요한가**: 코드 의도가 명확해지고 직렬화·디버깅도 쉬워지면서, 핫 패스에서는 `HashMap` 대비 수 배 더 빠르고 GC 친화적입니다.
