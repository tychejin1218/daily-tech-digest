### PostgreSQL `GENERATED ALWAYS AS ... STORED` 컬럼 — 파생 값 계산을 애플리케이션이 아닌 DB에 위임하기

`total_price = quantity * unit_price` 같은 파생 컬럼을 애플리케이션 코드로 계산해 저장하면 로직이 여러 곳에 흩어지고 정합성이 깨지기 쉽다. PostgreSQL 12+의 `GENERATED ALWAYS AS (expr) STORED`는 삽입·수정 시 자동으로 값을 계산해 저장하며, 이 컬럼에 인덱스도 직접 걸 수 있다.

```sql
CREATE TABLE orders (
  id           BIGSERIAL PRIMARY KEY,
  quantity     INT NOT NULL,
  unit_price   NUMERIC(10,2) NOT NULL,
  total_price  NUMERIC(12,2) GENERATED ALWAYS AS (quantity * unit_price) STORED,
  search_text  TEXT GENERATED ALWAYS AS (lower(customer_name || ' ' || product_name)) STORED
);
CREATE INDEX idx_orders_total ON orders(total_price);
```

> 💡 **왜 중요한가**: 파생 값 계산 책임을 DB에 두면 앱 코드가 아무리 늘어나도 데이터 정합성이 스키마 수준에서 강제된다.

### MySQL `SELECT ... FOR UPDATE SKIP LOCKED` — 대기 없이 다음 처리 가능한 행으로 넘어가기

멀티 워커가 같은 큐 테이블에서 작업을 꺼낼 때 일반 `FOR UPDATE`는 락 대기로 처리량이 급락한다. MySQL 8.0+의 `SKIP LOCKED`는 이미 잠긴 행을 건너뛰고 다음 잠글 수 있는 행을 즉시 반환해 워커 병렬성을 극대화한다.

```sql
START TRANSACTION;
SELECT id, payload
  FROM job_queue
 WHERE status = 'PENDING'
 ORDER BY created_at
 LIMIT 10
 FOR UPDATE SKIP LOCKED;

UPDATE job_queue SET status = 'PROCESSING' WHERE id IN (...);
COMMIT;
```

> 💡 **왜 중요한가**: 워커를 N배로 늘려도 락 경합 없이 선형 확장되는 분산 작업 큐를 DB만으로 구현할 수 있다.
