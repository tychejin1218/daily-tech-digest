### `@RegisterReflectionForBinding`으로 GraalVM Native Image 직렬화 대상 명시

Spring Boot 3.x에서 GraalVM Native Image로 빌드할 때, 리플렉션으로 접근되는 DTO/직렬화 대상 클래스는 빌드 타임에 메타데이터가 등록되어야 런타임 오류가 발생하지 않습니다. `@RegisterReflectionForBinding({UserDto.class, OrderDto.class})`를 컴포넌트나 설정 클래스에 붙이면 해당 타입의 필드와 생성자에 대한 리플렉션 힌트가 자동 등록되어, 별도 `RuntimeHints` 구현 없이도 외부 API 응답 매핑이나 JSON 역직렬화가 정상 동작합니다.

> 💡 **왜 중요한가**: Native Image 빌드는 클로즈드월드 가정으로 동작하므로, 명시되지 않은 리플렉션 대상은 런타임에 `ClassNotFoundException`이나 빈 객체로 매핑되는 침묵 실패를 일으킵니다.

### `@ServiceConnection`으로 Testcontainers 컨테이너를 자동 와이어링

Spring Boot 3.1+의 `@ServiceConnection`을 Testcontainers 컨테이너 빈에 붙이면, `spring.datasource.url`이나 `spring.data.redis.host` 같은 프로퍼티를 수동으로 설정하지 않아도 Spring Boot가 컨테이너의 호스트/포트/자격증명을 자동으로 감지해 주입합니다. PostgreSQL, Redis, Kafka, MongoDB, RabbitMQ 등 주요 컨테이너에 대해 `ConnectionDetails` 빈을 자동 생성하므로 `@DynamicPropertySource` 보일러플레이트가 사라집니다.

> 💡 **왜 중요한가**: 프로퍼티 키를 손으로 매핑하면 모듈/버전 차이에 따라 깨지기 쉬운데, `@ServiceConnection`은 컨테이너 이미지 종류를 보고 올바른 키를 추론하므로 통합 테스트 셋업이 단순해지고 휴먼 에러가 제거됩니다.
