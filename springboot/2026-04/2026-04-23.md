### `@SpringBootTest` 대신 `@DataJpaTest`로 리포지토리 계층만 슬라이스 테스트하기

`@SpringBootTest`는 전체 컨텍스트를 띄워 리포지토리 하나 검증하는 데도 수 초가 걸린다. `@DataJpaTest`는 JPA/DataSource 관련 빈만 로드하고 각 테스트를 자동으로 롤백하며, 기본적으로 임베디드 DB로 전환한다. 실제 DB로 검증하려면 `@AutoConfigureTestDatabase(replace = Replace.NONE)`를 함께 붙인다.

```java
@DataJpaTest
@AutoConfigureTestDatabase(replace = Replace.NONE)
class MemberRepositoryTest {
    @Autowired MemberRepository memberRepository;
    @Autowired TestEntityManager em;

    @Test
    void findByEmail_대소문자_구분() {
        em.persist(new Member("user@ex.com"));
        em.flush(); em.clear();
        assertThat(memberRepository.findByEmail("USER@EX.COM")).isEmpty();
    }
}
```

> 💡 **왜 중요한가**: 슬라이스 테스트는 컨텍스트 로딩 시간을 몇 배 단축해 리포지토리 회귀 테스트를 자주 돌릴 수 있게 만든다.

### `spring.mvc.problemdetails.enabled=true`가 아니라 `ResponseEntityExceptionHandler` 상속으로 커스터마이징하기

Spring 6는 `MethodArgumentNotValidException` 같은 내부 예외도 `ProblemDetail`로 응답할 수 있지만, 기본 응답에는 필드 에러 상세가 빠져 클라이언트가 어떤 필드가 왜 틀렸는지 알 수 없다. `ResponseEntityExceptionHandler`를 상속해 `handleMethodArgumentNotValid`를 오버라이드하고 `problemDetail.setProperty("errors", ...)`로 필드별 위반 정보를 채워 넣어야 실무에서 쓸 만해진다.

```java
@RestControllerAdvice
class ApiExceptionHandler extends ResponseEntityExceptionHandler {
    @Override
    protected ResponseEntity<Object> handleMethodArgumentNotValid(
            MethodArgumentNotValidException ex, HttpHeaders h, HttpStatusCode s, WebRequest r) {
        var pd = ProblemDetail.forStatusAndDetail(s, "요청 값이 올바르지 않습니다");
        pd.setProperty("errors", ex.getBindingResult().getFieldErrors().stream()
                .map(fe -> Map.of("field", fe.getField(), "reason", fe.getDefaultMessage()))
                .toList());
        return ResponseEntity.status(s).body(pd);
    }
}
```

> 💡 **왜 중요한가**: 프로퍼티 하나로 켜는 기본 ProblemDetail은 껍데기일 뿐, 필드 단위 검증 실패 정보를 채워야 프론트/모바일에서 실제로 활용 가능한 에러 표준이 된다.
