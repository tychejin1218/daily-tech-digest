### 1. Portal로 띄운 모달 안의 클릭이 "모달 바깥 영역 onClick"에 걸려 모달이 즉시 닫히는 버그 — React 이벤트는 DOM 트리가 아닌 "JSX 트리"를 따라 버블링한다

`createPortal`로 `document.body`에 모달을 띄운 뒤, 부모에 `onClick={() => setOpen(false)}`로 바깥 클릭을 감지하려 하면 **모달 안쪽 버튼 클릭조차 부모의 onClick까지 올라와** 모달이 열리자마자 닫히는 현상이 발생한다. React의 합성 이벤트(SyntheticEvent)는 실제 DOM 위치가 아니라 JSX에서 선언된 **React 컴포넌트 트리**를 기준으로 버블링하기 때문이다. 안전한 해결책은 모달 내부에 `e.stopPropagation()`을 거는 방식보다, `useRef` + `document`의 네이티브 `mousedown` 리스너로 "ref 바깥을 클릭했는지"를 판정하는 쪽이다 — 네이티브 이벤트는 실제 DOM 트리를 따르므로 Portal을 뚫지 않는다.

> 💡 **왜 중요한가**: "DOM상 모달 바깥이면 닫는다"는 직관이 React 이벤트 모델에서는 통하지 않기 때문에, outside-click 로직은 합성 이벤트가 아닌 네이티브 + ref 조합으로 설계해야 한다.

### 2. `children`을 prop으로 넘기면 부모가 리렌더링되어도 자식은 리렌더링되지 않는다 — `React.memo` 없는 "구성(composition) 최적화"

`<Parent><Heavy /></Parent>`처럼 JSX로 자식을 끼워 넣으면 `<Heavy />` 엘리먼트는 **`Parent`가 아니라 그 바깥에서 생성**되기 때문에, `Parent`의 state가 바뀌어도 `children` prop의 참조가 동일하게 유지되어 React 재조정(reconciliation)이 `Heavy`의 서브트리를 건너뛴다. 반대로 `Parent` 내부에서 `<Heavy />`를 직접 렌더링하면 state 변경 시마다 새 엘리먼트가 만들어져 매번 다시 그려진다. 즉 `React.memo`나 `useMemo`를 끼얹지 않아도 "무거운 트리를 바깥에서 주입"하는 구조만으로 리렌더링 경계가 공짜로 생긴다 — 대표 사례가 `<Layout>{page}</Layout>` 패턴에서 Layout의 state가 바뀌어도 page가 다시 그려지지 않는 이유다.

> 💡 **왜 중요한가**: 메모이제이션을 덧바르기 전에 구조부터 바꾸는 것이 React 공식 가이드의 1순위 — "최적화의 가장 저렴한 비용은 코드를 다시 쓰지 않는 것"이라는 원칙의 실천 지점이다.
