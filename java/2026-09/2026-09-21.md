### 1. `Collectors.toUnmodifiableList()`로 `Stream.toList()`와의 미묘한 차이 구분하기 (Java 10 정식)

`Stream.toList()`(Java 16)는 `null` 요소를 허용하는 반면, `Collectors.toUnmodifiableList()`는 `null`을 만나면 즉시 `NullPointerException`을 던진다. 둘 다 불변 리스트를 반환하지만, `null` 방어가 필요한 API 경계에서는 `toUnmodifiableList()`가 더 엄격한 계약을 강제한다.

```java
// Stream.toList() — null 허용, 조용히 통과
List<String> a = Stream.of("x", null, "y").toList();  // OK, [x, null, y]

// Collectors.toUnmodifiableList() — null 즉시 거부
List<String> b = Stream.of("x", null, "y")
    .collect(Collectors.toUnmodifiableList());  // NPE!

// 실무: 외부 API 응답을 DTO 필드에 담을 때
public record UserResponse(List<String> roles) {
    public UserResponse {
        // toList()면 null role이 섞여 들어가 나중에 NPE 폭발
        roles = roles.stream().collect(Collectors.toUnmodifiableList());
    }
}
```

| API | null 허용 | 불변성 | 반환 타입 |
|---|---|---|---|
| `Stream.toList()` | ✅ | ✅ | `List` (수정 시 UOE) |
| `Collectors.toUnmodifiableList()` | ❌ NPE | ✅ | `List` (수정 시 UOE) |
| `Collectors.toList()` | ✅ | ❌ | `ArrayList` (가변) |

> 💡 **왜 중요한가**: "둘 다 불변 리스트니까 아무거나 써도 되겠지"라고 넘기면, `null`이 조용히 흘러 들어가 3단계 아래의 다른 메서드에서 NPE가 터지고 스택 트레이스로는 원인을 찾기 어렵다.

### 2. `Thread.startVirtualThread(Runnable)`로 가상 스레드 1회성 실행의 보일러플레이트 벗어나기 (Java 21 정식)

일회성으로 백그라운드 작업을 던질 때 `Thread.ofVirtual().start(runnable)` 대신 `Thread.startVirtualThread(runnable)` 정적 팩토리 한 줄로 끝낼 수 있다. 재사용할 팩토리나 이름/데몬 설정이 필요 없는 fire-and-forget 시나리오에서 빌더 체인 습관을 벗어나게 해주는 지름길이다.

```java
// Before — 빌더 체인 관성 (재사용 안 하는데 굳이)
Thread.ofVirtual().start(() -> sendMetric(event));
Thread.ofVirtual().unstarted(() -> auditLog(user)).start();

// After — 1회성이면 정적 팩토리로 끝
Thread.startVirtualThread(() -> sendMetric(event));
Thread.startVirtualThread(() -> auditLog(user));

// 실무: 요청 처리 후 부수 효과를 non-blocking으로 발사
@PostMapping("/orders")
public OrderResponse create(@RequestBody OrderRequest req) {
    Order order = orderService.create(req);
    Thread.startVirtualThread(() -> notificationService.notify(order));
    Thread.startVirtualThread(() -> analyticsService.track(order));
    return OrderResponse.from(order);  // 응답은 즉시 반환
}
```

**언제 무엇을 쓸까:**
- `Thread.startVirtualThread()` → 1회성, 이름/설정 불필요
- `Thread.ofVirtual().name("worker-", 0).factory()` → 반복 생성 + 디버깅 위해 이름 필요
- `Executors.newVirtualThreadPerTaskExecutor()` → `Future`/`invokeAll` 등 구조적 제어 필요

> 💡 **왜 중요한가**: 가상 스레드는 "값싼 스레드"라는 특성상 코드 곳곳에서 즉흥적으로 생성되는데, 그때마다 빌더 체인을 쓰면 의도(재사용? 1회성?)가 흐려진다. 정적 팩토리는 "그냥 던진다"는 신호를 코드로 명확히 남긴다.
