### 1. `List.copyOf(collection)` (Java 10 정식)로 `Collections.unmodifiableList(new ArrayList<>(src))` 이중 래핑 관성 벗어나기

`unmodifiableList`는 원본 리스트의 **뷰(view)**를 감싸는 것이라, 원본이 바뀌면 "불변" 사본도 같이 바뀌는 함정이 있다. 그래서 다들 `new ArrayList<>(src)`로 한 번 복사하고 다시 `unmodifiableList`로 감싸는 2단 콤보를 썼는데, `List.copyOf(src)`는 **진짜 복사 + 진짜 불변**을 한 번에 해준다. 보너스: 입력이 이미 불변이면 그대로 재사용해서 할당도 아낀다.

```java
// 관성
List<String> safe = Collections.unmodifiableList(new ArrayList<>(src));

// Java 10+
List<String> safe = List.copyOf(src);  // null 원소 있으면 NPE
```

> 💡 **왜 중요한가**: 방어적 복사(defensive copy)의 표준 숙어가 1줄로 축약되고, "불변인 줄 알았는데 원본 변경이 새어 들어오는" 가장 흔한 버그 하나가 통째로 사라진다.

### 2. `Objects.requireNonNullElseGet(obj, supplier)` (Java 9 정식)로 `obj != null ? obj : expensiveDefault()` 삼항 관성 벗어나기

`Objects.requireNonNullElse(obj, default)`는 default가 **항상 평가**되기 때문에 디폴트 생성이 비싸면(DB 조회, 리스트 생성, UUID 등) null이 아닐 때도 쓸데없이 돌아간다. `requireNonNullElseGet`은 `Supplier`를 받아 **null일 때만 lazy 평가**한다 — 삼항 연산자를 쓸 수밖에 없던 유일한 이유였던 "지연 평가"가 메서드 쪽으로 넘어온 셈이다.

```java
// 관성 (디폴트 생성 비용 때문에 Objects.requireNonNullElse 못 쓰고 삼항 유지)
List<Order> orders = cache.get(userId) != null
    ? cache.get(userId)
    : orderRepository.findRecentByUser(userId);  // DB 호출

// Java 9+
List<Order> orders = Objects.requireNonNullElseGet(
    cache.get(userId),
    () -> orderRepository.findRecentByUser(userId)  // null일 때만 호출
);
```

> 💡 **왜 중요한가**: "lazy default가 필요하면 삼항, eager면 `requireNonNullElse`" — 이 구분이 서면 null-coalescing 로직을 Optional 체인으로 과잉설계하지 않고 한 줄로 끝낼 수 있다.
