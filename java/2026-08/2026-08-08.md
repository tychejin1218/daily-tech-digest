### 1. `StructuredTaskScope`로 여러 비동기 작업을 하나의 작업 단위로 묶어 관리하기 (Java 25 정식)

여러 개의 병렬 작업을 실행할 때 `ExecutorService` + `Future`는 한 작업이 실패해도 나머지가 계속 돌아가서 리소스가 낭비되고 예외 처리도 파편화됩니다. `StructuredTaskScope.open()`으로 스코프를 열고 `fork()`로 서브태스크를 등록한 뒤 `join()`하면, 하나가 실패할 때 나머지를 자동 취소하거나 모두 완료될 때까지 기다리는 등의 정책을 선언적으로 지정할 수 있습니다.

```java
// 기존: 실패 전파와 취소가 수동
ExecutorService pool = Executors.newFixedThreadPool(2);
Future<User> userF = pool.submit(() -> fetchUser(id));
Future<Order> orderF = pool.submit(() -> fetchOrder(id));
try {
    User u = userF.get();      // orderF가 실패해도 여기서 대기
    Order o = orderF.get();    // 취소 로직을 직접 짜야 함
} finally {
    pool.shutdown();
}

// 개선: 구조화된 동시성으로 한 단위처럼 처리
try (var scope = StructuredTaskScope.open()) {
    Subtask<User> user = scope.fork(() -> fetchUser(id));
    Subtask<Order> order = scope.fork(() -> fetchOrder(id));
    scope.join();  // 하나가 실패하면 나머지 자동 취소
    return new UserOrder(user.get(), order.get());
}
```

> 💡 **왜 중요한가**: 부모 스코프가 닫히면 자식 태스크도 반드시 정리되므로, 스레드 누수와 좀비 태스크가 구조적으로 사라집니다.

### 2. `SequencedCollection`으로 List·Deque·LinkedHashSet의 "첫/끝 원소" 접근을 통일하기 (Java 21 정식)

`List.get(0)`, `Deque.peekFirst()`, `LinkedHashSet`의 첫 원소를 얻으려면 iterator를 돌려야 하는 등, 순서가 있는 컬렉션마다 첫/끝 원소 접근 방식이 제각각이었습니다. Java 21에서 도입된 `SequencedCollection` 인터페이스는 `getFirst()`, `getLast()`, `addFirst()`, `addLast()`, `reversed()`를 공통 API로 제공해서 순서 있는 모든 컬렉션을 동일한 방식으로 다룰 수 있습니다.

```java
// 기존: 타입마다 다른 API
List<String> list = List.of("a", "b", "c");
String firstL = list.get(0);
String lastL  = list.get(list.size() - 1);

LinkedHashSet<String> set = new LinkedHashSet<>(List.of("a", "b", "c"));
String firstS = set.iterator().next();  // 마지막 원소는 순회 필요

// 개선: 공통 API
String firstL2 = list.getFirst();
String lastL2  = list.getLast();
String firstS2 = set.getFirst();
String lastS2  = set.getLast();

// 역순 뷰도 표준화
for (String s : list.reversed()) { ... }
```

> 💡 **왜 중요한가**: 컬렉션 구현체가 바뀌어도 호출부 코드는 그대로 유지되어, 리팩터링 비용과 인덱스 계산 실수가 함께 사라집니다.
