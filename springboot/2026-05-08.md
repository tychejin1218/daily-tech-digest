### `@HttpExchange` 인터페이스로 선언적 HTTP 클라이언트 정의하기

Spring 6+에서 제공하는 `@HttpExchange` 어노테이션을 인터페이스에 선언하면, `HttpServiceProxyFactory`가 `RestClient`/`WebClient` 기반의 구현체를 런타임에 자동 생성해줍니다. Feign처럼 외부 API 호출을 타입 안전한 메서드 시그니처로 표현할 수 있어, URL 조립이나 응답 파싱 보일러플레이트가 사라지고 테스트 시에는 인터페이스 자체를 모킹하면 됩니다.

```java
public interface PaymentClient {
    @GetExchange("/payments/{id}")
    Payment findById(@PathVariable String id);
}

@Bean
PaymentClient paymentClient(RestClient.Builder builder) {
    RestClient client = builder.baseUrl("https://api.pay.example").build();
    return HttpServiceProxyFactory.builderFor(RestClientAdapter.create(client))
        .build()
        .createClient(PaymentClient.class);
}
```

> 💡 **왜 중요한가**: 외부 API 호출 코드가 도메인 의도 그대로 드러나고, 별도 라이브러리(Feign 등) 없이 Spring 표준만으로 선언적 클라이언트를 구현할 수 있습니다.

### `ProblemDetail`로 RFC 7807 표준 에러 응답 일관화하기

Spring 6부터 표준화된 `ProblemDetail`(RFC 7807)을 `@ExceptionHandler`에서 반환하면, `type`/`title`/`status`/`detail`/`instance` 필드가 포함된 일관된 에러 본문을 자동으로 만들어 줍니다. `@ControllerAdvice`가 `ResponseEntityExceptionHandler`를 상속하면 `MethodArgumentNotValidException` 같은 프레임워크 예외도 동일한 포맷으로 응답되어, 클라이언트(프론트엔드, 모바일)가 단일 파서로 모든 에러를 처리할 수 있게 됩니다.

```java
@RestControllerAdvice
class ApiExceptionHandler extends ResponseEntityExceptionHandler {
    @ExceptionHandler(OrderNotFoundException.class)
    ProblemDetail handle(OrderNotFoundException e) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
        pd.setType(URI.create("https://errors.example.com/order-not-found"));
        pd.setProperty("orderId", e.getOrderId());
        return pd;
    }
}
```

> 💡 **왜 중요한가**: 프로젝트마다 제각각이던 에러 DTO 대신 업계 표준 포맷을 채택하면, API 게이트웨이·관측 도구·클라이언트 SDK가 별도 매핑 없이 에러 의미를 해석할 수 있습니다.
