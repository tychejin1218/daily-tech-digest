### 1. useOptimistic (React 19): "서버 응답을 기다리기 전에 UI를 먼저 바꾸는" 선언적 낙관적 업데이트

좋아요·댓글 등록·투표처럼 서버가 거의 성공할 액션에서 응답을 기다리면 UX가 "멈춘 것처럼" 보인다. `useOptimistic(state, updateFn)`은 트랜지션이 진행되는 동안에만 유효한 "가상 상태"를 반환하고, 액션이 성공하든 실패하든 끝나면 자동으로 원래 state로 되돌아간다 — 수동 롤백 코드가 사라진다.

> 💡 **왜 중요한가**: 과거엔 "임시 state 삽입 → try/catch → 실패 시 이전 값 복원"이라는 10줄짜리 보일러플레이트가 필요했는데, 이제 2줄로 끝나고 복구가 React Transition에 묶여 자동으로 처리된다.

### 2. React.lazy + Suspense: 라우트 하나 때문에 초기 번들이 2MB를 넘는 문제의 해결사

관리자 페이지·차트 라이브러리·에디터처럼 "대부분 사용자가 안 들어가는" 화면이 초기 번들에 포함되면 첫 페이지 로딩이 급격히 느려진다. `const Admin = React.lazy(() => import('./Admin'))`로 감싸고 `<Suspense fallback={<Spinner/>}>` 아래 두면, 그 컴포넌트가 실제로 렌더링될 시점에만 해당 chunk가 네트워크로 fetch된다.

> 💡 **왜 중요한가**: 코드 스플리팅을 Webpack 설정이 아니라 "컴포넌트 import 한 줄"로 처리하는 React의 선언적 API — 라우터 레벨에만 적용해도 초기 로딩이 2~3배 빨라지는 경우가 흔하다.
