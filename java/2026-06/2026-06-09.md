### `Stream.mapMulti()`로 flatMap보다 가볍게 1:N 변환하기 (Java 16 정식)

`flatMap`은 요소마다 새로운 `Stream` 객체를 생성해야 하지만, `mapMulti((element, downstream) -> ...)`는 `Consumer`에 직접 결과를 밀어 넣어 중간 스트림 할당을 건너뜁니다. 변환 결과가 0~소수 개이거나 조건부로 방출해야 할 때, 또는 원시 타입 변환(`mapMultiToInt` 등)이 필요할 때 성능과 가독성 모두에서 이득을 봅니다.

```java
List<Integer> result = Stream.of("1,2", "skip", "3,4,5")
    .<Integer>mapMulti((s, downstream) -> {
        if (s.equals("skip")) return;
        for (String part : s.split(",")) {
            downstream.accept(Integer.parseInt(part));
        }
    })
    .toList();
// [1, 2, 3, 4, 5]
```

> 💡 **왜 중요한가**: 1:N 변환에서 가장 흔한 핫스팟인 "요소마다 임시 Stream 생성" 오버헤드를 제거해 GC 부담을 줄여줍니다.

### `HttpClient`의 `sendAsync()` + `BodyHandlers.ofLines()`로 SSE/스트리밍 응답 처리하기 (Java 11 정식)

서드파티 SSE 라이브러리 없이도 표준 `java.net.http.HttpClient`만으로 LLM API나 서버-센트 이벤트 같은 라인 단위 스트리밍 응답을 처리할 수 있습니다. `BodyHandlers.ofLines()`는 응답 본문을 `Stream<String>`으로 노출하며, 각 라인이 도착하는 즉시 lazy하게 소비할 수 있어 메모리 사용량이 일정합니다.

```java
HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder(URI.create("https://api.example.com/stream"))
    .header("Accept", "text/event-stream")
    .build();

client.sendAsync(req, HttpResponse.BodyHandlers.ofLines())
    .thenAccept(resp -> resp.body()
        .filter(line -> line.startsWith("data: "))
        .map(line -> line.substring(6))
        .forEach(System.out::println));
```

> 💡 **왜 중요한가**: 외부 의존성 없이 JDK 표준 라이브러리만으로 실시간 스트리밍 응답을 처리할 수 있어 LLM/SSE 연동 코드가 훨씬 단순해집니다.
