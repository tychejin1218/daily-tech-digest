### 1. `@MockitoBean`과 `@MockitoSpyBean`으로 Spring Boot 3.4+ 테스트 더블 선언하기

Spring Boot 3.4부터 기존 `@MockBean`/`@SpyBean`은 deprecated 되고 Spring Framework 6.2의 `@MockitoBean`/`@MockitoSpyBean`이 표준으로 자리 잡았다. 단순 이름 변경처럼 보이지만 컨텍스트 캐시 키 계산이 개선되어 같은 모킹 구성을 쓰는 테스트끼리 컨텍스트를 재사용할 수 있고, `enforceOverride` 속성으로 "오버라이드 대상 빈이 반드시 존재해야 함"을 강제할 수 있다.

```java
@SpringBootTest
class OrderServiceTest {

    @MockitoBean(enforceOverride = true)
    PaymentGateway paymentGateway;

    @MockitoSpyBean
    OrderRepository orderRepository;

    @Test
    void 결제_실패_시_주문은_롤백된다() {
        given(paymentGateway.charge(any())).willThrow(new PaymentException());
        // ...
        verify(orderRepository, never()).save(any());
    }
}
```

> 💡 **왜 중요한가**: deprecated 애너테이션을 그대로 두면 6.x 메이저 업그레이드 시 일괄 변경 부담이 커지고, 새 애너테이션은 컨텍스트 캐시 적중률까지 끌어올려 테스트 부팅 시간이 줄어든다.

### 2. `server.shutdown=graceful`과 `spring.lifecycle.timeout-per-shutdown-phase`로 인플라이트 요청 보존하기

기본값(`immediate`)에서는 SIGTERM 수신 즉시 커넥터가 닫혀 처리 중이던 HTTP 요청이 502/끊김으로 끝난다. `server.shutdown=graceful`을 켜면 새 요청은 거부(503)하고 진행 중 요청은 완료를 기다리며, `spring.lifecycle.timeout-per-shutdown-phase`(기본 30초)로 단계별 타임아웃을 조정한다. K8s 환경이라면 `preStop` 훅으로 짧은 슬립을 두어 엔드포인트 제거 전파를 기다리는 패턴과 함께 써야 안전하다.

```yaml
server:
  shutdown: graceful
spring:
  lifecycle:
    timeout-per-shutdown-phase: 25s
  task:
    execution:
      shutdown:
        await-termination: true
        await-termination-period: 20s
```

> 💡 **왜 중요한가**: 무중단 배포·오토스케일링 환경에서 SIGTERM이 일상적으로 발생하므로, 그레이스풀 종료가 켜져 있어야 롤링 업데이트마다 사용자에게 보이는 5xx가 사라진다.
