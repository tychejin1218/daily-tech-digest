### 1. `React.memo`로 감싼 컴포넌트가 리렌더링을 멈추지 못하는 이유 — "얕은 비교"의 함정과 props에 숨은 인라인 객체

`React.memo`는 부모가 리렌더링되어도 자식의 리렌더링을 막아주는 HOC처럼 보이지만, 실제로는 props의 **얕은 비교(shallow equality)** 결과에 따라 동작한다. 부모에서 `<Child style={{ color: 'red' }} onClick={() => {}} />`처럼 인라인 객체/함수를 넘기면 매 렌더마다 참조가 바뀌므로 memo는 무력화되고, 개발자는 "왜 memo가 안 먹지?"라며 좌절한다. 해결책은 `useMemo`/`useCallback`으로 참조를 안정화하거나, 애초에 props로 원시값만 넘기도록 컴포넌트 경계를 다시 긋는 것이다.

```jsx
// ❌ memo 무력화: style 객체가 매 렌더마다 새로 생성됨
<MemoizedChild style={{ color: 'red' }} />

// ✅ 참조 안정화
const style = useMemo(() => ({ color: 'red' }), []);
<MemoizedChild style={style} />
```

> 💡 **왜 중요한가**: `React.memo`는 "리렌더링 방지 마법"이 아니라 "참조 동일성 체크기"일 뿐이다 — props 참조를 다스리지 못하면 memo로 감싼 모든 컴포넌트가 비용만 늘리는 장식이 된다.

### 2. `useEffect` 안에서 `setState`를 호출할 때 "무한 루프"가 터지는 메커니즘 — 의존성 배열과 상태 업데이트의 악순환

`useEffect(() => { setCount(count + 1); }, [count])`처럼 상태를 업데이트하는 effect가 그 상태에 의존하면, "effect → setState → 리렌더 → effect 재실행"의 무한 루프가 발생한다. 초보자가 가장 많이 당하는 함정이며, React DevTools에서 "Maximum update depth exceeded" 에러로 폭발한다. 해결 패턴은 세 가지 중 하나다: (1) 의존성 배열에서 해당 상태를 제거하고 함수형 업데이트 `setCount(c => c + 1)` 사용, (2) 조건을 걸어 특정 상황에서만 업데이트, (3) 애초에 effect 없이 **파생 상태**로 계산.

```jsx
// ❌ 무한 루프
useEffect(() => {
  setCount(count + 1);
}, [count]);

// ✅ 함수형 업데이트 + 조건
useEffect(() => {
  if (shouldIncrement) {
    setCount(c => c + 1);
  }
}, [shouldIncrement]);

// ✅✅ 더 나은 해법: effect 없이 렌더링 중에 계산
const displayCount = count + offset;
```

> 💡 **왜 중요한가**: `useEffect`는 "렌더링의 부수효과"를 선언하는 도구인데, 그 안에서 또 렌더링을 트리거하면 React의 흐름 자체를 역류시킨다 — 대부분의 "useEffect + setState" 조합은 애초에 effect가 필요 없는 **파생값 계산**으로 대체 가능하다.
