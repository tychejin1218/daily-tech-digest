### `Collectors.filtering()`으로 그룹화 후 조건에 맞는 요소만 골라 모으기 (Java 9 정식)

`groupingBy`로 묶은 뒤 `filtering`을 다운스트림 컬렉터로 넘기면, 각 그룹 안에서 조건에 맞는 요소만 남길 수 있습니다. 스트림 단계에서 미리 `filter`를 걸면 빈 그룹이 사라져 키가 누락되는 문제가 생기는데, `Collectors.filtering()`은 모든 그룹 키를 유지하면서 빈 리스트로라도 결과를 남겨줍니다.

```java
Map<Department, List<Employee>> seniorByDept = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::department,
        Collectors.filtering(e -> e.years() >= 10, Collectors.toList())
    ));
```

> 💡 **왜 중요한가**: "그룹별 합계/필터"를 SQL의 `GROUP BY ... HAVING` 흐름처럼 자연스럽게 표현할 수 있고, 빈 그룹 누락이라는 미묘한 버그를 예방해줍니다.

### `ScopedValue`로 ThreadLocal을 대체해 가상 스레드 친화적인 컨텍스트 전달하기 (Java 21 프리뷰, 24에서 정식 후보)

`ScopedValue`는 `ThreadLocal`과 달리 불변이고 명시적 스코프(`where(...).run(...)`) 안에서만 값이 보이도록 제한합니다. 가상 스레드를 수백만 개 띄울 때 `ThreadLocal`이 메모리/누수 부담을 주는 문제를 해결하면서, 자식 작업으로의 상속도 구조적 동시성과 자연스럽게 맞물려 동작합니다.

```java
private static final ScopedValue<UserId> CURRENT_USER = ScopedValue.newInstance();

ScopedValue.where(CURRENT_USER, userId).run(() -> {
    // 이 블록과 자식 가상 스레드에서만 CURRENT_USER.get() 가능
    service.handleRequest();
});
```

> 💡 **왜 중요한가**: 요청 컨텍스트(인증 정보, 트레이스 ID 등)를 가상 스레드 환경에서도 안전하게 전달할 수 있어, ThreadLocal 제거 없이 가상 스레드의 확장성을 온전히 누릴 수 있습니다.
