### `Files.mismatch()`로 두 파일의 내용 차이를 효율적으로 비교하기 (Java 12 정식)

`Files.mismatch(Path, Path)`는 두 파일을 바이트 단위로 비교해서 처음으로 일치하지 않는 위치(인덱스)를 반환하고, 완전히 동일하면 `-1L`을 반환합니다. 전체 파일을 메모리에 로드하지 않고 내부적으로 버퍼링하며 비교하므로 대용량 파일에서도 안전하며, 크기가 다른 경우 짧은 파일의 길이를 반환해 조기 종료까지 처리해 줍니다.

```java
long pos = Files.mismatch(Path.of("a.bin"), Path.of("b.bin"));
if (pos == -1L) {
    System.out.println("동일한 파일입니다");
} else {
    System.out.println(pos + " 바이트 위치에서 차이 발견");
}
```

> 💡 **왜 중요한가**: 해시 계산이나 수동 InputStream 비교 코드를 한 줄로 대체할 수 있으며, 차이가 발생한 정확한 오프셋까지 알려줘 디버깅에 유리합니다.

### `Optional.or()`로 빈 `Optional`에 대한 폴백 체인을 깔끔하게 구성하기 (Java 9 정식)

`Optional.or(Supplier<Optional<T>>)`는 현재 `Optional`이 비어 있을 때만 대체 `Optional`을 평가하므로, 여러 소스에서 값을 순차적으로 조회하는 폴백 로직을 if-else 없이 표현할 수 있습니다. `orElse()`나 `orElseGet()`이 `T`를 반환하는 것과 달리 `or()`은 `Optional<T>`를 그대로 유지해 추가 연산 체인을 이어갈 수 있다는 점이 핵심입니다.

```java
Optional<User> user = findInCache(id)
    .or(() -> findInDatabase(id))
    .or(() -> findInRemoteApi(id));

user.map(User::getName).ifPresent(System.out::println);
```

> 💡 **왜 중요한가**: 캐시 → DB → 외부 API처럼 계층적 조회가 흔한 백엔드 코드에서 중첩 if문이나 임시 변수 없이 지연 평가가 보장된 폴백 체인을 만들 수 있어 가독성과 성능이 동시에 개선됩니다.
