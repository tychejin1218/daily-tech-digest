### `@ServiceConnection`으로 Testcontainers와 Spring Boot 연결 자동 구성하기

Spring Boot 3.1부터 추가된 `@ServiceConnection`을 Testcontainers 컨테이너 빈에 붙이면, `spring.datasource.url`이나 `spring.data.redis.host` 같은 프로퍼티를 `@DynamicPropertySource`로 일일이 매핑하지 않아도 컨테이너 메타데이터를 보고 Spring이 자동으로 연결 정보를 구성한다. PostgreSQL, MySQL, MongoDB, Redis, Kafka, RabbitMQ 등 주요 컨테이너에 대해 `ConnectionDetails` 빈이 등록되어 보일러플레이트가 크게 줄어든다.

```java
@TestConfiguration(proxyBeanMethods = false)
class TestcontainersConfig {
    @Bean
    @ServiceConnection
    PostgreSQLContainer<?> postgres() {
        return new PostgreSQLContainer<>("postgres:16-alpine");
    }
}
```

> 💡 **왜 중요한가**: 컨테이너 정의와 Spring 설정 매핑이 한 줄로 묶여, 테스트 환경 구축 코드가 짧고 깨지지 않는다.

### `@EntityGraph`로 JPA 연관 엔티티의 N+1 쿼리 제거하기

`LAZY` 연관을 가진 엔티티를 리스트로 조회하면 컬렉션 접근 시점마다 추가 SQL이 발생하는 N+1 문제가 생기는데, Spring Data JPA의 `@EntityGraph(attributePaths = ...)`를 리포지토리 메서드에 선언하면 해당 호출에 한해 fetch join이 적용된 단일 쿼리로 묶어 가져온다. JPQL `fetch join`을 직접 쓰는 것보다 가독성이 좋고, 같은 엔티티에 대해 호출 경로별로 다른 그래프 전략을 선택할 수 있다는 점이 장점이다.

```java
public interface OrderRepository extends JpaRepository<Order, Long> {

    @EntityGraph(attributePaths = {"items", "customer"})
    List<Order> findByStatus(OrderStatus status);
}
```

> 💡 **왜 중요한가**: 도메인 매핑은 `LAZY`로 안전하게 두면서, 호출별로 필요한 연관만 한 번의 쿼리로 끌어와 성능 저하를 막을 수 있다.
