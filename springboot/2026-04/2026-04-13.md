### `@DynamicUpdate`로 변경된 컬럼만 UPDATE 쿼리에 포함시키기

Hibernate는 기본적으로 엔티티의 모든 컬럼을 UPDATE 문에 포함하는데, 컬럼이 많거나 인덱스가 걸린 컬럼이 많은 테이블에서는 불필요한 오버헤드가 된다. `@DynamicUpdate`를 붙이면 실제 변경된(더티) 필드만 SET 절에 포함하는 동적 SQL이 실행되어, 특히 넓은 테이블에서 락 경합과 인덱스 재계산을 줄일 수 있다.

```java
@Entity
@DynamicUpdate
public class Product {
    @Id
    private Long id;
    private String name;
    private BigDecimal price;
    private String description; // TEXT 컬럼
    private LocalDateTime updatedAt;
    // price만 바꿔도 기본 동작에서는 name, description까지 UPDATE 문에 포함됨
}
```

> 💡 **왜 중요한가**: 컬럼이 많은 엔티티에서 매 수정마다 전체 컬럼을 갱신하면 인덱스 갱신 비용과 옵티미스틱 락 충돌 확률이 함께 늘어난다.

### `spring-boot-devtools`의 `Restart` vs `Reload` — LiveReload로 프론트 리소스는 재시작 없이 반영하기

devtools의 `spring-boot-devtools` 의존성은 클래스패스 변경 시 애플리케이션을 자동 재시작(Restart)해 개발 생산성을 높이지만, 정적 리소스(`static/`, `templates/`)만 바뀐 경우에도 매번 전체 재시작이 일어난다면 낭비다. `spring.devtools.restart.exclude=static/**,public/**,templates/**`로 정적 자원을 제외 목록에 넣고, 내장 LiveReload 서버(35729 포트)를 브라우저 확장에 연결하면 재시작 없이 브라우저만 새로고침되어 훨씬 빠른 피드백 루프를 얻는다.

```properties
spring.devtools.restart.enabled=true
spring.devtools.restart.exclude=static/**,public/**,templates/**,META-INF/resources/**
spring.devtools.livereload.enabled=true
```

> 💡 **왜 중요한가**: Restart는 클래스로더를 새로 띄우는 무거운 작업이므로, 재시작이 불필요한 리소스는 LiveReload로 분리해야 실제 개발 속도가 살아난다.
