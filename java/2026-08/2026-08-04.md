### `Collectors.toUnmodifiableList()`로 스트림 결과를 바로 불변 리스트로 수집하기 (Java 10 정식)

기존 `Collectors.toList()`는 구현체가 `ArrayList`로 보장되어 수정이 가능한 리스트를 반환했습니다. `Collectors.toUnmodifiableList()`를 쓰면 수집 즉시 `UnsupportedOperationException`을 던지는 불변 리스트로 만들 수 있어, DTO나 응답 객체에 담기 전 방어적 복사를 별도로 할 필요가 없습니다. `null` 요소는 허용되지 않기 때문에 실수로 `null`이 섞이면 수집 단계에서 바로 실패합니다.

```java
List<String> names = users.stream()
    .map(User::getName)
    .filter(Objects::nonNull)
    .collect(Collectors.toUnmodifiableList());
// names.add("x") → UnsupportedOperationException
```

> 💡 **왜 중요한가**: API 경계에서 "이 리스트는 수정하면 안 됩니다"를 주석이 아닌 타입 계약으로 강제할 수 있어, 호출자의 실수로 인한 공유 상태 오염을 컴파일 이후 런타임까지 방어할 수 있습니다.

### `IntStream.range()` + `mapToObj()`로 인덱스가 필요한 순회를 함수형으로 처리하기 (Java 8 정식)

`for (int i = 0; i < list.size(); i++)` 패턴을 스트림으로 옮기려 할 때 가장 흔한 걸림돌이 "인덱스가 필요한 경우"입니다. `IntStream.range(0, list.size()).mapToObj(i -> ...)` 조합으로 인덱스와 요소를 함께 다루는 스트림을 구성할 수 있어, 순번이 있는 CSV 생성이나 순위 표기, `List<Pair>` 조립 같은 상황에서 명령형 루프 없이 파이프라인을 유지할 수 있습니다.

```java
List<String> ranked = IntStream.range(0, players.size())
    .mapToObj(i -> (i + 1) + "위: " + players.get(i).getName())
    .collect(Collectors.toUnmodifiableList());
// ["1위: Alice", "2위: Bob", "3위: Charlie"]
```

> 💡 **왜 중요한가**: "스트림에서는 인덱스를 못 쓴다"는 착각을 깨는 관용구로, 명령형 루프와 함수형 파이프라인을 오가는 컨텍스트 스위칭 비용을 없애 코드 일관성을 유지할 수 있습니다.
