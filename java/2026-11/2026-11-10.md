### 1. `Collectors.teeing(downstream1, downstream2, merger)` (Java 12 정식)로 한 번의 스트림 순회로 두 집계 합치기 — 스트림을 두 번 돌리거나 중간 리스트에 받아 다시 집계하는 관성 벗어나기

평균과 최댓값, 합과 개수처럼 "같은 데이터에서 두 가지 결과를 뽑아 하나로 합쳐야" 할 때 대부분 `stream.collect(averagingInt(...))` 한 번, `stream.collect(maxBy(...))` 한 번 — 이렇게 두 번 돌리거나 일단 `toList()`로 받아서 for 루프로 재집계합니다. `teeing`은 두 downstream collector를 **동시에** 적용한 뒤 merger로 결과를 합쳐주는 공식 수집기라, 소스가 무거운 스트림(DB, 파일, 네트워크)이거나 터미널 연산이라 재사용 불가능한 상황에서 특히 강력합니다.

```java
// 관성: 스트림 두 번 돌리기
double avg = orders.stream().mapToInt(Order::amount).average().orElse(0);
int max = orders.stream().mapToInt(Order::amount).max().orElse(0);
return new Summary(avg, max);

// 개선: 한 번 순회로 두 집계 + 병합
Summary s = orders.stream().collect(Collectors.teeing(
    Collectors.averagingInt(Order::amount),
    Collectors.maxBy(Comparator.comparingInt(Order::amount)),
    (avg, maxOrder) -> new Summary(avg, maxOrder.map(Order::amount).orElse(0))
));
```

> 💡 **왜 중요한가**: 스트림은 1회용이라 "두 가지 뽑기" 문제에서 소스 재스캔이나 중간 리스트 버퍼링을 유도하는데, `teeing`은 메모리 상주 없이 단일 패스로 끝내 성능과 가독성을 동시에 잡는 유일한 표준 수단이다.

### 2. `String.formatted(args)` (Java 15 정식, JEP 378)로 인스턴스 메서드 체이닝 — `String.format(fmt, args)` 정적 호출로 템플릿이 뒤로 밀리는 관성 벗어나기

로그 메시지, SQL, 예외 메시지에서 `String.format("user=%s id=%d", name, id)`를 쓰면 **템플릿 문자열이 메서드 이름에 가려** 시선이 한 번 꺾입니다. 특히 텍스트 블록(`"""`)과 조합하면 `String.format("""...""", a, b, c)` 처럼 긴 리터럴이 괄호 안에 갇혀 포매팅 역시 어색해집니다. `formatted`는 템플릿을 주어 자리에 놓고 인자만 뒤로 보내 **"무엇을 포매팅하는가 → 무엇으로 채우는가"** 자연스러운 왼→오 흐름을 만듭니다.

```java
// 관성: 템플릿이 괄호 안으로 밀려 들어감
log.warn(String.format("""
    [REJECT] user=%s reason=%s retry=%d
    """, user.name(), reason, retryCount));

// 개선: 템플릿 주어 + 인스턴스 메서드로 흐름 유지
log.warn("""
    [REJECT] user=%s reason=%s retry=%d
    """.formatted(user.name(), reason, retryCount));
```

> 💡 **왜 중요한가**: 가독성은 토큰 순서에 민감해서 "템플릿이 먼저, 치환값이 나중" 순서가 리뷰 속도를 눈에 띄게 올려주며, 텍스트 블록이 도입된 Java 15+ 코드베이스에서는 사실상 표준 관용구다.
