### 1. `Optional`의 `orElseThrow()`와 `ifPresentOrElse()`로 명시적 분기 처리하기

`Optional.get()`은 값이 없을 때 `NoSuchElementException`을 던지므로 의도가 불명확하지만, `orElseThrow(() -> new CustomException(...))`을 사용하면 비즈니스 예외를 명시적으로 표현할 수 있습니다. 또한 Java 9에서 추가된 `ifPresentOrElse(action, emptyAction)`은 값이 있을 때와 없을 때의 동작을 한 번의 호출로 분리해 가독성을 높여줍니다. 단, `Optional`은 메서드 반환 타입에만 사용하고 필드나 파라미터로는 쓰지 않는 것이 권장됩니다.

> 💡 **왜 중요한가**: `null` 체크와 `Optional.get()`이 뒤섞인 코드는 NPE 위험을 줄이지 못하므로, `Optional`의 분기 메서드를 적극 활용해야 그 도입 효과를 제대로 볼 수 있습니다.

### 2. `CompletableFuture`의 `orTimeout()`과 `completeOnTimeout()`으로 비동기 작업 타임아웃 안전하게 제어하기

Java 9에서 추가된 `orTimeout(Duration)`은 지정 시간 내에 완료되지 않으면 `TimeoutException`으로 future를 실패시키고, `completeOnTimeout(value, Duration)`은 타임아웃 시 기본값으로 정상 완료시킵니다. 이전에는 별도의 `ScheduledExecutorService`로 타이머를 직접 관리해야 했지만, 이제 한 줄로 외부 API 호출의 응답 지연을 차단할 수 있습니다. 두 메서드 모두 새로운 stage를 반환하므로 체이닝의 어느 위치에든 끼워 넣을 수 있습니다.

```java
CompletableFuture.supplyAsync(() -> callExternalApi())
    .orTimeout(3, TimeUnit.SECONDS)
    .exceptionally(ex -> "fallback");
```

> 💡 **왜 중요한가**: 외부 시스템과의 비동기 통신에서 타임아웃 누락은 스레드 고갈과 장애 전파의 주범이므로, 표준 API로 간결하게 방어선을 구축할 수 있어야 합니다.
