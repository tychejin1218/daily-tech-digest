### `Duration` / `Instant`로 시간 계산을 안전하게 — `long` 밀리초 산술은 이제 그만 (Java 8 정식)
`System.currentTimeMillis()`나 `long` 변수로 시간을 다루면 단위(ms vs ns), 시간대, 음수 결과, 오버플로우 같은 함정이 줄줄이 따라옵니다. `Instant`로 시점을, `Duration`으로 길이를 표현하면 단위와 의미가 코드에 박혀 표시되고, `between()`·`plus()`·`abs()` 같은 메서드로 산술이 안전해집니다.

```java
Instant start = Instant.now();
doWork();
Duration elapsed = Duration.between(start, Instant.now());

if (elapsed.compareTo(Duration.ofSeconds(2)) > 0) {
    log.warn("slow: {} ms", elapsed.toMillis());
}

Instant deadline = Instant.now().plus(Duration.ofMinutes(30));
```

> 💡 **왜 중요한가**: 타임아웃·SLA·재시도 백오프처럼 "시간 길이"가 비즈니스 로직인 곳에서 단위 실수를 컴파일러가 잡아주고, 분산 추적·로그의 시각 표현도 ISO-8601로 자연스럽게 통일됩니다.

### `BigDecimal.setScale(scale, RoundingMode)`로 금융 계산의 반올림 누락 막기 (Java 5+ `RoundingMode`)
`BigDecimal`은 부동소수점 오차는 없지만, `divide()`처럼 나누어떨어지지 않는 연산은 `ArithmeticException("Non-terminating decimal expansion")`을 던집니다. 곱·합·나눗셈 결과를 화면·DB에 내보내기 전에 항상 `setScale(scale, RoundingMode.HALF_UP)`으로 자릿수와 반올림 모드를 명시해야 합니다.

```java
BigDecimal price = new BigDecimal("19900");
BigDecimal vatRate = new BigDecimal("0.10");

BigDecimal vat = price.multiply(vatRate)            // 1990.00
                      .setScale(0, RoundingMode.HALF_UP); // 원 단위로 반올림 → 1990

// 1/3 같은 무한소수는 scale을 안 주면 예외
BigDecimal third = BigDecimal.ONE.divide(new BigDecimal("3"),
                                         10, RoundingMode.HALF_EVEN);
```

> 💡 **왜 중요한가**: 결제·정산·세금처럼 1원 오차가 감사 대상이 되는 도메인에서, "반올림은 어디서 일어났는가"가 코드에 명시되어 회계 검증과 회귀 테스트가 쉬워집니다.
