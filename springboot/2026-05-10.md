### 1. `FilterRegistrationBean`으로 서블릿 필터 등록 순서와 URL 패턴 명시적으로 제어하기

`@Component`로 `Filter`를 노출하면 Spring Boot가 자동 등록하지만, 적용 순서와 매칭 경로는 알 수 없는 기본값에 맡겨진다. `FilterRegistrationBean<T>`을 빈으로 등록하면 `setOrder()`, `setUrlPatterns()`, `setDispatcherTypes()`로 명시 제어할 수 있고, 자동 등록을 막으려면 필터 클래스 자체에 `@Component`를 붙이지 않거나 `setEnabled(false)`로 끄면 된다.

```java
@Bean
FilterRegistrationBean<RequestIdFilter> requestIdFilter() {
    var reg = new FilterRegistrationBean<>(new RequestIdFilter());
    reg.setUrlPatterns(List.of("/api/*"));
    reg.setOrder(Ordered.HIGHEST_PRECEDENCE + 10);
    reg.setDispatcherTypes(DispatcherType.REQUEST, DispatcherType.ASYNC);
    return reg;
}
```

> 💡 **왜 중요한가**: 인증/로깅/추적 필터가 의도한 순서로 동작하지 않으면 보안 우회나 MDC 누락 같은 미묘한 버그가 생기는데, 명시적 등록은 그 추적 비용을 0으로 만든다.

### 2. Spring Boot 3.4+ 내장 Structured Logging으로 JSON 로그를 한 줄 설정으로 활성화하기

Spring Boot 3.4부터 `logback-spring.xml`이나 별도 라이브러리(`logstash-logback-encoder` 등) 없이 `application.yml`에 `logging.structured.format.console=ecs`(또는 `gelf`, `logstash`) 한 줄만 추가하면 콘솔 출력이 즉시 JSON으로 전환된다. 파일 출력에는 `logging.structured.format.file`을, 커스텀 필드는 `LoggingStructuredLoggingJsonMembersCustomizer` 빈으로 추가한다.

```yaml
logging:
  structured:
    format:
      console: ecs
      file: ecs
    ecs:
      service:
        name: order-api
        version: 1.4.0
  file:
    name: logs/app.log
```

> 💡 **왜 중요한가**: 의존성·XML 설정 없이 ELK/Loki/Datadog가 즉시 파싱 가능한 구조화 로그를 얻을 수 있어, 로그 파이프라인 도입 비용이 크게 줄어든다.
