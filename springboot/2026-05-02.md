### `@TransactionalOperator`로 명령형 코드에서 프로그래밍 방식 트랜잭션 제어하기

`@Transactional` 어노테이션은 메서드 단위로만 동작하기 때문에, 메서드 내부의 일부 블록만 트랜잭션으로 묶거나 별도 전파 속성으로 실행하고 싶을 때는 한계가 있습니다. Spring 6의 `TransactionalOperator`(또는 `TransactionTemplate`)를 사용하면 람다 블록 단위로 트랜잭션 경계를 명시적으로 제어할 수 있어, 외부 API 호출 같은 비-DB 작업을 트랜잭션 밖으로 빼내거나 부분 롤백 로직을 깔끔하게 표현할 수 있습니다.

> 💡 **왜 중요한가**: 트랜잭션 경계를 코드로 표현하면 "어디까지가 DB 트랜잭션인가"가 명시화되어 커넥션 점유 시간과 락 범위를 정확히 통제할 수 있습니다.

---

### `@MockitoBean`으로 Spring Boot 3.4+ 테스트 슬라이스에서 빈 모킹 표준화하기

Spring Boot 3.4부터 `@MockBean`/`@SpyBean`이 deprecated 되고 `@MockitoBean`/`@MockitoSpyBean`이 공식 대체재로 도입되었습니다. 새 어노테이션은 `org.springframework.test.context.bean.override` 패키지의 일관된 Bean Override 메커니즘 위에서 동작하며, `reset` 시점 제어(`MockReset.AFTER`)와 컨텍스트 캐시 충돌 방지가 개선되어 테스트 격리도가 더 높아집니다.

> 💡 **왜 중요한가**: deprecated API를 미리 정리해두면 Boot 3.5+ 업그레이드 시 테스트 코드가 한 번에 깨지는 일을 막을 수 있고, 테스트 컨텍스트 캐시 재활용으로 전체 빌드 시간도 줄어듭니다.
