### PostgreSQL `tablesample` — 대용량 테이블 통계·샘플 쿼리를 초 단위로 끝내기

수억 건 테이블에서 분포 확인·A/B 샘플 추출을 할 때 `SELECT ... ORDER BY random() LIMIT` 은 전체를 스캔해 수분이 걸린다. `TABLESAMPLE SYSTEM(1)`은 1% 블록만 물리적으로 읽어 밀리초 안에 근사 결과를 반환하고, 균일 샘플이 필요하면 더 느리지만 정확한 `BERNOULLI`를 쓸 수 있다.

```sql
-- 1억 건 orders 테이블에서 약 1% 블록 샘플 (< 1초)
SELECT status, COUNT(*) * 100 AS estimated_total
FROM orders TABLESAMPLE SYSTEM(1)
GROUP BY status;

-- 재현 가능한 샘플 (동일 seed → 동일 행)
SELECT * FROM orders TABLESAMPLE BERNOULLI(0.5) REPEATABLE(42);
```

> 💡 **왜 중요한가**: 정확도를 조금 양보하면 대시보드·이상 탐지·데이터 검증 쿼리를 수백 배 빠르게 돌릴 수 있다.

### JPA `@Transactional(readOnly = true)` — 읽기 전용 트랜잭션으로 dirty checking 오버헤드 없애기

Hibernate는 기본적으로 영속 컨텍스트의 모든 엔티티에 대해 커밋 시점에 dirty checking(스냅샷 비교)을 수행한다. `readOnly = true`를 지정하면 스냅샷 자체를 만들지 않아 메모리·CPU를 아끼고, `FlushMode.MANUAL`로 자동 flush도 억제해 예기치 못한 `UPDATE` 발생을 원천 차단한다.

```java
@Transactional(readOnly = true)
public Page<OrderDto> searchOrders(OrderSearchCond cond, Pageable pageable) {
    return orderRepository.search(cond, pageable)
        .map(OrderDto::from);
}
```

> 💡 **왜 중요한가**: 조회 API의 CPU·힙 사용량을 줄이면서, 실수로 엔티티를 수정해도 DB에 반영되지 않아 안전성까지 얻는다.
