### 1. `@TransactionalEventListener(phase = AFTER_COMMIT)`로 트랜잭션 커밋 이후에만 도메인 이벤트 처리하기

`ApplicationEventPublisher.publishEvent()`로 발행한 이벤트를 일반 `@EventListener`로 받으면 트랜잭션이 롤백돼도 리스너가 먼저 실행되어 외부 시스템(메일, 메시지 큐, 외부 API)에 부정합 데이터가 전파될 수 있습니다. `@TransactionalEventListener`의 `phase = AFTER_COMMIT`을 사용하면 커밋이 성공한 후에만 리스너가 실행되어, 비즈니스 트랜잭션과 후처리 사이드 이펙트를 안전하게 분리할 수 있습니다. `AFTER_ROLLBACK`, `BEFORE_COMMIT` 등 단계별 훅도 제공해 보상 트랜잭션 패턴을 구현하기 좋습니다.

```java
@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository repo;
    private final ApplicationEventPublisher publisher;

    @Transactional
    public void place(OrderCommand cmd) {
        Order order = repo.save(Order.from(cmd));
        publisher.publishEvent(new OrderPlacedEvent(order.getId()));
    }
}

@Component
public class OrderNotificationListener {
    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onPlaced(OrderPlacedEvent event) {
        // 커밋이 확정된 후에만 실행되므로 롤백된 주문에 대한 알림이 발송되지 않음
        mailClient.sendOrderConfirmation(event.orderId());
    }
}
```

> 💡 **왜 중요한가**: "DB는 롤백됐는데 결제 알림 메일은 이미 나갔다" 같은 이중 쓰기(dual-write) 부정합을 코드 수정 없이 어노테이션 한 줄로 차단할 수 있습니다.

### 2. `JdbcClient`로 `JdbcTemplate`을 대체하는 Fluent SQL API 사용하기

Spring Framework 6.1(Boot 3.2+)부터 도입된 `JdbcClient`는 `JdbcTemplate`과 `NamedParameterJdbcTemplate`의 기능을 통합한 Fluent API로, `param().param().query().single()` 처럼 메서드 체이닝으로 SQL 실행 흐름을 자연스럽게 표현합니다. `RowMapper`를 직접 구현하지 않아도 `mappedTo(Record.class)`로 레코드/POJO에 자동 매핑되며, `optional()`·`single()`·`list()`로 결과 카디널리티를 명시적으로 강제할 수 있어 가독성과 타입 안정성이 모두 향상됩니다.

```java
@Repository
@RequiredArgsConstructor
public class UserDao {
    private final JdbcClient jdbc;

    public Optional<User> findByEmail(String email) {
        return jdbc.sql("SELECT id, email, name FROM users WHERE email = :email")
                   .param("email", email)
                   .query(User.class)
                   .optional();
    }

    public int updateName(long id, String name) {
        return jdbc.sql("UPDATE users SET name = :name WHERE id = :id")
                   .param("name", name)
                   .param("id", id)
                   .update();
    }
}
```

> 💡 **왜 중요한가**: JPA를 쓰기엔 과한 단순 조회/배치 SQL에서 `JdbcTemplate`의 콜백 지옥과 위치 파라미터 실수를 제거해, ORM과 Raw SQL 사이의 회색 영역을 깔끔하게 메웁니다.
