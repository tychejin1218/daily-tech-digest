### 1. CNCF, Cloud Native Buildpacks 정식 Graduation — "Dockerfile 없는 컨테이너"가 드디어 프로덕션 표준이 됐다
CNCF가 8월 11일 Cloud Native Buildpacks(CNB)를 Graduated 프로젝트로 승격시켰다. Heroku가 시작해 Pivotal·Google이 이어온 이 스펙은 소스코드만 던지면 OCI 이미지가 나오는 방식으로, `Dockerfile` 없이도 재현 가능한 빌드·자동 rebase·CVE 패치 자동 반영을 보장한다. 이번 승격으로 GKE·EKS·Heroku·Kpack이 모두 "Graduated 등급"의 공통 파이프라인 위에서 동작하게 됐고, 사내 플랫폼팀의 "골든 이미지" 관리 부담이 사실상 SBOM 검증 한 단계로 축소된다.

> 💡 **왜 중요한가**: `Dockerfile` 관리가 골칫거리였던 200개 서비스 팀의 빌드 파이프라인이 이제 CVE 패치를 "rebase 한 번"으로 재빌드 없이 흡수할 수 있게 됐다는 뜻이다.

### 2. CNCF, Kubernetes Global Balancer(K8gb) Incubating 승격 — DNS 기반 멀티클러스터 로드밸런싱이 "표준 코스"로 들어왔다
CNCF TOC가 8월 K8gb를 Sandbox → Incubating으로 승격시켰다. Istio Multi-Primary나 Cilium ClusterMesh처럼 전용 컨트롤플레인·mTLS 오버레이를 요구하지 않고, **CoreDNS 위에 CRD 한 벌**만 얹어 여러 리전의 클러스터를 하나의 글로벌 DNS 레코드로 묶는 접근을 택했다. AbsaOSS가 오픈소스한 프로젝트가 이제 Adobe·Deutsche Telekom 프로덕션 레퍼런스와 함께 정식 인큐베이팅 궤도에 올랐고, KubeCon NA 2026의 새 트랙 "AI Inference + Agentic"에서 멀티리전 추론 라우팅 사례로 데모될 예정이다.

> 💡 **왜 중요한가**: "서비스 메시부터 깔아야 멀티클러스터가 됩니까?"에 대한 CNCF의 공식 답변이 "아니오, DNS만 있어도 됩니다"로 바뀌었다 — 온프렘 GSLB 어플라이언스(F5 GTM, Infoblox)를 걷어낼 명분이 생겼다.

### 3. Meta Muse Code 공개 — 30B 오픈웨이트에 "네이티브 멀티에이전트 오케스트레이션"이 처음으로 내장됐다
Meta가 Muse Glimmer 후속으로 Muse Code를 오픈웨이트 공개했다. 특징은 프롬프트 레벨이 아니라 **모델 웨이트 자체에 서브에이전트 role 스위칭이 학습된 것** — `planner` / `implementer` / `critic` 토큰이 특수 vocab에 편입돼 있어서, 단일 프로세스 안에서 KV 캐시를 공유한 채로 역할을 스위칭한다. Anthropic이 Claude Code 서브에이전트 60개로 리만 제타 논문을 풀 때 31M 아웃풋 토큰을 태운 것과 대조적으로, Muse Code는 동일 서브에이전트 패턴을 **단일 모델 내에서** 재현해 토큰 비용을 5분의 1 수준으로 압축한다.

> 💡 **왜 중요한가**: "멀티에이전트 = 여러 프로세스"라는 지난 1년의 상식이 깨졌다 — 백엔드 관점에선 서브에이전트 오케스트레이션이 이제 "인프라 문제"가 아니라 "모델 웨이트 선택 문제"로 이동했다는 뜻.
