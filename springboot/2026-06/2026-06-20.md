### `@SpringBootTest(webEnvironment = RANDOM_PORT)`와 `@LocalServerPort`로 실제 포트 통합 테스트 작성하기
`MOCK` 모드는 빠르지만 서블릿 컨테이너·필터 체인·HTTP 인코딩까지는 검증하지 못합니다. `RANDOM_PORT`로 실제 톰캣을 띄우고 `@LocalServerPort`로 부여된 포트를 받아 외부 클라이언트처럼 호출하면, CORS·헤더·압축·HTTPS 같은 "프레임워크 경계" 동작까지 회귀로 잡아낼 수 있습니다.

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class OrderApiIT {
    @LocalServerPort int port;
    @Autowired TestRestTemplate rest;

    @Test
    void 주문_조회_200() {
        var res = rest.getForEntity("http://localhost:" + port + "/orders/42", String.class);
        assertThat(res.getStatusCode()).isEqualTo(HttpStatus.OK);
    }
}
```

> 💡 **왜 중요한가**: 단위 테스트로는 절대 발견되지 않는 "프로덕션에서만 터지는" 필터·인코딩·CORS 회귀를 CI 단계에서 잡을 수 있고, 병렬 빌드에서도 포트 충돌이 없습니다.

### `RouterFunction`(WebFlux)으로 함수형 엔드포인트 정의하기 — 어노테이션 없이 라우팅 한눈에 보기
WebFlux는 `@RestController` 대신 `RouterFunctions.route()` DSL로 라우트를 한곳에 모아 선언할 수 있습니다. 같은 핸들러를 여러 패스에 매핑하거나, 미들웨어를 함수 합성으로 끼우거나, 라우트 단위 테스트(`RouterFunctions.toWebHandler()`)를 만들 때 어노테이션 기반보다 훨씬 직관적입니다.

```java
@Bean
RouterFunction<ServerResponse> orderRoutes(OrderHandler h) {
    return RouterFunctions.route()
        .GET("/orders/{id}", h::get)
        .POST("/orders",     accept(MediaType.APPLICATION_JSON), h::create)
        .filter((req, next) -> {                          // 라우트 단위 필터
            log.info("{} {}", req.method(), req.path());
            return next.handle(req);
        })
        .build();
}
```

> 💡 **왜 중요한가**: 라우팅 테이블이 코드 한 화면에 모이므로 OpenAPI 동기화·게이트웨이 마이그레이션이 쉬워지고, 핸들러를 평범한 함수로 다룰 수 있어 테스트하기도 좋습니다.
