### 1. PostgreSQL `SELECT ... FOR UPDATE SKIP LOCKED` — DB만으로 동시성 작업 큐 만들기

여러 워커가 같은 작업 테이블에서 잡을 가져갈 때 `FOR UPDATE`만 쓰면 다른 워커가 락 해제를 기다리며 직렬화되지만, `SKIP LOCKED`를 붙이면 이미 잠긴 행은 건너뛰고 다음 후보를 즉시 반환한다. 별도 메시지 브로커 없이 PostgreSQL만으로 안전하고 확장 가능한 작업 큐를 구현할 수 있어, 워커 수를 늘릴수록 처리량이 거의 선형으로 증가한다.

```sql
SELECT id, payload FROM jobs
WHERE status = 'pending'
ORDER BY created_at
LIMIT 10
FOR UPDATE SKIP LOCKED;
```

> 💡 **왜 중요한가**: 락 경합을 회피해 워커 간 직렬화 병목 없이 수평 확장이 가능한 큐를 단일 DB로 구현할 수 있다.

### 2. PostgreSQL `pg_trgm` 확장 — `LIKE '%keyword%'` 검색에 인덱스 태우기

일반 B-tree 인덱스는 접두사(`'keyword%'`)에만 동작하고 양쪽 와일드카드(`'%keyword%'`)나 부분 일치 검색에는 무력해 풀스캔이 발생한다. `pg_trgm` 확장은 문자열을 3글자 단위(trigram)로 쪼개 GIN/GiST 인덱스를 만들어, 부분 일치·유사도(`similarity()`) 검색을 인덱스로 처리할 수 있게 해준다.

```sql
CREATE EXTENSION pg_trgm;
CREATE INDEX idx_products_name_trgm ON products USING GIN (name gin_trgm_ops);

SELECT * FROM products WHERE name ILIKE '%coffee%';
```

> 💡 **왜 중요한가**: 전용 검색 엔진(Elasticsearch 등)을 도입하지 않고도 부분 문자열 검색을 인덱스 기반으로 수 ms 안에 끝낼 수 있다.
