### 1. `Map.Entry.copyOf(entry)` (Java 17 정식)로 `Map.entry(e.getKey(), e.getValue())` 수동 복제 관성 벗어나기

`Map.entry()`로 매번 키/값을 꺼내 재조립하던 패턴이 `Map.Entry.copyOf(entry)` 한 줄로 끝난다. 반환되는 엔트리는 불변이며, 원본 맵이 수정되거나 사라져도 영향받지 않아 스냅샷 용도로 안전하다. 특히 `entrySet().stream()`을 외부로 흘려보낼 때 원본 맵 참조가 새는 것을 막는 가드로 유용하다.

```java
// 관성: 키/값 수동 추출
Map.Entry<String, Integer> snapshot = Map.entry(e.getKey(), e.getValue());

// Java 17+: 한 번에 불변 스냅샷
Map.Entry<String, Integer> snapshot = Map.Entry.copyOf(e);

// 실전: 외부로 넘기기 전 방어적 복사
List<Map.Entry<String, Order>> frozen = cache.entrySet().stream()
    .map(Map.Entry::copyOf)   // 원본 맵 변경에 면역
    .toList();
```

> 💡 **왜 중요한가**: `Map.entry(k, v)`는 null을 허용하지 않는 반면 원본 엔트리의 null 값까지 복제해야 할 때 조용히 NPE가 터지는데, `copyOf`는 입력 엔트리의 null 정책을 그대로 승계해 "복사"의 의미론을 깨지 않는다.

### 2. `Thread.ofVirtual().name("worker-", 0).factory()`로 가상 스레드에도 식별 가능한 이름 자동 부여하기 (Java 21 정식)

가상 스레드는 기본적으로 이름이 비어있어 스레드 덤프에서 `VirtualThread[#123]/runnable` 식으로만 찍혀 디버깅이 지옥이 된다. `Thread.ofVirtual().name(prefix, startIndex).factory()`로 ThreadFactory를 만들면 생성될 때마다 `worker-0`, `worker-1`, ...로 자동 넘버링되어 로그/프로파일러에서 즉시 추적 가능해진다.

```java
// 관성: 이름 없는 가상 스레드 — 덤프에서 식별 불가
ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor();

// Java 21+: 넘버링된 팩토리로 식별성 확보
ThreadFactory factory = Thread.ofVirtual()
    .name("order-worker-", 0)   // order-worker-0, order-worker-1, ...
    .factory();
ExecutorService executor = Executors.newThreadPerTaskExecutor(factory);

// 로그/덤프 예시
// before: VirtualThread[#47]/runnable@ForkJoinPool-1-worker-3
// after:  VirtualThread[#47,order-worker-12]/runnable@ForkJoinPool-1-worker-3
```

> 💡 **왜 중요한가**: 운영 중 가상 스레드 수천 개가 한 캐리어 위에서 돌 때, 이름 없는 덤프로는 "어떤 요청의 스레드가 블로킹됐는지" 역추적이 불가능하므로 팩토리 단계에서 네이밍 전략을 심어두는 것이 사실상 유일한 추적 수단이다.
