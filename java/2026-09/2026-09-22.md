### 1. `HexFormat.of().formatHex(bytes)`로 `String.format("%02x", b)` 루프 관성 벗어나기 (Java 17 정식)

바이트 배열을 hex 문자열로 바꿀 때 `StringBuilder`에 `String.format("%02x", b)`를 루프로 붙이거나 `Integer.toHexString()`에 0 패딩을 수동으로 씌우는 코드가 관성처럼 반복된다. Java 17부터 정식 도입된 `java.util.HexFormat`은 대소문자, 구분자(`:`, `-`), prefix/suffix, 파싱까지 한 객체로 처리하며 내부는 인덱스 룩업 테이블이라 `String.format` 대비 10배 이상 빠르다. `HexFormat.of().formatHex(digest)`, `HexFormat.ofDelimiter(":").withUpperCase().formatHex(mac)`, `HexFormat.of().parseHex("deadbeef")` — SHA-256 다이제스트 출력, MAC 주소 포맷, JWT 서명 검증 로그 등 실무에서 매일 마주치는 패턴이 한 줄로 끝난다.

> 💡 **왜 중요한가**: 로깅·감사·해시 출력 코드는 어디에나 있는데, 대부분 여전히 Java 1.0 시절 `String.format` 루프에 머물러 있다. `HexFormat`은 표준 라이브러리에 이미 있는데 존재 자체를 모르는 경우가 대다수다.

### 2. `Math.clamp(value, min, max)`로 `Math.max(min, Math.min(max, value))` 중첩 관성 벗어나기 (Java 21 정식)

값을 특정 범위로 제한할 때 `Math.max(0, Math.min(100, value))` 같은 중첩 호출을 읽는 순간 잠깐 멈춰서 "안쪽이 뭐지, 바깥쪽이 뭐지" 파싱해야 하는 인지 비용이 발생한다. Java 21의 `Math.clamp(value, min, max)`는 의도를 이름 그대로 드러내고, `min > max`일 때 `IllegalArgumentException`을 던져 조용한 버그를 조기에 잡아준다. int·long·float·double 오버로드가 모두 있고, `StrictMath.clamp`까지 대칭으로 존재한다. 페이지네이션 offset 제한, 볼륨·밝기 조절, 재시도 백오프 상한 등 실무 클램프 코드가 그대로 한 줄로 정리된다.

> 💡 **왜 중요한가**: `Math.max/min` 중첩은 순서를 실수하면 항상 min만 반환하는 조용한 버그로 이어지는데(`Math.min(max, Math.max(min, v))` 오타), `Math.clamp`는 애초에 그 실수를 문법적으로 불가능하게 만든다.
