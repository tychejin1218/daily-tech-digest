### 1. `StringTemplate.STR."..."` (Java 25 정식, JEP 517)로 문자열 조합할 때 `String.format("%s는 %d세", name, age)`나 `"+"` 연결 관성 벗어나기

`StringTemplate`은 `String name = "홍길동"; int age = 30; String s = STR."\{name}는 \{age}세";`처럼 **백슬래시 중괄호 보간**으로 변수를 직접 꽂아 넣는 방식이다. `%s`/`%d` 같은 포맷 지시자와 인자 순서를 머릿속에서 매칭할 필요가 없고, `+`로 토막토막 자르는 것보다 가독성이 압도적으로 높으며, 컴파일 시점에 템플릿 구조가 고정되어 JIT 최적화에도 유리하다.

> 💡 **왜 중요한가**: 로그 메시지·SQL·JSON 조립 같은 "변수 끼워 넣기"가 코드의 상당 비율을 차지하는데, 지시자/인자 분리 구조는 순서 실수와 타입 불일치로 런타임에 터지기 쉽다 — 보간은 그 실수 자체를 구조적으로 막는다.

### 2. `SequencedCollection#reversed()` / `getFirst()` / `getLast()` (Java 21 정식, JEP 431)로 List·Deque·LinkedHashSet의 "순서 있는 컬렉션"을 다룰 때 `list.get(list.size()-1)`나 `new ArrayList<>(list)`를 `Collections.reverse()`로 뒤집는 관성 벗어나기

Java 21부터 `List`, `Deque`, `LinkedHashSet` 등이 공통 상위 인터페이스 `SequencedCollection`을 구현해, `list.getFirst()` / `list.getLast()` / `list.reversed()` / `list.addFirst(x)`를 **컬렉션 종류와 무관하게 같은 API로** 쓸 수 있다. `reversed()`는 원본을 복사하지 않고 **역방향 뷰**를 돌려주므로 `Collections.reverse(new ArrayList<>(list))`처럼 복사+뒤집기 2단계 비용이 사라진다.

> 💡 **왜 중요한가**: "첫 요소/마지막 요소/역순"은 실무에서 하루에도 몇 번씩 나오는 연산인데, 지금까지 `LinkedList`냐 `ArrayList`냐 `Deque`냐에 따라 호출 방식이 제각각이라 추상화가 깨졌다 — `SequencedCollection`은 이 균열을 메우는 늦게 온 정답이다.
