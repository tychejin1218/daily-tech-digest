### 1. useRef의 두 얼굴: DOM 참조 말고 "리렌더 없는 값 저장소"로 써라

`useRef`를 단순히 `inputRef.current.focus()` 같은 DOM 접근 용도로만 쓰는 건 절반만 아는 것이다. `ref.current`에 할당해도 리렌더가 발생하지 않는다는 특성을 활용하면, **이전 값 추적, setInterval ID 보관, 최신 state 캡처(스테일 클로저 회피), 렌더링과 무관한 카운터** 같은 용도로 쓸 수 있다. `useState`를 썼다면 매번 리렌더가 터졌을 값들을 `useRef`로 조용히 보관하는 것이 핵심이다.

```jsx
function Timer() {
  const intervalRef = useRef(null);   // 렌더링과 무관한 ID 보관
  const prevCountRef = useRef(0);     // 이전 값 추적
  const [count, setCount] = useState(0);

  useEffect(() => {
    intervalRef.current = setInterval(() => {
      setCount(c => c + 1);
    }, 1000);
    return () => clearInterval(intervalRef.current);
  }, []);

  useEffect(() => {
    prevCountRef.current = count;  // 할당해도 리렌더 X
  }, [count]);

  return <div>현재: {count}, 이전: {prevCountRef.current}</div>;
}
```

| 구분 | `useState` | `useRef` |
|------|-----------|---------|
| 값 변경 시 리렌더 | ✅ 발생 | ❌ 안 함 |
| UI에 반영 | 즉시 | 다음 렌더 전까지 반영 X |
| 적합 용도 | 화면에 보이는 값 | 타이머 ID, 이전 값, DOM 참조 |

> 💡 **왜 중요한가**: "리렌더링을 일으키지 않고 값을 유지"하는 수단은 React에서 `useRef`가 유일하다 — 이걸 모르면 불필요한 `useState`로 리렌더 폭탄을 만든다.

### 2. useMemo vs useCallback: 메모이제이션 전에 "참조 동일성"부터 이해하라

둘 다 성능 최적화 훅으로 알려져 있지만, 사실 진짜 목적은 **참조 동일성(referential equality) 보존**이다. `useMemo`는 "계산 결과 값"을, `useCallback`은 "함수 참조"를 캐싱한다. 리렌더가 발생해도 의존성이 바뀌지 않으면 같은 참조를 돌려주므로, `React.memo`로 감싼 자식 컴포넌트나 `useEffect` 의존성 배열에 넘길 때 비로소 의미가 생긴다. **자식에게 넘기지 않거나 `React.memo`를 쓰지 않는다면 대부분 무의미한 최적화**다.

```jsx
function Parent({ users }) {
  // ❌ 무의미: 자식이 React.memo가 아니면 캐싱해도 소용없음
  const sorted = useMemo(() => users.sort(), [users]);

  // ✅ 의미 있음: 자식의 리렌더 방지 + useEffect 재실행 방지
  const handleClick = useCallback((id) => {
    console.log(id);
  }, []);

  return <MemoizedChild onClick={handleClick} />;
}

const MemoizedChild = React.memo(({ onClick }) => {
  console.log('렌더링!');
  return <button onClick={() => onClick(1)}>클릭</button>;
});
```

**판단 기준 흐름:**

```
렌더링마다 새 객체/함수 생성됨
        ↓
자식이 React.memo로 감싸져 있거나
useEffect/useMemo 의존성에 들어가는가?
        ↓
   YES → useMemo/useCallback 사용
   NO  → 쓰지 마라 (오히려 메모리 낭비)
```

> 💡 **왜 중요한가**: 메모이제이션 훅은 "빠르게 만드는 도구"가 아니라 "참조를 고정하는 도구"다 — 목적을 착각하면 코드만 복잡해지고 성능은 그대로다.
