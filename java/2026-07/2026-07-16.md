### `Math.clamp()`로 값을 범위 안으로 안전하게 제한하기 (Java 21 정식)
`Math.clamp(value, min, max)`는 값을 `[min, max]` 구간으로 잘라주는 표준 API입니다. 기존에는 `Math.max(min, Math.min(max, value))` 같은 이중 호출로 표현했는데, 읽기 어려울 뿐 아니라 `min > max`인 잘못된 인자를 조용히 삼키는 문제가 있었습니다. `Math.clamp()`는 `int`, `long`, `float`, `double` 오버로드를 제공하며 `min > max`이면 `IllegalArgumentException`을 던져 실수를 즉시 드러냅니다.

> 💡 **왜 중요한가**: UI 좌표, 볼륨, 재시도 백오프 등 "허용 범위로 자르기"는 어디에나 등장하는 패턴인데, 그동안 표준 API가 없어 각 팀이 유틸을 재작성해왔고 그 과정에서 경계 처리 버그가 반복됐습니다.

### Unnamed Variables `_`로 사용하지 않는 변수를 명시적으로 표현하기 (Java 22 정식)
람다 파라미터, `catch` 절, `for-each` 인덱스, 패턴 매칭의 구성 요소 중 값이 실제로 필요 없는 자리에 `_`(underscore) 하나만 써서 "이건 안 쓴다"를 컴파일러와 리뷰어 모두에게 알릴 수 있습니다. 기존에는 `ignored`, `unused` 같은 관습적 이름을 붙였고 IDE 경고가 남거나 이름을 지어야 한다는 부담이 있었는데, `_`는 언어 차원에서 "이 이름은 참조 불가"를 강제합니다. 여러 자리에 동시에 `_`를 써도 이름 충돌이 발생하지 않는 것도 장점입니다.

```java
map.forEach((_, v) -> total += v.size());
try { ... } catch (IOException _) { retry(); }
if (obj instanceof Point(int x, _)) useX(x);
```

> 💡 **왜 중요한가**: "사용하지 않는 변수"는 리뷰에서 반복적으로 지적되는 잡음인데, `_`는 그 의도를 문법적으로 못 박아서 IDE 경고와 팀 관습이 아니라 컴파일러가 규칙을 지키게 만듭니다.
