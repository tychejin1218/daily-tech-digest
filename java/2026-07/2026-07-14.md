### `Stream.mapMulti()`로 `flatMap`의 임시 스트림 생성 오버헤드 피하기 (Java 16 정식)
요소당 0개 이상의 결과를 방출해야 할 때 `flatMap`은 각 요소마다 임시 `Stream`을 만들어 소비하지만, `mapMulti`는 `Consumer`에 직접 값을 넣기 때문에 중간 스트림 생성을 건너뛴다. 특히 대부분의 요소가 1개 이하의 결과만 내보내거나 이미 for 루프에 가까운 로직을 갖고 있을 때 오버헤드가 눈에 띄게 줄어든다.

```java
List<Integer> result = numbers.stream()
    .<Integer>mapMulti((n, downstream) -> {
        if (n > 0) {
            downstream.accept(n);
            downstream.accept(n * n);
        }
    })
    .toList();
```

> 💡 **왜 중요한가**: 핫패스에서 `flatMap`을 남용해 GC 압력을 받는 파이프라인을 리팩터링 없이 그대로 개선할 수 있다.

### `CompletableFuture.orTimeout()`으로 비동기 작업에 타임아웃을 논블로킹으로 걸기 (Java 9 정식)
`future.get(timeout, unit)`은 호출 스레드를 차단해 버리므로 진짜 비동기 파이프라인에서는 쓸모가 없다. `orTimeout(duration, unit)`은 지정 시간이 지나면 `TimeoutException`으로 완료시키고, `completeOnTimeout(fallback, duration, unit)`은 대체 값으로 정상 완료시킨다 — 둘 다 논블로킹이며 뒤따르는 `thenApply`/`exceptionally` 체인과 자연스럽게 이어진다.

```java
fetchUserAsync(id)
    .orTimeout(2, TimeUnit.SECONDS)
    .exceptionally(ex -> User.guest())
    .thenAccept(this::render);
```

> 💡 **왜 중요한가**: 외부 API가 느려질 때 이벤트 루프나 가상 스레드 캐리어를 붙잡지 않고 응답성을 지킬 수 있다.
