### `@ConditionalOnMissingBean`으로 사용자 정의 빈 우선순위 보장하기

라이브러리·자동 설정에서 기본 빈을 제공하되 사용자가 같은 타입의 빈을 등록하면 그것이 우선하도록 하려면 `@ConditionalOnMissingBean`을 붙인다. Spring Boot 자동 설정이 내부적으로 광범위하게 쓰는 패턴이며, 커스텀 스타터를 만들거나 `@Configuration` 클래스에서 "합리적 디폴트"를 제공할 때 필수다.

```java
@Configuration
public class ObjectMapperAutoConfig {

    @Bean
    @ConditionalOnMissingBean  // 사용자가 ObjectMapper 빈을 등록하면 이 빈은 무시됨
    public ObjectMapper objectMapper() {
        return new ObjectMapper()
                .registerModule(new JavaTimeModule())
                .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
    }
}
```

> 💡 **왜 중요한가**: 오버라이드 가능한 기본값을 제공해야 라이브러리/공통 모듈이 유연하게 재사용된다.

### `HandlerMethodArgumentResolver`로 컨트롤러 파라미터 커스텀 바인딩하기

로그인 사용자, 요청 컨텍스트, 커스텀 헤더 파싱 등 반복되는 파라미터 추출 로직을 컨트롤러마다 복사하지 말고 `HandlerMethodArgumentResolver`로 추상화하면 메서드 시그니처가 깔끔해진다. `@LoginUser User user`처럼 어노테이션 하나로 인증 사용자 주입을 표준화할 수 있다.

```java
public class LoginUserArgumentResolver implements HandlerMethodArgumentResolver {

    @Override
    public boolean supportsParameter(MethodParameter parameter) {
        return parameter.hasParameterAnnotation(LoginUser.class)
                && parameter.getParameterType().equals(User.class);
    }

    @Override
    public Object resolveArgument(MethodParameter parameter, ModelAndViewContainer mavContainer,
                                  NativeWebRequest webRequest, WebDataBinderFactory binderFactory) {
        String token = webRequest.getHeader("Authorization");
        return userService.findByToken(token);  // 인증 로직을 한 곳에 응집
    }
}

@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addArgumentResolvers(List<HandlerMethodArgumentResolver> resolvers) {
        resolvers.add(new LoginUserArgumentResolver());
    }
}
```

> 💡 **왜 중요한가**: 컨트롤러가 HTTP 파싱 코드로 오염되지 않고 비즈니스 로직에만 집중할 수 있다.
