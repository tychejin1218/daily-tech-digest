### 1. Google Cloud Vertex AI, xAI Grok 4.1 계열 오늘부로 shutdown — MaaS 멀티모델의 첫 '이관 시험'
Gemini Enterprise Agent Platform(구 Vertex AI)에서 `xai/grok-4.1-fast-reasoning`·`grok-4.1-fast-non-reasoning`이 2026-08-20자로 완전 종료된다. 오늘 이후 해당 모델 ID로 `aiplatform.googleapis.com` OpenAI-호환 chat/completions 엔드포인트에 요청하면 400 에러만 돌아오고, Grok 4.2/4.3 또는 Model Garden 대체 모델로 라우팅 키만 바꿔서 이관하는 것이 공식 가이드다. 파트너 모델을 "MaaS로 통합해서 쓴다"는 전략이 실제 EOL 사이클에서 어떻게 작동하는지 처음으로 검증되는 순간.

> 💡 **왜 중요한가**: OpenAI SDK 호환 엔드포인트로 다중 벤더를 얹어 놓은 파이프라인이라면, 이제부터 벤더 EOL이 곧 GCP 리전 이슈처럼 다뤄져야 한다는 뜻이다.

### 2. Oracle OCI Enterprise AI, NVIDIA Nemotron 3.5 Lightning + 호스티드 엔드포인트 IAM 인증 — "always-on 에이전트"가 클라우드 IAM으로 잠긴다
OCI Enterprise AI가 8월 초 Nemotron 3.5 Lightning을 최초 지원 클라우드 중 하나로 붙였고, 이번 주 업데이트로 호스팅된 애플리케이션 엔드포인트가 OCI IAM 인증을 정식 지원한다. 즉, 모델 서빙 URL이 조직 정책·리소스 프린서플·다이나믹 그룹으로 잠기고, API 키 로테이션 대신 IAM 감사로그가 그 자리를 대체한다. 언제나 켜져 있는(always-on) 에이전트를 위해 훈련된 커스터마이저블 오픈 모델이라는 포지션과, 자격증명 관리를 클라우드 IAM에 위임한 서빙 계층이 세트로 묶였다.

> 💡 **왜 중요한가**: LLM API를 "API Key 헤더 하나" 대신 "IAM 리소스"로 다루기 시작하면, 에이전트 접근 통제가 애플리케이션 코드가 아니라 인프라 정책(policy)에서 결정된다.

### 3. GitHub Copilot 'Agent Plugins 1.0' 정식 GA — 한 번 만들면 VS Code·Copilot CLI·SDK·앱까지 그대로 동작
이번 주 GitHub Copilot 위클리 릴리스로 Agent Plugins 1.0이 GA로 승격됐고, JetBrains에서는 Ollama가 BYOK 프로바이더로 붙어 통합 터미널이 Copilot CLI를 자동 설치한다. 플러그인 하나를 만들면 VS Code, Copilot CLI, GitHub Copilot SDK, Copilot 앱까지 동일한 계약으로 실행되며, 모델도 Kimi K3·MAI-Code-1.1-Flash·Gemini 3.7 Flash가 같은 플러그인 위에서 갈아 끼워진다. 이제 '툴 인터페이스'는 MCP 서버로, '에이전트용 플러그인'은 Agent Plugins로 이원화되는 그림.

> 💡 **왜 중요한가**: 사내 에이전트 도구를 개발할 때 "어느 툴/에디터에서 돌릴 것인가"가 아니라 "어느 표준 계약을 구현할 것인가"만 정하면 되는 시대가 GA로 진입했다.
