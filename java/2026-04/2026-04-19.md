### `Optional.ifPresentOrElse()`로 값 존재 여부에 따른 분기를 콜백으로 처리하기 (Java 9 정식)

`Optional.ifPresent()`는 값이 있을 때만 동작하고 없을 때의 처리를 표현할 수 없어 결국 `isPresent()` 분기로 회귀하기 쉬웠다. `ifPresentOrElse(Consumer, Runnable)`은 값이 있으면 첫 번째 콜백을, 없으면 두 번째 `Runnable`을 실행해 두 갈래를 한 표현식으로 묶는다.

```java
userRepository.findByEmail(email)
    .ifPresentOrElse(
        user -> log.info("로그인 성공: {}", user.getId()),
        () -> log.warn("가입되지 않은 이메일: {}", email)
    );
```

`if (opt.isPresent()) { ... } else { ... }`로 되돌아가지 않고도 부재 경로를 명시할 수 있어 로깅·메트릭 기록 같은 사이드 이펙트를 짝지어 표현하기 좋다.

> 💡 **왜 중요한가**: `Optional`의 부재 경로를 콜백으로 표현할 수 있어 `isPresent()` 분기 상용구가 사라진다.

### `Thread.ofVirtual()`로 경량 스레드를 명시적으로 생성해 I/O 병렬 처리하기 (Java 21 정식)

가상 스레드는 JVM이 관리하는 경량 스레드로, 플랫폼 스레드 하나에 수천 개를 다중화해도 스택 오버헤드가 거의 없다. `Thread.ofVirtual()` 빌더로 즉석에서 만들 수 있으며, I/O 대기가 잦은 작업을 `ExecutorService` 없이도 직관적으로 병렬화한다.

```java
List<String> urls = List.of("https://a.com", "https://b.com", "https://c.com");

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<String>> results = urls.stream()
        .map(url -> executor.submit(() -> fetch(url)))
        .toList();

    for (Future<String> f : results) {
        System.out.println(f.get());
    }
}
```

기존 `newFixedThreadPool(200)` 같은 튜닝 없이도 요청당 스레드 하나 모델을 부담 없이 쓸 수 있어, 블로킹 I/O 기반 서버 코드의 처리량을 스레드 풀 크기 고민 없이 끌어올린다.

> 💡 **왜 중요한가**: 스레드 풀 크기를 튜닝할 필요 없이 요청당 스레드 하나 모델로 블로킹 I/O 병렬성을 확보한다.
