### 1. `Stream.mapMulti(BiConsumer<T, Consumer<R>>)`로 flatMap의 중간 Stream 생성 오버헤드 없이 요소 확장하기 (Java 16 정식)

`flatMap`은 요소마다 새 `Stream` 인스턴스를 만들어 병합하지만, `mapMulti`는 `Consumer`에 직접 push해서 중간 스트림 생성 비용이 없다. 특히 대부분 요소가 0~1개만 방출되는 **조건부 확장**(필터+변환의 결합) 시나리오에서 체감 차이가 크다.

```java
// flatMap: 요소마다 Stream.of / Stream.empty 인스턴스 생성
var odds = list.stream()
    .flatMap(n -> n % 2 == 1 ? Stream.of(n * 10) : Stream.empty())
    .toList();

// mapMulti: downstream Consumer에 직접 push, 중간 Stream 없음
var odds = list.stream()
    .<Integer>mapMulti((n, downstream) -> {
        if (n % 2 == 1) downstream.accept(n * 10);
    })
    .toList();
```

주의: 타입 추론이 약해서 `.<Integer>mapMulti(...)` 처럼 witness 타입을 명시해줘야 하는 경우가 많다. 원시 타입 특화 버전(`mapMultiToInt`, `mapMultiToLong`, `mapMultiToDouble`)도 함께 제공된다.

> 💡 **왜 중요한가**: `flatMap`은 개념적으로 우아하지만 짧은 스트림을 대량으로 만들면 GC 압박과 파이프라인 오버헤드가 커지고, JEP 461(Gatherers)이 정식화되기 전까지는 조건부·소량 확장의 표준 해법이 `mapMulti`다.

### 2. `instanceof` 패턴 매칭으로 타입 검사와 캐스팅·지역 변수를 한 줄에 압축하기 (Java 16 정식)

`if (obj instanceof String s)` 처럼 타입 검사와 동시에 지역 변수 `s`를 바인딩하여, 별도의 명시적 캐스팅 라인이 사라진다. `&&`로 이어지는 후속 조건에서도 바인딩이 유효하므로, 방어적 검사 로직 여러 줄이 한 표현식으로 압축된다.

```java
// Before: instanceof 검사 → 캐스팅 → 사용 (3단 구조)
if (obj instanceof String) {
    String s = (String) obj;
    if (!s.isBlank()) return s.toUpperCase();
}

// After: 검사·바인딩·후속 조건이 한 줄
if (obj instanceof String s && !s.isBlank()) {
    return s.toUpperCase();
}
```

`else` 블록에서는 `s` 스코프가 없다는 규칙(flow scoping) 덕분에 잘못된 참조를 컴파일 타임에 잡아준다. Java 21의 `switch` 패턴 매칭과 레코드 디컨스트럭션(`case Point(int x, int y)`)도 이 문법의 확장이다.

> 💡 **왜 중요한가**: 명시적 캐스팅이 사라지면 `ClassCastException` 리스크와 중복 변수 선언이 함께 사라지고, `sealed` 계층 위에서 `switch` 패턴 매칭으로 확장하면 컴파일러가 exhaustiveness까지 검사해주는 대수적 데이터 타입(ADT) 스타일로 발전한다.
