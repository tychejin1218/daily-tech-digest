### 1. `Scoped Values`로 스레드 간 불변 컨텍스트를 안전하게 공유하기 (Java 25 정식)

`ScopedValue`는 `ThreadLocal`의 대안으로, 한 번 바인딩되면 변경할 수 없는 불변 값을 호출 스택의 특정 범위(scope) 안에서만 공유하도록 강제합니다. `ScopedValue.where(USER, currentUser).run(() -> service.process())` 형태로 사용하며, 가상 스레드 환경에서 메모리 누수와 상속 비용 문제를 해결하기 위해 설계되었습니다. 인증 정보, 트랜잭션 컨텍스트, 요청 ID 등 "한 요청 처리 동안만 유효한" 데이터를 전달하기에 적합합니다.

> 💡 **왜 중요한가**: `ThreadLocal`은 가상 스레드를 수백만 개 띄우는 환경에서 메모리 폭증과 정리 누락의 원인이 되는데, `ScopedValue`는 스코프 종료 시 자동으로 해제되어 안전하고 가볍습니다.

### 2. `JEP 483 Ahead-of-Time Class Loading & Linking`으로 JVM 시작 시간 단축하기 (Java 24 정식)

AOT 캐시는 애플리케이션이 자주 사용하는 클래스를 미리 로드·링크된 상태로 디스크에 저장해 두고, 다음 실행 시 그대로 메모리에 매핑하는 기능입니다. 운영 단계에서 `java -XX:AOTMode=record -XX:AOTConfiguration=app.aotconf -cp app.jar Main`으로 프로파일을 기록한 뒤 `-XX:AOTMode=create`로 캐시를 생성하면, 이후 실행 시 클래스 로딩 단계가 대부분 생략됩니다. CDS(Class Data Sharing)의 후속 기능으로, 별도 빌드 도구 없이 표준 JVM 옵션만으로 사용할 수 있습니다.

> 💡 **왜 중요한가**: 서버리스·컨테이너 환경처럼 콜드 스타트 지연이 비용으로 직결되는 곳에서 GraalVM Native Image 같은 별도 툴체인 없이도 시작 시간을 30~40% 단축할 수 있습니다.
