### 1. `@Sql`과 `@SqlMergeMode`로 테스트 메서드별 데이터 셋업을 누적·격리하기
`@Sql`은 테스트 실행 전후에 SQL 스크립트를 실행해 데이터를 준비하는 애너테이션이며, 클래스 레벨과 메서드 레벨에 모두 붙일 수 있습니다. `@SqlMergeMode(MERGE)`를 함께 사용하면 클래스 레벨 공통 셋업 위에 메서드별 추가 스크립트를 누적할 수 있고, 기본값인 `OVERRIDE`는 메서드 레벨이 클래스 레벨을 완전히 덮어씁니다. Testcontainers로 띄운 실제 DB에서 픽스처를 선언적으로 관리할 때 특히 유용합니다.

> 💡 **왜 중요한가**: 테스트 간 데이터 오염 없이 공통 픽스처와 개별 픽스처를 명확히 분리해 통합 테스트의 가독성과 재현성을 동시에 확보할 수 있습니다.

---

### 2. `HandlerMethodArgumentResolver`로 컨트롤러 메서드 파라미터에 인증 컨텍스트 주입하기
컨트롤러마다 `SecurityContextHolder.getContext().getAuthentication()`을 호출해 사용자 정보를 꺼내는 대신, 커스텀 `HandlerMethodArgumentResolver`를 등록하면 `@CurrentUser User user`처럼 메서드 시그니처에 바로 주입할 수 있습니다. `WebMvcConfigurer.addArgumentResolvers`에 등록하고 `supportsParameter`에서 커스텀 애너테이션을 확인하는 패턴이 표준이며, 토큰 파싱·테넌트 식별·요청 단위 컨텍스트 전달에도 동일하게 쓸 수 있습니다.

> 💡 **왜 중요한가**: 횡단 관심사인 인증 정보 추출을 프레임워크 레이어로 밀어내 컨트롤러 로직을 순수 비즈니스 코드로 유지하고, 테스트 시에는 단순히 객체를 전달하면 되므로 테스트 작성이 훨씬 쉬워집니다.
