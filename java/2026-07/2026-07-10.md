### `Files.mismatch(Path, Path)`로 두 파일의 차이 위치를 표준 API로 찾기 (Java 12 정식)

두 파일이 동일한지 비교할 때 전체를 읽어 해시를 계산하거나 바이트 배열로 로드하는 대신, `Files.mismatch()`는 첫 번째로 다른 바이트의 오프셋(0-based)을 반환하고 완전히 일치하면 `-1L`을 돌려준다. 스트림을 순차적으로 비교하다 다른 바이트를 만나면 즉시 종료하므로 대용량 파일에서도 효율적이다.

```java
long pos = Files.mismatch(Path.of("expected.bin"), Path.of("actual.bin"));
if (pos == -1L) {
    System.out.println("두 파일이 완전히 동일");
} else {
    System.out.println("바이트 오프셋 " + pos + "에서 불일치 시작");
}
```

> 💡 **왜 중요한가**: 파일 동일성 검증과 첫 차이 지점 탐지를 한 번의 표준 API 호출로 처리할 수 있어 테스트·백업 검증 코드가 간결해진다.

### `Stream.mapMulti()`로 flatMap보다 가볍게 1:N 요소를 방출하기 (Java 16 정식)

`flatMap()`은 각 요소마다 중간 스트림 객체를 생성해 오버헤드가 있지만, `mapMulti()`는 `Consumer`에 결과를 직접 push하는 방식이라 임시 스트림을 만들지 않는다. 특히 조건에 따라 0~N개의 값을 방출해야 하거나 방출할 값이 원시 타입일 때 성능과 가독성이 모두 유리하다.

```java
List<Integer> result = Stream.of(1, 2, 3, 4, 5)
    .<Integer>mapMulti((n, downstream) -> {
        if (n % 2 == 0) {
            downstream.accept(n);
            downstream.accept(n * 10);
        }
    })
    .toList();
// [2, 20, 4, 40]
```

> 💡 **왜 중요한가**: 조건부 다중 방출이나 재귀적 펼치기가 필요한 스트림 파이프라인에서 `flatMap`보다 할당 비용을 크게 줄일 수 있다.
