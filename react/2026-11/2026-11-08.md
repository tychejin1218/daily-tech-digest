### 1. useTransition: "입력창이 끊기는" 무거운 리스트 필터링을 매끄럽게 만드는 React 18의 우선순위 분리

입력값이 바뀔 때마다 10,000개 리스트를 필터링하면 타이핑이 뚝뚝 끊긴다. `useTransition`으로 "리스트 업데이트"를 긴급하지 않은 작업으로 표시하면, React가 입력창 렌더링을 먼저 처리하고 리스트는 뒤로 미룬다. `isPending` 플래그로 로딩 UI까지 공짜로 얻는다.

```jsx
const [isPending, startTransition] = useTransition();
const [input, setInput] = useState("");
const [list, setList] = useState([]);

const onChange = (e) => {
  setInput(e.target.value);              // 긴급: 입력창 즉시 반영
  startTransition(() => {
    setList(filterHuge(e.target.value)); // 비긴급: 중단 가능
  });
};
```

```
[키 입력] ─► setInput ──► 입력창 즉시 리렌더 (16ms 내)
         └► startTransition ──► 필터링 (중단 가능, 뒤늦게 반영)
```

트레이드오프: UI가 "최신"이 아닐 수 있다. 결제 금액·재고 숫자처럼 **stale 값을 보여주면 안 되는 상태**에는 쓰지 마라. 검색/필터/탭 전환처럼 "조금 늦어도 괜찮은 뷰"에만 적용한다.

> 💡 **왜 중요한가**: 디바운스(debounce)는 입력을 "지연"시키는 꼼수지만, `useTransition`은 "렌더 우선순위"를 OS 스케줄러처럼 조정하는 React의 공식 해법이다.

### 2. Error Boundary는 왜 아직도 클래스 컴포넌트인가: Hook으로 못 만드는 유일한 패턴

React 18이 되어도 에러 경계(Error Boundary)는 `componentDidCatch` / `getDerivedStateFromError` 생명주기 메서드로만 만들 수 있다. Hook 버전(`useErrorBoundary`)은 **공식 API에 없다**. 이유는 명확하다 — Hook은 "렌더 중 에러"가 나면 그 Hook 자체가 호출되지 못하기 때문이다. 즉 자기 자신을 구할 수 없다.

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { logToSentry(error, info); }
  render() {
    return this.state.hasError ? <Fallback /> : this.props.children;
  }
}

// 사용: 라우트 단위, 위젯 단위로 "격리 범위"를 설계
<ErrorBoundary><Dashboard /></ErrorBoundary>
```

```
[자식 렌더 에러]
       │
       ▼
getDerivedStateFromError ──► state.hasError = true ──► Fallback UI
       │
       └► componentDidCatch ──► 에러 로깅 (Sentry 등)
```

함정: Error Boundary는 **이벤트 핸들러, 비동기 코드, 서버 사이드 렌더링, 자기 자신의 에러는 못 잡는다.** `onClick` 안의 에러는 `try/catch`로, Promise 에러는 `.catch`로 따로 처리해야 한다. 그래서 실무에서는 `react-error-boundary` 라이브러리의 `useErrorHandler()` Hook으로 비동기 에러를 가장 가까운 Boundary로 "다시 던지는" 패턴을 쓴다.

> 💡 **왜 중요한가**: Error Boundary 없이 배포한 React 앱은 자식 트리 어디선가 에러 하나만 나도 **화면 전체가 하얘진다(white screen of death)** — 격리 범위 설계는 선택이 아니라 프로덕션 생존 전략이다.
