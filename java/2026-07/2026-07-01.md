### `Files.mismatch()`로 두 파일의 동일성을 효율적으로 비교하기 (Java 12 정식)

두 파일이 동일한지 확인할 때 전체를 읽어 해시를 비교하거나 바이트 배열로 로드할 필요 없이 `Files.mismatch(Path, Path)` 한 줄로 처리할 수 있습니다. 두 파일의 첫 불일치 바이트 위치(0부터 시작)를 반환하며, 완전히 동일하면 `-1L`을 돌려줍니다. 내부적으로 청크 단위로 비교하므로 메모리 효율이 좋고, 크기가 다르면 즉시 짧은 쪽 길이를 반환해 빠르게 종료합니다.

```java
long pos = Files.mismatch(Path.of("a.bin"), Path.of("b.bin"));
if (pos == -1L) {
    System.out.println("두 파일은 동일합니다");
} else {
    System.out.println("첫 차이 위치: " + pos);
}
```

> 💡 **왜 중요한가**: 직접 스트림을 열고 버퍼를 비교하는 보일러플레이트 없이, 표준 API로 메모리·속도 모두 안전한 파일 비교를 한 줄로 끝낼 수 있습니다.

### `Stream.toList()`로 불변 리스트 수집을 간결하게 (Java 16 정식)

`stream.collect(Collectors.toList())`는 반환 타입이 가변이지만 보장되지 않고, 불변 리스트가 필요하면 `Collectors.toUnmodifiableList()`로 따로 써야 했습니다. Java 16부터는 `Stream.toList()`로 한 단어만에 **null 허용·불변** 리스트를 얻을 수 있어 일상적인 수집 코드를 크게 줄여줍니다. 단, 반환된 리스트는 `add()`·`set()` 호출 시 `UnsupportedOperationException`이 발생하므로 가변이 필요하면 기존 `Collectors.toList()`를 써야 합니다.

```java
List<String> upper = names.stream()
    .filter(Objects::nonNull)
    .map(String::toUpperCase)
    .toList();
```

> 💡 **왜 중요한가**: 의도하지 않은 변경을 컴파일·런타임 양쪽에서 막아주고, 반복 호출되는 `.collect(...)` 보일러플레이트를 없애 스트림 파이프라인의 가독성을 한 단계 끌어올립니다.
