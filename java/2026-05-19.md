### `Stream.toList()`로 불변 리스트를 간결하게 수집하기 (Java 16 정식)
스트림의 종단 연산으로 `collect(Collectors.toList())` 대신 `Stream.toList()`를 사용하면 코드가 짧아지고, 반환되는 리스트가 **수정 불가능한(unmodifiable) 리스트**가 됩니다. 또한 내부적으로 크기를 미리 알 수 있는 경우 배열을 한 번에 할당해 약간의 성능 이점도 있고, `null` 요소도 허용한다는 점에서 `Collectors.toUnmodifiableList()`와 차이가 있습니다.

```java
List<String> names = users.stream()
    .map(User::name)
    .filter(Objects::nonNull)
    .toList();
// names.add("x") → UnsupportedOperationException
```

> 💡 **왜 중요한가**: 의도치 않은 컬렉션 변경을 컴파일 이후 단계에서 차단해 방어적 복사 비용 없이 불변성을 확보할 수 있습니다.

### `CompletableFuture.orTimeout()`과 `completeOnTimeout()`으로 비동기 작업에 타임아웃 부여하기 (Java 9 정식)
`CompletableFuture`에 별도의 스케줄러를 만들지 않고도 `orTimeout(Duration)`으로 지정 시간 내 완료되지 않으면 `TimeoutException`으로 실패시키거나, `completeOnTimeout(value, Duration)`으로 기본값을 채워 완료시킬 수 있습니다. 외부 API 호출이나 DB 쿼리 등에서 무한 대기를 막는 가장 간단한 방법입니다.

```java
CompletableFuture.supplyAsync(() -> callSlowApi())
    .completeOnTimeout("FALLBACK", 2, TimeUnit.SECONDS)
    .orTimeout(5, TimeUnit.SECONDS)
    .thenAccept(System.out::println);
```

> 💡 **왜 중요한가**: 타임아웃 처리를 위해 `ScheduledExecutorService`를 별도로 구성하는 보일러플레이트를 없애 비동기 파이프라인을 견고하게 만들 수 있습니다.
