### 1. `Predicate.not(predicate)` (Java 11 정식)로 람다 없이 조건 반전 — `.filter(s -> !s.isBlank())`처럼 `!` 하나 쓰려고 메서드 레퍼런스를 포기하는 관성 벗어나기

`Predicate.not()`은 메서드 레퍼런스를 그대로 유지한 채 부정만 깔끔하게 씌운다. `import static java.util.function.Predicate.not;`으로 가져오면 `filter(not(String::isBlank))`처럼 자연어에 가까운 흐름이 된다. `Collection::contains`, `Objects::isNull` 같은 기존 메서드 레퍼런스에도 그대로 결합된다.

```java
// Before — ! 때문에 람다로 퇴화
lines.stream().filter(s -> !s.isBlank()).toList();
users.stream().filter(u -> !banned.contains(u.id())).toList();

// After — 메서드 레퍼런스 유지
lines.stream().filter(not(String::isBlank)).toList();
users.stream().filter(not(banned::contains)).toList();
```

> 💡 **왜 중요한가**: `!` 하나 때문에 메서드 레퍼런스가 람다로 내려앉으면, 가독성·정적 분석·IDE 리팩터링이 모두 한 단계씩 흐려진다.

### 2. `Stream.mapMulti((element, consumer) -> ...)` (Java 16 정식, JEP 406)로 0..N 방출 — 작은 결과만 뱉는 상황에서도 `flatMap`이 원소마다 `Stream` 객체를 할당하는 관성 벗어나기

`mapMulti`는 중간 `Stream`을 만들지 않고 `Consumer`에 직접 값을 밀어 넣어 다운스트림으로 흘려보낸다. 원소당 0~소수의 결과를 뽑아내는 경우(조건부 확장, 두세 개 필드 전개, 재귀 전개 등)에 `flatMap` 대비 할당이 거의 없고, 타입 witness(`.<R>mapMulti`)로 타입 추론도 명시적으로 고정할 수 있다.

```java
// Before — 이벤트마다 Stream.of(...) / Stream.empty() 할당 누적
events.stream()
      .flatMap(e -> e.isCritical()
                  ? Stream.of(e.body(), e.alertKey())
                  : Stream.empty())
      .toList();

// After — Stream 생성 없이 Consumer로 직접 방출
events.stream()
      .<String>mapMulti((e, out) -> {
          if (e.isCritical()) {
              out.accept(e.body());
              out.accept(e.alertKey());
          }
      })
      .toList();
```

> 💡 **왜 중요한가**: `flatMap`은 원소마다 짧은 수명의 `Stream`을 찍어낸다 — 뜨거운 루프에서는 GC와 escape analysis 실패 지점이 되기 쉽고, `mapMulti`는 이 비용을 0에 가깝게 줄인다.
