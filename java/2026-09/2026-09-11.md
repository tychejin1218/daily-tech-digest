### 1. `Collectors.flatMapping(mapper, downstream)`로 `groupingBy` 후 `flatMap` 이중 처리 관성 벗어나기 (Java 9 정식)

`groupingBy`로 묶은 뒤 각 그룹의 요소를 다시 컬렉션으로 풀어 헤치는 코드는 보통 `stream().flatMap(...).collect(...)`를 두 번 돌리게 된다. `Collectors.flatMapping(Function<T, Stream<U>>, Collector<U, ?, R>)`은 그룹핑 단계에서 바로 요소를 스트림으로 펼쳐 downstream으로 흘려보내므로, 중첩 컬렉션 → 평탄화 → 재수집의 3단계를 한 번에 접는다. 특히 `Map<Category, List<Tag>>`처럼 값이 컬렉션인 필드를 그룹별로 합칠 때 `mapping` + `reducing` 조합 대신 자연스럽게 읽힌다.

```java
Map<Department, List<String>> skillsByDept = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::department,
        Collectors.flatMapping(e -> e.skills().stream(), Collectors.toList())
    ));
```

> 💡 **왜 중요한가**: `groupingBy` 결과를 두 번째 스트림 파이프라인으로 다시 풀지 않아도 되므로, 중간 컬렉션 할당과 순회 비용이 사라지고 의도가 한 줄에 드러난다.

### 2. `Duration.toMillisPart()` 계열 `*Part()` API로 수동 나머지 연산 관성 벗어나기 (Java 9 정식)

`Duration`에서 "시:분:초.밀리초" 포맷을 만들 때 `toHours()`, `toMinutes() % 60`, `toSeconds() % 60` 같은 나머지 연산을 손으로 계산하는 코드가 여전히 흔하다. Java 9부터 `toHoursPart()`, `toMinutesPart()`, `toSecondsPart()`, `toMillisPart()`, `toNanosPart()`가 정식 도입되어 각 단위의 "잘려나간 나머지"를 바로 반환한다. 60·1000 같은 매직 넘버가 사라지고, 음수 Duration에서도 부호 처리가 일관된다.

```java
Duration elapsed = Duration.between(start, end);
String pretty = String.format("%02d:%02d:%02d.%03d",
    elapsed.toHours(),
    elapsed.toMinutesPart(),
    elapsed.toSecondsPart(),
    elapsed.toMillisPart());
```

> 💡 **왜 중요한가**: `% 60`, `% 1000` 같은 수동 나머지 계산은 단위가 바뀔 때마다 버그 온상이 되는데, `*Part()`는 표준 API가 부호와 단위를 대신 책임져 준다.
