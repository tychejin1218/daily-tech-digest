### 1. `Stream.gatherers(Gatherer)` (Java 24 정식, JEP 485)로 윈도우/슬라이딩/상태있는 중간 연산할 때 `IntStream.range` + 인덱스 접근으로 수동 윈도우 만들거나 `reduce` + `ArrayList`에 담아가며 상태 관리하는 관성 벗어나기

`Stream`의 중간 연산은 `map/filter/flatMap` 정도로 제한적이어서, "3개씩 묶기(windowFixed)", "슬라이딩 윈도우(windowSliding)", "누적 스캔(scan)" 같은 상태 있는 변환은 `Stream` 밖으로 끌어내서 `List`로 뽑은 뒤 `for` 루프로 처리하거나 `reduce`에 가변 `ArrayList`를 억지로 끼워 넣는 식으로 짰다. Java 24에서 정식화된 `Gatherer`는 `Collector`의 중간 연산 버전으로, `stream.gather(Gatherers.windowSliding(3))` 한 줄이면 슬라이딩 윈도우 스트림이 나오고, 커스텀 `Gatherer.ofSequential(initializer, integrator)`로 상태 있는 연산을 선언적으로 끼울 수 있다.

```java
// Before: 슬라이딩 윈도우 수동 구현
List<Integer> data = List.of(1,2,3,4,5);
List<List<Integer>> windows = IntStream.rangeClosed(0, data.size()-3)
    .mapToObj(i -> data.subList(i, i+3))
    .toList();

// After: Gatherers.windowSliding(3)
List<List<Integer>> windows = Stream.of(1,2,3,4,5)
    .gather(Gatherers.windowSliding(3))
    .toList(); // [[1,2,3],[2,3,4],[3,4,5]]
```

> 💡 **왜 중요한가**: `Collector`가 종료 연산 확장 지점이었다면 `Gatherer`는 중간 연산 확장 지점 — 이제 Stream API 밖으로 나가지 않고도 상태 있는 변환을 파이프라인에 그대로 꽂을 수 있다.

### 2. `StructuredTaskScope.open()` (Java 25 정식, JEP 505)으로 여러 가상 스레드 병렬 호출 조율할 때 `CompletableFuture.allOf(...).join()` + 개별 `get()` try-catch로 실패/취소 전파 수동 관리하는 관성 벗어나기

여러 외부 API를 병렬로 부르고 하나라도 실패하면 나머지를 취소해야 하는 경우, `CompletableFuture.supplyAsync` 여러 개 띄우고 `allOf(...).join()` 뒤에 각 `future.get()`을 try-catch로 꺼내는 코드가 표준이었다. 문제는 하나가 터져도 나머지는 계속 돌면서 자원을 낭비한다는 점 — 수동으로 `cancel(true)`를 뿌려야 했다. Java 25에서 정식화된 `StructuredTaskScope`는 부모-자식 스레드의 생명주기를 **구조적**으로 묶어서, scope가 닫히면 자식 태스크들도 자동 취소되고 `Joiner.anySuccessfulResultOrThrow()` / `awaitAllSuccessfulOrThrow()` 같은 조인 정책으로 실패 전파가 선언적으로 끝난다.

```java
// Before: CompletableFuture + 수동 취소
CompletableFuture<User> u = CompletableFuture.supplyAsync(() -> fetchUser(id), vtExec);
CompletableFuture<Order> o = CompletableFuture.supplyAsync(() -> fetchOrder(id), vtExec);
try {
    CompletableFuture.allOf(u, o).get(5, TimeUnit.SECONDS);
    return new Dashboard(u.get(), o.get());
} catch (Exception e) {
    u.cancel(true); o.cancel(true); // 수동 취소
    throw new RuntimeException(e);
}

// After: StructuredTaskScope — scope 닫히면 자동 취소
try (var scope = StructuredTaskScope.open()) {
    var user  = scope.fork(() -> fetchUser(id));
    var order = scope.fork(() -> fetchOrder(id));
    scope.join(); // 하나 실패하면 나머지 자동 취소
    return new Dashboard(user.get(), order.get());
}
```

> 💡 **왜 중요한가**: 가상 스레드로 태스크를 수천 개 뿌리기 쉬워진 만큼 **"언제 멈추고 누가 책임지는가"** 가 더 중요해졌다 — `StructuredTaskScope`는 try-with-resources의 블록 스코프에 스레드 수명을 묶어, 누수와 좀비 태스크를 구조적으로 차단한다.
