### 1. `key`를 바꾸는 것만으로 컴포넌트를 "통째로 리마운트"할 수 있다 — `useEffect`로 state를 초기화하지 마라

유저 ID가 바뀔 때마다 자식 컴포넌트의 폼 상태·스크롤 위치·입력값을 리셋하려고 `useEffect(() => setState(initial), [userId])`를 덕지덕지 붙이는 패턴이 흔하지만, 이건 "리셋해야 할 state 개수만큼 effect가 늘어나는" 안티패턴이다. `<Profile key={userId} />`처럼 key를 바꾸면 React가 "다른 컴포넌트"로 인식해서 언마운트 후 새 인스턴스를 만들기 때문에, 내부 state·ref·effect가 자연스럽게 초기 상태로 돌아간다. "같은 자리에 있지만 사실은 다른 대상"임을 표현하는 선언적 신호가 바로 key다.

> 💡 **왜 중요한가**: state 리셋 로직을 자식에 흩뿌리지 않고 "이건 다른 인스턴스다"라는 사실을 부모가 한 줄로 선언할 수 있어, 리셋 누락 버그와 effect 지옥을 한 번에 없앤다.

### 2. `useTransition`: "무거운 state 업데이트가 input 타이핑을 끊기게 하는" 문제의 해결사 — urgent/non-urgent의 분리

검색창에 타이핑할 때마다 1만 건 리스트를 필터링하면 키 입력이 뚝뚝 끊기는데, 이건 "input 업데이트"와 "리스트 재렌더링"이 같은 우선순위로 동기 처리되기 때문이다. `const [isPending, startTransition] = useTransition()`으로 감싼 `startTransition(() => setQuery(value))`는 그 업데이트를 "급하지 않음(non-urgent)"으로 격하시켜, 더 급한 작업(다음 키 입력)이 들어오면 React가 중간에 버리고 다시 시작한다. `isPending`으로 "지금 뒤에서 느린 렌더가 돌고 있어요" UI를 띄우는 것은 덤.

> 💡 **왜 중요한가**: debounce처럼 "데이터가 늦게 반영되는" 트릭 없이, 입력 반응성과 무거운 렌더링을 동시에 확보할 수 있는 React 18+의 유일한 선언적 수단이다.
