### 1. `ProblemDetail`로 RFC 7807 표준 에러 응답 만들기 (Spring 6+)

Spring 6부터는 `ProblemDetail` 클래스가 내장되어, 별도 DTO를 만들지 않고도 RFC 7807 규격의 에러 응답(`type`, `title`, `status`, `detail`, `instance`)을 반환할 수 있습니다. `@RestControllerAdvice`에서 `ExceptionHandler`가 `ProblemDetail`을 반환하도록 하면 클라이언트가 표준 방식으로 에러를 파싱할 수 있고, `setProperty()`로 커스텀 필드도 추가할 수 있습니다.

```java
@ExceptionHandler(OrderNotFoundException.class)
public ProblemDetail handleOrderNotFound(OrderNotFoundException e) {
    ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
    pd.setType(URI.create("https://api.example.com/errors/order-not-found"));
    pd.setProperty("orderId", e.getOrderId());
    return pd;
}
```

> 💡 **왜 중요한가**: 팀마다 다른 에러 응답 포맷을 고민할 필요 없이, 웹 표준(RFC 7807)을 그대로 따르므로 클라이언트·프론트엔드와의 인터페이스 계약이 단순해집니다.

### 2. `spring.jpa.open-in-view=false`로 OSIV 끄기

Spring Boot는 기본적으로 OSIV(Open Session In View)를 켜서 뷰 렌더링 시점까지 영속성 컨텍스트를 유지합니다. 편리하지만 트랜잭션 밖에서 지연 로딩이 일어나 DB 커넥션이 요청 전체 동안 점유되고, N+1 쿼리가 컨트롤러/뷰 계층에서 숨어 발생하기 쉽습니다. `application.yml`에 `spring.jpa.open-in-view: false`를 설정하면 서비스 계층 트랜잭션 종료 시점에 세션이 닫혀, 지연 로딩 문제를 컴파일 시점이 아닌 개발 초기에 명시적 예외(`LazyInitializationException`)로 드러낼 수 있습니다.

```yaml
spring:
  jpa:
    open-in-view: false
```

> 💡 **왜 중요한가**: 트래픽이 늘어난 뒤에야 커넥션 풀 고갈로 발견되는 성능 문제를, 개발 단계에서 강제로 드러내 서비스 계층에서 필요한 데이터를 명시적으로 로딩하도록 유도합니다.
