### 1. `@TransactionalEventListener(phase = AFTER_COMMIT)`로 트랜잭션 커밋 후에만 이벤트 발행하기

`ApplicationEventPublisher`로 도메인 이벤트를 발행할 때, 일반 `@EventListener`는 트랜잭션 롤백 여부와 무관하게 즉시 실행되어 "주문 저장은 실패했는데 알림은 발송된" 데이터 불일치를 일으킬 수 있습니다. `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`을 쓰면 발행 트랜잭션이 정상 커밋된 시점에만 리스너가 실행되며, `AFTER_ROLLBACK`이나 `BEFORE_COMMIT` 단계도 선택적으로 훅 걸 수 있어 외부 시스템 연동을 안전하게 분리할 수 있습니다.

```java
@Service
public class OrderService {
    private final ApplicationEventPublisher publisher;

    @Transactional
    public void placeOrder(Order order) {
        orderRepository.save(order);
        publisher.publishEvent(new OrderPlacedEvent(order.getId()));
    }
}

@Component
public class OrderNotificationListener {
    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onOrderPlaced(OrderPlacedEvent event) {
        notificationClient.send(event.orderId());
    }
}
```

> 💡 **왜 중요한가**: 도메인 이벤트가 트랜잭션 경계와 동기화되어, 롤백된 작업의 부수효과(외부 알림·결제·메시징)가 실 세계로 새어 나가는 사고를 원천 차단합니다.

### 2. `RestClient`로 `RestTemplate`을 대체하기 (Spring 6.1+)

Spring 6.1부터 도입된 `RestClient`는 `RestTemplate`의 동기 모델과 `WebClient`의 플루언트 API를 결합한 후속 클라이언트로, `WebFlux` 의존성 없이도 `.get().uri().retrieve().body(Type.class)` 형태의 가독성 좋은 호출이 가능합니다. `ResponseSpec`을 통한 상태 코드별 에러 핸들러 등록, `Converter`/`Interceptor` 재사용이 깔끔해 마이그레이션 시 코드량이 30~40% 줄어드는 경우가 많고, 내부적으로 `RestTemplate`과 동일한 `ClientHttpRequestFactory`를 사용해 기존 인프라(Apache HttpClient, JDK HttpClient 등)를 그대로 가져갈 수 있습니다.

```java
@Configuration
public class RestClientConfig {
    @Bean
    RestClient paymentClient(RestClient.Builder builder) {
        return builder
            .baseUrl("https://api.payment.example.com")
            .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + token)
            .defaultStatusHandler(HttpStatusCode::is4xxClientError,
                (req, res) -> { throw new PaymentClientException(res.getStatusCode()); })
            .build();
    }
}

PaymentResult result = paymentClient.post()
    .uri("/charges")
    .contentType(MediaType.APPLICATION_JSON)
    .body(request)
    .retrieve()
    .body(PaymentResult.class);
```

> 💡 **왜 중요한가**: `RestTemplate`은 사실상 유지보수만 되는 레거시이며, `RestClient`는 리액티브 스택을 끌어들이지 않고도 현대적인 API와 더 나은 테스트 지원(`MockRestServiceServer` 호환)을 제공해 신규 프로젝트의 표준 선택지입니다.
