### 1. `String.indent()`와 `String.stripIndent()`로 텍스트 블록의 들여쓰기 제어하기 (Java 13 정식)

`String.indent(int n)`은 각 줄 앞에 공백을 추가하거나 제거하며, `stripIndent()`는 텍스트 블록 컴파일러가 적용하는 부수적 들여쓰기 제거 알고리즘과 동일한 로직을 런타임에 수행합니다. 동적으로 생성한 멀티라인 문자열의 들여쓰기를 정규화할 때 정규식이나 수동 split 없이 간결하게 처리할 수 있습니다.

```java
String code = """
    if (x > 0) {
        return x;
    }
    """;
String indented = code.indent(4);  // 모든 줄 앞에 4칸 추가
String normalized = "  line1\n    line2\n  line3".stripIndent();  // 공통 들여쓰기 제거
```

> 💡 **왜 중요한가**: 코드 생성기, 템플릿 엔진, 로그 포매터에서 들여쓰기 정규화 로직을 직접 구현하지 않고 표준 API로 안전하게 처리할 수 있습니다.

### 2. `Thread.ofVirtual().name(prefix, counter).start()`로 가상 스레드에 디버깅 친화적인 이름 부여하기 (Java 21 정식)

가상 스레드는 기본적으로 익명(`""`)으로 생성되어 스택 트레이스나 스레드 덤프에서 식별이 어렵습니다. `Thread.ofVirtual().name("worker-", 0)` 빌더를 사용하면 카운터가 자동 증가하는 이름을 부여할 수 있고, JFR/스레드 덤프 분석 시 어떤 작업의 가상 스레드인지 즉시 파악할 수 있습니다.

```java
ThreadFactory factory = Thread.ofVirtual()
    .name("order-processor-", 1)
    .factory();
try (var executor = Executors.newThreadPerTaskExecutor(factory)) {
    executor.submit(() -> processOrder(order));  // "order-processor-1", "order-processor-2"...
}
```

> 💡 **왜 중요한가**: 운영 환경에서 수만 개의 가상 스레드가 동시에 실행될 때, 의미 있는 이름은 장애 진단 시간을 극적으로 단축시키며 별도의 추적 컨텍스트 없이도 스레드 덤프만으로 문제를 좁힐 수 있습니다.
