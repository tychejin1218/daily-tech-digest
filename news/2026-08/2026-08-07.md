### 1. Google Cloud Run, 'Service Health' 정식 출시 — 리전 장애를 감지해 자동 페일오버하는 첫 서버리스

Google Cloud Run이 오늘 리전 간 자동 페일오버 기능인 Service Health를 GA로 공개했다. 인스턴스 단위 readiness probe를 표준으로 삼아, 리전 하나가 죽으면 트래픽을 몇 초 안에 다른 리전으로 흘려보낸다. 서버리스 컨테이너가 마침내 "멀티리전 HA는 알아서 해줘"의 영역에 진입한 셈이다.

> 💡 **왜 중요한가**: 지금까지 Cloud Run 사용자는 멀티리전 로드밸런서 + 커스텀 헬스체크를 직접 조립해야 했다. 이제 SRE 손을 거의 안 대고도 리전 장애 대응이 기본값이 된다.

### 2. Google, AlphaEvolve Gemini 코드 최적화 에이전트 전 고객 GA — "알고리즘을 진화시키는 협업자"

DeepMind가 만든 AlphaEvolve가 Google Cloud 전 고객에게 열렸다. 사람이 목적 함수와 제약을 넘겨주면 에이전트가 후보 알고리즘을 계속 변이·평가하며 더 나은 구현을 찾아낸다. 정렬·매칭·스케줄러 같은 "1% 성능이 곧 인프라 비용"인 코드에서 특히 효과를 노린다.

> 💡 **왜 중요한가**: 코딩 에이전트가 "코드를 쓰는" 단계에서 "코드를 진화시키는" 단계로 넘어간 첫 상용 케이스다. 벤치마크와 목적 함수가 새로운 프롬프트가 된다.

### 3. LLM CLI 0.32 릴리스 — reasoning trace·서버사이드 툴·CAS SQLite로 로컬 워크플로 재설계

Simon Willison의 `llm` CLI가 프로젝트 시작 이후 가장 큰 업데이트인 0.32를 냈다. 모델의 reasoning trace를 표시·저장하고, OpenAI Responses·서버사이드 툴 실행 결과를 그대로 로깅하며, 대화 이력을 content-addressable SQLite로 재구성해 중복 저장을 없앤다. "여러 프로바이더를 하나의 로컬 스크립트에서 쓴다"는 사용 패턴이 훨씬 단단해졌다.

> 💡 **왜 중요한가**: 백엔드 개발자가 프로덕션 LLM 호출을 디버깅·감사할 때, 프레임워크 없이도 로컬에서 재현·비교할 수 있는 표준 도구가 생겼다.
