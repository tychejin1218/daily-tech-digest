### `HexFormat`으로 바이트 배열 ↔ 16진수 문자열 변환을 표준 API로 처리하기 (Java 17 정식)

`HexFormat.of().formatHex(byte[])` 하나로 바이트 배열을 16진수 문자열로 변환할 수 있고, 반대로 `parseHex(String)`으로 되돌릴 수도 있습니다. 그동안 `String.format("%02x", ...)` 루프나 Apache Commons Codec, Guava의 `BaseEncoding.base16()`에 의존해야 했던 작업이 JDK 표준 API로 편입된 것입니다. `HexFormat.of().withDelimiter(":").withUpperCase()`로 MAC 주소나 인증서 지문 같은 포맷도 한 줄로 만들 수 있습니다.

```java
byte[] hash = MessageDigest.getInstance("SHA-256").digest("hello".getBytes());

// 기존: String.format 루프 or 외부 라이브러리
StringBuilder sb = new StringBuilder();
for (byte b : hash) sb.append(String.format("%02x", b));

// Java 17+: 표준 API 한 줄
String hex = HexFormat.of().formatHex(hash);
// "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"

// 구분자 + 대문자 포맷 (예: MAC 주소, 인증서 지문)
String fingerprint = HexFormat.ofDelimiter(":").withUpperCase().formatHex(hash);
// "2C:F2:4D:BA:5F:B0:A3:0E:..."

// 역방향 파싱도 표준
byte[] restored = HexFormat.of().parseHex(hex);
```

> 💡 **왜 중요한가**: 해시 값 로깅, 토큰 직렬화, 바이너리 프로토콜 디버깅처럼 실무에서 매일 마주치는 작업에서 외부 라이브러리 의존성을 제거하고 JDK만으로 해결할 수 있습니다.

### `Thread.startVirtualThread(Runnable)`로 가상 스레드를 즉시 시작하기 (Java 21 정식)

`Thread.ofVirtual().start(runnable)`보다 더 짧게, `Thread.startVirtualThread(runnable)` 한 번의 호출로 가상 스레드를 생성하고 즉시 실행할 수 있습니다. 반환값은 시작된 `Thread` 객체이므로 필요하면 `join()`이나 `interrupt()`도 그대로 사용 가능합니다. 팩토리를 만들거나 이름·데몬 설정이 필요 없는 일회성 비동기 작업에 가장 간결한 진입점입니다.

```java
// 기존 팩토리 방식
Thread t1 = Thread.ofVirtual().start(() -> processTask(id));

// Java 21+: 정적 팩토리 한 줄
Thread t2 = Thread.startVirtualThread(() -> processTask(id));

// 실무 예: 대량의 I/O 작업을 fire-and-forget으로 던지기
List<Thread> workers = orders.stream()
    .map(order -> Thread.startVirtualThread(() -> sendNotification(order)))
    .toList();

for (Thread w : workers) w.join(); // 모두 끝날 때까지 대기

// 플랫폼 스레드와 달리 수만 개를 동시에 띄워도 OS 스레드는 소량만 사용
```

> 💡 **왜 중요한가**: 가상 스레드의 진입 장벽을 최소한으로 낮춰, `new Thread(r).start()` 수준의 문법적 부담만으로 I/O 바운드 작업을 수만 개 병렬 처리할 수 있습니다.
