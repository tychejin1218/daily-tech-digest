### 1. `SslBundles`로 SSL 키스토어/트러스트스토어 설정을 중앙화하기

Spring Boot 3.1+에서 도입된 `SslBundles`는 여러 클라이언트(`RestClient`, `WebClient`, `RestTemplate`, Kafka 등)가 공유하는 SSL 설정을 `application.yaml`의 `spring.ssl.bundle.*`에 이름으로 묶어 정의하고, `SslBundles.getBundle("name")`으로 주입받아 적용할 수 있게 해줍니다. 인증서 경로·비밀번호가 코드와 설정 곳곳에 흩어지는 문제를 없애고, 핫 리로드(`reload-on-update: true`) 한 줄로 운영 중 인증서 교체도 무중단으로 처리할 수 있습니다.

> 💡 **왜 중요한가**: mTLS·사내 PKI를 사용하는 환경에서 인증서 갱신마다 빌드/재배포 없이 설정 한 곳만 바꾸면 모든 HTTP 클라이언트와 서버가 새 인증서를 즉시 반영하므로, 운영 부담과 만료 사고 위험이 크게 줄어듭니다.

### 2. `@Observed`와 `ObservationRegistry`로 메트릭·트레이스를 어노테이션 한 줄로 수집하기

Spring Boot 3.0+ Micrometer Observation API의 `@Observed`를 메서드(또는 클래스)에 붙이면 해당 호출 구간에 대해 타이머 메트릭(`http.server.requests` 스타일)과 분산 트레이스 스팬이 자동으로 생성됩니다. 활성화하려면 `micrometer-observation`과 `spring-boot-starter-aop` 의존성을 추가하고, `ObservedAspect`를 빈으로 등록(`@Bean ObservedAspect observedAspect(ObservationRegistry r) { return new ObservedAspect(r); }`)하기만 하면 되며, `name`·`contextualName`·`lowCardinalityKeyValues`로 서비스 단위 라벨까지 일관되게 부여할 수 있습니다.

> 💡 **왜 중요한가**: 도메인 서비스·외부 연동 메서드 등 "HTTP 경계 바깥"의 핵심 비즈니스 로직까지 코드 변경 없이 메트릭/트레이스가 붙어, Grafana·Tempo·Zipkin에서 병목 원인을 컨트롤러 단이 아닌 실제 호출 지점까지 끝까지 추적할 수 있습니다.
