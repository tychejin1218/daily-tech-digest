### PostgreSQL `SKIP LOCKED`로 작업 큐 만들기

`SELECT ... FOR UPDATE SKIP LOCKED`는 이미 다른 트랜잭션이 잠근 행을 건너뛰고 다음 잠글 수 있는 행을 반환한다. 별도 메시지 브로커 없이 DB 테이블만으로 여러 워커가 경합 없이 작업을 나눠 처리하는 안전한 큐를 만들 수 있다.

```sql
-- 워커가 처리할 다음 작업 하나 잠금 획득
BEGIN;
SELECT id, payload
FROM jobs
WHERE status = 'pending'
ORDER BY created_at
LIMIT 1
FOR UPDATE SKIP LOCKED;

-- 처리 후
UPDATE jobs SET status = 'done' WHERE id = $1;
COMMIT;
```

> 💡 **왜 중요한가**: Redis·Kafka를 도입하기 전에, DB 하나만으로도 신뢰성 있는 작업 큐를 만들 수 있다.

### MySQL `SEQUENCE` 대신 `AUTO_INCREMENT`의 `innodb_autoinc_lock_mode`

`innodb_autoinc_lock_mode=2`(interleaved)로 설정하면 다중 행 INSERT 시 auto-increment 잠금을 문장 단위로 잡지 않아 동시성이 크게 향상된다. 다만 `binlog_format=STATEMENT`에서는 복제본과 마스터의 ID가 어긋날 수 있으므로 `ROW` 포맷과 함께 사용해야 안전하다.

```ini
# my.cnf
innodb_autoinc_lock_mode = 2   # interleaved
binlog_format = ROW
```

- `0` (traditional): 항상 테이블 락 — 안전하지만 느림
- `1` (consecutive, 기본): 단일 INSERT는 경량 락, 벌크는 테이블 락
- `2` (interleaved): 락 최소화, 대량 삽입 처리량 최대

> 💡 **왜 중요한가**: 대량 배치 INSERT의 처리량은 auto-increment 락 전략 하나로 수 배 차이가 난다.
