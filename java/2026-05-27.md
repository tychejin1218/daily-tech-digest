### `SequencedCollection`으로 컬렉션의 첫·끝 원소를 통일된 API로 다루기 (Java 21 정식)

`List`, `LinkedHashSet`, `LinkedHashMap`, `Deque` 등 "순서가 있는" 컬렉션이 `SequencedCollection`·`SequencedMap` 인터페이스를 구현하게 되어, `getFirst()`·`getLast()`·`addFirst()`·`addLast()`·`reversed()`를 동일한 방식으로 쓸 수 있습니다. 기존에 마지막 원소를 꺼내려면 `list.get(list.size() - 1)`처럼 컬렉션마다 다른 관용구가 필요했고 `LinkedHashSet`은 아예 전체 순회를 해야 했지만, 이제 한 가지 메서드로 끝납니다. `reversed()`는 원본을 복사하지 않는 뷰(view)라 역순 순회도 메모리 부담 없이 가능합니다.

```java
var list = new ArrayList<>(List.of("a", "b", "c"));
list.getFirst();      // "a"  (= get(0))
list.getLast();       // "c"  (= get(size()-1))
list.addFirst("z");   // [z, a, b, c]
list.reversed();      // [c, b, a, z]  (원본을 비추는 뷰)

var map = new LinkedHashMap<String, Integer>();
map.putLast("x", 1);
map.firstEntry();     // 삽입 순서상 첫 엔트리
```

> 💡 **왜 중요한가**: 컬렉션 종류마다 제각각이던 "앞/뒤 접근" 코드를 표준 메서드 하나로 통일해 가독성과 일관성을 동시에 높여줍니다.

### `Stream.gather()`와 `Gatherers`로 슬라이딩 윈도우 같은 커스텀 중간 연산 만들기 (Java 24 정식)

`Collector`가 종단 연산(`collect`)을 확장하는 도구였다면, `Gatherer`는 `map`·`filter` 같은 **중간 연산**을 직접 정의하게 해주는 도구입니다. 기본 제공되는 `Gatherers.windowFixed(n)`·`windowSliding(n)`·`scan(...)`·`fold(...)`·`mapConcurrent(...)`만으로도 표준 스트림 연산으로는 까다롭던 고정/슬라이딩 윈도우, 누적 스캔, 동시성 매핑을 한 줄로 표현할 수 있습니다. 상태를 가지는 1:N 변환을 직접 구현할 수도 있어 스트림 파이프라인의 표현력이 크게 넓어집니다.

```java
import java.util.stream.Gatherers;

// 2개씩 묶기
Stream.of(1, 2, 3, 4, 5)
      .gather(Gatherers.windowFixed(2))
      .toList();                       // [[1, 2], [3, 4], [5]]

// 누적 합(scan)
Stream.of(1, 2, 3, 4)
      .gather(Gatherers.scan(() -> 0, Integer::sum))
      .toList();                       // [1, 3, 6, 10]

// 동시 매핑(가상 스레드 활용, 최대 4개 병렬)
urls.stream()
    .gather(Gatherers.mapConcurrent(4, this::fetch))
    .toList();
```

> 💡 **왜 중요한가**: 그동안 외부 라이브러리나 어색한 우회 코드가 필요하던 "상태 있는 중간 연산"을 표준 API로 깔끔하게 작성할 수 있게 되었습니다.
