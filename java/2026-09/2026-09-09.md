### 1. `Collectors.partitioningBy(predicate, downstream)`로 이진 분류 후 집계를 한 번에 처리하기

`groupingBy`로 `true`/`false` 두 그룹만 나눌 때 습관적으로 `groupingBy(pred, counting())`을 쓰지만, 이진 분류는 `partitioningBy`가 전용 최적화 경로입니다. 내부적으로 `HashMap` 대신 두 슬롯짜리 구조를 쓰기 때문에 해시 계산·리사이징 오버헤드가 없고, 결과 Map은 항상 `true`/`false` 두 키를 보장하므로 `getOrDefault` 방어 코드도 사라집니다.

```java
Map<Boolean, Long> byStatus = orders.stream()
    .collect(Collectors.partitioningBy(
        Order::isPaid,
        Collectors.counting()));

long paid = byStatus.get(true);   // null 걱정 없음
long unpaid = byStatus.get(false);
```

> 💡 **왜 중요한가**: "그룹이 정확히 둘"이라는 도메인 사실을 타입 시스템과 컬렉터 선택에 반영하면, 런타임 방어 코드와 해시맵 오버헤드를 동시에 없앨 수 있습니다.

### 2. `Thread.startVirtualThread(Runnable)`로 짧은 일회성 비동기 작업의 보일러플레이트 벗어나기 (Java 21 정식)

가상 스레드를 시작할 때 매번 `Executors.newVirtualThreadPerTaskExecutor()`를 열거나 `Thread.ofVirtual().start(...)`를 쓸 필요 없이, 짧은 fire-and-forget 작업은 `Thread.startVirtualThread(r)` 한 줄이면 충분합니다. 이 메서드는 새 가상 스레드를 만들어 즉시 시작하고 `Thread` 객체를 반환하므로 필요하면 `join()`으로 대기하거나 이름을 부여할 수 있습니다.

```java
Thread t = Thread.startVirtualThread(() -> {
    log.info("배경 정리 작업 실행");
    cleanupTempFiles();
});

// 필요하면 대기
t.join();
```

주의: 반환된 `Thread`를 붙잡지 않으면 관측·취소·대기 수단이 사라지므로, 결과가 필요한 워크로드는 여전히 `StructuredTaskScope`나 `ExecutorService`로 감싸야 합니다.

> 💡 **왜 중요한가**: "이 작업 하나만 별도 스레드로 던지고 싶다"는 가장 흔한 요구를 표준 API 한 줄로 표현할 수 있으면, 잘못된 스레드 풀 재사용이나 executor 누수 같은 실수를 원천 차단할 수 있습니다.
