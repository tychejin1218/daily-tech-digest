### 1. PostgreSQL `EXCLUDE USING gist` + `tstzrange` — 예약 시간대 겹침을 DB 제약으로 원천 차단하기
회의실 예약, 강의실 배정처럼 "같은 자원의 시간대가 겹치면 안 된다"는 규칙을 애플리케이션 코드에서 `SELECT ... FOR UPDATE` + 겹침 검사로 구현하면 경쟁 조건이 남기 쉽습니다. `btree_gist` 확장을 켠 뒤 `EXCLUDE USING gist (room_id WITH =, during WITH &&)` 제약을 걸면, DB가 인덱스 레벨에서 `&&`(겹침) 연산자로 검증해 동시 INSERT 두 개 중 하나가 반드시 실패합니다.

> 💡 **왜 중요한가**: 도메인 규칙 중 "겹치면 안 됨" 같은 조건은 애플리케이션 락으로 지키면 취약하지만, 배타 제약은 트랜잭션 격리 수준과 무관하게 완벽히 보장됩니다.

### 2. Hibernate `@Filter` — 소프트 삭제·멀티테넌시 조건을 세션 레벨에서 자동 주입하기
`deleted = false`나 `tenant_id = :current`를 매 쿼리 `WHERE`마다 붙이는 대신, 엔티티에 `@FilterDef` + `@Filter("deleted = :isDeleted")`를 정의하고 세션 시작 시 `session.enableFilter("activeFilter").setParameter(...)` 한 번만 하면, 이후 모든 JPQL·연관관계 로딩에 자동으로 조건이 붙습니다. `@Where`와 달리 런타임에 켜고 끌 수 있어서 관리자 화면에서 삭제 데이터 조회할 때 유용합니다.

> 💡 **왜 중요한가**: `@Where`는 정적이라 조건 해제가 불가능하고, 매 Repository에서 조건을 붙이면 누락 위험이 큽니다. `@Filter`는 횡단 관심사를 인프라 레벨로 끌어올려 실수를 원천 봉쇄합니다.
