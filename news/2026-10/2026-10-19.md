### 1. OpenAI 'aurora-red/green/blue-alpha' 3종, 발표 없이 API 모델 리스트에 등장 — 10/19 주 공개 루머에 불이 붙었다

10월 17일 새벽(UTC 01:13~01:15) OpenAI의 API `/v1/models`에 `aurora-red-alpha`, `aurora-green-alpha`, `aurora-blue-alpha` 세 식별자가 공지 없이 추가됐고, 10/18 커뮤니티가 발견했다. `aurora-red-alpha`는 404가 아닌 503(용량 부족)을 돌려주며 백엔드가 이미 결선됐음을 암시하고, 나머지 둘은 아직 404 — "10/19 주에 신모델을 공개한다"는 루머와 맞물려 Codex 계열 코딩 특화일 가능성이 유력하다.

> 💡 **왜 중요한가**: OpenAI가 '공식 발표 → 롤아웃' 순서를 뒤집어 '백엔드 결선 → 조용히 띄우기 → 발표'로 가고 있다는 신호 — API 모델 리스트가 사실상 비공식 체인지로그가 됐다.

### 2. Reflection AI 'Beam' 501B MoE 오픈웨이트 Apache 2.0 공개 — 'Kimi K3 급은 아니지만 추론 효율이 무기'라는 포지셔닝

10월 5일 공개된 501B 파라미터 / 23B 활성 희소 MoE 모델 Beam이, 10월 16일 Hugging Face에 BF16·FP8·NVFP4 세 정밀도 + 스펙큘러티브 디코딩 드래프터까지 Apache 2.0으로 풀렸다. Reflection은 23.8T 토큰 사전학습 + GB300 10.5K장 4주짜리 RL(1억+ 롤아웃)로 Qwen 3.8-Max·GLM 5.2에 근접했다고 밝히면서도 "Kimi K3가 아직 앞선다"는 걸 인정했고, 대신 "추론 시 효율"을 셀링포인트로 내세웠다.

> 💡 **왜 중요한가**: 오픈웨이트 코딩/에이전트 모델이 '벤치 1등'이 아니라 '토큰당 비용·레이턴시'로 경쟁하는 국면에 들어왔다 — 자체 서빙하는 팀은 이제 '뭐가 제일 똑똑하냐'가 아니라 '뭐가 내 GPU 예산에 맞냐'로 질문이 바뀐다.

### 3. Neon 'Realtime' 퍼블릭 베타 — Postgres 쿼리를 WebSocket처럼 'subscribe'한다, 코딩 에이전트의 상태 추적 패턴이 바뀐다

10월 15일 Neon이 Lakebase Postgres 위에서 모든 SQL 쿼리를 라이브 쿼리로 바꾸는 Realtime을 퍼블릭 베타로 열었다. 쿼리를 구독하면 기저 데이터가 바뀔 때마다 결과가 자동으로 최신화되고 — scale-to-zero·브랜칭·SSR·낙관적 쓰기까지 그대로 — 폴링/리페치 로직이 사라진다. 공식 블로그가 "에이전트가 세팅할 수 있는 프리미티브(primitive coding agents can set up)"라고 명시해 코딩 에이전트가 DB 상태를 '구독'하는 패턴을 겨냥했다.

> 💡 **왜 중요한가**: 지금까지 에이전트가 DB 상태를 추적하려면 `SELECT ... WHERE updated_at >` 를 폴링해야 했다 — Neon이 이걸 '구독'으로 뒤집으면서, "에이전트 1개당 DB 1개"의 다음 단계인 "에이전트 1개당 라이브 쿼리 N개"가 열렸다.
