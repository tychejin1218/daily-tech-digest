### 1. `TaskDecorator`로 `@Async`·`@Scheduled` 스레드에 MDC/SecurityContext 전파하기
`ThreadPoolTaskExecutor`에 커스텀 `TaskDecorator`를 등록하면 비동기 스레드로 작업이 넘어가도 로깅 MDC, Spring Security의 `SecurityContext`, `LocaleContext` 같은 `ThreadLocal` 값이 그대로 이어집니다. 기본 설정으로는 `@Async` 실행 순간 이 컨텍스트가 전부 유실되어 로그 상관관계(correlation ID)가 끊기거나 인증 정보가 사라지는 사고가 자주 납니다.

```java
public class ContextCopyingDecorator implements TaskDecorator {
    @Override
    public Runnable decorate(Runnable runnable) {
        Map<String, String> mdc = MDC.getCopyOfContextMap();
        SecurityContext sc = SecurityContextHolder.getContext();
        return () -> {
            try {
                if (mdc != null) MDC.setContextMap(mdc);
                SecurityContextHolder.setContext(sc);
                runnable.run();
            } finally {
                MDC.clear();
                SecurityContextHolder.clearContext();
            }
        };
    }
}
```

> 💡 **왜 중요한가**: 비동기 작업의 로그 추적성과 인가 정보를 잃지 않아 운영·보안 사고를 원천 차단합니다.

### 2. `hibernate.jdbc.batch_size` + `order_inserts=true`로 JPA 벌크 INSERT 성능 극대화하기
JPA로 수백~수천 건을 저장할 때 기본값은 한 건씩 INSERT를 날리므로 라운드트립 오버헤드가 폭발합니다. `spring.jpa.properties.hibernate.jdbc.batch_size=50` 정도로 배치 크기를 설정하고, `order_inserts=true`, `order_updates=true`를 함께 켜면 같은 테이블끼리 묶어 JDBC 배치가 실제로 활성화되어 INSERT/UPDATE가 십수 배 빨라집니다. 단, `IDENTITY` 전략은 배치가 무효화되므로 `SEQUENCE`(또는 `pooled` optimizer)로 전환해야 효과가 납니다.

```yaml
spring:
  jpa:
    properties:
      hibernate:
        jdbc.batch_size: 50
        order_inserts: true
        order_updates: true
        batch_versioned_data: true
```

> 💡 **왜 중요한가**: 대량 데이터 마이그레이션·집계 저장 작업의 응답시간과 DB 커넥션 점유 시간을 극적으로 줄일 수 있습니다.
